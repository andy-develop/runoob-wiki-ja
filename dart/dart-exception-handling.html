Dart 例外処理

例外とは、プログラムの実行中に発生するエラーイベントです。

適切な例外処理により、プログラムはエラーに遭遇した際に直接クラッシュするのではなく、優雅に機能を低下させることができます。

この章では、Dart の try/catch/finally、throw による例外スロー、on による指定型のキャッチ、rethrow による再スローを紹介します。

try / catch / finally の基本

try ブロックには例外をスローする可能性のあるコードを置き、catch ブロックは例外をキャッチして処理し、finally ブロックは例外の有無にかかわらず実行されます。

例

void main() {
  // 基本的な try-catch
  try {
    int result = 10 ~/ 0;  // ゼロ除算は例外をスローする
    print('結果: $result');  // この行は実行されない
  } catch (e) {
    // e は例外オブジェクト
    print('例外をキャッチ: $e');
  }

  // 例外とスタック情報を取得する
  try {
    List<int> numbers = [1, 2, 3];
    print(numbers[10]);  // 範囲外インデックスにアクセス
  } catch (e, stackTrace) {
    // e は例外、stackTrace はコールスタック
    print('RUNOOB 例外: $e');
    print('スタック情報:\n$stackTrace');
  }

  // finally: 例外の有無にかかわらず実行される
  try {
    print('操作を実行しています...');
    int result = 5 ~/ 0;
    print('この行は実行されません: $result');
  } catch (e) {
    print('エラー: $e');
  } finally {
    // finally ブロックのコードは常に実行され、リソースのクリーンアップに使用される
    print('リソースのクリーンアップ完了（finally は常に実行される）');
  }
}

finally ブロックはリソースのクリーンアップに最適です。ファイルのクローズやデータベース接続の解放などに使用します。try または catch 内に return 文がある場合でも、finally は必ず実行されます。

throw で例外をスローする

throw キーワードを使用すると、能動的に例外をスローできます。

Dart では例外として任意のオブジェクトをスローできます（Exception のサブクラスだけでなく）。ただし、ベストプラクティスは Exception または Error のサブクラスをスローすることです。

例

// カスタム例外クラスを定義
class InvalidAgeException implements Exception {
  final int age;
  final String message;

  InvalidAgeException(this.age)
      : message = '無効な年齢: $age（年齢は0から150の間である必要があります）';

  @override
  String toString() => 'InvalidAgeException: $message';
}

// カスタム例外を使用する関数
void validateAge(int age) {
  if (age < 0) {
    throw InvalidAgeException(age);
  }
  if (age > 150) {
    throw InvalidAgeException(age);
  }
  print('年齢 $age は検証に合格しました');
}

// 組み込み例外をスローする
int divide(int a, int b) {
  if (b == 0) {
    throw ArgumentError('除数は0にできません');  // 組み込み例外を使用する
  }
  return a ~/ b;
}

void main() {
  // カスタム例外をテストする
  try {
    validateAge(-5);
  } catch (e) {
    print(e);
  }

  try {
    validateAge(200);
  } catch (e) {
    print(e);
  }

  validateAge(25);  // 正常なケース

  // 組み込み例外のスローをテストする
  try {
    divide(10, 0);
  } catch (e) {
    print('RUNOOB エラー: $e');
  }
}

Exception と Error の違い: Exception は予測可能で、プログラムが処理できるエラーです（例: ネットワークタイムアウト、ファイルが存在しない）。Error は予測不可能で、通常はプログラムのバグを示す問題です（例: 型エラー、ヌルポインタ）。コードでは Error ではなく Exception をキャッチすべきです。

on で指定型をキャッチする

on キーワードを使うと、例外の型ごとにキャッチでき、エラー処理をより細かく行えます。

例

void main() {
  // 型に応じて異なる例外をキャッチする
  try {
    // 異なるタイプの例外をシミュレートする
    int result = performOperation('divide_by_zero');
    print('結果: $result');
  } on IntegerDivisionByZeroException {
    // ゼロ除算例外のみキャッチする
    print('RUNOOB エラー: ゼロで割れません');
  } on FormatException catch (e) {
    // フォーマット例外をキャッチし、同時に例外情報を取得する
    print('RUNOOB フォーマットエラー: ${e.message}');
  } on RangeError {
    // 範囲エラーのみキャッチする
    print('RUNOOB エラー: インデックスが範囲外');
  } catch (e) {
    // フォールバック: その他のすべての例外をキャッチする
    print('未知のエラー: $e');
  } finally {
    print('操作終了\n');
  }

  // 順番にマッチングする例
  print('--- 異なる操作をテスト ---');
  for (var op in ['divide_by_zero', 'parse_error', 'out_of_range', 'normal']) {
    try {
      performOperation(op);
    } on IntegerDivisionByZeroException {
      print('$op -> ゼロ除算例外');
    } on FormatException {
      print('$op -> フォーマット例外');
    } on RangeError {
      print('$op -> 範囲例外');
    } catch (e) {
      print('$op -> その他の例外: $e');
    }
  }
}

int performOperation(String operation) {
  switch (operation) {
    case 'divide_by_zero':
      return 10 ~/ 0;  // IntegerDivisionByZeroException をスローする
    case 'parse_error':
      int.parse('not_a_number');  // FormatException をスローする
      return 0;
    case 'out_of_range':
      var list = [1, 2, 3];
      return list[100];  // RangeError をスローする
    case 'normal':
      return 42;
    default:
      throw Exception('未知の操作');
  }
}
RUNOOB 错误: 不能除以零
操作结束

--- 测试不同的操作 ---

parse_error -> 格式异常
out_of_range -> 范围异常

on と catch の並び順は重要です。Dart は上から下の順に例外型をマッチングします。より具体的な例外型は前に、より汎用的なものは後ろに置く必要があります。catch (e) を一番前に置くと、後ろの on は決して実行されません。

rethrow で再スローする

例外をキャッチした後に何らかの処理（例: ログ記録）を行い、その後で例外を上位へ伝播させ続けたい場合があります。

rethrow キーワードは、現在キャッチした例外を再スローし、元のスタック情報を保持するために使います。

例

// 多層呼び出しのシナリオをシミュレートする
void databaseOperation() {
  print(' データベースに接続しています...');
  throw Exception('RUNOOB データベース接続失敗');
}

void serviceLayer() {
  try {
    print(' サービス層: データベース操作を呼び出し');
    databaseOperation();
  } catch (e) {
    // 最初にログを記録し、その後再スローする
    print(' [ログ] データベース操作例外: $e');
    rethrow;  // 元の例外とスタックを保持し、上位へ伝播し続ける
  }
}

void controllerLayer() {
  try {
    print('コントローラー層: リクエストを処理');
    serviceLayer();
  } catch (e, stackTrace) {
    // 最外層でキャッチして処理する
    print('コントローラー層が例外をキャッチ');
    print('エラー情報: $e');
    print('ユーザーに返す: "サービスは一時的に利用できません。後でもう一度お試しください"');
  }
}

void main() {
  controllerLayer();
  print('\n'--- rethrow と throw e の違い ---');

  // rethrow と throw e の違いをデモする
  try {
    try {
      throw FormatException('元の例外');
    } catch (e) {
      // throw e: スタック情報がリセットされ、元の呼び出し位置が失われる
      print('throw e を使用（元のスタックが失われる）...');
      throw e;  // スタックはここから始まる
    }
  } catch (e, stack) {
    print('キャッチ: $e');
    print('スタックはここを指す（元の位置ではない）:\n$stack');
  }
}

rethrow と throw e の違いは非常に重要です。rethrow は元の例外のすべてのスタック情報を保持し、問題の根本を特定しやすくします。throw e はスタックをリセットし、現在の位置から再開します。ログ記録後に例外を伝播させ続ける必要がある場合は、rethrow を使用してください。

例外処理のベストプラクティス

実践説明
処理できる例外のみキャッチする「エラーを出さない」ためだけに盲目的にすべての例外を catch しないでください。処理方法がわからない場合は、上位に伝播させましょう
型ごとにキャッチするon で例外型を指定し、1つの catch で全例外を飲み込まないようにする
finally でリソースをクリーンアップファイルやネットワーク接続などのリソースは finally でクローズする
例外を飲み込まない例外をキャッチしたのに何もしない（空の catch ブロック）のは危険です。少なくともログを記録しましょう
rethrow を使用するログ記録後に例外を伝播させ続ける必要がある場合は、throw e ではなく rethrow を使う
例外メッセージは具体的にthrow Exception('データベース接続失敗: 192.168.1.1:3306') は throw Exception('エラーが発生しました') よりも有用です
