メモリアドレスとアドレッシング

プログラムで変数を宣言したとき、コンピュータはどうやってその変数を「見つける」のか？なぜ32ビットシステムでは4GBメモリモジュールしか挿せないのか？

この講義ではメモリアドレスの謎を解き明かし、アドレス空間—コンピュータが使用できるメモリの大きさを決める根本的な制約—を理解する手助けをします。

生活に身近な例え：アパートの郵便受け

アパートの建物を想像してください。各部屋には独立した郵便受けがあり、それぞれに唯一無二の部屋番号が付いています。

配達員は手紙を届けるとき、部屋番号（アドレス）を知っていれば、正確に対応する郵便受けに手紙を入れられます。CPUがメモリにアクセスする方法は、配達員が手紙を投函する方法とほぼ同じです：

  • 各メモリセル（1バイト）= 郵便受け1つ
  • メモリアドレス= 郵便受けの部屋番号（0から始まる番号）
  • アドレスバスの幅= 部屋番号の最大桁数（最大でいくつの番号を割り当てられるかを決める）

部屋番号が2桁（00〜99）しかなければ、この建物には最大で100個の郵便受けしかありません。同様に、アドレスバスが32ビット幅しかなければ、CPUは最大2^32個の異なるメモリセルを区別できるだけです。

メモリアドレスの本質

アドレスとは番号のこと

ハードウェアの観点から見ると、メモリは0と1を格納できる物理セルが一列に並んだものです。各セルは1バイト（8ビット）を格納し、各セルには一意の番号があります。この番号がメモリアドレスです。

CPUは3つのバスからなるシステムを介してメモリを読み書きします：

  1. CPUは対象アドレスをアドレスバスに載せます—「103番の郵便受けを探します」
  2. CPUはコントロールバスに「読み取り」または「書き込み」信号を送ります—「中身をください」または「これを入れてください」
  3. メモリはデータをデータバスに載せ（読み取り）、またはデータバスからデータを取り去ります（書き込み）

なぜ各アドレスが1バイトに対応するのか？

これは設計上の選択です。初期のコンピュータには「ワードアドレッシング」（各アドレスが2バイトまたは4バイトに対応）を採用したものもありましたが、現代のコンピュータはほぼすべてバイトアドレッシング—各アドレスが1バイトに対応します。

この利点：文字（ASCIIでは各文字が1バイト）を処理する際に非常に自然で、追加のアライメントや分割のロジックが不要です。

内存地址：  0      1      2      3      4      5      6      7
         +------+------+------+------+------+------+------+------+
内容：    | 0x48 | 0x65 | 0x6C | 0x6C | 0x6F | 0x00 | 0xFF | ... |
         +------+------+------+------+------+------+------+------+
           'H'    'e'    'l'    'l'    'o'    '\0'

一个 32 位整数 0x12345678 在内存中的存储（小端序）：
地址：    0      1      2      3
         +------+------+------+------+
内容：    | 0x78 | 0x56 | 0x34 | 0x12 |
         +------+------+------+------+
          低字节在低地址——这就是「小端序」(Little Endian)

なぜ32ビットシステムでは最大4GBメモリしか使えないのか

直接の原因：アドレスバスの幅

32ビットのアドレスは、32個の0または1で構成される2進数です。

32ビットで表現できる異なる値の数は：

2^32 = 2 × 2 × 2 × ...（32回）=4,294,967,296

すなわち約4GB（GigaBytes）。

各アドレスが1バイトに対応する場合、32ビットアドレス空間で合計4,294,967,296バイト = 4GBをアドレス指定できます。

導出計算

1 KB  = 2^10 字节 = 1,024 字节
1 MB  = 2^20 字节 = 1,048,576 字节
1 GB  = 2^30 字节 = 1,073,741,824 字节

2^32  = 2^2 × 2^30
      = 4 × 1 GB
      = 4 GB

したがって、32ビット = 4GBこれは偶然ではなく、アドレスのビット数とアドレス可能空間の間の厳密な数学的関係です。

例え：電話番号の桁数

ある都市の電話番号が8桁（00000000〜99999999）だと仮定すると、この都市には最大でいくつの異なる電話番号があり得るでしょうか？

10^8 = 1億個です。人口が1億を超えると、8桁では足りなくなります—9桁にアップグレードする必要があります。

同じ論理で：32ビットアドレスを限界まで使っても4GBです。メモリ需要が4GBを超えると、32ビットシステムでは対応できません—これが業界全体が64ビットへ移行した理由です。

64ビットの意味

64ビットアドレス空間の理論上の上限は：

2^64 = 18,446,744,073,709,551,616 バイト ≈16 EB（ExaBytes）

この数字はどれくらい大きいのでしょうか？

  • 1 EB = 10億 GB
  • 16 EBは、2025年の世界のインターネットにおける1日分のデータトラフィックの数百倍に相当します
  • もし各バイトが砂1粒だとしたら、16 EBの砂で約2000個の標準プールを埋められます。

現在、これほど大きなメモリをサポートするコンシューマ向けマザーボードはありません。現代の64ビットCPUは通常、48ビットの物理アドレスラインのみを実装しており（256 TBをアドレス指定可能）、Windows 10 Homeは128 GBに制限されています—しかし、現在および予見可能な将来にとっては、これで「十分」です。

64ビットの本当の意味は、どれだけ大きなメモリを挿せるかではなく、次の点にあります：ソフトウェアとOSは、アドレス空間の不足に対して様々な回避策を考える必要がなくなります（例：32ビット時代のPAE—物理アドレス拡張）。

    if unit_idx == 0:
        return f"{int(value):,} {units[unit_idx]}"
    elif value >= 100:
        return f"{value:,.0f} {units[unit_idx]}"
    elif value >= 10:
        return f"{value:,.1f} {units[unit_idx]}"

PAE：32ビットシステムの「延命」策

64 ビットが普及する前、4GB の制限に直面し、Intel は回避策を設計しました——PAE（物理アドレス拡張）。

PAE は物理アドレス線を 32 ビットから 36 ビットに拡張し、32 ビット CPU が最大 2^36 = 64 GB の物理メモリをアドレス指定できるようにします。

しかし、ここには重要な制限があります：各プロセスの仮想アドレス空間は依然として 32 ビット（4GB）です。単一のプログラムは依然として最大 4GB のメモリしか使用できません。PAE の利点は、サーバーがより多くのプログラムを同時に実行でき、各プログラムがそれぞれ独自の 4GB を使用できることです。

PAE はあくまでも過渡的な対策であり、本当の解決策は全面的に 64 ビットへ移行することです。

仮想アドレス vs 物理アドレス

先ほど説明した「アドレス」は主に物理アドレス——メモリモジュール上の実際の、ハードウェアレベルの番号です。

しかし、現代のオペレーティングシステムでは、あなたが書いたプログラムが見るアドレスは物理アドレスではなく、仮想アドレス。

なぜ仮想アドレスが必要なのか？

  1. 隔離保護：プログラム A はプログラム B のメモリを読み書きできません（そうでなければ、クラッシュしたプログラムがシステム全体を破壊する可能性があります）。
  2. プログラミングの簡素化：各プログラムは自分がアドレス空間全体（たとえば 0 から 4GB）を独占していると思い込み、他のプログラムがどのアドレスを使っているかを気にする必要がありません。
  3. 柔軟なメモリ管理：オペレーティングシステムは使用頻度の低いメモリを一時的にハードディスクに書き出し（スワップ/ページング）、必要なときに読み戻すことができます。

CPU 内部にはハードウェアユニットがあり、MMU（メモリ管理ユニット）と呼ばれ、仮想アドレスをリアルタイムで物理アドレスに変換する役割を担っています。

程序看到的虚拟地址 → [MMU 翻译] → 物理地址 → [地址总线] → 内存条

程序写:  *(0x08048000) = 42
         ↓
MMU 查表: 虚拟页 0x08048 → 物理页 0x1A3F0
         ↓
物理地址: 0x1A3F0000 的内存单元被写入 42

仮想アドレスは現代のオペレーティングシステムの安定性の基盤です。仮想アドレスと MMU がなければ、範囲外の読み書きを行うプログラムがシステム全体をブルースクリーンにする可能性があります——このような悪夢は DOS 時代には毎日起こっていました。

プログラミングにおけるメモリアドレスの現れ方

C/C++ では、メモリアドレス（ポインタ）を直接操作できます。ここで直感的な例を示します：

"""

b = 42
