新しいリポジトリの作成

新しいフォルダを作成し、開いて、実行してください。
git init
新しいgitリポジトリを作成するために。

リポジトリのチェックアウト

ローカルリポジトリのクローンを作成するには、次のコマンドを実行します：
git clone /path/to/repository
リモートサーバー上のリポジトリの場合、コマンドは次のようになります：
git clone username@host:/path/to/repository

ワークフロー

あなたのローカルリポジトリは、git が管理する3つの「ツリー」で構成されています。1つ目はあなたの作業ディレクトリ、それは実際のファイルを保持します；二つ目は暂存区（Index）、これはキャッシュエリアのようなもので、変更を一時的に保存します。最後はHEAD、それは最後のコミットの結果を指します。

追加とコミット

変更を提案するには（ステージングエリアに追加）、次のコマンドを使用します：
git add <filename>
git add *
これは git の基本ワークフローの最初のステップです。実際に変更をコミットするには、次のコマンドを使用します：
git commit -m "代码提交信息"
これで、あなたの変更はコミットされました。HEAD、しかしまだあなたのリモートリポジトリには届いていません。

変更をプッシュ

あなたの変更は現在ローカルリポジトリのHEAD完了です。これらの変更をリモートリポジトリにプッシュするには、次のコマンドを実行します：
git push origin master
〜を〜できるmasterプッシュしたい任意のブランチに置き換えてください。

既存のリポジトリをクローンしておらず、自分のリポジトリをリモートサーバーに接続したい場合は、次のコマンドで追加できます：
git remote add origin <server>
これで、追加したサーバーに変更をプッシュできるようになります。

ブランチ

ブランチは、機能開発を分離するために使用されます。リポジトリを作成すると、masterが「デフォルト」のブランチです。他のブランチで開発を行い、完了したらそれらをメインブランチにマージします。

“feature_x”という名前のブランチを作成し、そこに切り替えます：
git checkout -b feature_x
メインブランチに切り替え：
git checkout master
そして、新しく作成したブランチを削除します：
git branch -d feature_x
リモートリポジトリにブランチをプッシュしない限り、そのブランチは他人からは見えない：
git push origin <branch>

更新とマージ

ローカルリポジトリを最新の変更に更新するには、次のコマンドを実行します：
git pull
作業ディレクトリ内で获取（fetch） 并 合并（merge）リモートの変更。
他のブランチを現在のブランチ（例: master）にマージするには、次のコマンドを実行します：
git merge <branch>
どちらの場合も、git は変更を自動的にマージしようとします。残念ながら、これは毎回成功するとは限らず、問題が発生する可能性があります。冲突（conflicts）。この場合は、これらのファイルを修正して、これらの冲突（conflicts）衝突（conflicts）。修正後、次のコマンドを実行して、それらをマージ成功としてマークする必要があります：
git add <filename>
変更をマージする前に、次のコマンドで差分をプレビューできます：
git diff <source_branch> <target_branch>

タグ

ソフトウェアのリリースにはタグを作成することが推奨されます。この概念は以前から存在し、SVN にもあります。次のコマンドを実行すると、という名前のタグを作成できます：1.0.0のラベル：
git tag 1.0.0 1b2e1d63ff
1b2e1d63ffは、タグ付けしたいコミットIDの最初の10文字です。コミットIDは次のコマンドで取得できます：
git log
コミットIDの先頭数桁だけを使用することもできます。一意に指し示す限り有効です。

ローカルの変更を置き換える

もし操作を誤った場合（もちろん、そんなことは決して起こらないのが望ましいですが）、次のコマンドでローカルの変更を置き換えることができます：
git checkout -- <filename>
このコマンドは、HEAD の最新の内容で、作業ディレクトリ内のファイルを置き換えます。ステージングエリアに追加された変更や新しいファイルは影響を受けません。

ローカルのすべての変更とコミットを破棄したい場合は、サーバーから最新のバージョン履歴を取得し、ローカルのメインブランチをそれにポイントさせます：
git fetch origin
git reset --hard origin/master

便利なヒント

組み込みのグラフィカルgit：
gitk
色付きのgit出力：
git config color.ui true
履歴を表示するとき、各コミットの情報を1行だけ表示します：
git config format.pretty oneline
ファイルを対話的にステージングエリアに追加します：
git add -i
