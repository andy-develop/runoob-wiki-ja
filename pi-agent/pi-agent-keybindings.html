Pi Agent キーボードショートカットのカスタマイズ

Pi Agent のショートカットキーは完全にカスタマイズ可能です。この章ではデフォルトのショートカットキー設定と、独自のショートカットキー構成を作成する方法を紹介します。

設定ファイル

ショートカットキー設定ファイルは次の場所にあります~/.pi/agent/keybindings.json。

変更後、次のコマンドを実行します/reload再起動せずに有効になります。

ショートカットキー形式

ショートカットキーの形式は次のとおりです修飾キー＋キー修飾キーには ctrl、shift、alt、super があり、組み合わせて使用できます。

なお、super は端末がその修飾キーを単独で報告できる場合（通常は Kitty キーボードプロトコルに依存）にのみ有効で、サポートしていない端末では無効な場合があります。

サポートされているキーは次のカテゴリに分類されます：

カテゴリ値例
英字a-zctrl+b、alt+d
数字0-9alt+1
ファンクションキーf1-f12f2
方向キーup、down、left、rightalt+left
特殊キーescape、enter、tab、space、backspace、delete、home、end、pageUp、pageDownshift+enter
記号` - = [ ] ; ' , . / などctrl+]、ctrl+-

設定ファイルでは修飾キーは小文字で記述します（例：ctrl+shift+p）。本文の表では Shift+Ctrl+P と表記するのが慣例ですが、両者は同等です。

デフォルトショートカットキー早見表

以下の4つの表に、機能領域ごとの出荷時デフォルトのバインドを一覧表示します。カスタマイズ時の比較基準として使用できます。

この章ではよく使うバインドのみを掲載しています。ctrl+]、ctrl+alt+]、pageUp/pageDown、alt+y、ctrl+z、セッションセレクタのキーなどは含まれていません。完全なリストはインタラクティブモードで /hotkeys を実行して確認できます。

カスタムショートカットキー設定

keybindings.json で上書きしたい操作を列挙するだけで、列挙されていない操作はデフォルトのままです。

特定のバインドの値を空配列にすると、例えば"tui.altScreen.pageUp": []そのショートカットキーを完全に無効化できます。

Emacs スタイル

Emacs のショートカットキーに慣れている場合は、次の場所で~/.pi/agent/keybindings.json以下の設定を使用できます：

例

{
  "tui.editor.historyPrevious": "ctrl+p",
  "tui.editor.historyNext": "ctrl+n",
  "tui.editor.cursorUp": ["up"],
  "tui.editor.cursorDown": ["down"],
  "tui.editor.cursorLeft": ["left", "ctrl+b"],
  "tui.editor.cursorRight": ["right", "ctrl+f"],
  "tui.editor.cursorWordLeft": ["alt+left", "alt+b"],
  "tui.editor.cursorWordRight": ["alt+right", "alt+f"],
  "tui.editor.deleteCharForward": ["delete", "ctrl+d"],
  "tui.editor.deleteCharBackward": ["backspace", "ctrl+h"],
  "tui.input.newLine": ["shift+enter", "ctrl+j"]
}

historyPrevious と historyNext という2つの履歴操作はデフォルトではバインドされておらず、送信履歴をめくるために専用に用意されています。複数行入力でも履歴エントリを切り替えます。

ctrl+p を履歴の前の項目にバインドすると、編集エリアがフォーカスを取得したとき Ctrl+P はこの履歴バインドによって占有され、モデルへの前方切り替えはこのシナリオでは一時的に無効になります。

モデルセレクタなどの選択リスト内の Ctrl+P は影響を受けず、セレクタ自身の動作を実行します。

Vim スタイル

Vim の方向キーに慣れている場合は、以下の設定を使用できます：

例

{
  "tui.editor.cursorUp": ["up", "alt+k"],
  "tui.editor.cursorDown": ["down", "alt+j"],
  "tui.editor.cursorLeft": ["left", "alt+h"],
  "tui.editor.cursorRight": ["right", "alt+l"],
  "tui.editor.cursorWordLeft": ["alt+left", "alt+b"],
  "tui.editor.cursorWordRight": ["alt+right", "alt+w"]
}

ここでは alt+h/j/k/l を選んでいます。これは Ctrl+H/Ctrl+D などの組み込みバインドを避けるためで、Alt 系を使用しています。

Pi Agent のショートカットキー設定はデフォルト値を上書きします。

各操作には1つ以上のショートカットキーをバインドできます。

設定ファイルに列挙されていない操作は、デフォルトのショートカットキーのままです。

すべてのショートカットキーを表示

インタラクティブモードで、次のコマンドを使用してすべてのショートカットキーと現在のバインドを表示します：

/hotkeys

出力例：

编辑器
  tui.editor.cursorUp            up
  tui.editor.cursorDown          down
  tui.editor.cursorWordLeft      alt+left, ctrl+left, alt+b
  tui.input.submit               enter
模型与推理
  app.model.select               ctrl+l
  app.model.cycleForward         ctrl+p
  app.model.cycleBackward        shift+ctrl+p

ショートカットキー操作には名前空間付きの id を使用し、形式は「モジュール.アクション」です。

旧バージョンの設定ファイルにある名前空間のないID（cursorUp、expandToolsなど）は、起動時に自動的に名前空間付きIDへ移行されるため、手動で変更する必要はありません。

このコマンドは、利用可能なすべてのショートカットキー操作、現在のバインド、所属する機能領域を一覧表示します。ショートカットキーの競合を調査したり、特定機能のショートカットキーを探したりするのに最適な方法です。

全画面モードでのキー操作

用 --tui-mode fullscreen起動時、対話記録（トランスクリプト）はターミナルビューポート内でスクロールし、編集領域と下部のステータス領域は固定されたままです。

このとき、修飾キーなしのhome、end、pageUp、pageDownは対話記録のスクロールに使用され、それらのCtrl変種は引き続きエディタ用です。

通常モードでは、これらの2つのキーグループはどちらもエディタに作用します。

全画面モードには専用の検索とジャンプもあります。ctrl+shift+fで対話記録を検索し、ctrl+up、ctrl+downで前/次のマーク付きメッセージへジャンプします。

全画面スクロールのバインドはエディタのバインドより優先度が高くなりますが、通常のアクションバインドで調整可能です。

キー操作通常モード全画面モード
home、endエディタ対話記録のスクロール
ctrl+home、ctrl+endエディタエディタ
pageUp、pageDownエディタ対話記録のスクロール
ctrl+pageUp、ctrl+pageDownエディタエディタ
ctrl+shift+f（Windows/WSLではctrl+f）効果なし対話記録の検索
ctrl+up、ctrl+down効果なし前/次のマーク付きメッセージへジャンプ
