HTML 書式設定タグ

HTML ではタグ <b>（"bold"）と <i>（"italic"）を使用して出力テキストを書式設定します。例：太字 or 斜体

これらのHTMLタグは書式設定タグと呼ばれます（下部の完全なタグリファレンスを参照してください）。

通常、タグ <strong> は太字タグ <b> の代わりに使用され、<em> は <i> タグの代わりに使用されます。

ただし、これらのタグの意味は異なります：

<b> と <i> は太字または斜体のテキストを定義します。

<strong> または <em> は、表示するテキストが重要であることを意味するため、強調表示します。現在の主要なブラウザはすべて、さまざまな効果のフォントをレンダリングできます。ただし、将来のブラウザはより良いレンダリング効果をサポートするかもしれません。

    <b> と <strong> について

    表示上は、これらの2つのタグはどちらも太字テキストですが、なぜ機能が「同じ」タグが2つあるのでしょうか？また、strong だけではないようです。

    • まず、これら2つは完全に同じではありません。たとえば、ウェブページリーダーでウェブページを読む場合（視覚障害者が使用）、strong は強調して読み上げられますが、b はそうなりません。
    • 次に、起源から言えば、strong は将来的にセマンティックウェブを構築するために生まれました。知っておくべきことは、HTML は表示を担当するマークアップであり、意味を表すことはできません。つまり、ブラウザはこのタグがどのように表示されるかを知っていますが、タグがマークする内容がどのような意味を持つべきかは知りません。そして strong は意味論的に第一歩を踏み出しました。

    1、<em> はテキストを強調コンテンツとして定義します

    <em>このタグは、ブラウザに内部のテキストを強調コンテンツとして表現するよう指示します。すべてのブラウザにとって、これはこのテキストを斜体で表示することを意味します。

    とはいえ、現在は<em>タグで修飾された内容はすべて斜体で表示されますが、これらの内容にはより広い意味もあります。将来のある日、ブラウザが強調テキストを表示するために他の特別な効果を使用する可能性もあります。テキストを単に斜体で表示したいだけの場合は、<i>タグを使用してください。これ以外にも、ドキュメントにはテキスト表示を変更するためのカスケードスタイル定義を含めることができます。

    2、<i> は斜体テキスト効果を表示します

    <i>タグとコンテンツベースのスタイルタグは<em>似ています。内部のテキストを斜体（italic）または傾斜（oblique）フォントで表示するようブラウザに指示します。この斜体フォントがそのブラウザで利用できない場合は、ハイライト、反転表示、下線などのスタイルを使用できます。

    3、<dfn> は定義項目を定義します

    <dfn>タグは、特定の用語やフレーズの定義をマークできます。

    現在の一般的なブラウザは通常、斜体で表示します <dfn>内のテキストを。将来、<dfn>ドキュメントのインデックスや用語集の作成にも役立つ可能性があります。

    他の多くのコンテンツベースのスタイルタグや物理スタイルタグと同様に、<dfn>タグはできるだけ使用を控えるのが良いでしょう。

    つまり、実現しようとする目的は異なりますが、どちらも同じ表現方法、つまり斜体を使用します。

    HTML 要素における b、em、strong の違いは何ですか？

    言うならば、デフォルトの HTML スタイルシート定義では、b 和 strongのスタイルは同じで、 { font-weight: bolder } 而 emのデフォルトスタイルは{ font-style: italic }であり、iと同じです。

    HTML 4 では、emは emphasized text を表し、strongは strong emphasized text を表すため、strong の強度はより強いです。一方 HTML 5 では、strongの定義は important text に変更されました。もちろん、emphasized と strong emphasized、さらには important の間の境界は曖昧ですが、重要なのは自分で HTML コードを書くときに使用法を一貫させることです。b と i は単に「ここは太字で表示するべき」「ここは斜体で表示するべき」を表すだけです。

    <acronym>タグと<abbr>タグは歴史的に HTML で省略語や頭字語を表すために使用されてきましたが、特に現代の HTML 標準とブラウザサポートの面では、それらの間にはいくつかの違いがあります：

    1. 意味的な含意：

      • <abbr>タグは、単語やフレーズの一部の文字で構成される略語や頭字語（例：「VIP」「CEO」）、または単独の語として読める頭字語（例：「UNESCO」「NASA」）など、あらゆる種類の略語や頭字語を表すために使用されます。
      • <acronym>タグはもともと、単語やフレーズの頭文字から構成され、それらが組み合わさって発音可能な単語を形成するもの（例：「ASCII」「FAQ」）など、単独の語として読める頭字語を表すために特別に使用されていました。

    2. ブラウザのサポートと標準の現状：

      • <abbr>タグはすべての最新ブラウザで良好にサポートされており、HTML5標準の一部です。
      • <acronym>タグは以前のHTML 4.01で定義されていましたが、HTML5では非推奨となり、推奨されなくなりました。これは、一部の古いブラウザは依然としてサポートする可能性がありますが、最新ブラウザは互換性を保証しない可能性があり、またそれを使用すると最新標準に準拠しないコードになる可能性があることを意味します。

    3. 置き換えの提案：

      • 〜ため、<acronym>タグは非推奨となっており、略語が発音可能な頭字語であるかどうかに関係なく、統一して<abbr>タグを使用して表す必要があります。
      • 略語の説明を提供する必要がある場合は、どちらのタグを使用する場合でも、title属性を利用して完全な用語またはフレーズを提供し、ユーザーがマウスをホバーしたときにヒントが表示されるようにする必要があります。

    まとめると、<acronym> 和 <abbr>タグは意味的に微妙な違いがありますが、実際の応用では、<acronym>すでにHTML5標準で非推奨となったため、開発者は常に<abbr>タグを使用して、発音可能な頭字語であるかどうかに関係なく、あらゆる種類の略語をマークします。これにより、現在の標準に適合し、クロスブラウザの互換性も確保できます。

    ブロッククォート内では、引用を明示する際に<cite>タグも使用できます。

    <cite>タグと<footer>タグは、引用を表す際に異なる適用シーンと意味的含意を持ちます。どちらを使用するかは、明示したい署名の具体的な内容と文脈に依存します。

    <cite>タグ：

    • 用途：<cite>タグは、作品（記事、書籍、歌曲、映画、特許、訴訟事件など）のタイトル、または引用、論評、コメントなどの場合に言及される個人や組織の名称をマークするために使用されます。
    • 意味：作品や作成者への正式な引用または言及を表し、元の出典への尊重と承認を強調します。
    • 適用シーン：記事、ブログ、フォーラムの投稿などのコンテンツにおいて、他人の発言や意見を引用する必要がある場合、通常は引用内容の後に<cite>タグを使用して、引用元の著者、作品タイトル、出版日付などの情報をマークします。

    <footer>タグ：

    • 用途：<footer>タグは、文書またはページ領域のフッターコンテンツを定義するために使用され、通常は著作権情報、連絡先、利用規約、著者名、作成日など、文書全体またはページに関連する重要ではあるが主体ではないコンテンツを含みます。
    • 意味：文書またはページ構造上の下部領域を表し、単なる署名だけでなく、一連の付加情報やサービスを含みます。
    • 適用シーン：ウェブページ、電子書籍、文書などの下部で、所有者、作成者、発行者、改訂日などの全体的な情報、および場合によってはナビゲーションリンク、法的声明、連絡先などをまとめて表示するために使用されます。

    引用の署名の選択：

    • 記事、ブログ、フォーラムの投稿などの具体的なコンテンツ単位内部の署名の場合、その署名がコンテンツの著者や貢献者を示すものであれば、通常は<footer>タグを使用する方が適切です。この場合、署名はそのコンテンツブロックの一部として、著作権情報、作成日などとともに、そのコンテンツの完全な説明と帰属を示すものとなります。

    • 他人の作品を引用する際の署名、つまり引用された作品の著者や出典などの情報を明示する場合は、<cite>タグを使用すべきです。この場合、署名は引用された作品自体への表示であり、引用元を示し、原作者への尊重を表すことを目的としています。
