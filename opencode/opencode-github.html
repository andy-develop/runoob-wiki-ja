OpenCode GitHub

OpenCode は GitHub ワークフローと深く統合でき、AI が Issue、Pull Request、コードレビューのプロセスに直接参加できます。

コメントに /opencode または /oc を入力すると、AI が自動的にタスクを実行します。

OpenCode GitHub = AI をあなたの自動化開発メンバーに変え、Issue、PR、コードプロセスに直接参加させます。

一、コア機能

  • Issue 分析：問題を自動的に理解して説明を提供
  • 自動修正：ブランチを作成して PR を提出
  • コードレビュー：PR を分析して改善提案を行う
  • 自動実行：GitHub Actions 上で実行

特徴：

  • あなた自身の GitHub Runner 内で実行
  • 安全で制御可能、外部サーバーに依存せずコードを実行

二、クイックインストール（推奨）

GitHub プロジェクトのルートディレクトリで実行：

opencode github install

このコマンドは自動的に以下を実行します：

  • GitHub App のインストール
  • GitHub Actions ワークフローの作成
  • API Key の設定を案内

三、手動インストール（上級）

1、GitHub App のインストール

アクセス：

https://github.com/apps/opencode-agent

自分のリポジトリにインストール

2、ワークフローファイルの追加

ファイルを作成：

.github/workflows/opencode.yml

例：

name: opencode

on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]

jobs:
  opencode:
    if: |
      contains(github.event.comment.body, '/oc') ||
      contains(github.event.comment.body, '/opencode')
    runs-on: ubuntu-latest
    permissions:
      id-token: write
    steps:
      - name: Checkout repository
        uses: actions/checkout@v6
        with:
          fetch-depth: 1
          persist-credentials: false

      - name: Run OpenCode
        uses: anomalyco/opencode/github@latest
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-sonnet-4-20250514

3、Secrets の設定

GitHub リポジトリで：

  • Settings → Secrets → Actions に移動
  • API Key を追加（例：ANTHROPIC_API_KEY）

四、設定パラメータの説明

パラメータ 説明
model 使用するモデル（必須）
agent プロキシを指定
prompt カスタムプロンプト
share セッションを共有するかどうか
token GitHub Token

説明：

  • デフォルトで OpenCode GitHub App のトークンを使用します
  • GITHUB_TOKEN または PAT も使用可能

五、対応しているトリガーイベント

イベント 説明
issue_comment コメントで /opencode をトリガー
pull_request_review_comment コード行コメントでトリガー
issues Issue の作成/更新
pull_request PR の自動レビュー
schedule 定期タスク
workflow_dispatch 手動トリガー

六、一般的な使用方法

1、Issue の説明

Issue にコメント：

/opencode explain this issue

AI が問題を要約して説明します

2、Issue の自動修正

/opencode fix this

自動：

  • ブランチを作成
  • コードを修正
  • Pull Request を提出

3、PR の修正

Delete the attachment from S3 when the note is removed /oc

PR 上で直接修正を実行します

4、コード行レベルの操作（非常に強力）

PR の Files ページでコメント：

/oc add error handling here

OpenCode が自動的に取得：

  • ファイルパス
  • 行番号
  • コンテキスト diff

位置を手動で指定する必要はありません

七、定期タスク（自動化）

例：毎週 TODO をスキャン

on:
  schedule:
    - cron: "0 9 * * 1"

プロンプト例：

Review the codebase for TODO comments and summarize them

注意：

  • 定期タスクには prompt の指定が必須です
  • 書き込み権限が必要（contents / pull-requests）

八、PR の自動レビュー

例：

on:
  pull_request:
    types: [opened, synchronize]

デフォルトの動作：

  • コード品質を分析
  • 潜在的なバグを検出
  • 改善提案を行う

九、Issue の自動分類

新しい Issue を自動処理できます。例：

  • スパムアカウントをフィルタリング
  • 自動返信の提案
  • ドキュメントの説明を補足

注意：

  • issues イベントには prompt の指定が必須です

十、カスタムプロンプト（上級用法）

デフォルトの動作を上書きできます：

prompt: |
  Review this pull request:
  - Check for bugs
  - Suggest improvements

用途：

  • コード規約の統一
  • レビュー基準のカスタマイズ
  • チームプロセスの自動化

十一、セキュリティと権限

推奨権限構成：

permissions:
  id-token: write
  contents: write
  pull-requests: write
  issues: write

説明：

  • 最小権限の原則
  • 必要な機能のみを開放
