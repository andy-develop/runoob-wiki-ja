Vibe Coding 思考パターン

従来のプログラミング vs Vibe Coding の思考の違い

従来のプログラミングの思考経路は：

私には要件がある → どんな構文が必要？ → どうコードを書く？ → 書く → デバッグ

Vibe Coding の思考経路は：

我有需求 → 我该怎么描述这个需求？→ AI 生成代码 → 我验证结果 → 继续调整描述

核心的な違いは：従来のプログラミングはコードを書くこと、Vibe Coding は要件を記述すること。

例で違いを体感する

あなたが作ろうとしているのはユーザー登録フォーム、ユーザー名とパスワードを検証するものだとしよう。

従来のプログラミング思考：

用什么框架？React 还是 Vue？
表单验证库用哪个？Formik 还是 React Hook Form？
正则表达式怎么写？
状态管理怎么设计？

Vibe Coding 思考：

ユーザーはこのフォームで何をする必要がありますか？ どのような入力フィールドがありますか？ どのような検証ルールがありますか？ 検証が失敗した場合は何を表示すべきですか？ 検証が成功した場合はどこにリダイレクトすべきですか？

前者の思考はどう実装するかを中心に、後者の思考はユーザーが何を必要としているかを中心にしている。

Vibe Coding はあなたの思考を技術実装からプロダクトデザインへと引き上げる。正規表現の書き方を知る必要はないが、次のことは知らなければならない。ユーザー名は3文字以上という規則だ。

Vibe Coding の3つの核心的思考

思考その1：あなたは監督であり、俳優ではない

監督はすべての役を自ら演じる必要はない。監督に必要なのは：

  • このシーンで何を表現するかを知っていること（要件が明確）。

  • 俳優の演技が良いかどうかを判断できること（結果の検証）。

  • 具体的な調整指示を出せること（的確なフィードバック）。

Vibe Coding では、AI があなたの俳優チームであり、あなたが監督です。

  • 間違ったやり方：AI に自由にやらせ、境界を設けず、結果を確認せず、最終的に「見た目は良いが使えない」ものを作り上げてしまう。

  • 正しいやり方：AI に明確なシーン、役割、基準を与え、各出力を確認し、満足できない箇所に具体的なフィードバックを与える。

思考その2：一発完成より反復が優れている

従来の開発は一度で正しく書くことを追求し、Vibe Coding は迅速な反復で正しくすることを追求する。

典型的な Vibe Coding の反復プロセス：

第 1 轮：先让 AI 做一个能跑的版本，即使很简陋
第 2 轮：添加核心功能，让它能用
第 3 轮：修复明显的 bug 和体验问题
第 4 轮：优化细节和边缘情况
第 5 轮：添加测试和文档

各ラウンドであなたは検証・フィードバック・調整を行い、各ラウンドで AI は前のラウンドを基に改善する。

重要な原則：まず機能させること、次に良くすること、最後に洗練させること。

思考その3：記述力 > プログラミング能力

Vibe Coding では、あなたの最も重要なスキルはコードを書くことではなく、自分が何を望んでいるかを明確に記述することです。

良い要件記述には5つの要素が含まれます：

要素説明例
目標何をするかユーザーログインフォームを作成する
制約どのような制限があるかReact + TypeScript を使用し、サードパーティのUIライブラリを導入しない
入力どのようなデータを受け取るかユーザー名（3〜20文字）とパスワード（6文字以上）
出力どのような結果を生成するか検証は API を呼び出して行い、失敗時はエラーメッセージを表示する
受け入れ基準どうなれば合格か空のユーザー名で送信をクリックすると「ユーザー名を入力してください」と表示される

実践：2つの思考の違いを体験する

以下は実践練習です。同じタスクを2つの異なる方法で記述し、AI の成果にどのような違いがあるか見てみましょう。

方法1：曖昧な記述（初心者に多い）

カウンターを作ってください。

AI はシンプルなカウンターを返すかもしれませんが、次のような可能性があります：

  • スタイルがなく、数字とボタンだけのもの。

  • あなたが知らないフレームワークを使っている。

  • 負の数のケースを考慮していない。

  • リセット機能がない。

方法2：構造化された記述（Vibe Coding 方式）

帮我做一个计数器组件，要求：
- 目标：一个带加减按钮的数字计数器
- 约束：使用 HTML + CSS + 原生 JavaScript，单文件
- 输入：初始值 0，最小值 0（不能减到负数），最大值 99
- 输出：显示当前数字，两个按钮（+ 和 -），一个重置按钮
- 验收标准：
  - 点 + 数字加 1，到 99 后按钮变灰不可点击
  - 点 - 数字减 1，到 0 后按钮变灰不可点击
  - 点重置回到 0
  - 数字变化时有短暂的放大动画
  - 深色背景，白色卡片，圆角设计

2つの記述をそれぞれ AI に送り、成果の違いを比較してみましょう。

気づくでしょう：構造化された記述で得られるコードは、品質と実用性が曖昧な記述よりもはるかに高いことを。

AI はあなたの考えを推測しません。あなたが具体的に記述すればするほど、その成果は期待に沿ったものになります。これは AI の限界ではなく、あなたの能力の境界です。

いつ Vibe Coding を使うべきか、いつ使うべきでないか

Vibe Coding は万能薬ではありません。以下のシナリオ比較が判断の助けになります：

Vibe Coding に適しているVibe Coding に適さない
プロトタイプ検証、迅速なMVP作成性能とセキュリティに極限の要求がある核心システム
CRUD 系のビジネスロジックメモリとアルゴリズムを正確に制御する必要がある低レイヤーモジュール
UI コンポーネントとページレイアウト既存の複雑なコードベースを深く理解する必要がある変更
データ変換とフォーマットコンプライアンスや規制に関わる金融/医療コード
テストケース生成特許保護が必要な独自アルゴリズム
ドキュメントとコメント生成セキュリティ監査が必要な暗号化モジュール

AI にバグをどう記述するか

コードに問題があるとき、AI へのバグの記述にも構造化思考が必要です。

「このコードは問題がある」と言うのではなく、次のようにします：

我在运行以下代码时遇到了问题：
[粘贴代码]

预期行为：点击按钮后数字应该加 1
实际行为：点击按钮后数字没有变化，控制台报错：
  Uncaught TypeError: count is not defined

我的环境：Chrome 浏览器，直接在 HTML 文件中运行

この記述に含まれるもの：

  • コード：AI が完全なコンテキストを見ることができる。

  • 期待 vs 実際：AI が目標とギャップの箇所を知ることができる。

  • エラーメッセージ：これは最も価値のある手がかりであり、AI が問題を直接特定できる。

  • 環境：AI が的を絞った解決策を提示するのに役立つ。
