C はじめに

C 言語は汎用の高水準プログラミング言語であり、当初はデニス・リッチー（Dennis Ritchie）によってベル研究所で UNIX オペレーティングシステムを開発するために設計されました。C 言語は 1972 年に DEC PDP-11 コンピュータ上で初めて実装され、現代のプログラミング言語体系の中で最も影響力のある言語の一つです。

1978 年、ブライアン・カーニハン（Brian Kernighan）とデニス・リッチー（Dennis Ritchie）は共同で『The C Programming Language』を出版しました。この本は C 言語について初めて完全な公開記述を行ったもので、このバージョンは K&R 標準と呼ばれ、その後数年間にわたり事実上の C 言語仕様となりました。

UNIX オペレーティングシステム、C コンパイラ、そしてほぼすべての UNIX アプリケーションは C 言語で書かれています。その簡潔な構文、ハードウェアに近い制御能力、優れた実行効率により、C 言語はシステムプログラミング分野で最も重要な専門言語となり、C++、Java、Go、Rust など数多くの後続言語の設計に深い影響を与えました。

  • 構文が簡潔で、学習・習得が容易です。
  • 構造化プログラミング言語であり、ロジックが明確です。
  • コンパイル後に高効率な機械語コードが生成され、実行速度はアセンブリ言語に匹敵します。
  • メモリとハードウェアを直接操作でき、低レベルのタスクを処理できます。
  • 可搬性（ポータビリティ）が高く、さまざまなコンピュータプラットフォームやオペレーティングシステム上でコンパイルして実行できます。
  • 豊富な標準ライブラリを備え、エコシステムが成熟しており、コミュニティも大規模です。

C について

  • C 言語は当初 UNIX オペレーティングシステムを記述するために発明され、1972 年にベル研究所で生まれました。
  • C 言語は B 言語を基に進化したもので、B 言語はケン・トンプソン（Ken Thompson）によって 1970 年前後に設計されました。
  • 1983 年、米国規格協会（ANSI）は C 言語標準の策定に着手し、1989 年に C89（ANSI C とも呼ばれる）を正式に公開しました。これは C 言語の最初の公式標準です。
  • 1973 年までに、UNIX オペレーティングシステムのカーネルは完全に C 言語で書き直されました。これは C 言語がシステムプログラミング分野において基盤を築いたことを示しています。
  • C 言語は現在最も広く使用されているシステムプログラミング言語であり、組み込み開発、オペレーティングシステム、コンパイラなどの分野で長年にわたり中心的な地位を占めています。
  • 多くの重要な基盤ソフトウェアやフレームワーク（CPython インタプリタ、V8 エンジンの低層コンポーネントなど）は、C 言語で実装されています。
  • 現在最も人気のある Linux オペレーティングシステムのカーネルと、リレーショナルデータベース管理システム MySQL の中核部分は、いずれも C 言語で書かれています。
  • C 言語は C89、C99、C11、C17 など複数の標準バージョンの進化を経て、活力と現代性を維持し続けています。

なぜ C を使うのか？

C 言語は当初、システム開発、特にオペレーティングシステムを構成する中核プログラムに使用されていました。C 言語はコンパイル後に生成される機械語コードの実行速度がアセンブリ言語とほぼ同等でありながら、アセンブリよりも優れた可読性と保守性を備えているため、システムレベル開発の第一選択言語となりました。以下に C 言語の代表的な応用シーンをいくつか挙げます：

  • オペレーティングシステムのカーネル（Linux、Windows NT カーネル、macOS XNU カーネルなど）
  • 言語コンパイラとインタプリタ（GCC、Clang、CPython など）
  • アセンブラとリンカ
  • テキストエディタとコマンドラインツール
  • プリンタのファームウェアとドライバ
  • ネットワークプロトコルスタックとネットワークドライバ
  • 組み込みシステムとマイコン開発
  • データベースシステム（SQLite、MySQL、PostgreSQL など）
  • 高性能計算・科学計算ライブラリ（BLAS、LAPACK など）
  • ゲームエンジンの低層部とグラフィックスレンダリングライブラリ（OpenGL 実装など）

C プログラム

C 言語プログラムは、わずか数行の場合もあれば数百万行に及ぶ場合もあり、ソースコードは拡張子が".c"のテキストファイルに保存されます。例えばhello.c。大規模プロジェクトでは、コードは通常複数の".c"ソースファイルと".h"ヘッダファイルに分割され、ビルドシステムがコンパイルを一元管理します。

あなたは"vi"、"vim"、"VS Code"またはその他のテキストエディタを使用して C 言語プログラムを作成できます。作成後、GCC や Clang などのコンパイラを使用してソースコードを実行可能ファイルにコンパイルします：

gcc hello.c -o hello   # 编译
./hello                # 运行（Linux/macOS）

本チュートリアルでは、テキストファイルの編集方法と、プログラムファイルにソースコードを記述する方法をすでに知っていることを前提としています。

C11

C11（C1X とも呼ばれる）は C 言語の 3 番目の主要な公式標準であり、ISO 標準 ISO/IEC 9899:2011 に対応し、2011 年 12 月に正式に公開されました。C99 を基に言語機能をさらに充実させ、マルチスレッドサポート、ジェネリックプログラミング、安全性の強化に重点を置いています。

新機能

  • アライメント処理（Alignment）の標準化：導入されたのは、_Alignas指定子とalignof演算子、およびaligned_alloc()関数と<stdalign.h>ヘッダファイルで、プログラマがメモリ上のデータのアライメント方法を正確に制御できるようになります。これはパフォーマンスに敏感な低レベル開発にとって特に重要です。

  • _Noreturn関数マーカー：決して戻らない関数をマークするために使用されます（例：exit()、abort()）。これは GCC の__attribute__((noreturn))に似ており、コンパイラがより良い最適化と警告分析を行うのに役立ちます。

  • _Genericジェネリック選択キーワード：式の型に基づいてコンパイル時に異なるコードパスを選択できます。これは C 言語で型安全なジェネリックマクロを実装するための基礎メカニズムであり、C 言語に長らく欠けていたジェネリック機能の不足を補うものです。

  • マルチスレッド（Multithreading）サポート：C 言語標準のレベルで初めてネイティブなマルチスレッドサポートを導入しました。含まれるもの：

    • _Thread_localスレッドローカルストレージ型識別子。各スレッドがそれぞれ独立した変数のコピーを持ちます。
    • <threads.h>ヘッダファイルは、スレッド作成（thrd_create）、同期（mtx_lock/cnd_wait）などの管理関数を提供します。
    • _Atomic型修飾子と<stdatomic.h>ヘッダファイルは、ロックフリーのアトミック操作を提供し、マルチスレッドプログラミングの重要な基盤です。

  • 強化された Unicode サポート：ISO/IEC TR 19769:2004 に基づき、char16_tとchar32_tデータ型が新たに追加されました。それぞれ UTF-16 と UTF-32 エンコーディングに対応し、<uchar.h>ヘッダファイルには Unicode 文字列変換関数が含まれており、C 言語の国際化プログラミングへのサポートが改善されました。

  • 削除されたgets()関数：gets()はバッファ境界をチェックしないため、歴史的にバッファオーバーフロー脆弱性の一般的な原因でした。C11 はこれを標準から正式に削除し、より安全なfgets()または新しく追加されたgets_s()の使用を推奨しています。

  • 境界チェック関数インターフェース（Annex K）：_s接尾辞を持つ一連の安全な関数を定義しています。例えばfopen_s()、strcat_s()、strcpy_s()などです。これらの関数は呼び出し元にバッファサイズの入力を要求し、バッファオーバーフロー問題を根本から防ぎます。

  • より多くの浮動小数点処理マクロ：<math.h>と<fenv.h>内の浮動小数点処理マクロを拡張し、よりきめ細かい浮動小数点演算の制御と例外処理機能を提供して、高精度な科学計算のニーズに応えます。

  • 匿名構造体 / 共用体のサポート：構造体または共用体の内部に、名前のない構造体または共用体をネストして定義できます。そのメンバーにアクセスする際に中間層の名前が不要になり、複雑なデータ構造の定義が簡素化されます。この機能は GCC ではすでに拡張として存在していましたが、C11 で標準に取り入れられました。

  • 静的アサーション_Static_assert()：コンパイル時に定数式に対してアサーションチェックを行い、条件を満たさない場合は（実行時エラーではなく）コンパイルエラーを生成します。型のサイズや構造体のオフセットなど、コンパイル時の前提条件の検証によく使用され、コードの堅牢性を高めます。

  • fopen()新しい排他モード"x"：ファイルオープンモード文字列に"x"（例："wx"）を追加します。排他作成を意味し、ファイルがすでに存在する場合は失敗します。POSIX のO_CREAT|O_EXCLフラグに似ており、安全な一時ファイル作成の場面でよく使用されます。

  • 新たに追加されたquick_exit()関数：3 番目のプログラム終了方法を提供します（他の 2 つはreturnとexit()）。exit()が正常にクリーンアップを完了できない場合、quick_exit()はat_quick_exit()によって登録された処理関数を実行した後、直ちに終了します。マルチスレッドプログラムの緊急終了シーンに適しています。
