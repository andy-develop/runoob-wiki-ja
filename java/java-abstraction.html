Java 抽象クラス

オブジェクト指向の概念では、すべてのオブジェクトはクラスによって記述されます。しかし逆に、すべてのクラスがオブジェクトを記述するために使われるわけではありません。クラスの中に具体的なオブジェクトを記述するための十分な情報が含まれていない場合、そのようなクラスは抽象クラスです。

抽象クラスは、オブジェクトをインスタンス化できないこと以外は、クラスの他の機能は依然として存在し、メンバー変数、メンバーメソッド、コンストラクタのアクセス方法は通常のクラスと同じです。

抽象クラスはオブジェクトをインスタンス化できないため、使用するには抽象クラスを継承する必要があります。この理由から、通常は設計段階で抽象クラスを設計するかどうかを決定します。

親クラスはサブクラス集合の共通メソッドを含みますが、親クラス自体が抽象的であるため、これらのメソッドを使用することはできません。

Java では、抽象クラスは継承関係を表します。1つのクラスは1つの抽象クラスしか継承できませんが、1つのクラスは複数のインターフェースを実装できます。

抽象クラス

Java 言語では、abstract class を使用して抽象クラスを定義します。次の例のとおりです。

Employee.java ファイルのコード：

/*ファイル名 : Employee.java*/ public abstract class Employee { private String name; private String address; private int number; public Employee(String name, String address, int number) { System.out.println("Constructing an Employee"); this.name = name; this.address = address; this.number = number; } public double computePay() { System.out.println("Inside Employee computePay"); return 0.0; } public void mailCheck() { System.out.println("Mailing a check to " + this.name + " " + this.address); } public String toString() { return name + " " + address + " " + number; } public String getName() { return name; } public String getAddress() { return address; } public void setAddress(String newAddress) { address = newAddress; } public int getNumber() { return number; } }

この Employee クラスは何も違いがないことに注意してください。このクラスは抽象クラスですが、それでも3つのメンバー変数、7つのメンバーメソッド、1つのコンストラクタを持っています。次に、以下の例を試してみると：

AbstractDemo.java ファイルのコード：

/*ファイル名 : AbstractDemo.java*/ public class AbstractDemo { public static void main(String [] args) { /*以下は許可されておらず、エラーが発生します。*/ Employee e = new Employee("George W.", "Houston, TX", 43); System.out.println("\n Call mailCheck using Employee reference--"); e.mailCheck(); } }

AbstractDemo クラスをコンパイルしようとすると、次のエラーが発生します：

Employee.java:46: Employee is abstract; cannot be instantiated
      Employee e = new Employee("George W.", "Houston, TX", 43);
                   ^
1 error

抽象クラスの継承

次の方法で Employee クラスの属性を継承できます：

Salary.java ファイルのコード：

/*ファイル名 : Salary.java*/ public class Salary extends Employee { private double salary; //Annual salary public Salary(String name, String address, int number, double salary) { super(name, address, number); setSalary(salary); } public void mailCheck() { System.out.println("Within mailCheck of Salary class "); System.out.println("Mailing check to " + getName() + " with salary " + salary); } public double getSalary() { return salary; } public void setSalary(double newSalary) { if(newSalary >= 0.0) { salary = newSalary; } } public double computePay() { System.out.println("Computing salary pay for " + getName()); return salary/52; } }

Employee クラスのオブジェクトをインスタンス化できなくても、Salary クラスのオブジェクトをインスタンス化すると、そのオブジェクトは Employee クラスから7つのメンバーメソッドを継承し、それらのメソッドを通じて3つのメンバー変数を設定または取得できます。

AbstractDemo.java ファイルのコード：

/*ファイル名 : AbstractDemo.java*/ public class AbstractDemo { public static void main(String [] args) { Salary s = new Salary("Mohd Mohtashim", "Ambehta, UP", 3, 3600.00); Employee e = new Salary("John Adams", "Boston, MA", 2, 2400.00); System.out.println("Call mailCheck using Salary reference --"); s.mailCheck(); System.out.println("\n Call mailCheck using Employee reference--"); e.mailCheck(); } }

上記のプログラムをコンパイルして実行した結果は次のとおりです：

Constructing an Employee
Constructing an Employee
Call mailCheck using  Salary reference --
Within mailCheck of Salary class
Mailing check to Mohd Mohtashim with salary 3600.0

Call mailCheck using Employee reference--
Within mailCheck of Salary class
Mailing check to John Adams with salary 2400.

抽象メソッド

このようなクラス、つまり特別なメンバーメソッドを含み、そのメソッドの具体的な実装がサブクラスによって決定されるクラスを設計したい場合、親クラスでそのメソッドを抽象メソッドとして宣言できます。

Abstract キーワードは抽象メソッドの宣言にも使用できます。抽象メソッドはメソッド名のみを含み、メソッド本体を持ちません。

抽象メソッドは定義を持たず、メソッド名の直後には波括弧ではなくセミコロンが続きます。

public abstract class Employee { private String name; private String address; private int number; public abstract double computePay(); //その他のコード }

抽象メソッドを宣言すると、次の2つの結果が生じます：

  • クラスが抽象メソッドを含む場合、そのクラスは抽象クラスでなければなりません。
  • すべてのサブクラスは親クラスの抽象メソッドをオーバーライドするか、自身を抽象クラスとして宣言する必要があります。

抽象メソッドを継承したサブクラスはそのメソッドをオーバーライドする必要があります。そうしない場合、そのサブクラスも抽象クラスとして宣言する必要があります。最終的には、いずれかのサブクラスがその抽象メソッドを実装する必要があります。そうでなければ、最初の親クラスから最終的なサブクラスまで、オブジェクトのインスタンス化に使用できません。

Salary クラスが Employee クラスを継承する場合、computePay() メソッドを実装する必要があります：

Salary.java ファイルのコード：

/*ファイル名 : Salary.java*/ public class Salary extends Employee { private double salary; // Annual salary public double computePay() { System.out.println("Computing salary pay for " + getName()); return salary/52; } //その他のコード }

抽象クラスのまとめとルール

  • 1. 抽象クラスはインスタンス化できません（初心者が犯しやすい間違いです）。インスタンス化するとエラーが発生し、コンパイルが通りません。抽象クラスの非抽象サブクラスのみがオブジェクトを作成できます。

  • 2. 抽象クラスには抽象メソッドが含まれるとは限りませんが、抽象メソッドを持つクラスは必ず抽象クラスです。

  • 3. 抽象クラス内の抽象メソッドは宣言のみで、メソッド本体を含みません。つまり、メソッドの具体的な実装、すなわちメソッドの具体的な機能を提供しません。

  • 4. コンストラクタとクラスメソッド（static で修飾されたメソッド）は抽象メソッドとして宣言できません。

  • 5. 抽象クラスのサブクラスは、抽象クラス内の抽象メソッドの具体的な実装を提供する必要があります。ただし、そのサブクラスも抽象クラスである場合は除きます。

    Shape クラスを定義して一般的な2次元図形を表します。Shape は抽象メソッド area と perimeter を持ち、それぞれ図形の面積と周囲の長さを計算します。いくつかの2次元図形クラス（長方形、三角形、円など）を定義してみてください。これらはすべて Shape クラスのサブクラスであり、これらの図形の面積と周囲の長さを計算し、関連情報を出力します。

    図形クラス:

    public abstract class Shape {
    public abstract double area();
    public abstract double perimeter();
}

    長方形クラス:

    public class Rectangle extends Shape {
    private double length;
    private double width;

    public double getLength() {
        return length;
    }

    public void setLength(double length) {
        this.length = length;
    }

    public double getWidth() {
        return width;
    }

    public void setWidth(double width) {
        this.width = width;
    }

    @Override
    public double area() {
        return getLength() * getWidth();
    }

    @Override
    public double perimeter() {
        return 2 * (getWidth() + getWidth());
    }
}

    三角形クラス:

    public class Triangle extends Shape {
    private double a, b, c;

    public double getA() {
        return a;
    }

    public void setA(double a) {
        this.a = a;
    }

    public double getB() {
        return b;
    }

    public void setB(double b) {
        this.b = b;
    }

    public double getC() {
        return c;
    }

    public void setC(double c) {
        this.c = c;
    }

    @Override
    public double area() {
        double p = (getA() + getB() + getC()) / 2;
        return Math.sqrt(p * (p - getA()) * (p - getB()) * (p - getC()));
    }

    @Override
    public double perimeter() {
        return getA() + getB() + getC();
    }
}

    円クラス:

    public class Circle extends Shape {
    private double diameter;

    public double getDiameter() {
        return diameter;
    }

    public void setDiameter(double diameter) {
        this.diameter = diameter;
    }

    @Override
    public double area() {
        return Math.PI * Math.pow(getDiameter() / 2, 2);
    }

    @Override
    public double perimeter() {
        return Math.PI * getDiameter();
    }
}

    テストコード:

    public class Test {
    public static void main(String [] args){
        Rectangle rec = new Rectangle();
        rec.setLength(10);
        rec.setWidth(5);
        double rec_area = rec.area();
        double rec_perimeter = rec.perimeter();

        Triangle tri = new Triangle();
        tri.setA(3);
        tri.setB(4);
        tri.setC(5);
        double tri_area = tri.area();
        double tri_perimeter = tri.perimeter();
        System.out.println("三角形的面积："+tri_area+"，周长"+tri_perimeter);

        Circle cir = new Circle();
        cir.setDiameter(10);
        double cir_area = cir.area();
        double cir_perimeter = cir.perimeter();
        System.out.println("圆形的面积："+cir_area+"，周长"+cir_perimeter);
    }
}

    抽象クラスとインターフェースの違い

    1、構文レベルの違い

    • 1）抽象クラスはメンバーメソッドの実装の詳細を提供できますが、インターフェースには public abstract メソッドのみ存在できます；
    • 2）抽象クラス内のメンバー変数は様々な型にできますが、インターフェース内のメンバー変数は public static final 型のみです；
    • 3）インターフェースは静的コードブロックと静的メソッドを含むことはできませんが、抽象クラスは静的コードブロックと静的メソッドを持つことができます；
    • 4）1つのクラスは1つの抽象クラスしか継承できませんが、1つのクラスは複数のインターフェースを実装できます。

    2、設計レベルの違い

    1）抽象クラスはある事物の抽象化、つまりクラスの抽象化であり、インターフェースは振る舞いの抽象化です。抽象クラスはクラス全体を属性や振る舞いを含めて抽象化しますが、インターフェースはクラスの一部（振る舞い）を抽象化します。簡単な例を挙げると、飛行機と鳥は異なる種類の事物ですが、両方とも飛ぶという共通点があります。設計する際、飛行機をクラス Airplane として設計し、鳥をクラス Bird として設計できますが、しかし～を飞行この特性もクラスとして設計されるため、それは単なる振る舞い特性であり、ある種類の事物の抽象的な記述ではありません。この場合、飛行をインターフェースFlyとして設計し、メソッドfly()を含めることができます。そして、AirplaneとBirdはそれぞれ自分の必要に応じてFlyインターフェースを実装します。さらに、異なる種類の飛行機、例えば戦闘機や民間機などは直接Airplaneを継承すればよく、鳥についても同様で、異なる種類の鳥は直接Birdクラスを継承すればよいです。ここからわかるように、継承は「である」の関係であり、インターフェースの実装は「持っているかどうか」の関係です。あるクラスが抽象クラスを継承した場合、そのサブクラスは必ず抽象クラスの一種であることになります。一方、インターフェースの実装は、持っているか持っていないか、備わっているかどうかの関係です。例えば、鳥が飛べるかどうか（または飛行という特性を備えているかどうか）について、飛べるならこのインターフェースを実装でき、飛べないならこのインターフェースを実装しません。

    2）設計レベルが異なり、抽象クラスは多くのサブクラスの親クラスとして、テンプレート式設計です。一方、インターフェースは行動規範であり、放射式設計です。テンプレート式設計とは何か？最も簡単な例として、皆さんは ppt の中のテンプレートを使ったことがあるでしょう。テンプレート A を使って ppt B と ppt C をデザインした場合、ppt B と ppt C の共通部分がテンプレート A です。それらの共通部分を変更する必要があれば、テンプレート A だけを変更すればよく、ppt B と ppt C を再度変更する必要はありません。一方、放射式設計とは、例えば、あるエレベーターにすべて特定の警報器が取り付けられている場合、警報器を更新する必要があれば、全てを更新しなければなりません。つまり、抽象クラスでは、新しいメソッドを追加する必要がある場合、抽象クラスに直接具体的な実装を追加でき、サブクラスは変更しなくても構いません。しかしインターフェースではそれはできず、インターフェースが変更された場合、そのインターフェースを実装するすべてのクラスが対応する変更を行う必要があります。

    次に、ネット上で最も広く知られている例を見てみましょう：ドアと警報の例です。ドアにはすべてopen()とclose()2つの動作があり、このとき抽象クラスとインターフェースを通じてこの抽象概念を定義できます：

    abstract class Door {
    public abstract void open();
    public abstract void close();
}

    または：

    interface Door {
    public abstract void open();
    public abstract void close();
}

    しかし今、ドアに警報機能を持たせる必要がある場合、どのように実装すればよいでしょうか？以下に2つの考え方を示します。

    1）これら3つの機能をすべて抽象クラス内に置く方法。しかしそうすると、この抽象クラスを継承するすべてのサブクラスが警報機能を持つことになりますが、一部のドアは必ずしも警報機能を持つとは限りません。

    2）これら3つの機能をすべてインターフェース内に置く方法。警報機能が必要なクラスは、このインターフェースの open( ) と close( ) を実装する必要がありますが、そのクラスには open( ) と close( ) という2つの機能がまったくないかもしれません。例えば火災警報器などです。

    ここからわかるように、Door の open() 、close() と alarm() は根本的に異なる2つの範疇に属する動作です。open() と close() はドア自体が本来持つ動作特性に属し、alarm() は拡張された付加動作に属します。したがって、最善の解決策は、警報を独立したインターフェースとして設計し、alarm() 動作を含め、Door を独立した抽象クラスとして設計し、open と close の2つの動作を含めることです。さらに、警報ドアを設計して Door クラスを継承し、Alarm インターフェースを実装します。

    interface Alram {
    void alarm();
}
 
abstract class Door {
    void open();
    void close();
}
 
class AlarmDoor extends Door implements Alarm {
    void oepn() {
      //....
    }
    void close() {
      //....
    }
    void alarm() {
      //....
    }
}

    なぜ抽象クラスが必要なのか？

    抽象メソッドと抽象クラスは一見すると冗長に思えます。抽象メソッドは、どう実装すればよいかわからないのであれば、空のメソッド本体を定義すればよいではないか、と思います。また抽象クラスはオブジェクトの生成を許可しないため、不必要な制限を追加しているだけのように見えます。

    抽象メソッドと抽象クラスを導入することは、Javaが提供する構文ツールであり、一部のクラスやメソッドについて、利用者が正しく使用するように導き、誤用を減らすためのものです。

    空のメソッド本体ではなく抽象メソッドを使用することで、サブクラスはそのメソッドを必ず実装しなければならないことを認識し、無視することができなくなります。

    抽象クラスを使用することで、クラスの利用者はオブジェクトを生成する際に、特定の具体的なサブクラスを使用しなければならないことを認識し、不完全な親クラスを誤用することができなくなります。

    プログラムを書くときも、普段他の何かを行うときも、誰でも間違いを犯す可能性があります。エラーを減らすには、人の優れた素質だけに頼るのではなく、普通の人でも物事を正しく行いやすく、間違えにくくする仕組みが必要です。抽象クラスは、Javaが提供するそのような仕組みの一つです。
