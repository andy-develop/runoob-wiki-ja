ECharts レスポンシブ

ECharts のグラフは、ユーザーが指定した高さと幅の DOM ノード（コンテナ）に表示されます。

PC とモバイルデバイスの両方でグラフの内容をうまく表示し、レスポンシブデザインを実現したい場合があります。この問題を解決するために、ECharts はコンポーネントの位置設定を整備し、さらに同様CSS Media Queryの適応能力を実現しました。

ECharts コンポーネントの位置指定とレイアウト

ほとんどの「コンポーネント」と「シリーズ」は、2つの位置指定方式に従います。

left/right/top/bottom/width/height の位置指定方式

この6つの量は、それぞれ「絶対値」「パーセンテージ」「位置の説明」のいずれかにすることができます。

  • 絶対値

    単位はブラウザのピクセル（px）で、number数値形式で記述します（単位は省略）。例：{left: 23, height: 400}。

  • パーセンテージ

    DOMコンテナの高さ・幅に対する割合を示し、string文字列形式で記述します。例：{right: '30%', bottom: '40%'}。

  • 位置の説明

    • 設定できます。left: 'center'水平方向の中央を表します。
    • 設定できます。top: 'middle'垂直方向の中央を表します。

この6つの量の概念は、CSSにおける6つの量の概念と似ています：

  • left：DOMコンテナの左端からの距離。
  • right：DOMコンテナの右端からの距離。
  • top：DOMコンテナの上端からの距離。
  • bottom：DOMコンテナの下端からの距離。
  • width：幅。
  • height：高さ。

横方向では、left、right、widthの3つの量のうち、2つだけ値があれば十分です。任意の2つの量でコンポーネントの位置とサイズを決定できるためです。例えば、leftとright、またはrightとwidthで、コンポーネントの位置とサイズを決定できます。縦方向では、top、bottom、heightの3つの量についても同様ですので、説明は省略します。

center / radius の位置指定方式

  • center

    center は配列で、[x, y][x, y] を表します。ここで、x、yx と y は「絶対値」または「パーセンテージ」にでき、意味は前述と同じです。

  • radius

    radius は配列で、[内半径、外半径][内半径, 外半径] を表します。ここで、内外半径は「絶対値」または「パーセンテージ」にでき、意味は前述と同じです。

    コンテナサイズを自動調整する場合、パーセンテージ設定は非常に便利です。

横方向（horizontal）と縦方向（vertical）

EChartsの「外観が細長い」タイプのコンポーネント（legend、visualMap、dataZoom、timelineなど）の多くは、「横方向レイアウト」「縦方向レイアウト」の選択肢を提供しています。例えば、細長いモバイル端末の画面では「縦方向レイアウト」が適している場合があり、PCのワイド画面では「横方向レイアウト」が適している場合があります。

横・縦レイアウトの設定は、一般に「コンポーネント」または「シリーズ」の orient または layout 設定項目で、'horizontal' または 'vertical' に設定します。

option に Media Query を設定するには、次の形式に従う必要があります：

option = {
    baseOption: { // 这里是基本的『原子option』。
        title: {...},
        legend: {...},
        series: [{...}, {...}, ...],
        ...
    },
    media: [ // 这里定义了 media query 的逐条规则。
        {
            query: {...},   // 这里写规则。
            option: {       // 这里写此规则满足下的option。
                legend: {...},
                ...
            }
        },
        {
            query: {...},   // 第二个规则。
            option: {       // 第二个规则对应的option。
                legend: {...},
                ...
            }
        },
        {                   // 这条里没有写规则，表示『默认』，
            option: {       // 即所有规则都不满足时，采纳这个option。
                legend: {...},
                ...
            }
        }
    ]
};

上記の例では、baseOption、および media の各 option はすべて「原子 option」です。つまり、各コンポーネントやシリーズの定義を含む通常の option です。そして、「原子 option」を組み合わせてできた全体の option を「複合 option」と呼びます。baseOption は必ず使用されます。さらに、ある query 条件が満たされた場合、対応する option が chart.mergeOption() によってマージされます。

query

各 query は次のような形式です：

{
    minWidth: 200,
    maxHeight: 300,
    minAspectRatio: 1.3
}

現在サポートされているのは、width、height、aspectRatio（縦横比）の3つのプロパティです。各プロパティには min または max の接頭辞を付けることができます。例えば、minWidth: 200 は「幅が200px以上」を意味します。2つのプロパティを一緒に書くことは「かつ」を意味します。例：{minWidth: 200, maxHeight: 300} は「幅が200px以上、かつ高さが300px以下」を意味します。

option

media 内の option は「原子 option」なので、理論上は任意の option 設定を記述できます。ただし、通常はレイアウト位置に関連するものだけを記述します。例えば、上記の例から query option の一部を抜粋すると、次のようになります：

media: [
    ...,
    {
        query: {
            maxAspectRatio: 1           // 当长宽比小于1时。
        },
        option: {
            legend: {                   // legend 放在底部中间。
                right: 'center',
                bottom: 0,
                orient: 'horizontal'    // legend 横向布局。
            },
            series: [                   // 两个饼图左右布局。
                {
                    radius: [20, '50%'],
                    center: ['50%', '30%']
                },
                {
                    radius: [30, '50%'],
                    center: ['50%', '70%']
                }
            ]
        }
    },
    {
        query: {
            maxWidth: 500               // 当容器宽度小于 500 时。
        },
        option: {
            legend: {
                right: 10,              // legend 放置在右侧中间。
                top: '15%',
                orient: 'vertical'      // 纵向布局。
            },
            series: [                   // 两个饼图上下布局。
                {
                    radius: [20, '50%'],
                    center: ['50%', '30%']
                },
                {
                    radius: [30, '50%'],
                    center: ['50%', '75%']
                }
            ]
        }
    },
    ...
]

複数の query が満たされたときの優先順位

複数の query が同時に満たされる場合があることに注意してください。その場合、それらはすべて mergeOption されます。定義が後にあるものほど後に merge されます（つまり優先度が高くなります）。

デフォルトの query

media 内のある項目に query を書かない場合、それは「デフォルト値」を意味します。つまり、すべてのルールが満たされない場合に、この option を採用します。

コンテナサイズがリアルタイムに変化する場合の注意事項

多くの場合、コンテナの DOM ノードをドラッグに応じて任意にサイズ変更する必要はなく、異なる端末に応じていくつかの代表的なサイズを設定するだけです。

しかし、コンテナの DOM ノードをドラッグに応じて任意にサイズ変更できる必要がある場合、現在使用する際には次の点に注意する必要があります：ある設定項目が、特定の query option に現れる場合、他の query option にも必ず現れなければなりません。そうしないと、元の状態に戻ることができません。（left/right/top/bottom/width/height はこの制限を受けません。）

「複合 option」内の media は merge をサポートしません

つまり、2回目（または3回目、4回目、5回目...）の chart.setOption(rawOption) の際に、rawOption が複合 option（つまり media リストを含む）である場合、新しい rawOption.media リストは古い media リストと merge されず、単純に置き換えられます。もちろん、rawOption.baseOption は依然として通常どおり古い option と merge されます。 実際には、「複合 option」を使用して複数回 setOption を行う必要がある場面はほとんどありません。推奨される方法は、mediaQuery を使用する場合、最初の setOption では「複合 option」を使用し、以降の setOption では「原子 option」のみを使用することです。つまり、setOption で baseOption のみを変更するということです。
