TypeScript パフォーマンス最適化

TypeScript プロジェクトのパフォーマンス最適化は、コンパイル速度、実行時パフォーマンス、コードサイズなど複数の側面に関わります。

本チュートリアルでは、一般的なパフォーマンス最適化のテクニックを紹介し、より効率的な TypeScript アプリケーションの構築を支援します。

SVG 図:パフォーマンス最適化の次元

なぜパフォーマンス最適化が必要か

TypeScript は強力な型システムを提供していますが、使用方法を誤るとコンパイル速度や実行パフォーマンスに影響を与える可能性があります。

大規模プロジェクトのコンパイルには数分かかることがあり、開発体験に大きな影響を与えます。

本チュートリアルで紹介する設定とテクニックにより、TypeScript プロジェクトのパフォーマンスを大幅に向上させることができます。

最適化の目標:より速いコンパイル速度、より小さいバンドルサイズ、より高い実行時パフォーマンス。

コンパイル設定の最適化

tsconfig.json の設定を最適化してコンパイル速度を向上させます。

tsconfig.json の最適化設定

{
    "compilerOptions": {
        // インクリメンタルコンパイルを有効化し、前回のコンパイル情報を保存する
        "incremental": true,

        // node_modules の型チェックをスキップする
        // コンパイル速度を大幅に向上させる
        "skipLibCheck": true,

        // 宣言ファイルの生成をスキップする(最終ビルド時のみ生成)
        "noEmit": true,

        // 高速インクリメンタルビルドを有効化
        "assumeChangesOnlyAffectDirectDependencies": true,

        // 並列実行
        "parallel": true,

        // キャッシュを有効化
        "tsBuildInfoFile": ".tsbuildinfo",

        // 解析が不要なファイル
        "exclude": [
            "node_modules",
            "dist",
            "build",
            "**/*.test.ts"
        ]
    }
}

skipLibCheck：これは最も重要な最適化オプションであり、コンパイル時間を 50% 以上削減できます。

プロジェクト参照の最適化

プロジェクト参照を使用して大規模プロジェクトを小さなモジュールに分割し、インクリメンタルコンパイルを実現します。

packages/utils/tsconfig.json

{
    // 基本設定を継承する
    "extends": "../../tsconfig.base.json",

    "compilerOptions": {
        "composite": true,
        "outDir": "./dist",
        "declaration": true,
        "declarationMap": true
    },

    "include": ["src/**/*"],
    "exclude": ["node_modules", "dist"]
}

composite：有効にすると、TypeScript は .tsbuildinfo ファイルを生成し、以降のコンパイルを高速化します。

型推論の最適化

TypeScript の型推論を最大限に活用し、過剰な型注釈を避けます。

< h2 class="example">例
// 悪い書き方:型注釈が過剰
const name: string = "Alice";
const age: number = 25;
const isActive: boolean = true;

// 良い書き方:型推論を活用
const name = "Alice";
const age = 25;
const isActive = true;

// 関数の戻り値の型は省略可能(TypeScript が自動的に推論する)
function add(a: number, b: number) {
    return a + b;
}

// 複雑なオブジェクトでは型推論を使用
const user = {
    id: 1,
    name: "Bob",
    email: "bob@example.com"
};
// TypeScript は次のように推論します:
// { id: number; name: string; email: string }

// 型推論が正確でない場合にのみ明示的な型注釈が必要
const elements: HTMLElement[] = [];

型注釈を減らす:TypeScript の型推論は非常に賢く、ほとんどの場合で明示的な型注釈は不要です。

any の使用を避ける

any を使用すると型チェックの利点が失われ、実行時パフォーマンスに影響を与えます。

例

// 悪い書き方:any を使用
function processData(data: any): any {
    return data.value;
}

// 良い書き方:unknown または具体的な型を使用
function processData<T extends { value: string }>(data: T): string {
    return data.value;
}

// 型が本当に不明な場合は unknown を使用
function parseJSON(json: string): unknown {
    return JSON.parse(json);
}

// 使用時に型チェックを行う
const data = parseJSON('{"key": "value"}');
if (typeof data === "object" && data !== null) {
    const obj = data as { key: string };
    console.log(obj.key);
}

// より良い方法:ジェネリクスを使用
function identity<T>(value: T): T {
    return value;
}

const result = identity("hello");
console.log("結果: " + result);

unknown vs any：unknown は型安全な any であり、使用前には型チェックが必要です。

インターフェース vs 型エイリアス

シーンに応じて適切な型定義方法を選択します。

例

// インターフェース:オブジェクト型の定義に適しており、宣言のマージをサポート
interface User {
    id: number;
    name: string;
}

// インターフェースの拡張
interface User {
    email: string;
}

// 型エイリアス:ユニオン型、タプル、関数型に適している
type ID = string | number;
type Status = "pending" | "success" | "error";
type Callback = (data: string) => void;

// ユーティリティ型は通常 type を使用
type PartialUser = Partial<User>;
type ReadonlyUser = Readonly<User>;

// パフォーマンスの考慮:インターフェースは通常、型エイリアスよりもコンパイル速度が速い
// 単純なオブジェクト型には interface を使用できる
interface Point {
    x: number;
    y: number;
}

// ユニオン型には type を使用
type Shape = Circle | Square | Triangle;

選択の推奨:オブジェクト型にはインターフェース、ユニオン型には type、関数型には type を使用します。

ビルドツールの最適化

最適なパフォーマンスを得るためにビルドツールを設定します。

vite.config.ts

// vite をインポート
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

// Vite 設定の最適化
export default defineConfig({
    plugins: [react()],

    // ビルド最適化
    build: {
        // コード分割を有効化
        rollupOptions: {
            output: {
                // 手動分割
                manualChunks: {
                    'vendor': ['react', 'react-dom'],
                    'utils': ['lodash', 'axios']
                }
            }
        },

        // コードの圧縮
        minify: 'terser',

        // sourcemap の生成
        sourcemap: false,

        // チャンクサイズの制限
        chunkSizeWarningLimit: 500
    },

    // 開発サーバーの最適化
    server: {
        // ホットリロードを有効化
        hmr: {
            overlay: true
        }
    },

    // 依存関係の解決を最適化
    optimizeDeps: {
        include: ['react', 'react-dom'],
        exclude: ['some-large-library']
    }
});

コード分割:manualChunks を使用して大規模なライブラリを分離し、メインバンドルのサイズを削減します。

Tree Shaking

Tree Shaking をサポートするようにモジュールを設定し、未使用のコードを除去します。

src/utils/index.ts

// ES モジュールでエクスポートし、Tree Shaking をサポート
export function add(a: number, b: number): number {
    return a + b;
}

export function subtract(a: number, b: number): number {
    return a - b;
}

export function multiply(a: number, b: number): number {
    return a * b;
}

export function divide(a: number, b: number): number {
    if (b === 0) {
        throw new Error("Cannot divide by zero");
    }
    return a / b;
}

// デフォルトエクスポートよりも名前付きエクスポートの方が Tree Shaking に有利
// 誤り:export default は Tree Shaking を妨げる
// export default { add, subtract, multiply, divide };

// 正しい:名前付きエクスポートを使用
console.log("ツールモジュール読み込み");

名前付きエクスポート:デフォルトエクスポートではなく名前付きエクスポートを使用すると、ビルドツールがより効果的に Tree Shaking を行うことができます。

注意事項

  • skipLibCheck：本番環境では必ず有効化
  • インクリメンタルコンパイル:開発環境では有効化を推奨
  • any を避ける:代わりに unknown を使用
  • Tree Shaking：ES モジュールと名前付きエクスポートを使用

ベストプラクティス:開発初期に最適化設定を整え、後期のリファクタリングを避けます。

まとめ

TypeScript のパフォーマンス最適化は複数の側面に関わります。

  • コンパイル最適化:skipLibCheck、incremental、project references
  • 型の最適化:型推論の活用、any の回避、適切な型定義の選択
  • ビルド最適化:コード分割、Tree Shaking、依存関係の最適化
  • 実行時最適化:型安全性、ジェネリクス制約

推奨事項:コンパイル時間とバンドルサイズを定期的に確認し、プロジェクトのパフォーマンスを継続的に最適化します。
