TypeScript アクセス修飾子

アクセス修飾子（Access Modifiers）は、TypeScript のオブジェクト指向プログラミングにおける中核的な機能の1つです。

これらは、クラスメンバー（プロパティ、メソッド、コンストラクタ）の可視性を制御するために使用されます。

アクセス修飾子を使用することで、カプセル化を実現し、クラスの内部実装の詳細を保護できます。

なぜアクセス修飾子が必要か

オブジェクト指向プログラミングの三大原則の1つはカプセル化です。

カプセル化とは、データとデータを操作するメソッドを隠蔽し、外部には必要なインターフェースだけを公開することを意味します。

アクセス修飾子はカプセル化を実現する手段であり、クラスメンバーの可視範囲を制御します。

概念の説明:アクセス修飾子は、クラスメンバーがどこからアクセスできるかを決定します。TypeScript は、public、protected、private の3つのアクセス修飾子を提供します。

public 修飾子

public はデフォルトのアクセス修飾子であり、メンバーがどこからでもアクセスできることを示します。

クラス内部、サブクラス、クラス外部のいずれからでも、public メンバーにアクセスできます。

例

// 動物クラスを定義
class Animal {
    // public で name プロパティを修飾（省略可能、デフォルトで public）
    public name: string;

    // コンストラクタ
    public constructor(name: string) {
        this.name = name;
    }

    // 公開された speak メソッド
    public speak(): void {
        console.log(this.name + " が声を出す");
    }
}

// インスタンスを作成
var animal = new Animal("動物");

// クラス外部から public プロパティにアクセス
console.log(animal.name);

// クラス外部から public メソッドを呼び出し
animal.speak();

実行結果:

動物
動物は声を出す

説明:アクセス修飾子を記述しない場合、TypeScript はデフォルトで public を使用します。そのため public は省略できますが、コードを明確にするために明示的に宣言することをお勧めします。

private 修飾子

private はプライベートメンバーを表し、定義されたクラス内部でのみアクセスできます。

サブクラスおよびクラス外部からは private メンバーにアクセスできません。

これは、クラスの内部実装の詳細を隠し、データが誤って変更されないように保護するためによく使用されます。

例

// 銀行口座クラスを定義
class BankAccount {
    // private で残高を修飾、クラス内部でのみアクセス可能
    private balance: number;

    // コンストラクタ
    constructor(initialBalance: number) {
        this.balance = initialBalance;
    }

    // 入金メソッド
    public deposit(amount: number): void {
        if (amount > 0) {
            this.balance += amount;  // クラス内部から private プロパティにアクセス可能
            console.log("入金成功、現在の残高: " + this.balance);
        }
    }

    // 残高を取得
    public getBalance(): number {
        return this.balance;  // クラス内部から private プロパティにアクセス可能
    }
}

// 口座インスタンスを作成
var account = new BankAccount(1000);

// 入金
account.deposit(500);

// 公開メソッドを介して残高を取得
console.log("残高: " + account.getBalance());

// エラー: クラス外部から private プロパティに直接アクセスできない
// console.log(account.balance); // コンパイルエラー!

実行結果:

存款成功，当前余额: 1500
余额: 1500

ベストプラクティス:クラスの内部状態を private にし、public メソッドを介して制御されたアクセス手段を提供することは、カプセル化を実現する標準的な方法です。

protected 修飾子

protected は保護されたメンバーを表し、クラス内部とサブクラスからアクセスできます。

クラス外部からは protected メンバーに直接アクセスできません。

これは、サブクラスに親クラスの特定の機能を継承させつつ、実装の詳細を隠す必要がある場合に非常に役立ちます。

例

// 人物の基底クラスを定義
class Person {
    // protected で name を修飾、サブクラスからアクセス可能
    protected name: string;

    constructor(name: string) {
        this.name = name;
    }
}

// 従業員クラスを定義し、Person を継承
class Employee extends Person {
    // 部門はプライベート
    private department: string;

    constructor(name: string, department: string) {
        super(name);  // 親クラスのコンストラクタを呼び出し
        this.department = department;
    }

    // 自己紹介メソッド
    public introduce(): string {
        // サブクラスから protected メンバー name にアクセス可能
        return "私は " + this.name + "、" + this.department + " で働いています";
    }
}

// 従業員インスタンスを作成
var emp = new Employee("Alice", "技術部");

console.log(emp.introduce());

// エラー: クラス外部から protected メンバーにアクセスできない
// console.log(emp.name); // コンパイルエラー!

実行結果:

我是 Alice，在 技术部 工作

適用シーン:protected は、サブクラスが使用する必要があるが、外部に公開すべきではないプロパティを定義するためによく使用されます。

readonly 修飾子

readonly はプロパティを読み取り専用に設定するために使用されます。

宣言時またはコンストラクタ内でのみ代入でき、それ以降は変更できません。

これは、定数や識別子を定義するときに非常に役立ちます。

例

// ユーザークラスを定義
class User {
    // readonly で修飾されたプロパティは初期化時のみ代入可能
    // ユーザー ID
    readonly id: number;
    // ユーザー名
    readonly name: string;

    constructor(id: number, name: string) {
        this.id = id;
        this.name = name;
    }
}

// ユーザーインスタンスを作成
var user = new User(1, "Alice");

console.log("ユーザー: " + user.id + ", " + user.name);

// エラー: readonly プロパティは変更できない
// user.id = 2; // コンパイルエラー!
// user.name = "Bob"; // コンパイルエラー!

実行結果:

用户: 1, Alice

注意:readonly と private は競合しません。readonly と private を同時に使用でき、変更も外部からのアクセスもできません。

パラメータプロパティ

TypeScript は、パラメータプロパティ（Parameter Properties）の短縮構文を提供します。

コンストラクタのパラメータに直接アクセス修飾子を使用することで、プロパティを自動的に作成して初期化できます。

例

// 点クラスを定義
class Point {
    // コンストラクタのパラメータに直接修飾子を使用
    // プロパティの宣言と代入を同時に行うのと同等
    constructor(
        // public 修飾: 公開プロパティ x を作成
        public x: number,
        // public 修飾: 公開プロパティ y を作成
        public y: number,
        // private 修飾: プライベートプロパティ z を作成
        private z: number
    ) {
        // コンストラクタ本体は空でもよい、プロパティは自動で作成済み
    }

    // 3次元の合計を計算
    public sum(): number {
        // クラス内部ではすべてのプロパティにアクセス可能
        return this.x + this.y + this.z;
    }
}

// 点のインスタンスを作成
var point = new Point(1, 2, 3);

// 公開プロパティは外部からアクセス可能
console.log("x: " + point.x);
console.log("y: " + point.y);

// メソッドを呼び出し
console.log("合計: " + point.sum());

// エラー: プライベートプロパティは外部からアクセスできない
// console.log(point.z); // コンパイルエラー!

実行結果:

x: 1
y: 2
总和: 6

コードの簡略化:パラメータプロパティを使用すると、クラス定義を大幅に簡素化し、重複する宣言と代入のコードを避けることができます。

アクセス修飾子の比較

以下は、3つのアクセス修飾子の作用範囲の比較です。

修飾子 クラス内部 サブクラス クラス外部（インスタンス）
public ✓ アクセス可能 ✓ アクセス可能 ✓ アクセス可能
protected ✓ アクセス可能 ✓ アクセス可能 ✗ アクセス不可
private ✓ アクセス可能 ✗ アクセス不可 ✗ アクセス不可

選択の推奨事項：デフォルトでは private を使用し、サブクラスからのアクセスが必要な場合は protected を使用し、完全に公開する必要がある場合は public を使用します。

注意事項

  • デフォルトの修飾子：修飾子を書かない場合はデフォルトで public になります
  • コンストラクタ：コンストラクタもアクセス修飾子を使用して、インスタンス化の権限を制御できます
  • readonly の組み合わせ：readonly は public、protected、private と組み合わせて使用できます
  • コンパイルへの影響：アクセス修飾子はコンパイル時にのみチェックされ、実行時には無効です

ベストプラクティス：可能な限り最も厳格なアクセス修飾子を使用します。必要な公開インターフェースのみを公開し、内部実装は private または protected に設定します。

まとめ

アクセス修飾子は、TypeScript でカプセル化を実現するための核心的なツールです。

  • public：公開アクセス、デフォルト値です
  • private：プライベート、クラス内部のみ参照可能
  • protected：プロテクテッド、クラス内部とサブクラスから参照可能
  • readonly：読み取り専用、初期化後に変更不可
  • パラメータプロパティ：プロパティ宣言を簡素化する構文

提案：アクセス修飾子を使用する習慣を身につけることが、高品質な TypeScript コードを書くための基礎です。
