TypeScript オプショナルチェーン

オプショナルチェーン（Optional Chaining）は、TypeScript と JavaScript における安全なプロパティアクセス方法です。

開発者はチェーン呼び出しの形で、ネストされたオブジェクトのプロパティに安全にアクセスできます。アクセス経路上のいずれかのプロパティが null または undefined の場合、式全体は短絡して undefined を返し、エラーをスローしません。

これにより、深くネストされたオブジェクトのプロパティアクセスコードが大幅に簡素化されます。

なぜオプショナルチェーンが必要か

JavaScript/TypeScript 開発では、深くネストされたオブジェクトのプロパティにアクセスする必要がよくあります。

従来の書き方では、プロパティが存在するかを層ごとにチェックする必要があります。この方法はコードが冗長になるだけでなく、チェック漏れによる実行時エラーも発生しやすくなります。

概念の説明:オプショナルチェーンの核心は「短絡評価」です。チェーン内のあるプロパティの値が null または undefined の場合、式全体の結果は直ちに undefined を返し、後続のプロパティへのアクセスは続行されません。

基本構文

使用?.演算子を使用すると、存在しない可能性のあるプロパティに安全にアクセスできます。

従来の && によるチェーン検査と比較すると、オプショナルチェーンの構文はより簡潔で直感的です。

例

// ネストされたユーザーオブジェクトを定義する
// 名前と住所情報を含み、住所には都市がある
var user = {
    name: "RUNOOB",
    address: {
        city: "Beijing"
    }
};

// 従来の方法: && で層ごとにチェックする
// この方法はコードが冗長で、漏れが発生しやすい
var city1 = user && user.address && user.address.city;

// オプショナルチェーンの方法: ?. 演算子を使用する
// いずれかの層が null または undefined の場合、直接 undefined を返す
var city2 = user?.address?.city;

console.log("従来の方法: " + city1);
console.log("オプショナルチェーン: " + city2);

実行結果:

传统方式: Beijing
可选链: Beijing

ヒント:オブジェクトのプロパティが存在する場合、2つの方法の結果は同じです。ただし、オプショナルチェーンのコードはより簡潔で読みやすいです。

存在しないプロパティの処理

アクセス経路上のプロパティが存在しない場合、オプショナルチェーンは安全に undefined を返し、エラーをスローしません。

これは、API からのデータやユーザーフォームの入力を処理する場合に特に役立ちます。

例

// 不完全なユーザーオブジェクトを定義する
// name プロパティのみで、address プロパティがない
var user = {
    name: "RUNOOB"
    // address プロパティは存在しない
};

// オプショナルチェーンを使って深いプロパティにアクセスする
// user.address が undefined のため、city も undefined
var city = user?.address?.city;

// さらに深いネストされたプロパティにアクセスする
// country も存在しない場合でも、エラーにせず undefined を返す
var country = user?.address?.country?.name;

console.log("都市: " + city);
console.log("国: " + country);

実行結果:

城市: undefined
国家: undefined

注意:オプショナルチェーンはプロパティアクセス時に undefined を返すだけで、新しいオブジェクトやプロパティを作成しません。

オプショナルチェーンと配列の組み合わせ

オプショナルチェーンは配列のインデックスアクセスと組み合わせて、配列の要素に安全にアクセスできます。

使用?.[index]構文を使用すると、配列要素が存在しない場合に undefined を返せます。

は存在しない（配列は2要素のみ）ため、undefined を返す

// ユーザーの配列を定義する
var users = [
    { name: "Alice" },
    { name: "Bob" }
];

// 配列の最初の要素の名前を安全にアクセスする
// users?.
var firstUser = users?.[0]?.name;

// 配列に存在しない要素を安全にアクセスする
// users?.
var tenthUser = users?.[9]?.name;

console.log("最初のユーザー: " + firstUser);
console.log("10番目のユーザー: " + tenthUser);

実行結果:

第一个用户: Alice
第十个用户: undefined

説明:?.[index] 与 ?.違いは、前者は配列に使用され、後者はオブジェクトのプロパティに使用されることです。

オプショナルチェーンとメソッド呼び出し

オプショナルチェーンは、存在しない可能性のあるメソッドを安全に呼び出すために使用できます。

使用?.()構文を使用すると、メソッドが存在しない場合に undefined を返し、エラーをスローしません。

例

// 名前と greet メソッドを含むユーザーオブジェクトを定義する
var user = {
    name: "Alice",
    // 挨拶メソッドを定義する
    greet: function() {
        return "Hello, " + this.name;
    }
};

// 存在するメソッドを安全に呼び出す
// user.greet が存在するので、正常に呼び出して結果を返す
var message1 = user.greet?.();

// 存在しないメソッドを安全に呼び出す
// user.sayHello が存在しないので、エラーにせず undefined を返す
var message2 = user.sayHello?.();

console.log("greet: " + message1);
console.log("sayHello: " + message2);

実行結果:

greet: Hello, Alice
sayHello: undefined

適用シーン:これは、オプションのコールバック関数やイベントハンドラーを処理する場合に特に役立ちます。

オプショナルチェーン代入

オプショナルチェーンは代入操作にも使用できますが、その動作に注意が必要です。

オプショナルチェーン代入は既に存在する経路のみを変更し、中間オブジェクトを自動的に作成しません。

例

// 単純なユーザーオブジェクトを定義する
var user = {
    name: "Alice"
};

// オプショナルチェーン代入を試みる
// user?.address が存在しないため、代入全体がスキップされる
// user オブジェクトは変更されない
user?.address?.city = "Beijing";

console.log("ユーザー: " + JSON.stringify(user));

実行結果:

用户: {"name":"Alice"}

注意:オプショナルチェーン代入は新しいプロパティの作成には使用できません。ネストされたオブジェクトを作成する必要がある場合は、従来の方法で先に中間オブジェクトを作成すべきです。

ヌル合体とオプショナルチェーン

オプショナルチェーンは、ヌル合体演算子と??組み合わせて使用されることがよくあります。

この組み合わせにより、プロパティが存在しない場合にデフォルト値を提供でき、コードをより堅牢にします。

例

// 不完全なユーザーオブジェクトを定義する
var user = {
    name: "Alice"
    // address は存在しない
};

// オプショナルチェーン + ヌル合体: city が null または undefined の場合にデフォルト値を使用する
var city = user?.address?.city ?? "不明な都市";

console.log("都市: " + city);

// 比較: 従来の方法の複雑な書き方
var country = user && user.address && user.address.country
    ? user.address.country
    : "不明な国";

console.log("国: " + country);

実行結果:

都市: 未知の都市
国: 未知の国

説明:??値が null または undefined の場合にのみデフォルト値を使用し、||値が falsy（0、""、false）の場合にもデフォルト値を使用します。数値や文字列を扱う場合は、優先的に??。

注意事項

  • 短絡評価:オプショナルチェーンは null または undefined に遭遇すると直ちに返り、後続のプロパティへのアクセスを続行しません。
  • プロパティを作成できない:オプショナルチェーン代入は中間オブジェクトを自動的に作成しません。
  • ヌル合体との併用:常に使用することをお勧めします??デフォルト値を提供し、... をあまり使わない||
  • パフォーマンスの考慮:オプショナルチェーンの方が安全ですが、プロパティが必ず存在する場合は、直接アクセスの方がパフォーマンスが良いです。

提案:実際の開発では、API レスポンスやユーザー入力などの外部データ由来のプロパティに対しては、オプショナルチェーンを優先的に使用して安全にアクセスしてください。

まとめ

オプショナルチェーンは、現代の JavaScript/TypeScript においてネストされたオブジェクトを扱う重要な機能です。

  • ?.：オブジェクトのプロパティに安全にアクセスする
  • ?.[index]：配列の要素に安全にアクセスする
  • ?.()：存在しない可能性のあるメソッドを安全に呼び出す
  • ??：デフォルト値を提供し、undefined の場合を処理する

ベストプラクティス：存在しない可能性のある深いプロパティにアクセスする場合は、常にオプショナルチェーンを使用します。Null 合体演算子と組み合わせることで、安全かつ簡潔なコードを書くことができます。
