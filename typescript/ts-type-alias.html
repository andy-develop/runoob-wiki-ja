TypeScript リテラル型

TypeScript type エイリアス

type エイリアス（Type Alias）は、既存の型にエイリアスを作成するために使用され、コードをより簡潔で読みやすくします。

型エイリアスを使用すると、複雑な型に短い名前を定義でき、コードの保守性が向上します。

SVG 図解：type エイリアス

なぜ type エイリアスが必要なのか

コード内で同じ複雑な型を何度も使用する場合、毎回完全な型を記述すると冗長になります。

type エイリアスは複雑な型に簡潔な名前を定義でき、コードをより読みやすく、保守しやすくします。

特にユニオン型、関数型、タプルなどの複雑な型を使用する場合、type エイリアスは非常に役立ちます。

概念の説明：type エイリアスはtype`type` キーワードで定義され、既存の型に新しい名前を付けるだけで、新しい型を作成するわけではありません。

基本的な使い方

type キーワードを使用して型にエイリアスを定義します。

実例

// 型エイリアス：ユニオン型にエイリアスを定義
// ID は文字列または数値
type ID = string | number;

// 型エイリアス：オブジェクト型にエイリアスを定義
// Point は座標点を表します
type Point = { x: number; y: number };

// 型エイリアスの使用
var userId: ID = "123";
var productId: ID = 456;

// Point 型エイリアスの使用
var point: Point = { x: 10, y: 20 };

console.log("ユーザーID: " + userId);
console.log("製品ID: " + productId);
console.log("座標: " + JSON.stringify(point));

実行結果：

用户ID: 123
产品ID: 456
坐标: {"x":10,"y":20}

説明：型エイリアスは型に新しい名前を付けるだけで、コンパイル後に実際のコードは生成されず、開発時の型チェックにのみ使用されます。

インターフェース vs 型エイリアス

型エイリアスとインターフェースは非常に似ており、どちらもオブジェクト型を定義できますが、いくつかの細かい違いがあります。

実例

// type エイリアスを使用してオブジェクト型を定義
// type はオブジェクトだけでなく、あらゆる型を定義できる
type PersonType = {
    name: string;
    age: number;
};

// インターフェースを使用してオブジェクト型を定義
// インターフェースは宣言のマージが可能で、クラスで実装できる
interface PersonInterface {
    name: string;
    age: number;
}

// どちらも変数の型を宣言するために使用できる
var person1: PersonType = { name: "Alice", age: 25 };
var person2: PersonInterface = { name: "Bob", age: 30 };

console.log("PersonType: " + JSON.stringify(person1));
console.log("PersonInterface: " + JSON.stringify(person2));

違い：type はあらゆる型（ユニオン型、タプル、関数型など）を定義できますが、インターフェースは主にオブジェクト型の定義に使用されます。インターフェースは宣言のマージをサポートしますが、type はサポートしません。

型エイリアスとユニオン型

型エイリアスはユニオン型の定義に非常に適しており、コードがより明確になります。

実例

// ユニオン型エイリアス：状態の可能な値を定義
// Status はこれら3つの文字列リテラルのいずれかのみ
type Status = "pending" | "success" | "error";

// ユニオン型エイリアス：複数の可能な戻り値の型を定義
// Result は文字列、数値、またはブール値
type Result = string | number | boolean;

// ユニオン型エイリアスの使用
function getStatus(status: Status): void {
    console.log("状態: " + status);
}

getStatus("success");
getStatus("error");

// Result 型の使用
var result: Result = "hello";
result = 42;
console.log("結果: " + result);

実行結果：

ステータス: success
ステータス: error
结果: 42

適用シナリオ：ユニオン型エイリアスは、ステータスコード、エラータイプ、API の戻り値などを定義するシナリオでよく使用されます。

型エイリアスとタプル

型エイリアスはタプル型の定義にも使用できます。

実例

// タプル型エイリアス：座標を定義
// Coordinate は2つの数値を含むタプル
type Coordinate = [number, number];

// タプル型エイリアス：名前と年齢を定義
// NameAge は文字列と数値のタプル
type NameAge = [string, number];

// タプル型エイリアスの使用
var coord: Coordinate = [10, 20];
var person: NameAge = ["Alice", 25];

console.log("座標: " + coord);
console.log("情報: " + person[0] + ", " + person[1]);

説明：タプル型エイリアスによりタプルの使用がより明確になり、毎回完全なタプル型を記述する必要がなくなります。

型エイリアスと関数

型エイリアスは関数型の宣言を簡素化できます。

実例

// 関数型エイリアス：コールバック関数の型を定義
// Callback は文字列パラメータを受け取り、void を返す
type Callback = (result: string) => void;

// 関数型エイリアス：数学演算関数の型を定義
// MathOperation は2つの数値パラメータを受け取り、数値を返す
type MathOperation = (a: number, b: number) => number;

// 関数型エイリアスの使用
var add: MathOperation = function(a, b) { return a + b; };
var multiply: MathOperation = function(a, b) { return a * b; };

console.log("加算: " + add(2, 3));
console.log("乗算: " + multiply(4, 5));

実行結果：

加法: 5
乘法: 20

利点：関数型エイリアスは、特に同じ関数シグネチャを何度も使用する必要がある場合に、関数型の宣言をより簡潔にします。

型エイリアスとジェネリック

型エイリアスはジェネリックと組み合わせて使用でき、再利用可能な型定義を作成できます。

実例

// ジェネリック型エイリアス：結果の型を定義
// Result<T> はジェネリック型で、T は成功時のデータ型
type Result<T> = { success: boolean; data?: T; error?: string };

// ジェネリック型エイリアス：キーと値のペアの型を定義
// Pair<K, V> には2つの型パラメータがある
type Pair<K, V> = { key: K; value: V };

// ジェネリック型エイリアスの使用
var result: Result<string> = { success: true, data: "Hello" };
var pair: Pair<string, number> = { key: "age", value: 25 };

console.log("結果: " + JSON.stringify(result));
console.log("キーと値のペア: " + JSON.stringify(pair));

実行結果：

结果: {"success":true,"data":"Hello"}
键值对: {"key":"age","value":25}

ジェネリックの利点：ジェネリック型エイリアスはさまざまなデータ型に対応でき、コードの再利用性が向上します。

型エイリアスとマップ型

型エイリアスはマップ型と組み合わせて、強力な型変換を作成できます。

実例

// マップ型：すべてのプロパティを読み取り専用にする
// Readonly<T> は T のすべてのプロパティを走査し、readonly を追加する
type Readonly<T> = { readonly [P in keyof T]: T[P] };

// マップ型：すべてのプロパティをオプションにする
// Partial<T> は T のすべてのプロパティを走査し、? を追加する
type Partial<T> = { [P in keyof T]?: T[P] };

// ユーザーインターフェースを定義
interface User {
    name: string;
    age: number;
}

// マップ型エイリアスの使用
var readonlyUser: Readonly<User> = { name: "Alice", age: 25 };
// readonlyUser.name = "Bob"; // エラー：読み取り専用プロパティは変更できない

var partialUser: Partial<User> = { name: "Bob" };

console.log("読み取り専用ユーザー: " + JSON.stringify(readonlyUser));
console.log("部分ユーザー: " + JSON.stringify(partialUser));

ヒント：マップ型は TypeScript の非常に強力な機能であり、既存の型に基づいて新しい型のバリエーションを作成できます。

注意事項

  • 重複定義は不可：同じ type エイリアスは重複定義できません（インターフェースは宣言のマージが可能）
  • コンパイル時のみ有効：type エイリアスはコンパイル後にコードを生成しません
  • 可読性を優先：型エイリアスを乱用せず、簡潔で明確なコードの方が良い

ベストプラクティス：型を再利用する必要がある場合、または型名が長すぎる場合は type エイリアスを使用します。単純なオブジェクト型の場合は、チームの習慣に応じて type またはインターフェースを選択できます。

まとめ

type エイリアスは TypeScript で非常に便利な機能です。

  • 基本的な使い方：type キーワードを使用して複雑な型にエイリアスを定義
  • ユニオン型：複数の可能な型の組み合わせを定義
  • 関数型：関数型の宣言を簡素化
  • ジェネリック：再利用可能なジェネリック型を作成する
  • マップ型：既存の型に基づいて新しい型を作成する

提案：type エイリアスを適切に使用するとコードがより明確になりますが、使いすぎないようにしてください。コードを簡潔で読みやすく保つことが最も重要です。
