TypeScript 入門

TypeScript は、マイクロソフトが開発しオープンソース化したプログラミング言語です。JavaScript のスーパーセットであり、JavaScript の構文と完全に互換性を持ちながら、オプションの静的型システムとクラスベースのオブジェクト指向プログラミング機能を追加しています。

TypeScript のコードは最終的に純粋な JavaScript にコンパイルされ、ブラウザ、Node.js、モバイルなど、JavaScript をサポートするあらゆる環境で実行できます。

なぜ TypeScript が必要か

JavaScript は動的型付け言語であり、変数の型は実行時にしか確定しません。

この柔軟性は小規模なプロジェクトでは優れていますが、プロジェクトの規模が大きくなるにつれて、問題が明らかになってきます。

問題となるシナリオJavaScript の課題TypeScript の解決方法
関数の引数に間違った型を渡す実行時になって初めてエラーが発生し、事前に発見するのが難しいコンパイル段階でエラーになり、IDE がリアルタイムに警告する
存在しないプロパティにアクセスする返すundefined、動作は予測しにくいコンパイラが直接エラーを報告し、通過を拒否する
大規模プロジェクトのリファクタリング一箇所を変更すると、どこが壊れるか分からない型システムがすべての参照を自動的に追跡する
チームでの協力関数がどんな引数を受け取り、何を返すかはすべてコメントやドキュメントに依存する型シグネチャがドキュメントとなり、IDE が自動補完する
コードの可読性関数定義を見てもデータ構造を直接知ることはできないインターフェースと型エイリアスにより、データ構造が一目瞭然になる

TypeScript の本質的な目標は、JavaScript を置き換えることではなく、大規模な JavaScript プロジェクトを管理可能で保守可能にすることです。TypeScript は JavaScript の「安全網」であり、競争相手ではありません。

もっともわかりやすい例を見てみましょう：

例

// JavaScript：実行時にのみエラーになる
function greet(name) {
    return "Hello, " + name.toUpperCase();
}

greet(123); // 実行時エラー：name.toUpperCase is not a function

例

// TypeScript：コンパイル時にエラーを発見できる
function greet(name: string): string {
    return "Hello, " + name.toUpperCase();
}

greet(123); // コンパイルエラー：Argument of type 'number' is not assignable to parameter of type 'string'
greet("runoob"); // 正しい：Hello, RUNOOB

TypeScript と JavaScript の関係

TypeScript と JavaScript の関係は、一言でまとめられます：TypeScript は JavaScript のスーパーセットです、つまり、すべての有効な JavaScript コードは、同時に有効な TypeScript コードでもあります。

集合関係の図

JavaScript（すべての JS コード）
⊂ TypeScript（JS + 型システム + 新機能）
⊂ コンパイル成果物（標準 JavaScript、あらゆる環境で実行可能）

両者の核心的な違いの比較：

比較項目JavaScriptTypeScript
型システム動的型付け、実行時に決定静的型付け、コンパイル時にチェック（オプション）
実行方法ブラウザ / Node.js で直接実行JS にコンパイルしてから実行する必要がある
エラー発見のタイミング実行時コンパイル時（事前に発見）
IDE サポート基本的な補完強力な型推論、正確な補完、リファクタリングサポート
学習曲線比較的なだらか型システムを追加で学ぶ必要がある
既存 JS との互換性—完全互換、段階的に移行可能
ファイル拡張子.js.ts 或 .tsx（JSX を含む）

TypeScript は「段階的採用」をサポートしています。プロジェクト全体を一度に書き直す必要はありません。まず.jsに変更し.ts、段階的に重要なモジュールに型を追加し、既存のコードはそのまま動作します。

コア機能

TypeScript は JavaScript を基盤として、完全な型システムを導入しています。以下は最もよく使われるコア機能です。

基本的な型注釈

変数、関数の引数、戻り値の後にコロンで型を宣言します。これは TypeScript の最も基本的な書き方です。

例

// 基本型：number、string、boolean、null、undefined、symbol、bigint
let age: number = 25;
let username: string = "runoob";
let isActive: boolean = true;

// 配列型、2つの等価な書き方
let scores: number[] = [90, 85, 92];
let tags: Array<string> = ["typescript", "javascript"];

// タプル：固定長と固定型の配列
let point: [number, number] = [10, 20];
let entry: [string, number] = ["RUNOOB", 100];

// 関数：引数の型 + 戻り値の型
function add(a: number, b: number): number {
    return a + b;
}

// void：関数に戻り値がない
function log(msg: string): void {
    console.log(msg);
}

// オプション引数：引数名の後に ? を付ける
function greet(name: string, title?: string): string {
    return title ? `${title} ${name}` : name;
}

console.log(greet("RUNOOB"));          // 出力：RUNOOB
console.log(greet("runoob", "Mr."));  // 出力：Mr. runoob

インターフェース（Interface）

インターフェースはオブジェクトの「形状」（Shape）を記述し、オブジェクトが持つべきプロパティとメソッドを定義します。

例

// インターフェースを定義：ユーザーオブジェクトの構造を記述
interface User {
    id: number;          // 必須
    name: string;        // 必須
    email?: string;      // オプション、? でマーク
    readonly role: string; // 読み取り専用、代入後に変更不可
}

// 関数の引数にインターフェース型を使用
function printUser(user: User): void {
    console.log(`ID: ${user.id}, Name: ${user.name}`);
    if (user.email) {
        console.log(`Email: ${user.email}`);
    }
}

const admin: User = {
    id: 1,
    name: "RUNOOB",
    email: "runoob@example.com",
    role: "admin",
};

printUser(admin);
// 出力：ID: 1, Name: RUNOOB
// 出力：Email: runoob@example.com

// admin.role = "user"; // エラー：Cannot assign to 'role' because it is a read-only property.

// インターフェースの継承
interface AdminUser extends User {
    permissions: string[];
}

型エイリアス（Type Alias）

型エイリアスはtypeキーワードで作成し、ユニオン型や交差型などの複雑な構造を含む、あらゆる型にエイリアスを定義できます。

例

// ユニオン型：変数は複数の型のいずれか
type ID = string | number;

let userId: ID = "abc-123"; // 合法
userId = 456;               // これも合法

// リテラル型：変数は特定の値のみに制限
type Direction = "up" | "down" | "left" | "right";
type Status = "pending" | "active" | "inactive";

function move(dir: Direction): void {
    console.log(`Moving ${dir}`);
}

move("up");    // 正しい
// move("diagonal"); // エラー：リテラルの範囲外

// 交差型：複数の型を結合
type WithTimestamp = {
    createdAt: Date;
    updatedAt: Date;
};

type UserRecord = User & WithTimestamp; // User と WithTimestamp のすべてのプロパティを同時に持つ

// 関数型エイリアス
type Transformer<T, U> = (input: T) => U;
const toNumber: Transformer<string, number> = (s) => parseInt(s, 10);

ジェネリック（Generics）

ジェネリックは再利用可能なコンポーネントを書きつつ、型安全性を保つことを可能にします。ジェネリックは「型の変数」と理解できます——使用時に具体的な型を渡します。

例

// ジェネリックなしの書き方：number 型しか扱えない
function firstNumber(arr: number[]): number {
    return arr[0];
}

// ジェネリックを使用：T は型パラメータで、呼び出し時に具体的な型が決まる
function first<T>(arr: T[]): T {
    return arr[0];
}

const n = first<number>([1, 2, 3]);    // n の型は number
const s = first<string>(["a", "b"]);  // s の型は string
const inferred = first([true, false]); // TypeScript は T を boolean と自動推論する

// ジェネリックインターフェース
interface ApiResponse<T> {
    data: T;
    status: number;
    message: string;
}

// ジェネリックインターフェースの使用
const userResponse: ApiResponse<User> = {
    data: { id: 1, name: "RUNOOB", role: "admin" },
    status: 200,
    message: "success",
};

// ジェネリック制約：T に id プロパティが必須であることを制限する
function getById<T extends { id: number }>(items: T[], id: number): T | undefined {
    return items.find(item => item.id === id);
}

列挙型（Enum）

列挙型は一連の名前付き定数を定義するために使われ、コード内の「マジックナンバー」や「マジック文字列」を意味のあるものにします。

例

// 数値列挙（デフォルトで 0 から自動インクリメント）
enum Direction {
    Up,     // 0
    Down,   // 1
    Left,   // 2
    Right,  // 3
}

console.log(Direction.Up);    // 出力：0
console.log(Direction[0]);    // 出力："Up"（逆方向のマッピング）

// 文字列列挙（より推奨。デバッグ時に値が読みやすい）
enum Color {
    Red = "RED",
    Green = "GREEN",
    Blue = "BLUE",
}

function paint(color: Color): void {
    console.log(`Painting in ${color}`);
}

paint(Color.Red); // 出力：Painting in RED
// paint("red"); // エラー：文字列 "red" は Color 型ではない

// const 列挙：コンパイル後にインライン化され、実行時オーバーヘッドを削減
const enum HttpStatus {
    OK = 200,
    NotFound = 404,
    InternalError = 500,
}

const status: HttpStatus = HttpStatus.OK; // コンパイル後に直接数値 200 に置き換えられる

型推論

TypeScript はすべての変数に手動で型を注釈する必要はなく、コンパイラが代入に基づいて自動的に推論します。

例

// TypeScript は変数の型を自動推論するため、明示的な注釈は不要
let count = 0;            // number と推論
let name = "RUNOOB";      // string と推論
let flag = true;          // boolean と推論

// 配列の要素の型を推論
let numbers = [1, 2, 3];  // number[] と推論

// 関数の戻り値の型を推論
function double(n: number) {  // 戻り値は自動的に number と推論
    return n * 2;
}

// オブジェクトリテラルの推論
const config = {
    host: "localhost",    // string
    port: 3000,           // number
    debug: false,         // boolean
};

// config.port = "3000"; // エラー：Type 'string' is not assignable to type 'number'.

実用的なアドバイス：関数のパラメータには通常、明示的な型注釈が必要です（呼び出し側はパラメータの値から型を推論できないため）。一方、関数内のローカル変数や戻り値は、ほとんどの場合推論に任せてよく、すべて手動で注釈する必要はありません。

クラスとアクセス修飾子

TypeScript は ES6 のクラス構文を完全にサポートし、さらにpublic、private、protected、readonly4つのアクセス修飾子が追加されました。

例

class Animal {
    readonly name: string;         // 読み取り専用。初期化後は変更不可
    private age: number;           // プライベート。クラス内部からのみアクセス可能
    protected species: string;     // プロテクテッド。サブクラスからアクセス可能

    constructor(name: string, age: number, species: string) {
        this.name = name;
        this.age = age;
        this.species = species;
    }

    // public メソッド（デフォルトで public のため省略可）
    public introduce(): string {
        return `I'm ${this.name}, a ${this.species}.`;
    }

// getter：プロパティにアクセスするようにメソッドを呼び出す
    get info(): string {
        return `${this.name} (${this.age} years old)`;
    }
}

class Dog extends Animal {
    private breed: string;

    constructor(name: string, age: number, breed: string) {
super(name, age, "Canis lupus familiaris"); // 親クラスのコンストラクタを呼び出す
        this.breed = breed;
    }

// サブクラスは protected プロパティにアクセスできる
    describe(): string {
        return `${this.name} is a ${this.species}, breed: ${this.breed}`;
    }
}

const dog = new Dog("RUNOOB", 3, "Labrador");
console.log(dog.introduce()); // 出力：I'm RUNOOB, a Canis lupus familiaris.
console.log(dog.info);         // 出力：RUNOOB (3 years old)
// console.log(dog.age); // エラー：プライベートプロパティは外部からアクセスできない

デコレータ（Decorator）

デコレータはメタプログラミング構文であり、クラス・メソッド・プロパティに追加の振る舞いを付与するために使われます。Angular や NestJS などのフレームワークでよく見られます。

TypeScript 5.0 ではデコレータが正式標準（Stage 3 提案）として実装され、もはやexperimentalDecoratorsフラグを有効にする必要はありません。

例

// クラスデコレータ：クラス定義時に実行
function sealed(constructor: Function) {
    Object.seal(constructor);         // 新しいプロパティの追加を禁止
    Object.seal(constructor.prototype);
}

// メソッドデコレータ：ログ記録や権限チェックなどに利用可能
function log(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
    const original = descriptor.value;
    descriptor.value = function (...args: any[]) {
        console.log(`Calling ${propertyKey} with args:`, args);
        const result = original.apply(this, args);
        console.log(`${propertyKey} returned:`, result);
        return result;
    };
}

@sealed
class Calculator {
    @log
    add(a: number, b: number): number {
        return a + b;
    }
}

const calc = new Calculator();
calc.add(1, 2);
// 出力：Calling add with args: [ 1, 2 ]
// 出力：add returned: 3

発展の歴史

TypeScript の誕生と成長の歴史は JavaScript エコシステムの進化と密接に関連しており、主要バージョンのリリースにはそれぞれ明確なエンジニアリングニーズが背景にあります。

起源（2010〜2012年）

TypeScript の物語は、マイクロソフト内部のエンジニアリング上の課題、すなわち「大規模な JavaScript プロジェクトを保守可能にするにはどうすればよいか」から始まりました。

設計者Anders Hejlsbergは業界の伝説的存在——C# のチーフアーキテクトであり、Turbo Pascal と Delphi の生みの親です。彼は 2010 年頃にこの言語の設計を開始し、中核目標は JavaScript との互換性を壊さずに静的型チェックを導入することでした。

マイクロソフトが TypeScript を発表したもう一つの背景は Windows 8 のリリースです——アプリケーションを HTML + JavaScript で開発できるようになり、マイクロソフトは .NET プログラマーの参加を引き付けたいと考えました。そのため TypeScript の多くの構文は意図的に C# や .NET に近づけられています。

2012 年 10 月、TypeScript 0.8 が公開リリースされました。それ以前にマイクロソフト内部で約 2 年間開発されていました。

将来の展望：Go でコンパイラを書き直す

2025年初頭、マイクロソフトは重大な決定を発表：TypeScriptコンパイラをGo言語で書き直す。プロジェクトのコードネームはCorsa。

公式によると、書き換え後のコンパイラはパフォーマンスが10倍以上向上する見込みで、大規模プロジェクトのビルド時間は分単位から秒単位に短縮される。

計画によると、Go版はTypeScript 7.xで正式リリースされる予定で、現在のTypeScript 5.x / 6.xは引き続き通常どおり反復開発とメンテナンスが行われる。リファクタリングは2025年末に完了する見込み。

今回の書き換えでTypeScript言語自体の構文や型システムが変わることはなく、開発者にとっては透過的なアップグレードとなる。コードを変更する必要は一切なく、コンパイル速度が大幅に向上するだけだ。

TypeScript と他の静的型付け言語の比較

他の強い型付け言語のバックグラウンドがあれば、以下の比較によってTypeScriptの設計思想を素早く把握できるだろう。

比較項目TypeScriptJava / C#Go
型システム構造的型付け（ダックタイピング）名前的型付け（継承関係を明示的に宣言する必要がある）構造的型付け（暗黙のインターフェース）
ヌル安全性有効にするとstrictNullChecksサポートされるJavaはアノテーションやOptionalを利用する必要があり、C# 8+はサポートerror値とnilチェックによる
ジェネリクスサポート。構文はJava/C#に近いサポート。Javaには型消去の制限があるGo 1.18+でサポート。構文は比較的シンプル
コンパイル成果物JavaScript（JS環境で実行）バイトコード（JVM / CLR上で実行）ネイティブマシンコード
実行時型チェックなし（型情報はコンパイル後に消去される）あり（リフレクション機構）无
学習曲線JS開発者に優しく、段階的に採用可能初心者には比較的急比較的シンプルで、学習曲線は中程度

TypeScriptが使用しているのは構造的型システム（Structural Typing）：2つの型の「形状」が一致していれば互換性があると見なされ、継承関係を明示的に宣言する必要はない。これはJava/C#の名前の型付け（Nominal Typing）とは本質的に異なり、TypeScriptがJavaScriptとシームレスに相互運用できる鍵となる理由でもある。

TypeScript の限界

TypeScriptは銀の弾丸ではない。その境界を理解することも同様に重要だ。

限界説明対応策
実行時に型がない型情報はコンパイル後にすべて消去され、実行時に型に依存した判断はできない実行時検証が必要な場合は使用するzod、io-tsなどのライブラリ
コンパイル工程純粋なJSと比べてコンパイル工程が1つ増え、プロジェクトの複雑さが増す現代のビルドツール（Vite、esbuild）はこれに対してすでに良好な最適化が行われている
any型の脱出ハッチ乱用するとany型チェックが形骸化してしまう有効化noImplicitAnyとstrictモード、ESLintルールとの併用
型体操のハードル複雑な条件型やマップ型は初心者に不親切ほとんどのビジネスコードは高度な型を必要としないため、段階的に学べばよい
サードパーティライブラリのサポート一部の古いライブラリには型定義がなく、自分で.d.tsを作成する必要があるまず確認する@types/*、それでもなければ自分で宣言ファイルを書く
