TypeScript 条件付き型

条件型（Conditional Types）は TypeScript の型システムの中で最も強力な機能の1つです。

条件に応じて動的に型を選択でき、プログラミング言語の三項演算子に似ています。

条件型により型定義がより柔軟になり、高度なユーティリティ型を実装するための基盤となります。

SVG図：条件型のフロー

なぜ条件型が必要なのか

実際の TypeScript 開発では、異なる入力型に応じて異なる型を返す必要がよくあります。

たとえば、関数が文字列または数値の引数を受け取る場合、引数の型に応じて異なる結果型を返す必要があります。

条件型は型レベルで論理判断を行う能力を提供し、型定義をより柔軟かつ強力にします。

概念の説明：条件型の構文はT extends U ? X : Y。型 T が型 U に代入可能な場合は型 X を返し、それ以外の場合は型 Y を返します。

基本構文

条件型は三項演算子の構文を使用し、型レベルで条件判断を行います。

これにより、入力型に基づいて戻り値の型を動的に計算できます。

例

// 条件型の構文：T extends U ? X : Y
// T が文字列型なら true を返し、それ以外は false を返す
type IsString<T> = T extends string ? true : false;

// 条件型を使用
// string extends string は true なので、A 型は true
type A = IsString<string>;
// number extends string は false なので、B 型は false
type B = IsString<number>;

// これらの型を使用
var a: A = true;
var b: B = false;

console.log("string 是字符串?: " + a);
console.log("number 是字符串?: " + b);

実行結果：

string 是字符串?: true
number 是字符串?: false

説明：条件型は型チェック時に自動的に評価され、具体的な型が生成されます。

実践的な応用：型フィルタリング

条件型の最も一般的な用途の1つは型のフィルタリングです。

たとえば、null と undefined を除外する型を作成できます。

例

// 条件型を使用して NonNullable を実装
// T が null または undefined なら never（空の型）を返し、それ以外は T 自身を返す
type NonNullable<T> = T extends null | undefined ? never : T;

// NonNullable 型を使用
// string は null/undefined ではないので、型は string
type A = NonNullable<string>;
// null は null/undefined なので、型は never
type B = NonNullable<null>;
// undefined は null/undefined なので、型は never
type C = NonNullable<undefined>;

// 型を検証
var a: A = "hello";
console.log("非空: " + a);

実行結果：

非空: hello

never 型：never は決して存在しない型を表します。条件が満たされない場合、TypeScript は never を使って「利用不可」の型を表します。

型推論：infer キーワード

infer キーワードは条件型の中で最も強力な機能の1つです。

型から特定の型部分を「抽出」または「推論」することができます。

例

// infer を使用して関数の戻り値の型を推論
// T が関数型なら推論された戻り値の型 R を返し、それ以外は never を返す
type ReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

// ユーザーオブジェクトを返す関数を定義
function getUser() {
    return { name: "Alice" };
}

// 数値を返す関数を定義
function getNumber() {
    return 42;
}

// ReturnType を使用して関数の戻り値の型を取得
// { name: string } と推論される
type R1 = ReturnType<typeof getUser>;
// number と推論される
type R2 = ReturnType<typeof getNumber>;

// 推論された型を使用
var r1: R1 = { name: "Bob" };
var r2: R2 = 100;

console.log("用户: " + JSON.stringify(r1));
console.log("数字: " + r2);

実行結果：

用户: {"name":"Bob"}
数字: 100

infer の役割：infer は型システムにおける「変数」のようなもので、型の特定部分を捕捉し、結果型で使用できます。

分配条件型

条件型のジェネリック型パラメータが Union 型の場合、自動的に「分配」処理が行われます。

つまり、条件は Union 型の各メンバーに対して個別に実行され、結果が結合されます。

例

// ToArray は型 T を配列型に変換する
// T が Union 型の場合、各型に自動的に分配処理される
type ToArray<T> = T extends any ? T[] : never;

// Union 型は自動的に分配される
// string | number は次のように分配される：ToArray<string> | ToArray<number>
// すなわち：string[] | number[]
type StrOrNum = ToArray<string | number>;

// string[] または number[] を代入できる
var arr: StrOrNum = ["hello"];
// number も代入できる
arr = 42;

console.log("数组: " + arr);

実行結果：

数组: 42

分配の仕組み：条件型の分配特性は自動的に有効になります。分配を無効にしたい場合は、角括弧を使用できます：[T] extends U。

条件型とマップ型の組み合わせ

条件型はマップ型と組み合わせて、強力な型変換ツールを作成できます。

この組み合わせは TypeScript の組み込みユーティリティ型を実装するための基盤です。

例

// ユーザーインターフェースを定義
interface User {
    // ユーザー ID
    id: number;
    // ユーザー名
    name: string;
    // ユーザーメール
    email: string;
}

// マップ型と条件型を使用して Partial を実装
// T のすべてのプロパティを走査し、オプション修飾子 ? を追加
type Partial<T> = {
    [P in keyof T]?: T[P];
};

// マップ型と条件型を使用して Required を実装
// T のすべてのプロパティを走査し、オプション修飾子 -? を削除
type Required<T> = {
    [P in keyof T]-?: T[P];
};

// Partial を使用：すべてのプロパティがオプションになる
var partial: Partial<User> = { name: "Alice" };

// Required を使用：Partial<User> のプロパティを必須にする
// 事前に Partial<User> 型が必要
type RequiredUser = Required<Partial<User>>;
var required: RequiredUser = { name: "Bob", id: 1 };

console.log("可选: " + JSON.stringify(partial));
console.log("必填: " + JSON.stringify(required));

実行結果：

可选: {"name":"Alice"}
必填: {"name":"Bob","id":1}

組み合わせて使用：条件型とマップ型の組み合わせにより、Partial、Required、Readonly などの組み込みユーティリティ型のような、複雑な型変換を実現できます。

上級の例：型チェック

条件型はより複雑な型チェックの実装にも使用できます。

以下は実際の開発で役立つ型チェックの例です。

例

// 型が any かどうかをチェック
// any はあらゆる型との交差でも any となり、0 extends any は true
type IsAny<T> = 0 extends (1 & T) ? true : false;

// IsAny をテスト
// any は特殊な型で、あらゆる型との交差は any を返す
type A = IsAny<any>;       // true
// string は any ではない
type B = IsAny<string>;    // false

console.log("any 是 any?: " + A);
console.log("string 是 any?: " + B);

// 型が代入可能かどうかをチェック
// T が U に代入可能なら true を返し、それ以外は false を返す
type IsAssignableTo<T, U> = T extends U ? true : false;

// 型の代入可能性をテストする
// string は any に代入できるので、true を返す
type CanAssign = IsAssignableTo<string, any>;
console.log("string を any に代入?: " + CanAssign);

実行結果：

any 是 any?: true
string 是 any?: true

注意：any は TypeScript の中で最も「緩い」型であり、任意の型に代入できるだけでなく、任意の型の代入も受け取ることができます。

注意事項

  • 遅延評価：条件型は遅延評価され、具体的な型を使用したときにのみ計算されます。
  • 分配特性：Union型は条件型の分配メカニズムを自動的にトリガーします。
  • infer は extends 条件の中でのみ使用できます：これは infer が出現できる唯一の場所です。
  • マッピング型と組み合わせる：条件型とマッピング型を組み合わせることで、強力なユーティリティ型を作成できます。

発展：多くの TypeScript 組み込みユーティリティ型（Partial、Required、Extract など）は条件型を使って実装されています。

まとめ

条件型は TypeScript の型システムの中でも最も強力な機能のひとつです。

  • 基本構文：T extends U ? X : Y
  • infer キーワード：型から特定の部分を推論する
  • 分配特性：Union型は自動的に分配処理される
  • 適用場面：型フィルタリング、型推論、型チェック
  • ユーティリティ型：ほとんどの組み込みユーティリティ型は条件型に基づいて実装されています

ベストプラクティス：条件型を熟練すれば、より柔軟で型安全なコードを書くことができます。
