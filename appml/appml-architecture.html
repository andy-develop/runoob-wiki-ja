<AppML>アーキテクチャ

MVC アーキテクチャ

 

<AppML> は MVC アーキテクチャを採用しています。

MVC の正式名称は Model View Controller で、モデル（Model）－ビュー（View）－コントローラ（Controller）の略語であり、ソフトウェア設計の模範です。

モデル(Model)アプリケーションを記述します。

ビュー(View)データを表示します。

コントローラ(Controller)アプリケーションを制御します。

 

Wikipedia: Model, View, Controller

 

        

モデル(MODEL) - 単なるシンプルなXMLファイル

モデルはアプリケーションを記述し、異なるハードウェアおよびソフトウェアプラットフォーム（PC、iPhone、タブレットなど）で再利用できます。モデルはユーザーインターフェース（UI）や表現形式には関心がありません。

モデルはXMLで記述され、Webサーバーに格納されます。

<appml>

<datasource>
  <database>
    <connection>Northwind</connection>
    <sql>SELECT CustomerName,ContactName,City,Country FROM Customers</sql>
  </database>
</datasource>

<filters>
<query>
  <field label="Customer">CustomerName</field>
  <field>City</field>
  <field>Country</field>
</query>
<order>
  <field label="Customer">CustomerName</field>
  <field>City</field>
  <field>Country</field>
</order>
</filters>

</appml>

上記のインスタンスは、データソースが Northwind データベースからのものであることを定義しています。

このモデルは、事前定義されたSQLを使用してデータを取得できます。また、Customer、City、Countryによるデータのクエリと並べ替えも可能です。

ビュー（VIEW） - 単なる普通のHTMLファイル

ビューとはUI（User Interface：ユーザーインターフェース）です。通常は、データを表示および入力する（オプション）HTMLページです：

<!DOCTYPE html>
<html>
<head>
<link rel="stylesheet" href="appml.css.html" />
</head>
<body>

<h1>My First Web Application</h1>
<div id="Place01"></div>

<script src="appml.js.html"></script>
<script>
customers=new AppML("appml.html","Customers.xml");
customers.run("Place01");
</script>

</body>
</html>

上記のHTMLページは、スクリプト言語を実行してAppMLオブジェクトを作成し、データを id="Place01" の div に表示します。

"appml.js" スクリプトファイルが使用されています。

コントローラ(CONTROLLER) - 単なるブラウザとサーバー側のスクリプト

サーバー側スクリプトは、以下の方法でアプリケーションを制御します：

  • ブラウザからリクエストデータを受信する
  • モデルとデータをブラウザに返す
  • ブラウザから更新データを受信する
  • サーバー上でデータを更新する
  • データ通信プロセスでは、データセキュリティの検証を行ってください。

ブラウザスクリプトは、以下の方法でアプリケーションを制御します：

  • ページの読み込み時に、<AppML> コントローラをページに読み込むことができます。
  • コントローラを使用すると、ページに <AppML> オブジェクトを作成できます。
  • <AppML> オブジェクトを実行すると、サーバーにデータを要求します。
  • <AppML> オブジェクトはサーバーからデータを受け取ります（データモデルを使用）。
  • <AppML> オブジェクト（またはあなたのコード）がページにデータを表示します。
  • （オプション）Webユーザーがデータを変更します。
  • （オプション）<AppML> はサーバーに変更リクエストを送信できます。

典型的なWebファイルとフォルダ：


Webフォルダ：Demo

データフォルダ：Data

モデルフォルダ： Models

アプリケーション：Demo.htm

スタイル：Demo.css

<AppML> 設定ファイル：appml_config.php (または .htmlx)

<AppML> スタイルファイル：appml.css

<AppML> ブラウザコントローラ：appml.js

<AppML> サーバーコントローラ：appml.php(または .htmlx)

高速で柔軟なアプリケーション開発

高速アプリケーション開発（Rapid Application Development、RAD）は、要件抽出方法であるだけでなく、ソフトウェア開発を統合した方法でもあります。高速アプリケーション開発の目的は、システムソリューションを迅速にリリースすることであり、技術的な美しさはリリースの速度に比べれば二次的なものです。

<AppML> は超高速のプロトタイプ設計を提供し、従来のソフトウェア開発方法よりも100倍高速です。

アプリケーションのプロトタイプは、コードを一切記述せずにモデル上で実行できます。

Wikipedia: Rapid Application Development

アプリケーションは、プロトタイプから段階的にステップバイステップで実装できます。

<AppML> アプリケーションは、プロトタイプから完全なアプリケーションまで、段階的にステップバイステップで実装できます。

Wikipedia: Agile Software Development

宣言型プログラミング

ソフトウェア開発は、多くの場合、時間と予算どおりに完了できません。ソフトウェアのコーディングエラーも頻繁に発生します。これは、コンピュータコードの開発、テスト、保守が非常に難しいためです。

コーディングはすでに時代遅れです。あなたは、どのように実装するかではなく、何をするかをもっと記述すべきです。

<AppML> を使用する場合、モデル内で宣言するあなたのアプリケーションを。

使用<AppML>できるコードをほとんど書かないか、まったく書かない。

Wikipedia: Declarative Programming

コードファースト（Code First）

Webアプリケーション開発では、以下の2つの異なる方法を使用できます：

1. コードファースト（Code First）：事前にプログラミングされ、事前にテストされたコードを使用し、新しいアプリケーションの説明のみを追加します。

2. コントラクトファースト（Contract First）：完全なアプリケーションの説明要件を最初から使用してアプリケーションを記述します。

<AppML>最も合理的な概念を採用：サービス指向アーキテクチャ（service-oriented architecture、SOA）。

サービス指向アーキテクチャ（service-oriented architecture、SOA）

Web Service典型的なものを提供する

ページにデータを提供します。Web Service<AppML> を使用すると、HTMLがユーザーインターフェースとして表示され、<AppML> がデータを提供します。

設計では、SOAP、WSDL、UDDIなどのXMLマークが使用されています。

Original Web Services理解しやすい - 私たちが読むことができる

Modern Web Services軽量 - 不要なコードやマークがない

  • 実装が容易 - 必要な開発ツールがない
  • サービス指向アーキテクチャ（service-oriented architecture、SOA）はコンポーネントモデルであり、アプリケーションの異なる機能ユニット（サービスと呼ばれる）を、これらのサービス間で明確に定義されたインターフェースと契約によって結び付けます。インターフェースは中立的な方法で定義され、サービスを実装するハードウェアプラットフォーム、オペレーティングシステム、プログラミング言語から独立している必要があります。これにより、さまざまなシステムに構築されたサービスが、統一的かつ汎用的な方法で相互運用できるようになります。
  • Web Servicesの利点

Web services は少量のコードしか必要としません

Web Servicesの利点

  • Web services はHTTPベースの通信プロトコルを使用します
  • Web services はオペレーティングシステムに依存しません
  • Web services はプログラミング言語に依存しません
  • Web services は異なるアプリケーション、システム、およびデバイスを接続できます
  • Web Services は情報を非常に簡単に公開できます
  • Web Services は迅速なアプリケーション開発に役立ちます
  • 例えば、Web services は、最新の株式取引価格を提供する小さなアプリケーションとして設計できます。
  • Web services はHTTPプロトコルを使用して他のシステムと通信します。Webサービスはオペレーティングシステムやプログラミング言語から独立しています。

Web services を呼び出すアプリケーションは、常にHTTPプロトコルを使用してリクエストを送信します。呼び出し側アプリケーションは、他のコンピューターが実行しているオペレーティングシステムやプログラミング言語を気にすることはありません。

Web services は、大量の情報を簡単に配布する方法を提供するため、より多くの企業に新たな可能性をもたらすことができます。

例：フライトスケジュールと航空券予約システム。

クラウドコンピューティング(Cloud Computing)

クラウドコンピューティング（Cloud Computing）はSOAの拡張です：アプリケーション・アズ・ア・サービス（Application-as-a-Service）、ストレージ・アズ・ア・サービス（Storage-as-a-Service）、データ・アズ・ア・サービス（Data-as-a-Service）。

クラウドコンピューティング(Cloud Computing)

云计算（Cloud Computing）是SOA的扩展：应用即服务（Application-as-a service），存储即服务（Storage-as-a-service），数据即服务（Data-as-a-service）。

大多数の人々にとって、クラウドコンピューティングはWeb上でデータを保存することです。

  • メールとカレンダー
  • ドキュメントとスプレッドシート
  • 書籍、ノート、ToDoリスト
  • 音楽、画像、映画
  • データベースとアプリケーション

理由は明らかだ：

  • 世界中からアクセスデータがある
  • 他の人とデータを共有する
  • ハードウェアのアップグレードやクラッシュ

<AppML> はデータベースとアプリケーションを簡単にクラウドに置くことができます。
