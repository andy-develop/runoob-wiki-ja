3.7 AsyncTask非同期タスク

分類 Android 基礎入門チュートリアル

本節の導入：

この節で紹介するのは、Androidが提供する、非同期タスクを処理するための軽量なクラス、AsyncTaskです。通常はAsyncTaskを継承し、クラス内で非同期操作を実装し、非同期実行の進捗をUIメインスレッドにフィードバックします。さて、概念が分からない方もいるかもしれませんので、マルチスレッドの概念について解説する必要があると思います。まずはいくつかの概念的なことを説明しましょう！

1. 関連概念

1）マルチスレッドとは何か：

答え：まずこれらの名称を理解する必要があります：アプリケーション、プロセス、スレッド、マルチスレッド！！

  • アプリケーション(Application)：特定のタスクを達成するために、ある言語で書かれた一連の命令の集合（静的なコードの集まり）
  • プロセス(Process) :実行中のプログラム、システムのスケジューリングとリソース割り当ての独立した単位、オペレーティングシステムは各プロセスにメモリ空間を割り当てます。プログラムの逐次動的実行は、コードのロード -> 実行 -> 実行完了という完全なプロセスを経ます！
  • スレッド(Thread)：プロセスよりも小さな実行単位であり、各プロセスは複数のスレッドを持つ可能性があります。スレッドはプロセス内に配置されて初めて実行できます！スレッドはプログラムが管理を担当します！！！一方、プロセスはシステムによってスケジューリングされます！！！
  • マルチスレッドの概念(Multithreading)：複数の命令を並行して実行し、CPUのタイムスライスをスケジューリングアルゴリズムに従って各スレッドに割り当てます。実際には時分割実行であり、ただこの切り替え時間が非常に短いため、ユーザーには同時に実行されているように感じられるだけです！

簡単な例を挙げます：QQを起動したまま、急に音楽を聴きたくなったとします。QQを閉じてからXXプレイヤーを起動する必要がありますか？答えはノーです。プレイヤーを開いて音楽を再生すればよく、QQはまだ動作していますよね！これが簡単なマルチスレッドです。実際の開発でもこのような例があります。例えば、アプリが実行中に新しいバージョンを見つけ、バックグラウンドで更新したい場合、通常はバックグラウンドスレッドを1つ作成して新しいバージョンのapkをダウンロードしますが、このときアプリの他の機能も引き続き使用できます！これがマルチスレッドの使用例です。

2）同期と非同期の概念：

答え：同期：ある機能を実行するとき、結果が得られるまでこの呼び出しは返ってきません。簡単に言うと、前のことを終わらせてからでないと次のことをできないということです。簡単な例を挙げます：例えば、エッチをするとき、妊娠しないように、まずゴムを着けてからエッチをするでしょう？ゴムを着ける -> それからエッチ。もしゴムがなければ、エッチは待たなければならず、ゴムを買ってきて着けるまで待って、そのときにエッチを始められます。という分かりやすい例です。♪(^∇^*)非同期：非同期は同期と対照的で、ある機能を実行した後、すぐに結果を得る必要はなく、通常通り他の操作を行うことができます。この機能は完了後に通知またはコールバックで知らせてくれます。先ほどのバックグラウンドダウンロードの例ですが、バックグラウンドでダウンロードを実行した後、ダウンロードの過程を気にする必要はなく、ダウンロードが完了したら通知してもらえばよいのです。

3) Androidはなぜ非同期タスクを導入するのか

答え：Androidプログラムが起動すると、同時に対応するメインスレッド(Main Thread)が起動します。このメインスレッドは主にUI関連のイベントを処理します！これをUIスレッドと呼ぶこともあります！Androidアプリでは、このシングルスレッドモデルのルールを守らなければなりません：AndroidのUI操作はスレッドセーフではなく、これらの操作はすべてUIスレッドで実行する必要があります！もし非UIスレッドで、例えばメインスレッドでnew Thread()を使用して別のスレッドを作成し、その中で直接UIコントロールの値を変更した場合、次の例外がスローされます：android.view.ViewRoot$CalledFromWrongThreadException: Only the original thread that created a view hierarchy can touch its viewsさらに、もう1点、時間のかかる操作をすべてUIスレッドに置いた場合、UIスレッドが5秒以上ユーザーのリクエストに応答しないと、ANR(Application Not Responding)例外が発生します。つまりアプリが無応答になります。最後にもう1点：Android 4.0以降、UIスレッドでのネットワーク操作は禁止されています。そうしないとエラーが発生します：android.os.NetworkOnMainThreadException

以上のような様々な理由から、Androidが非同期タスクを導入した意味が分かります。もちろん、非同期を実現するために必ずしもこの節で解説するAsyncTaskを使う必要はありません。自分でスレッドを作成し、関連する操作を完了した後、以下の2つの方法でUIを更新できます：

  1. 以前学んだHandlerでは、Handler内でUI更新を記述し、sendMessage()などのメソッドでUI更新を通知しました。また、Handlerをメインスレッドと子スレッドのどちらに書くかの違いを忘れないでくださいね。
  2. Activity.runOnUiThread(Runnable)を利用して、UI更新のコードをRunnable内に作成します。UI更新時には、Runnableオブジェクトを渡せばよいです。

2. AsyncTask徹底解説：

1）なぜAsyncTaskを使うのか？

答え：上記の2つの方法で非同期操作を実行できます。しかし、書く必要がある非同期操作が多かったり、比較的煩雑だったりする場合、毎回new Thread()して上記の方法でUI更新を通知するのでしょうか？プログラマーは怠けるのが好きです。公式がAsyncTaskというカプセル化された軽量な非同期クラスを提供しているのに、なぜ使わないのでしょうか？数十行のコードで非同期操作を完了でき、進捗も制御できます。Handlerと比較して、AsyncTaskはより簡単で迅速です。もちろん、これは単純な非同期操作に適しています。また、実際に非同期が最も多く使われるのはネットワーク操作、画像読み込み、データ転送などです。AsyncTaskは初心者のニーズをひとまず満たし、小さなアプリを作成することができます。しかし、会社で実際にプロジェクトを行うようになると、Volley、OkHttp、android-async-http、XUtilsなど、より多くのサードパーティフレームワークを使用します。後の発展的チュートリアルでは1～2つのフレームワークを選んで学習します。もちろん、自分で資料を探して学ぶこともできますが、AsyncTaskを習得することはやはり非常に必要です！

ダウンロードをシミュレートするための遅延操作を定義します：

public class DelayOperator {  
    //延时操作,用来模拟下载  
    public void delay()  
    {  
        try {  
            Thread.sleep(1000);  
        }catch (InterruptedException e){  
            e.printStackTrace();;  
        }  
    }  
}

AsyncTaskをカスタマイズ：

public class MyAsyncTask extends AsyncTask<Integer,Integer,String>  
{  
    private TextView txt;  
    private ProgressBar pgbar;  
  
    public MyAsyncTask(TextView txt,ProgressBar pgbar)  
    {  
        super();  
        this.txt = txt;  
        this.pgbar = pgbar;  
    }  
  
  
    //该方法不运行在UI线程中,主要用于异步操作,通过调用publishProgress()方法  
    //触发onProgressUpdate对UI进行操作  
    @Override  
    protected String doInBackground(Integer... params) {  
        DelayOperator dop = new DelayOperator();  
        int i = 0;  
        for (i = 10;i <= 100;i+=10)  
        {  
            dop.delay();  
            publishProgress(i);  
        }  
        return  i + params[0].intValue() + "";  
    }  
  
    //该方法运行在UI线程中,可对UI控件进行设置  
    @Override  
    protected void onPreExecute() {  
        txt.setText("开始执行异步线程~");  
    }  
  
  
    //在doBackground方法中,每次调用publishProgress方法都会触发该方法  
    //运行在UI线程中,可对UI控件进行操作  
  
  
    @Override  
    protected void onProgressUpdate(Integer... values) {  
        int value = values[0];  
        pgbar.setProgress(value);  
    }  
}

MainActivity.java：

public class MyActivity extends ActionBarActivity {  
  
    private TextView txttitle;  
    private ProgressBar pgbar;  
    private Button btnupdate;  
  
    @Override  
    protected void onCreate(Bundle savedInstanceState) {  
        super.onCreate(savedInstanceState);  
        setContentView(R.layout.activity_main);  
        txttitle = (TextView)findViewById(R.id.txttitle);  
        pgbar = (ProgressBar)findViewById(R.id.pgbar);  
        btnupdate = (Button)findViewById(R.id.btnupdate);  
        btnupdate.setOnClickListener(new View.OnClickListener() {  
            @Override  
            public void onClick(View v) {  
                MyAsyncTask myTask = new MyAsyncTask(txttitle,pgbar);  
                myTask.execute(1000);  
            }  
        });  
    }  
}
