SWFUpload

SWFUpload最初はVinterwebb.se開発されたクライアント側ファイルアップロードツールです。JavaScriptとFlashを組み合わせ、ブラウザで従来のアップロードタグ <input type="file" /> よりも優れた機能（および優れたユーザーエクスペリエンス）を提供します。

SWFUpload の主な特徴：

  • ファイル選択ダイアログで複数のファイルを選択できます。
  • AJAXスタイルのアップロードで、ページを再リフレッシュする必要はありません。
  • アップロードプロセス中の各種イベント。
  • クライアント側で画像サイズを調整できます。
  • それが使用するクラス名前空間は、さまざまなJSライブラリ（i.e., jQuery、Prototype、など）と互換性があります。
  • Flash 9 および Flash 10 をサポート（v2.2.0以降、Flash 8のサポートは廃止）

SWFUploadの設計理念は、他のFlashベースのアップロードツールとは異なります。SWFUploadは開発者に可能な限り多くのUI制御能力を提供します。開発者はXHTML、CSS、JavaScriptを使用して、自社サイトのスタイルにより適合させることができます。アップロード状態を更新する一連のシンプルなJSイベントを提供し、開発者はこれらのイベントに基づいてWebページにファイルのアップロード進捗を表示できます。

しかし残念ながら、Flash Player 10 では、ファイル選択ダイアログを開くために（クリック後に）ボタンを使わざるを得ません。しかしSWFUploadは開発者がJSを使ってこのボタンのテキストなどの外観を変更できるようにします。

SWFUpload v2

SWFUpload v2 には多くの新機能が含まれ、安定性が向上し、Flash Player のいくつかのバグを解決し、有用なプラグイン（Plug-ins）を提供します。新機能は以下のとおりです:

  • Flash Player 10 のセキュリティ機能を利用可能。
  • アップロードと一緒に追加のデータをPOSTできます。
  • ファイルアップロードごとにPOSTデータを送信します。
  • 充実した各種イベント群。
  • すべての設定、パラメータを柔軟に構成できます。
  • サーバーから返信されたデータを取得できます。
  • アップロード中のファイルをキャンセルするのではなく、一時停止できます。
  • アップロードの順序を任意に変更できます。
  • 単一または複数ファイルの選択ダイアログを提供できます。
  • アップロードファイルのキューの長さ、ファイルサイズ、アップロードファイル数を制限できます。
  • 0バイトのファイルをより適切に処理できます。
  • 各ファイルにはアップロード確認イベントがあります。

Overview

HTML Upload

標準的なHTMLアップロードボックスは、ユーザーが単一のファイルを選択するためのボタンとテキストボックスのみを提供します。その後、フォーム送信を行います。ファイル全体がアップロード完了するまで、ファイルサイズやファイル拡張子を確認・検査することができず、アップロード中のフィードバックもほとんどありません。これにより、いくつかの使用上の不便が生じます。

しかし、従来のHTMLアップロードは非常にシンプルで、単一のステップであり、すべてのブラウザがそれをサポートしています。

SWFUpload

SWFUpload はFlashムービー（flash movie）を使用してファイルを選択およびアップロードします。ムービー内にはファイル選択ダイアログをアクティブにするカスタマイズ可能なボタンがあります。ファイル選択ダイアログでは、ユーザーは単一のファイルまたは複数のファイルを選択できます。選択できるファイルタイプも制限でき、開発者はユーザーが指定した適切なファイル（例: *.jgp;*.gif）のみを選択できるように制限できます。

ファイルを選択して確定をクリックすると、各ファイルが検証され、キューに入れられます。Flashがファイルをアップロードするとき、開発者が事前に定義したJavascriptイベントがトリガーされ、ページ内のUI表示を更新し、アップロード状態やエラー情報をリアルタイムに提供できます。

ファイルのアップロードはページやフォームから独立しています。各ファイルは個別に処理ページへアップロードされるため、サーバーはファイルを簡単かつ手軽に処理できます。Flashが提供するアップロードサービスにより、ページ全体を送信またはリフレッシュする必要がありません。これはAJAXプログラムに似ています。ページ内のFormフォームデータは、FLASHが制御するファイルアップロードとは別に処理されます。

入门 Getting Started

SWFUpload はドラッグ＆ドロップ式のアップロードコントロールではありません。そのため、DOMとJSに関するある程度の知識が必要です。いくつかのデモが、swfUploadの能力と、それらを使用してタスクを完了する方法を示します。

SWFUpload は4つの部分から構成されます：

  1. 初期化と設定（JavaScript）
  2. JavaScript 库: SWFUpload.js
  3. Flashコントロール: swfupload.swf と swfupload_fp9.swf
  4. イベント処理メカニズム（JavaScript）

SWFUpload を使用する際の問題の多くは設定に起因します。誤ったイベント処理、Flash/ブラウザのバグ、またはサーバー設定です。

初期化と設定 Initialization and Settings

SWFUpload はページ上で初期化する必要があります。通常、JSのwindow.onloadイベント内で行われます。SWFUpload のコンストラクタは、Object型のオブジェクト（JS）を取得する必要があります。このオブジェクトのデータはコンストラクタに直接渡されます。

初期化されたSWFUploadオブジェクトの参照（reference）は保存しておく必要があります。（yukon: つまり変数に格納します。例の中のswfuのように）ファイルアップロードの開始や他の機能を制御する際にもこの参照が必要だからです。

例子:SWFUploadの初期化時に、匿名オブジェクトを直接渡してパラメータを構成します。

var swfu; window.onload = function () { swfu = new SWFUpload({ upload_url : "http://www.swfupload.org/upload.php", //处理上传文件的地址 flash_url : "http://www.swfupload.org/swfupload.swf", //核心功能swf的地址 flash9_url : "http://www.swfupload.org/swfupload_fp9.swf", file_size_limit : "20 MB" //文件大小限制 }); };

例子:SWFUploadの初期化時に、オブジェクト変数（settings_object）を使用して設定パラメータを渡すこともできます。

var swfu; window.onload = function () { var settings_object = { upload_url : "http://www.swfupload.org/upload.php", flash_url : "http://www.swfupload.org/swfupload.swf", flash9_url : "http://www.swfupload.org/swfupload_fp9.swf", file_size_limit : "20 MB" }; swfu = new SWFUpload(settings_object); };

js库 JavaScript library

swfuploadを使用する場合は、JSライブラリファイル（swfupload.js）を使用するページに含める必要があります。

SWFUpload オブジェクトが作成されると、多くの機能関数にアクセスできます。開発者はこれを使用してSWFUploadを制御できます。

例:swfupload.js ライブラリの導入方法

<script type="text/javascript" src="../www.swfupload.org/swfupload.js"></script>

例:必要に応じてSWFUploadを初期化します。

var swfu = new SWFUpload({ upload_url : "http://www.swfupload.org/upload.php", flash_url : "http://www.swfupload.org/swfupload.swf", flash9_url : "http://www.swfupload.org/swfupload_fp9.swf", button_placeholder_id : "spanSWFUploadButton" //yukon：这里有个新参数，将会使用js在id为"spanSWFUploadButton"的标签容器如span，div中创建一个"选择"按钮 });

【新規追加】フラッシュコントロール Flash Control

SWFUpload JSライブラリはFlashコントロール（swfupload.swf または swfupload_fp9.swf）を動的にロードできます。

Flashコントロールのファイルアドレスは、初期化時にSWFUpload設定オブジェクト内で定義する必要があります。

Flashコントロールは実際にはFlashの小さなムービーであり、ファイルの選択、検証、アップロードを制御できます。

これはページ上でユーザーにUIをカスタマイズできるボタンとして表示され、Flash Playerのバージョン（9、10）を検出して、ユーザーのプレイヤーバージョンに適したFlashコントロールを自動的にロードできます。

flash_url と flash9_url を使用して、swfupload.swf または swfupload_fp9.swf のパスを設定できます。（yukon：前述の例ですでに書かれています）

事件处理 The Event Handlers

開発者はSWFUploadのイベントを処理するための一連のJS関数を作成する必要があります。さまざまな重要なイベントが発生すると、これらの関数がトリガーされて実行されます。

SWFUploadのイベントを処理することで、開発者はアップロード進捗、エラー情報、アップロード完了などの情報フィードバックを提供できます。注意：開発者はSWFUpload.prototypeに格納されている関数を書き換えないでください。

例:SWFUploadのイベント処理と初期化。

// 上传开始（uploadStart）事件处理函数. 设置对象的"upload_start_handler"属性的值应是此函数的名字 var myCustomUploadStartEventHandler = function (file) { var continue_with_upload; if (file.name === "the sky is blue") { continue_with_upload = true; } else { continue_with_upload = false; } return continue_with_upload; }; // 上传成功（ uploadSuccess ）事件处理函数. 设置对象的"upload_success_handler"属性的值应是此函数的名字 var myCustomUploadSuccessEventHandler = function (file, server_data, receivedResponse) { alert("The file " + file.name + " has been delivered to the server. The server responded with " + server_data); }; // Create the SWFUpload Object var swfu = new SWFUpload({ upload_url : "http://www.swfupload.org/upload.php", flash_url : "http://www.swfupload.org/swfupload.swf", flash9_url : "http://www.swfupload.org/swfupload_fp9.swf", file_size_limit : "200 MB", upload_start_handler : myCustomUploadStartEventHandler, upload_success_handler : myCustomUploadSuccessEventHandler

グローバル変数と定数 Globals and Constants

SWFUploadはいくつかのグローバル変数と定数を定義しています。これらはSWFUploadの高度なアプリケーションやエラー処理に非常に役立ちます。これらはすべて読み取り専用です。

【新增内容】SWFUpload.instances

SWFUpload.instances は、ページ内のすべてのSWFUploadインスタンスへの参照を格納する配列オブジェクトです。Flash Playerはこのオブジェクト配列を使用して、正しいイベント処理関数を呼び出します。SWFUpload.instancesオブジェクト配列のインデックス（SWFUpload.instances[index]）は、プロパティ movieName です。

SWFUpload.movieCount

SWFUpload.movieCountはグローバル変数で、ページ内で作成されたSWFUploadオブジェクトインスタンスの数を記録し、各Flashムービーに一意のmovieNameが割り当てられることを保証するために使用されます。

【新增内容】SWFUpload.QUEUE_ERROR

SWFUpload.QUEUE_ERROR は単純なJSオブジェクトで、キューのエラーコード（Queue Error code）の定数を含みます。ファイルキューのエラー（fileQueueError）が発生したときに、どのエラーコードが送信されるかを決定するために使用されます。

SWFUpload.QUEUE_ERROR = { QUEUE_LIMIT_EXCEEDED : -100, FILE_EXCEEDS_SIZE_LIMIT : -110, ZERO_BYTE_FILE : -120, INVALID_FILETYPE : -130 };
  • QUEUE_LIMIT_EXCEEDED - ユーザーがキューに追加したファイルが多すぎて、キューの最大長を超えていることを示します。ただし、キュー内のファイルがアップロードまたは削除されると、ユーザーはファイルをアップロード待機キューに追加できます。
  • FILE_EXCEEDS_SIZE_LIMIT - 制限されたファイルサイズ（file_size_limit）を超えたことを示します。
  • ZERO_BYTE_FILE - 選択されたファイルが0バイトであることを示します。Flash Playerは空のファイルを処理できません。Windowsショートカットアイコンをアップロードすると、このエラーも発生します。
  • INVALID_FILETYPE - 選択されたファイルの拡張子が許可されたものと一致しないことを示します。ユーザーがマウスでファイルを選択する代わりに、拡張子が一致しないファイル名を手動で入力すると、このエラーが発生する可能性があります。

【新增内容】SWFUpload.UPLOAD_ERROR

SWFUpload.UPLOAD_ERROR も単純なJS配列オブジェクトで、アップロードエラーコード定数（Upload Error code constants）を含みます。アップロードエラー（uploadError）イベントが発生したときに、どのエラーコードを送信するかを決定するために使用されます。

SWFUpload.UPLOAD_ERROR = { HTTP_ERROR : -200, MISSING_UPLOAD_URL : -210, IO_ERROR : -220, SECURITY_ERROR : -230, UPLOAD_LIMIT_EXCEEDED : -240, UPLOAD_FAILED : -250, SPECIFIED_FILE_ID_NOT_FOUND : -260, FILE_VALIDATION_FAILED : -270, FILE_CANCELLED : -280, UPLOAD_STOPPED : -290 };
  • HTTP_ERROR - サーバーへのアップロードを試みたが、サーバーが200ステータスコードを返さなかった場合（200は異常なしを意味します）。
  • MISSING_UPLOAD_URL - 没有设置上传地址（upload_url）.
  • IO_ERROR - ファイルの読み取りおよび送信中に何らかのエラーが発生しました。通常は、サーバーが予期せず接続を閉じたときに発生します。
  • SECURITY_ERROR - セキュリティエラー。アップロードがセキュリティ制約に違反しています。比較的まれです。
  • UPLOAD_LIMIT_EXCEEDED - ユーザーが設定数より多くのファイルをアップロードしようとした。
  • UPLOAD_FAILED - アップロードの初期化中にエラーが発生しました。まれです。
  • SPECIFIED_FILE_ID_NOT_FOUND - ファイルのアップロードが開始されたが、そのファイルが見つかりませんでした。（yukon: ファイルを選択してキューに追加した後、ユーザーがディスク上でファイル名を変更したり、ファイルを削除した場合など）
  • FILE_VALIDATION_FAILED - アップロード開始時に何らかのエラーが返されました。
  • FILE_CANCELLED - アップロードをキャンセルしました（cancelUpload関数が呼び出されました）。
  • UPLOAD_STOPPED - アップロードを停止しました（stopUpload関数が呼び出されました）。
  • RESIZE_ERROR - 画像のサイズを調整するときに何らかのエラーが発生しました

【新增内容】SWFUpload.FILE_STATUS

SWFUpload.FILE_STATUS は、ファイルステータスコード定数（File Status code constants）を含むJS配列オブジェクトです。Fileオブジェクトのファイルステータスプロパティ（file status）を検出するために使用します。

SWFUpload.FILE_STATUS = { QUEUED : -1, IN_PROGRESS : -2, ERROR : -3, SUCCESS : -4, CANCELLED : -5 };
  • QUEUED - このファイルがアップロード待機キューにあることを示します
  • IN_PROGRESS - このファイルが現在アップロード中であることを示します
  • ERROR - このファイルがキューまたはアップロードエラーを引き起こしたことを示します
  • COMPLETE - このファイルがサーバーに正常に転送されたことを示します
  • CANCELLED - このファイルのアップロードがキャンセルされたことを示します（cancelUpload関数が呼び出されました）。

【新規追加】SWFUpload.UPLOAD_TYPE[機能：アップロードタイプの決定]

SWFUpload.UPLOAD_TYPE は、アップロードタイプ定数（Upload Type constants）を含むJS配列オブジェクトです。Fileオブジェクトのアップロードタイププロパティ（upload type property）を検出するために使用します。

  • NORMAL - 通常のSWFUploadアップロード
  • RESIZED - サイズ変更された画像がアップロードされ、データはHTTPのPOST方式で送信されます。

【新規追加内容】SWFUpload.BUTTON_ACTION[機能: ボタンをクリックした後に実行されるアクションを決定します]

SWFUpload.BUTTON_ACTIONはJS配列オブジェクトで、ボタンアクションコード定数（button action code constants）を含みます。ボタンアクション（button_action）の値の設定に使用され、Flashムービー内の対話型ボタンのさまざまなマウス操作に対する関連応答を設定できます。

SWFUpload.BUTTON_ACTION = { SELECT_FILE : -100, SELECT_FILES : -110, START_UPLOAD : -120 }

  • SELECT_FILE - ボタンをクリックすると、単一ファイルの選択ダイアログが開きます。（JSで設定された）マウスクリックイベントはトリガーされません。
  • SELECT_FILES - ボタンをクリックすると、複数ファイルの選択ダイアログが開きます。（JSで設定された）マウスクリックイベントはトリガーされません。
  • START_UPLOAD - ボタンをクリックすると、アップロードキューの最初のファイルがアップロードされます。（JSで設定された）マウスクリックイベントはトリガーされません。
  • NONE - この場合、（JSで設定された）マウスクリックイベントがトリガーされます。
  • JAVASCRIPT - NONEと同じです。この値は非推奨です。

【新規追加内容】SWFUpload.CURSOR[機能: マウススタイルを変更します]

SWFUpload.CURSOR はJS配列オブジェクトで、ボタンのカーソル定数を含みます。ボタンカーソル（button_cursor）の値の設定に使用され、マウスがボタンを指しているときのマウススタイルを変更します。

SWFUpload.CURSOR = { ARROW : -1, HAND : -2 }
  • ARROW - カーソルは矢印ポインタとして表示されます
  • HAND - カーソルが手の形になる

【新規追加】SWFUpload.WINDOW_MODE[機能：ムービーの表示モード]

SWFUpload.WINDOW_MODE は、ボタンムービーのウィンドウモードパラメータ定数（button movie wmode parameter constants）を含むJS配列オブジェクトです。ブラウザにFlashムービーの表示方法を指示するために使用します。

一部の WINDOW_MODE/WMODE 設定は、ブラウザの問題を引き起こす可能性があります。詳細は次を参照してください。Known Issues.

SWFUpload.WINDOW_MODE = { WINDOW : "window", TRANSPARENT : "transparent", OPAQUE : "opaque" };
  • WINDOW はデフォルトモードです。Flashムービーはページの最前面に描画されます。

function uploadSuccess(file, serverData, receivedResponse) { if (this.customSettings.custom_setting_A === true) { alert("Checked the custom setting!"); } }

【新增】void startResizedUpload(file_id, width, height, encoding, quality, allowEnlarging)【用途: 画像サイズ調整機能付きアップロード】

startResizedUploadはfile_idパラメータを受け取り、ファイルをアップロードします。SWFUploadは（Flashがサポートする画像形式の場合）ファイルの幅・高さなどの設定を調整しようとします。画像形式がサポートされていない場合、アップロードエラー（uploadError）が発生します。

width と height パラメータは、画像の最大幅と高さを設定するために使用します。ただし、調整中は画像の縦横比が維持されます。

encoding の値は、SWFUpload.RESIZE_ENCODING 内に存在する定数でなければなりません。

quality は JPEG 形式画像の品質を調整する場合のみ使用できます。許容範囲は 0～100 です。この範囲外の場合は、強制的に 0 または 100 に設定されます。

allowEnlarging パラメータは、SWFUpload が元の画像の拡大を許可するかどうかを定義します。（デフォルトは true）元の画像の幅と高さが前述の width と height より小さい場合に適用されます。この値を false に設定すると、画像はエンコードされますが、拡大はされません。

startResizedUploadメソッドを呼び出すと、通常のアップロードイベントチェーンが発生します。ただし、Flash Playerは定期的に uploadProgress イベントを提供しません。SWFUploadは、シミュレートされた 0% と 100% のアップロード進行イベント（uploadProgress events）のみを送信します。

リサイズされた画像は POST 方式でデータを送信します。（FILE のようにではなく）Flash Player 10 でセキュリティ機能が導入されたためです。画像サイズ調整機能付きのアップロード用PHP処理ページは、通常のアップロード用PHP処理ページとは異なります：

$resizedImageData = $_POST["Filedata"]; // 服务器端以$_POST方式接收数据而不是 $_FILE $fileHandle = fopen("image.jpg", "w"); //以file系列操作函数来存储图片 fwrite($fileHandle, $resizedImageData); fclose($fileHandle);

【新規追加】イベント Events

SWFUploadは操作中に一連のイベントをトリガーします。開発者はこれらのコールバック処理イベントを利用して、UIの制御、操作の制御、エラーの報告を行うことができます。

すべてのイベントはSWFUploadインスタンスのコンテキストで呼び出されるため、これらのコールバックイベント内でthisを使用すると、そのイベントをトリガーしたインスタンスオブジェクトに直接アクセスできます。

すべてのイベントは、インスタンス初期化時にsettingパラメータで事前に設定しておく必要があります。

【新：】

ファイルをアップロードするとき、イベントは次の順序で呼び出されます（アップロードイベントチェーン）：

  • 画像サイズ調整機能を追加したアップロード開始 uploadResizeStart
  • 通常のアップロード開始 uploadStart
  • アップロード中 uploadProgress（ファイルのアップロード中に繰り返し呼び出されます）
  • アップロードエラー uploadError（何らかのエラーが発生したときに呼び出され、アップロード中のファイルはキャンセルまたは停止されます）
  • アップロード成功 uploadSuccess（ファイルが正常にアップロードされ、サーバーが有効なデータを受信しました）
  • アップロード完了 uploadComplete（アップロードが完了し、SWFUploadが次のアップロードを開始する準備をします）

uploadResizeStartイベント処理関数は、画像のサイズ調整が開始されるときに呼び出されます。調整中はprogressイベントと処理メソッドは提供されません。ただし、画像の再エンコードにはある程度の時間がかかります。この間にエラーが発生した場合、uploadErrorイベントがトリガーされます。

uploadStart(file object)

ファイルがサーバーへのアップロードを開始する前にuploadStartイベントがトリガーされます。このイベント処理関数では、アップロード前の最終検証や、POSTデータの追加、変更、削除など、必要な他の操作を実行できます。

最後の操作を完了した後、関数がfalseを返すと、このアップロードは開始されません。trueを返すか、何も返さない場合は、アップロードが正式に開始されます。

uploadProgressイベントは、Flashコントロールによって定期的にトリガーされます。3つのパラメータを提供し、それぞれアップロードファイルオブジェクト、アップロード済みのバイト数、総バイト数にアクセスします。したがって、このイベント内でページのUI要素を定期的に更新して、アップロード進捗をリアルタイムに表示する効果を達成できます。

uploadError(file object, error code, message)

アップロードが中止されたり、正常に完了しなかった場合は、常にuploadErrorイベントがトリガーされます。error codeパラメータは現在のエラーのタイプを示します。より具体的なエラータイプは、SWFUpload.UPLOAD_ERRORの定義を参照してください。Messageパラメータはエラーの説明を示します。Fileパラメータはアップロードに失敗したファイルオブジェクトを示します。

例えば、サーバー上に存在しないファイル処理ページをリクエストした場合、エラーコードは-200、メッセージは404になります。停止、終了、uploadStartがfalseを返す、HTTPエラー、IOエラー、ファイルアップロード数の制限超過などは、すべてこのイベントをトリガーします。キャンセルされたがまだキューで待機中のファイルについては、Upload errorは発生しません。（公式のこの発言についてはまだ疑問があります。ファイルが退出した後、どうしてまだファイルアップロードキューに残っているのでしょうか？）

提醒：設定内のカスタムイベントupload_error_handlerに対応します。

注意：この時点ではファイルアップロードの周期はまだ終了していないため、ここで次のファイルのアップロードを開始することはできません。

【新增内容】uploadSuccess(file object, server data, received response)

ファイルアップロードの処理が完了したとき（ここでの完了は、ターゲット処理プログラムにFiles情報を送り終えたというだけで、送信のみで、正常に受信されたかどうかは問わない）、かつサーバーが200のHTTPステータスを返したときにトリガーされます。uploadSuccess事件。server dataサーバーが送信した一部のデータ（例えば自分でechoしたものなど）を指します。そしてreceived responseサーバー自身が送信したHTTPステータスコードです。

一部のFlash Playerのバグにより、HTTPステータスコードが取得できず、uploadSuccessイベントがトリガーされないことがあります。このため、2.50版では設定オブジェクトに新しいプロパティassume_success_timeoutが追加され、HTTPステータスコードの受信待ちの最大時間を超えたかどうかを設定し、超えた場合はuploadSuccessをトリガーします。この場合、（received response）パラメータは無効になります。

設定オブジェクトの http_success は、HTTPステータスコードが200以外の値でも uploadSuccess イベントをトリガーすることを許可します。この場合、Flash Player からサーバーデータは利用できません。

注意：

  2. この時点ではファイルアップロードのサイクルはまだ終了していないため、ここで次のファイルのアップロードを開始することはできません。

uploadComplete(file object)

アップロードキュー内のファイルが1つのアップロードサイクルを完了すると、成功（uploadSuccessがトリガー）か失敗（uploadErrorがトリガー）かに関係なく、uploadCompleteイベントがトリガーされます。これは1つのファイルのアップロードが完了したことを示し、次のファイルのアップロードを開始できます。

次のファイルを自動アップロードする場合、この時点でthis.startUpload()を呼び出して次のファイルのアップロードを開始するのは良い選択です。ただし、使用には注意が必要です。注意事項を参照してください。

提醒：設定内のカスタムイベント upload_complete_handler に対応

注意：複数ファイルをアップロードしているときに、途中でcancelUploadを使用してアップロード中のファイルをキャンセルしたり、stopUploadを使用してアップロード中のファイルを停止したりした場合、uploadComplete内でthis.startUpload()を慎重に使用する必要があります。上記の状況では、uploadErrorとuploadCompleteが順番に実行されるため、現在のファイルのアップロードは停止されますが、直後に次のファイルのアップロードが開始されます。奇妙に感じるかもしれませんが、実際にはプログラムに間違いはありません。キューの自動アップロード全体を終了したい場合は、追加のプログラム処理が必要です。

file_post_name

默认值：Filedata

file_post_name パラメータを使用すると、POST情報内のアップロードファイルの name 値を設定できます（従来のフォームで <input type="file" name="Filedata"/> の name 属性を設定するのと似ています）。

注意：（2.5版待定）Linuxではこのパラメータの設定は無効で、受信されるnameは常にFiledataになります。そのため、最大限の互換性を確保するには、このパラメータはデフォルト値を使用することをお勧めします。

【新】post_params

默认值：空のObjectオブジェクト

post_paramsは、各ファイルのアップロード時にサーバーに付随してPOSTすることを許可するキー/値ペアを定義します。このプロパティにはJavaScriptの配列オブジェクトを割り当てることができます。キー/値ペアは純粋な文字列または数値である必要があります。（JavaScriptのtypeof()関数で検出できます。）

注意: Flash Player 8 はpostデータの添付送信をサポートしていません。SWFUpload は自動的に post_params をクエリ文字列の形式で送信します。

use_query_string

默认值：false

このプロパティの選択値はtrueとfalseで、post_paramsをGETメソッドで送信するかどうかを設定します。falseの場合、POST形式で送信されます。v2.1.0で導入されました。

【新】preserve_relative_urls

默认值：false

preserve_relative_urlsの選択値はboolean変数です。SWFUploadが相対URLを絶対URLに変換するかどうかを示します。trueに設定すると変換されません。デフォルトはfalse、つまり自動変換です。

requeue_on_error

默认值：false

このプロパティの選択値はtrueとfalseです。trueに設定すると、ファイルオブジェクトでuploadErrorが発生した場合（fileQueueエラーとFILE_CANCELLEDエラーを除く）、そのファイルオブジェクトは破棄されずにファイルアップロードキューの先頭に再挿入されます。必要に応じて、再入隊されたファイルを再度アップロードできます。アップロードキューからそのファイルオブジェクトを削除するには、cancelUploadメソッドを使用する必要があります。

アップロード失敗に関連するすべてのイベントも同様に1つずつトリガーされます。そのため、アップロードに失敗したファイルを再入隊させると、Queue Plugin（またはファイルキュー全体を自動アップロードするカスタムコード）と競合する可能性があります。コード内でstartUploadメソッドを呼び出して次のファイルのアップロードを自動的に行い、同時にアップロードに失敗したファイルをアップロードキューから退出させる措置を講じていない場合、この再入隊されたアップロード失敗ファイルが再びアップロードを開始し、また失敗し、再入隊、再アップロード...という無限ループに入ります。

この設定はv2.1.0で導入されました。

http_success

默认值：[]

この配列は、successイベントをトリガーするHTTPステータス値をカスタマイズできます。200のステータス値は常にsuccessをトリガーし、200のステータスのみがserverDataを提供します。

【新】assume_success_timeout

默认值：0

assume_success_timeoutは、SWFUploadがサーバー応答を検出するために待機する秒数を設定し、タイムアウト時にアップロード成功（uploadSuccess）イベントを強制的にトリガーします。このプロパティはFlash Playerのバグの下でも正常に動作するためのものです。サーバー応答の長時間待機を回避し、macOSでFlash Playerがサーバーから返されたコンテンツを取得できないバグも解決します。

Flashは、最後のuploadProgressイベントがトリガーされてから30秒後にサーバーの応答を無視し、アップロード成功イベントを強制的にトリガーします。

assume_success_timeoutが0に設定されている場合、この機能は無効になります。SWFUploadは、Flash PlayerがuploadSuccessイベントをトリガーするまで長時間待機します。

默认值：*.*

提醒：この設定はクライアント側のブラウザにのみ有効で、サーバー側のファイル処理には何の制限もありません。厳密なファイルフィルターが必要な場合は、サーバー側でもプログラムによる処理が必要です。

默认值：0

注意：この値はページをまたいで使用できません。ページがリフレッシュされるとこの値もリセットされます。厳密なファイルアップロード数の制限はサーバー側で検出・管理する必要があります。

file_queue_limit

默认值：0

既知の問題 Known Issues

Flash Playerおよび多くのブラウザのバグがSWFUploadを悩ませています。しかし、私たちは常に努力を続けています。

Linuxでのキャンセル Cancelling in Linux

Flash 9 Player以前のバージョンでは、Linuxオペレーティングシステム上でアップロードキャンセルを実行すると、ブラウザがクラッシュする可能性があります。ただし、新しいバージョンのFlash Playerではこの問題が改善されています。

Linux 上のアップロード進捗 Upload Progress in Linux

Linux上のFlash Playerは、Windowsのようにアップロード中に継続的にイベントを発行するのではなく、アップロード完了後に一度だけアップロード進捗イベント（uploadProgress）を発行します。

これは、一部のLinuxディストリビューションがアップロード中にブラウザ全体をロックするためです。

MAC上のアップロード進捗 Upload Progress in OS X

MAC OS上のFlash PlayerでuploadProgressイベントが発生しないという報告をいくつか受けています。詳細な状況はまだ調査中ですが、潜在的な問題に注意してください。

MIME Type

ファイルの実際のMIME形式が何であれ、Flash PlayerはMIME形式で...application/octet-streamすべてのファイルをアップロード

文件最大可选择数 Maximum number of selected files

Flash Player自体は選択可能なアップロードファイル数の最大値に制限を設けていませんが、総ファイル名の最大長に制限があります。この文字列は、「ファイル名」スペース「ファイル名」...という構成です。アップロードできるファイル数は、オペレーティングシステムのファイル名総長の制限によって決まります。ユーザーがファイルを選択しすぎると、Flash Playerの警告メッセージが表示され、ファイル選択ダイアログに表示されます（yukon：私はXPで一度に173個のファイルをアップロードしましたが、それでも警告はありませんでした...）。

代理 Proxies

Flash Playerはプロキシを正常に使用できない場合があります。プロキシ認証の処理にいくつか問題があり、何らかの競合が発生する可能性があります。

一部のアンチウイルスソフトウェアは、ローカルクライアントプロキシを使用してアップロードファイルを受信し、スキャンします（アップロードファイルをインターセプトしてプロキシサーバーに書き込み、スキャン完了後に実際にターゲットサーバーへ送信するようです）。これにより、SWFUploadはファイル全体がアップロードされたと誤って判断し、100%完了まで大量のuploadProgressイベントを発行します。プロキシが実際にターゲットサーバーへアップロードしている間、SWFUploadは一時停止しているように見えます。

カスペルスキーアンチウイルスソフトウェア：カスペルスキー（他の一部のアンチウイルスソフトウェアも）ローカルからのアップロードデータをインターセプトするためにクライアント側プロキシを実装しています。SWFUploadはこのプロキシシステムの存在を検出できません。これらのプロキシサーバーはアップロードファイルを非常に高速に受信し、スキャンしてからターゲットファイルに送信します。

apache安全模块 Apache mod_security

Apacheのセキュリティモジュールmod_securityは、サーバーが受信したPOSTメッセージを検証します。Flash Playerはエッジケースな方法を実装しており（検証するかどうかを決定するパラメータがあります）、POSTによるファイルアップロードもサーバー側で実装されています。

セキュアソケットレイヤー SSL

Flash PlayerがSSLではアップロードできないという報告をいくつか受けています。この問題の具体的な状況はまだ確認されていませんが、SSL下でのアップロードは確かに信頼性が低いようです。特に公開鍵と自己署名証明書（self-signed certificates）を使用する場合に問題が発生します。

同様に、信頼されていない認証機関（CA）が発行したSSL証明書はFlashでは受け入れられません。Flashにはこのような証明書を受け取る方法が用意されていないためです。前述のCookieバグと同様に、Windows版のFlash Playerは、ブラウザが現在使用中の証明書に関係なく、信頼リストにあるCAが発行した証明書のみを受け入れます。

授权 Authentication

HTTPの認証メカニズムはFlash Playerで十分にサポートされていません。最新バージョンのFlash Playerでは改善されていますが、旧バージョンではブラウザがクラッシュする可能性があります。

过早终止连接 Prematurely terminated connections

レスポンスを早期に終了させる（例：ASP.NETのResponse.end()メソッド）と、アップロードが本来完了しているにもかかわらず、SWFUploadがアップロード失敗を報告することがあります。

ファイルのPOST名 Filedata POST name in Linux

ファイル受信名の変更（デフォルトは"Filedata"、設定オブジェクトのfile_post_nameプロパティ）は、LinuxのFlash Playerでは機能しません。

Cookie bug

Windows環境の非IEブラウザ（FireFox, Opera, Safari, など）では、FlashプラグインがIEのcookieを送信します。これにより、多くのサーバーのセッションおよび認証メカニズムが壊れます。

開発者は、Sessionおよび認証Cookie情報を渡す問題を自分で手動で解決し、サーバー上のセッションも自分で手動で修正する必要があります。セッションを使用したい場合です。

ただし、SWFUploadパッケージには、このバグを解決するPHPまたはASP.Netのサンプルコードが提供されています。

ExternalInterfaceクラスのバグ（ ExternalInterface bugs）

ブラウザ/JSとやり取りするとき、Flash Playerはescapeメソッドを使用してデータを正しくエンコードできません。SWFUploadはこの問題を解決するために多大な努力を払ってきました。将来このバグが修正されれば、SWFUploadは追加のエスケープエンコードデータを送信する予定です。

超长服务器数据bug （Server Data length bugs）

サーバーレスポンスデータが長すぎると、MACまたはLinuxシステムのFlash Playerではエラーが発生する可能性があります。データが切り詰められたり、変更されたり、一部が重複したりすることがあります。サーバーから返すデータはできるだけ短く簡潔にすることをお勧めします。

Avant Browser

一度キャッシュされると、SWFUploadはAvantブラウザで正しく動作しません。

SWFUpload v2.2.0以降、この問題を解決するために prevent_swf_caching 設定が追加されました。

ファイル選択ダイアログとページ変更 File Dialog & Page Changing

ファイル選択ダイアログが表示されている時にページを離れたり、リフレッシュするとブラウザがクラッシュすることがあります。（すべてのブラウザ、すべてのオペレーティングシステムで）

この状況は、主に<a>ハイパーリンクの「onclick」でselectFile/selectFilesを呼び出すように設定したが、デフォルトの遷移動作を禁止しなかった場合に発生します。そのハイパーリンクをクリックすると、他のページへ遷移すると同時にファイル選択ダイアログが開きます。

（yukon：もう一つの可能性として、プログラムがページの強制リフレッシュやリダイレクトを行う場合があります。例えば、HTMLの<meta>タグ内のrefresh、ASP.NETのResponse.Redirect()、PHPのheader()などです。）

サーバースクリプトの実行時間が長すぎる Long Running Upload Scripts

FlashがWebサーバーにファイルをアップロードすると、アップロード受信プログラムが実行されます。受信プログラムは、それらを保存するかどうか、サムネイルの作成、ウィルススキャンなどを決定します。受信プログラムが30秒以内にデータを返さない場合、Flashはリンクを切断し、IOエラーを返します。

これを望まない場合、処理の途中でサーバーに数文字またはデータを返させてください（可能であれば）。

例えばPHPでは、PHPスクリプトはFlashが切断した後も操作を正常に完了できますが、切断後はFlashは戻りデータを受け取れません。

窗口模式 WMODE / BUTTON_WINDOW_MODE

一部のブラウザでは、Flashコントロールがスクリーンの表示領域にない場合、設定されたWMODE（BUTTON_WINDOW_MODEによって設定）がFlashコントロールの読み込みを妨げます。スクロールバーをドラッグしてFlashコントロールがスクリーンの表示領域に入って初めて、読み込みと表示が行われます。

（yukon：これはページをできるだけ早く表示するためです。例えば、画像がたくさん入ったフォルダを開いて、表示方法をサムネイルに設定し、一気に下へスクロールすると、下の画像ファイルの内容が徐々に表示されていくのが見えます）

この特性はSWFObjectプラグインに悪影響を与える可能性があります。SWFUploadイベントが発火しない可能性があり、ボタンの背景画像はコントロールが表示されるまで読み込まれない可能性があります。

一部のオペレーティングシステム（Linux）では、WMODEが透明（transparent）に設定されている場合、Flashが開くファイル選択ダイアログがブラウザウィンドウの後ろに表示されます。

メモリリーク Memory Leaks

一部のブラウザ（特にIE）は、Flash PlayerがExternalInterfaceクラスを使用してJSとやり取りした後、メモリを回収できません（例：SWFUpload）。SWFUploadインスタンスを過剰に生成し、ページを数回リフレッシュすると、ブラウザのメモリ使用量が過多になり、ブラウザのクラッシュやその他のシステムエラーを引き起こす可能性があります。

SWFUpload v2.2.0では、メモリリークを防ぐためのいくつかのメカニズムを実装しました。ただし、ページを閉じるときにdestroy（）メソッドを呼び出すことをお勧めします。1つのページで数百のSWFUploadインスタンスを使用する場合は、メモリリークを防ぐために注意深くテストする必要があります。

  • 一部のユーザーは、Mac Flash Playerでアップロードパスにスペース文字が含まれると問題が発生すると報告しています。それらを+または%20に置き換えてください
  • 一部のユーザーは、Mac Flash PlayerがHTTP HOSTヘッダーにポート番号を追加することを報告しています（例：http://www.example.com:80）。このパラメータをチェックする場合、この問題には注意が必要です。
  • リソースフォーク（resource fork）のみを含むファイルは、Flash Playerによって0バイトファイルとして扱われ、アップロードできません（注：Flash Player 10.1でこの問題が解決された可能性があります）
