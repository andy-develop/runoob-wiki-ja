Java デザインパターン：コンポジットパターンと適用シーン

カテゴリ プログラミング技術

コンポジットパターンとは、あるオブジェクトの中に他のオブジェクトを含めるというものです。含まれるオブジェクトは、終端オブジェクト（それ以上他のオブジェクトを含まない）の場合もあれば、非終端オブジェクト（その内部にさらに他のオブジェクトを含むもの、またはグループオブジェクトとも呼ばれる）の場合もあります。オブジェクトをノードと呼びます。つまり、ルートノードが多数の子ノードを含み、それらの子ノードの中には子ノードを含まないものもあれば、まだ子ノードを含むものもあるという構造が続きます。明らかに、これはツリー構造です。終端ノードは葉ノードと呼ばれ、非終端ノード（グループノード）は枝ノードと呼ばれ、最初のノードはルートノードと呼ばれます。また、これはファイルディレクトリの構造にも似ています。ファイルは終端ノード、ディレクトリは非終端ノード（グループノード）と呼ぶことができます。

通常の実装

1、まず、ディレクトリ構造の通常の実装を見てみましょう。

ディレクトリノード：Noder

import java.util.ArrayList; import java.util.List; /** * ディレクトリノード * 含む： * 1、ディレクトリ名 * 2、下位ファイルリスト * 3、下位ディレクトリリスト * 4、ファイル追加メソッド * 5、ディレクトリ追加メソッド * 6、下位コンテンツ表示メソッド*/ public class Noder { String nodeName;//ディレクトリ名 //コンストラクタでディレクトリに名前を付ける public Noder(String nodeName){ this.nodeName = nodeName; } List<Noder> nodeList = new ArrayList<Noder>();//ディレクトリの下位ディレクトリリスト List<Filer> fileList = new ArrayList<Filer>();//ディレクトリの下位ファイルリスト //下位ディレクトリを追加 public void addNoder(Noder noder){ nodeList.add(noder); } //ファイルを追加 public void addFiler(Filer filer){ fileList.add(filer); } //下位ディレクトリとファイルを表示 public void display(){ for(Noder noder:nodeList){ System.out.println(noder.nodeName); noder.display();//再帰的にディレクトリリストを表示 } for(Filer filer:fileList){ filer.display(); } } }

ファイルノード：Filer

/** * ファイルノード * ファイルノードは終端ノードであり、下位ノードを持たない * 含む： * 1、ファイル名 * 2、ファイル表示メソッド*/ public class Filer { String fileName;//ファイル名 public Filer(String fileName){ this.fileName = fileName; } //ファイル表示メソッド public void display(){ System.out.println(fileName); } }

テストクラス：Clienter

import java.io.File; public class Clienter { public static void createTree(Noder node){ File file = new File(node.nodeName); File[] f = file.listFiles(); for(File fi : f){ if(fi.isFile()){ Filer filer = new Filer(fi.getAbsolutePath()); node.addFiler(filer); } if(fi.isDirectory()){ Noder noder = new Noder(fi.getAbsolutePath()); node.addNoder(noder); createTree(noder);//再帰を使用してツリー構造を生成する } } } public static void main(String[] args) { Noder noder = new Noder("E://ceshi"); createTree(noder);//ディレクトリのツリー構造を作成 noder.display();//ディレクトリとファイルを表示 } }

実行結果：

E:\ceshi\目录1
E:\ceshi\目录1\目录3
E:\ceshi\目录1\文件2.txt
E:\ceshi\目录2
E:\ceshi\目录2\文件3.txt
E:\ceshi\文件1.txt

2、コンポジットパターン

上記のコードから、ファイルノードオブジェクトとディレクトリノードオブジェクトをそれぞれ定義していることがわかります。これは、ファイルとディレクトリの操作が異なるためです。ファイルには下位ノードがありませんが、ディレクトリには下位ノードを持てます。しかし、次のように考えることはできないでしょうか。ファイルもディレクトリも、あるノードの下位ノードとして存在できるなら、両者を1つの種類のオブジェクトに抽象化できないでしょうか。両者の操作は異なりますが、実装クラスのメソッド実装内で具体的に定義できます。例えば、ファイルには下位ノードを追加するメソッドがないので、ファイルのこのメソッドでは例外をスローして具体的な実装を行わず、ディレクトリでは追加操作を具体的に実装します。表示操作は両者ともあるので、それぞれ実装できます。さらに、ファイルとディレクトリを1つの型として抽象化したので、ポリモーフィズムと組み合わせて、次のように実装できます。

抽象クラス：Node

/*ファイルとディレクトリを統一して1種類のノードとみなし、このノードを定義する抽象クラスを作成し、その実装クラスでファイルとディレクトリを区別し、実装クラスでそれぞれの具体的な実装内容を定義する*/ public abstract class Node { protected String name;//名称 //コンストラクタで名前を付ける public Node(String name){ this.name = name; } //ノード追加：ファイルノードにはこのメソッドがなく、ディレクトリノードがこのメソッドをオーバーライドする public void addNode(Node node) throws Exception{ throw new Exception("Invalid exception"); } //ノード表示：ファイルとディレクトリの両方がこのメソッドを実装する abstract void display(); }

ファイル実装クラス：Filter

/** * ファイルノードを実装する*/ public class Filer extends Node { //コンストラクタでファイルノードに名前を付ける public Filer(String name) { super(name); } //ファイルノードを表示 @Override public void display() { System.out.println(name); } }

ディレクトリ実装クラス：Noder

import java.util.*; /** * ディレクトリノードを実装する*/ public class Noder extends Node { List<Node> nodeList = new ArrayList<Node>();//内部ノードリスト（ファイルと下位ディレクトリを含む） //コンストラクタで現在のディレクトリノードに名前を付ける public Noder(String name) { super(name); } //ノードを追加 public void addNode(Node node) throws Exception{ nodeList.add(node); } //再帰ループで下位ノードを表示 @Override void display() { System.out.println(name); for(Node node:nodeList){ node.display(); } } }

テストクラス：Clienter

import java.io.File; public class Clienter { public static void createTree(Node node) throws Exception{ File file = new File(node.name); File[] f = file.listFiles(); for(File fi : f){ if(fi.isFile()){ Filer filer = new Filer(fi.getAbsolutePath()); node.addNode(filer); } if(fi.isDirectory()){ Noder noder = new Noder(fi.getAbsolutePath()); node.addNode(noder); createTree(noder);//再帰を使用してツリー構造を生成する } } } public static void main(String[] args) { Node noder = new Noder("E://ceshi"); try { createTree(noder); } catch (Exception e) { e.printStackTrace(); } noder.display(); } }

実行出力結果：

E://ceshi
E:\ceshi\文件1.txt
E:\ceshi\目录1
E:\ceshi\目录1\文件2.txt
E:\ceshi\目录1\目录3
E:\ceshi\目录2
E:\ceshi\目录2\文件3.txt

上記の実装からわかるように、いわゆるコンポジットパターンとは、実はオブジェクトがオブジェクトを含むという問題です。コンポジション（オブジェクト内部でオブジェクトを参照する）という方法でレイアウトを行います。私はこのコンポジションは継承とは異なると考えます。もう一つの意味は、ツリー構造の子ノードの抽象化（葉ノードと枝ノードを子ノードとして抽象化すること）であり、葉ノードと枝ノードを別々に定義する通常の方法とは異なります。

3、コンポジットパターンの適用シーン

このコンポジットパターンはまさにツリー構造のために生まれたものです。したがって、コンポジットパターンの使用シーンは、ツリー構造が現れる場所です。例えば、ファイルディレクトリの表示、多階層ディレクトリの表示など、ツリー構造データの操作です。
