4.8 Verilog 手続き的連続代入

カテゴリ Verilog チュートリアル

キーワード：deassign, force, release

手続き的連続代入は手続き代入の一種です。この代入文は、他のすべての wire または reg への代入を置き換え、wire または reg 型変数の現在の値を書き換えます。

手続き代入とは異なり、手続き的連続代入の式は wire または reg 型変数に継続的に駆動されます。つまり、手続き的連続代入が作用するとき、右辺式の任意のオペランドの変化により、手続き的連続代入文が再実行されます。

手続き的連続代入には主に2種類あり、assign-deassign と force-release です。

assign, deassign

assign（手続き代入操作）と deassign（手続き代入の取消操作）は、第1の種類の手続き的連続代入文を表します。代入対象はレジスタまたはレジスタ配列のみであり、wire 型変数は指定できません。

手続き的連続代入の実行中、レジスタには継続的に値が代入され、レジスタの値は再代入されるまで保持されます。

たとえば、リセット端子付き D フリップフロップは次のコードで記述できます。

例

module dff_normal(
    input       rstn,
    input       clk,
    input       D,
    output reg  Q
 );

    always @(posedge clk or negedge rstn) begin
        if(!rstn) begin   //Q = 0 after reset effective
            Q <= 1'b0 ;
        end
        else begin
            Q <= D ;       //Q = D at posedge of clock
        end
    end

endmodule  

次に、assign と deassign を使って書き換え、同じ機能を実現します。

すなわち、リセット信号が 0 のとき、Q 端子は assign 文によって代入され、常に 0 を出力します。

リセット信号が 1 のとき、Q 端子は deassign 文によって代入が取り消され、クロックの立ち上がりエッジで再代入されます。

例

module dff_assign(
    input       rstn,
    input       clk,
    input       D,
    output reg  Q
 );
 
    always @(posedge clk) begin
        Q <= D ;       //Q = D at posedge of clock
    end
 
    always @(negedge rstn) begin
        if(!rstn) begin
            assign Q = 1'b0 ; //change Q value when reset effective
        end
        else begin        //cancel the Q value overlay,
            deassign Q ;  //and Q remains 0-value until the coming of clock posedge
        end
    end
 
endmodule

force, release

force（強制代入操作）と release（強制代入の取消）は、第2の種類の手続き的連続代入文を表します。

使用方法と効果は assign と deassign に似ていますが、代入対象は reg 型変数でも wire 型変数でも構いません。

無条件の強制代入であるため、一般的には対話型デバッグプロセスで使用され、設計モジュール内では使用しないでください。

force がレジスタに作用すると、レジスタの現在の値は上書きされます。release 時には、そのレジスタの値は強制代入時の値が保持され続けます。その後、そのレジスタの値は元の手続き代入文によって変更できます。

force がネットに作用すると、ネットの値も強制的に代入されます。ただし、そのネット型変数が release されると、その値はすぐに元の駆動値に戻ります。

2種類の変数に対する強制代入の違いを直感的に確認するために、第1節のカウンタ counter10 を設計モジュールとして使用し、testbench を次のように設計します。

例

`timescale 1ns/1ns
 
module test ;
    reg          rstn ;
    reg          clk ;
    reg [3:0]    cnt ;
    wire         cout ;
 
    counter10     u_counter (
        .rstn    (rstn),
        .clk     (clk),
        .cnt     (cnt),
        .cout    (cout));
 
    initial begin
        clk       = 0 ;
        rstn      = 0 ;
        #10 ;
        rstn      = 1'b1 ;
        wait (test.u_counter.cnt_temp == 4'd4) ;
        @(negedge clk) ;
        force     test.u_counter.cnt_temp = 4'd6 ;
        force     test.u_counter.cout     = 1'b1 ;
        #40 ;
        @(negedge clk) ;
        release   test.u_counter.cnt_temp ;
        release   test.u_counter.cout ;
    end
 
    initial begin
        clk = 0 ;
        forever #10 clk = ~ clk ;
    end
 
    //finish the simulation
    always begin
        #1000;
        if ($time >= 1000) $finish ;
    end
 
endmodule // test

シミュレーション結果は次のとおりです。

図からわかるように、cnt_temp が 4 のとき（80ns）、cnt_temp は 6 に強制代入され、cout は 1 に強制代入されます。

release 時（120ns）には、cnt_temp はレジスタ型であるため、元の値が保持され続けます。クロックの立ち上がりエッジで加算代入操作が行われるまで値は変わらず、その後 7 になります。

一方、120ns のとき、cout はネット型変数であるため、その値を保持できません。元の counter10 モデルには駆動文が存在します：assign cout = (cnt_temp==4'd9)そのため、cout の値は 0 になります。
