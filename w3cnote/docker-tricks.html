dockerコンテナとイメージの関係について

コンテナ内で何を操作しても、ファイルを書いたり削除したりしても、そのコンテナの基本イメージは一切変わりません。これはDockerが親イメージから増分イメージを構築し、各コンテナの変更のみを保存するためです。したがって、300MBの親イメージがあり、コンテナに50MBの追加アプリやサービスをインストールした場合、コンテナは50MBだけで、親イメージは依然として300MBです。ただし、Dockfileまたはcommitコマンドを使用して、増分イメージと親イメージを一緒に新しいイメージとして生成することができます。

dock top -- 显示容器中运行的进程

コンテナのrootユーザー名とパスワードを確認する

docker logs <容器名orID> 2>&1 | grep '^User: ' | tail -n1

dockerコンテナ起動時、rootユーザーのパスワードはランダムに割り当てられます。そのため、この方法でredmineコンテナのrootユーザーのパスワードを取得できます。

コンテナのログをリアルタイムで確認する

docker logs -f <容器名orID>

すべてのコンテナを削除する

docker rm $(docker ps -a -q)

コンテナの停止、起動、強制終了

docker stop <容器名orID>
docker start <容器名orID>
docker kill <容器名orID>

すべてのイメージを確認する

docker images

すべてのイメージを削除する

docker rmi $(docker images | grep none | awk '{print $3}' | sort -r)

すべてのコンテナとイメージを削除する（大掃除）

ワンライナーコマンドで大掃除：

docker kill $(docker ps -q) ; docker rm $(docker ps -a -q) ; docker rmi $(docker images -q -a)

注：shell の $() は command と似ており、先にこの中の内容が実行されます。上のスクリプトでは次のようになります: docker kill "pids" ; docker kill は docker でコンテナを停止するために使用され、docker rm はコンテナを削除し、docker rmi はイメージを削除します。

実行中のコンテナがない場合や、コンテナがまったくない場合は、警告メッセージが表示されるだけです。試してみたいときには、これは非常に優れたワンライナーコマンドです。すべてのコンテナだけを削除したい場合は、次のコマンドを実行できます：

docker kill $(docker ps -q) ; docker rm $(docker ps -a -q)

Shell上でコマンドを実行しない

Shell の拡張を必要とする docker run コマンドを使って何かを処理する場合、例えば docker run --rm busybox ls '/var/log/' のようなコマンドは失敗します。この失敗の原因を突き止めるのにかなり苦労しました。この落とし穴はここにあります：元々 Shell がないのに、``` は Shell の拡張項目です。したがって、使用可能な Shell が必要です。正しい方法は次のとおりです。

docker run --rm busybox sh -c 'ls /var/log/*'

複数プログラムの自動起動方法：

dockerコンテナは起動するたびに、自動起動するコマンドをコンテナ起動前に指定する必要があります。例えば、docker run -I -t debian /bin/bash というコマンドは /bin/bash プログラムだけを実行し、他のプログラムは実行されません。複数のプログラムを実行したいコンテナにとっては特に厄介です。前述の起動コマンドを次のように置き換えることができます。

dockerrun -I -t debian /etc/rc.local

コンテナ内で、自動起動が必要なすべての起動コマンドを /etc/rc.local に置くことで、複数プログラムの自動起動を実現できます。

バックグラウンドで実行する場合は：

docker run -d -p 50001:22 debian /etc/rc.local

終了時にコンテナを削除する

コンテナ内で1つのコマンドをすばやく実行して終了し、コンテナの状態を気にしたくない場合は、run コマンドの後ろに --rm パラメータを追加します。これにより、保存してあった多くのコンテナを終了し、それらをクリーンアップできます。

docker run --rm -i -t busybox /bin/bash

新しいコンテナを起動し、同時に名前付け、ポートマッピング、フォルダーマッピングを行います。redmineイメージを例にします。

docker run --name redmine -p 9003:80 -p 9023:22 -d -v /var/redmine/files:/redmine/files -v /var/redmine/mysql:/var/lib/mysql sameersbn/redmine

あるコンテナを別のコンテナに接続する

docker run -i -t --name sonar -d -link mmysql:db   tpires/sonar-server
sonar

コンテナをmmysqlコンテナに接続し、mmysqlコンテナをdbにリネームします。これで、sonarコンテナはdbの関連する環境変数を使用できます。

イメージの保存とインポート

あるマシンのイメージを別のマシンに移行する必要がある場合、イメージの保存とロードが必要です。 マシンa

docker save busybox-1 > /home/save.tar

scpを使用してsave.tarをマシンbにコピーし、次に：

docker load < /home/save.tar

自分専用のイメージを構築する

docker build -t <镜像名> <Dockerfile路径>

Dockerfileが現在のパスにある場合：

docker build -t xx/gitlab .

containerのstdoutを再表示する

$ ID=$(sudo docker run -d ubuntu /usr/bin/top -b)

バックグラウンドで実行(-d)し、ポートを公開(-p)する

docker run -d -p 127.0.0.1:33301:22 centos6-ssh

containerからファイルをコピーする

sudo docker cp 7bb0e258aefe:/etc/debian_version .

7bb0e258aefe 内の /etc/debian_version を現在のディレクトリにコピーします。

注意：7bb0e258aefe が削除されていない限り、ファイル名前空間はまだ存在するため、exit状態のcontainerのファイルを安心してコピーできます。
