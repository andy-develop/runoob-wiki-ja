4.1.1 Activity入門

カテゴリ Android 基礎入門チュートリアル

本節のイントロダクション：

本節ではAndroidの四大コンポーネントの1つであるActivity（アクティビティ）について解説します。まず公式によるActivityの紹介を見てみましょう。 PS: 公式ドキュメント：Activity

紹介は以下の通りです： おおよその意味：

Activityはアプリケーションのコンポーネントであり、画面上に領域を提供し、ユーザーがその上でインタラクティブな操作（電話をかける、写真を撮る、メールを送信する、地図を表示するなど）を行うことを可能にします！Activityはユーザーインターフェースを描画するウィンドウと理解できます。このウィンドウは画面全体を埋めることもできますし、画面より小さい場合や他のウィンドウの上に浮かんでいる場合もあります！

上記の文章から、以下の情報が得られます：

1.Activityはユーザーインターフェースの表示に使用され、ユーザーはActivityを通じて操作を行います。2.1つのAppで複数のActivityを持つことができます。

さて、導入の概要はここまでです。詳しく知りたい場合はAPIを読み続けてください。それでは本節の内容を始めましょう~

1. Activityの概念とActivityのライフサイクル図：

注意事項：

1. onPause()とonStop()が呼び出される前提は：新しいActivityを開いたことです！前者は古いActivityがまだ表示されている状態、後者は古いActivityがすでに表示されていない状態です！
2. また、実際に試したところ：AlertDialogとPopWindowは上記の2つのコールバックメソッドをトリガーしません~

2. Activity/ActionBarActivity/AppCompatActivityの違い：

Activityの作成について説明する前に、この3つの違いについて説明します。 Activityは言うまでもありません。後の2つは低バージョン互換のために導入されたもので、どちらもv7パッケージの下にあります。 ActionBarActivityは廃止されています。名前から分かるようにActionBar~ですが、5.0以降はGoogleによって非推奨になり、現在はToolBar...を使います。そして今Android StudioでActivityを作成すると、デフォルトで継承されるのはAppCompatActivityです！ もちろんActivityだけを書くこともできますが、AppCompatActivityはいくつかの新しい機能を提供してくれるだけです。 どちらか1つを選んでください。Just you like~

3. Activityの作成フロー

PS:

さて、上で述べたように、ActivityとAppCompatActivityを継承できますが、後者はいくつかの新しい機能を提供するだけです！ また、覚えておいてください。Androidの四大コンポーネントは、定義したら、使うか使わないかに関わらず、AndroidManifest.xmlでこのコンポーネントを宣言する必要があります。そうしないと、実行時にプログラムが直接終了し、ClassNotFindException...が報告されます。

4. onCreate()の1つの引数と2つの引数の違い：

ASを使っている方は、ActivityのonCreate()メソッドをオーバーライドするときに、これには2つの引数があることに気づくでしょう：

しかし通常は引数が1つだけですよね：

うん、これが5.0で提供された新しいメソッドです。これを使うには、まず設定ファイルでActivityに属性を設定する必要があります：

android:persistableMode="persistAcrossReboots"

そうするとActivityは永続化の能力を持つようになります。通常は別の2つのメソッドと組み合わせて使います：

public void onSaveInstanceState(Bundle outState, PersistableBundle outPersistentState)
public void onRestoreInstanceState(Bundle savedInstanceState, PersistableBundle persistentState)

この2つのメソッド名に馴染みのある方もいるでしょう。前のメソッドは次のような状況で呼び出されます：

  1. ホームキーを押してホーム画面に戻る、または長押しして他のプログラムを選択して実行する
  2. 電源キーを押して画面をオフにする
  3. 新しいActivityを起動する
  4. 縦横画面切り替え時には必ず実行されます。縦横画面切り替えの際は、まずActが破棄されてから再作成されるためです。 重要な原則：システムが「あなたの許可なしに」あなたのActivityを破棄した場合、onSaveInstanceStateがシステムによって呼び出されます。これはシステムの責任であり、データを保存する機会を提供しなければならないからです（保存しても保存しなくても構いません）。

そして後者のメソッドは、onCreateと同様に前者が保存したデータを取得できます。 通常はonStart()とonResume()の間に実行されます！ 保存データを取得できるメソッドが2つあるのは、Actが遷移しても閉じられず、onCreate()メソッドが実行されない場合に、保存データを取り出したいためです~

話を戻すと：話を戻すと、このActivityは永続化の能力を持つようになりました。追加されたPersistableBundleパラメータにより、これらのメソッドはシステムのシャットダウン後の再起動のデータ復元能力を持つようになりました！！しかも、他のシリアライズ操作に影響しません。マジか！ 具体的な実装方法は、今のところわかりません。おそらく別のファイルに保存しているのでしょう~！後で原理が分かったら皆さんにお知らせします！ また、APIバージョンは>=21が必要です。つまり5.0以上のバージョンでないと有効になりません~

4. Activityを起動するいくつかの方法

Androidでは次の2つの方法で新しいActivityを起動できます。ここで注意してほしいのは「起動方法」であり、「起動モード」ではないことです！！明示的起動と暗黙的起動に分けられます！

1. 明示的起動：パッケージ名を指定して起動します。書き方は以下の通りです：

①最も一般的な方法：

startActivity(new Intent(当前Act.this,要启动的Act.class));
②IntentのComponentNameを使用する：
ComponentName cn = new ComponentName("当前Act的全限定类名","启动Act的全限定类名") ;
Intent intent = new Intent() ;
intent.setComponent(cn) ;
startActivity(intent) ;
③Intentを初期化するときにパッケージ名を指定する：
Intent intent = new Intent("android.intent.action.MAIN");
intent.setClassName("当前Act的全限定类名","启动Act的全限定类名");
startActivity(intent);

2. 暗黙的起動：Intent-filterのAction、Category、またはdataを使用して実現します。これはIntentのintent-filter**によって実現されます。このIntentの章で詳しく解説します！ ここでは概要だけ知っておけば十分です！

3. 他にも、パッケージ名を直接指定してapkを起動する方法があります：

Intent intent = getPackageManager().getLaunchIntentForPackage
("apk第一个启动的Activity的全限定类名") ;
if(intent != null) startActivity(intent) ;

5. 縦横画面切り替えと状態保存の問題

前にも述べたように、Appの縦横画面切り替え時には現在のActivityが破棄されて再作成されます。ライフサイクルの各メソッドにLogを出力する文を自分で追加して確認できます。また、ボタンとTextViewを設置し、ボタンをクリックしてTextViewのテキストを変更した後、縦横画面を切り替えると、不思議なことにTextViewのテキストが元に戻っていることに気づくでしょう！ 縦横画面切り替え時にActは次のライフサイクルをたどります：
onPause-> onStop-> onDestory-> onCreate->onStart->onResume
縦横画面切り替えに関して、以下のような問題に遭遇する可能性があります：

1. まずはどのように縦横画面の自動切り替えを禁止するか方法はとても簡単です。AndroidManifest.xmlでActに属性を追加します：android:screenOrientation、以下の選択値があります：

  • unspecified：デフォルト値。システムが表示方向を判断します。判定の戦略はデバイスに関連するため、デバイスによって表示方向が異なります。
  • landscape：横画面表示（幅が高さより長い）
  • portrait：縦画面表示（高さが幅より長い）
  • user：ユーザーが現在好む方向
  • behind：Activityスタック内でそのActivityの下にあるActivityの方向と同じ
  • sensor：物理センサーによって決定されます。ユーザーがデバイスを回転させると画面が縦横に切り替わります。
  • nosensor：物理センサーを無視するため、ユーザーがデバイスを回転させても変更されません（"unspecified"設定を除く）。

2.縦横画面時に異なるレイアウトを読み込みたい場合：

1）2セットの異なるレイアウトを用意すると、Androidが自動的に縦横画面に応じて異なるレイアウトを読み込みます： 2つのレイアウトフォルダを作成します：layout-land横画面、layout-port縦画面 次に、この2セットのレイアウトファイルをこれらの2つのフォルダに置きます。ファイル名が同じであれば、Androidが自動的に判断して対応するレイアウトを読み込みます！

2) 自分でコード内で判断し、自分が読み込みたいものを読み込む：

通常はonCreate()メソッドでレイアウトファイルを読み込みます。ここで縦横画面の状態を判断できます。重要なコードは次の通りです：

if (this.getResources().getConfiguration().orientation == Configuration.ORIENTATION_LANDSCAPE){  
     setContentView(R.layout.横屏);
}  

else if (this.getResources().getConfiguration().orientation ==Configuration.ORIENTATION_PORTRAIT) {  
    setContentView(R.layout.竖屏);
}

3. エミュレータで縦横画面を切り替える方法

エミュレータがGMの場合は、エミュレータ上の切り替えボタンを押すだけです。標準エミュレータではctrl + f11/f12で切り替えられます！

4. 状態保存の問題：

これも上で述べたように、Bundle savedInstanceStateパラメータを使って実現できます！ 3つのコアメソッド：

onCreate(Bundle savedInstanceState);
onSaveInstanceState(Bundle outState);
onRestoreInstanceState(Bundle savedInstanceState);

onSaveInstanceState()メソッドだけをオーバーライドし、このbundleにデータを書き込みます。例：

outState.putInt("num",1);

こうして、onCreateまたはonRestoreInstanceStateで保存されたデータを取り出すことができます。ただし、取り出す前にnullかどうかを判定してくださいね！

savedInstanceState.getInt("num");

それから、やりたいことをやればいいです〜
