2.Httpプロトコル入門

実際の開発では、サーバー側とやり取りする際、通常はHttpプロトコルに基づく通信を使用します。そのためHttpプロトコルをしっかり学ぶことは非常に重要です。もちろん、細かい部分をあまり気にしすぎる必要はなく、大まかに理解していれば十分です！どれも概念的なものです！

1）Httpプロトコルとは？

答：hypertext transfer protocol（ハイパーテキスト転送プロトコル）は、TCP/IPプロトコルにおけるアプリケーション層のプロトコルであり、WEBブラウザとWEBサーバー間でデータを交換するプロセスを定義します。クライアントがwebサーバーに接続した後、webサーバー内の特定のwebリソースを取得したい場合は、一定の通信形式に従う必要があります。HTTPプロトコルは、クライアントとwebサーバーが通信する際の形式を定義します。

2）Http 1.0 と Http 1.1 の違い

答：1.0プロトコルでは、クライアントはwebサーバーとの接続を確立した後、1つのwebリソースしか取得できません。一方、1.1プロトコルでは、クライアントがwebサーバーとの接続を確立した後、1つの接続上で複数のwebリソースを取得できます。

3）Httpプロトコルの下位層の動作フロー：

答：まず2つの用語を知っておく必要があります。

  • SYN（synchronous）: TCP/IPが接続を確立するときに使用するハンドシェイク信号
  • ACK（Acknowledgement）: 確認文字。送られてきたデータを誤りなく受け取ったことを確認する。

続いて、TCP/IP 3ウェイハンドシェイクの概念：

  • クライアントはsynパケット（syn = j）をサーバーに送信し、SYN_SEND状態になり、サーバーの確認を待ちます。
  • サーバーはsynパケットを受信し、クライアントのsynを確認して（ack = j + 1）、同時に自分もSYNパケット（syn=k）を送信します。すなわちSYN + ACKパケットです。サーバーはSYN_RECV状態になります。
  • クライアントはSYN + ACKパケットを受信し、サーバーに確認パケットACK（ack = k + 1）を送信します。送信完了後、クライアントとサーバーはESTABLISHED状態になり、3ウェイハンドシェイクが完了し、その後両者はデータ転送を開始します。

理解できましたね。では、Http操作の一連の流れを見てみましょう：

  • ユーザーがブラウザ上のURL（ハイパーリンク）をクリックすると、WebブラウザとWebサーバーが接続を確立します。
  • 接続確立後、クライアントはサーバーにリクエストを送信します。リクエストの形式は次のとおりです：統一資源識別子（URL） + プロトコルバージョン番号（通常は1.1） + MIME情報（複数のメッセージヘッダー） + 空行1つ
  • サーバーはリクエストを受信した後、対応する応答情報を返します。応答形式は次のとおりです：プロトコルバージョン番号 + ステータス行（処理結果） + 複数の情報ヘッダー + 空行 + エンティティコンテンツ（例：返されたHTML）
  • クライアントはサーバーから返された情報を受け取り、ブラウザを通じて表示し、サーバーとの接続を切断します。もちろん、途中のどこかの段階でエラーが発生した場合は、エラー情報がクライアントに返されて表示されます。例：古典的な404エラー！

4）Httpプロトコルの業務フロー

5）Httpの各種リクエスト方式

実際の開発でよく使う方式はGetとPostですが、実際の開発では他のリクエスト方式を使うこともあります。例えばPUTです。小猪の実際のプロジェクトでも使われました。以下、皆さんのためにすべてのリクエスト方式をまとめます：

  • Get：Request-URIで識別されるリソースの取得をリクエストする
  • POST：Request-URIで識別されるリソースの後に新しいデータを追加する
  • HEADRequest-URIで識別されるリソースの応答情報ヘッダーを取得するリクエスト
  • PUT：サーバーにリソースを1つ保存するようリクエストし、その識別子としてRequest-URIを使用する
  • DELETE：Request-URIで識別されるリソースを削除するようサーバーにリクエストする
  • TRACE：サーバーに受信したリクエスト情報をそのまま返すようリクエストする。主にテストや診断に使用される
  • CONNECT：将来の使用のために予約されている
  • OPTIONS：サーバーの性能、またはリソースに関連するオプションの照会をリクエストする

6）GetとPostの比較

最もよく使われる2つなので、もちろん比較してみます！

  • GET：リクエストのURLアドレスの後ろに「?」の形式でサーバーに渡すデータを付け加えます。複数のデータの間は「&」で区切ります。ただし、データ容量は通常2Kを超えることはできません。例：http://xxx?username=…&pawd=… のようなものがGETです。
  • POST：これはリクエストのエンティティコンテンツ内でサーバーにデータを送信できるもので、転送量に数量制限がありません。
  • もう1点言っておくと、この2つはどちらもデータを送信するもので、送信メカニズムが違うだけです。ネット上にある「GETはサーバーデータを取得し、POSTはサーバーにデータを送信する」という説明を信じてはいけません！！ また、GETは安全性が非常に低く、POSTは安全性が比較的高いですが、実行効率はPOST方式よりも優れています。通常、クエリのときはGETを使用し、データの追加・削除・変更のときはPOSTを使用します！！

7）Httpステータスコード集

もちろん、これらのステータスコードはあくまで参考用です。実際には決定権はサーバー側（バックエンド）の手にあります。1つの方法としては、リクエスト後にサーバーが私たちにステータスを返すことです。もう1つの方法は、アプリで多言語バージョンを用意する必要がない場合に最適で、結果情報を含むJson文字列を直接返してくれるので、それをそのまま表示すればよく、かなり手を抜けます！ 以下にステータスコード集を示すので、参考程度にしてください。

  • 100〜199 : リクエストを受け入れ成功。クライアントは処理全体を完了するために次のリクエストを送信する必要がある
  • 200: OK、クライアントのリクエストが成功
  • 300〜399：リクエストしたリソースは新しいアドレスに移動済み（302,307,304）
  • 401：リクエストが未承認です。このステータスコードはWWW-Authenticateヘッダーフィールドと一緒に使用する必要があります。
  • 403：Forbidden、サーバーはリクエストを受け取ったが、サービスの提供を拒否する
  • 404：Not Found、リクエストしたリソースが存在しません。これは言うまでもありませんね
  • 500：Internal Server Error、サーバーで予期しないエラーが発生
  • 503：Server Unavailable、サーバーは現在クライアントのリクエストを処理できません。しばらくすると正常に戻る可能性があります

8）Httpプロトコルの特徴

概念的なものなので、知っておけば十分で、暗記する必要はありません。百度百科の内容をそのままコピペします：

1. クライアント/サーバーモードをサポート。

2. シンプルで高速：クライアントがサーバーにサービスを要求するとき、リクエストメソッドとパスだけを送信すればよい。リクエストメソッドとして一般的なのはGET、HEAD、POSTである。各メソッドはクライアントとサーバーが接続するタイプが異なることを規定している。HTTPプロトコルはシンプルなので、HTTPサーバーのプログラム規模が小さくなり、通信速度が非常に速い。

3. 柔軟：HTTPは任意のタイプのデータオブジェクトの転送を許可する。転送中のタイプはContent-Typeでマークされる。

4. コネクションレス：コネクションレスの意味は、各接続が1つのリクエストだけを処理するように制限することです。サーバーはクライアントのリクエストを処理し、クライアントの応答を受け取った後、接続を切断します。この方式を採用することで転送時間を節約できます。

5. ステートレス：HTTPプロトコルはステートレスなプロトコルです。ステートレスとは、プロトコルがトランザクション処理に対して記憶能力を持たないことを指します。 状態が欠如しているということは、後続の処理が以前の情報を必要とする場合、それを再送信しなければならず、これにより毎回の接続で転送されるデータ量が増加する可能性があります。一方、サーバーが以前の情報を必要としない場合には、その応答は速くなります。

PS: OSI七層プロトコルとTCP四層モデルについては、基礎シリーズでは解説しません〜興味があれば自分で調べてみてください！
