なぜローカル内部クラスと匿名内部クラスはfinalのローカル変数しかアクセスできないのか？

カテゴリ プログラミング技術

最近内部クラスを見ていたときに、ひとつ疑問がありました。ローカル内部クラスと匿名内部クラスはfinalのローカル変数しかアクセスできない、ということです。いくつかのブログを読んで、だいぶ理解できました。

まず、ローカル内部クラスの例を見てみましょう。

例

class OutClass {
        private int age = 12;
 
        public void outPrint(final int x) {
                class InClass {
                        public void InPrint() {
                                System.out.println(x);
                                System.out.println(age);
                        }
                }
                new InClass().InPrint();
        }
}

ここに外部クラス OuterClass と内部クラス InClass があります。内部クラスは外部クラスのメソッド内のローカル変数 x にアクセスします。ここで、x は final でなければならず、そうでないとエラーになります。

Cannot refer to a non-final variable x inside an inner class defined in a different method

以下でこの問題を分析してみましょう。

根本原因を追究すると、スコープ内の変数のライフサイクルによるものです。

まず知っておくべき点は、内部クラスと外部クラスは同じレベルにあるということです。内部クラスはメソッド内に定義されていても、メソッドの実行が終わるとともに破棄されるわけではありません。

ここで問題が発生します。外部クラスのメソッドが終了すると、ローカル変数は破棄されますが、内部クラスのオブジェクトはまだ存在する可能性があります（誰からも参照されなくなったときにのみ消滅します）。ここで矛盾が生じます。内部クラスのオブジェクトが存在しない変数にアクセスする、ということです。この問題を解決するために、ローカル変数をコピーして内部クラスのメンバー変数とします。これにより、ローカル変数が消滅した後でも、内部クラスはそれにアクセスできます。実際にアクセスしているのはローカル変数の「コピー」です。これでローカル変数のライフサイクルを延長したかのようになります。生成された .class ファイルを逆コンパイルして実験できます。

メソッド内のローカル変数は、実際に内部クラスのメンバー変数としてコピーされて使用されることがわかります。

また問題が発生します。ローカル変数を内部クラスのメンバー変数としてコピーするとき、これら2つの変数が同じであることを保証しなければなりません。つまり、内部クラスでメンバー変数を変更した場合、メソッド内のローカル変数もそれに合わせて変更される必要があります。どうやって解決するのでしょうか？

そこでローカル変数を final に設定します。初期化後はこの変数を変更できないようにすることで、内部クラスのメンバー変数とメソッドのローカル変数の一貫性を保証します。これは実際には一種の妥協でもあります。

変数が final の場合：

  • 基本型の場合、その値は変更できないため、コピーと元のローカル変数の値が同じであることが保証されます。

  • 参照型の場合、その参照は変更できないため、コピーと元の変数が同じオブジェクトを参照していることが保証されます。

これにより、ローカル変数と内部クラス内に作成されたコピーが一致した状態に保たれます。
