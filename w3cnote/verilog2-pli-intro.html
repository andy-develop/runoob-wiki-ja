8.1 Verilog PLI 概要

カテゴリ Verilog チュートリアル上級編

デジタル設計を行う際、特別な状況にしばしば遭遇します。Verilog のタスクと関数はシミュレーションのニーズを満たせないことがあるため、独自のシステムタスクと関数を定義する必要があります。プログラミング言語インターフェース（PLI、Program Language Interface）は、設計内部のデータ構造にアクセスし、シミュレーション環境情報を抽出するための一連のインターフェースルーチンを提供します。ユーザーはこれらのルーチンを呼び出して、システムタスクとシステム関数を定義し、設計内部データや Verilog シミュレータ環境と対話できます。

PLI 機能

簡単に言うと、Verilog PLI は一連の C 言語関数を提供しています。設計者はこれらの組み込み関数を呼び出して、C プログラムを作成できます。RTL コンパイル時に、作成したソフトウェアプログラムもシミュレーション環境に統合されます。シミュレーション実行時には、システムタスク呼び出しを通じて、シミュレーション内のデータ構造に動的にアクセスできます。このアクセスは双方向であり、シミュレータのデータ構造から情報を読み取るだけでなく、データ構造の情報を変更することもできます。

PLI の機能は非常に強力であり、その用途は設計者の想像力によってのみ制限されます。

  • PLI を使用すると、ユーザーは C 言語で独自のシステムタスクと関数を記述でき、Verilog では実現できない複雑な操作を実行できます。
  • ファイル読み書きツールや遅延計算ツールなどの一部のアプリケーションソフトウェアも、PLI を使用して記述できます。
  • PLI は設計情報を抽出できます。例えば、階層へのアクセス、相互接続の状況、特定タイプの論理要素の数などです。
  • PLI は専用の出力表示プログラムの作成に使用できます。例えば、専用の波形ビューアを作成し、論理相互接続、階層、データ波形などの情報を生成できます。
  • PLI は、煩雑な監視タスクや刺激タスクを完了できます。
  • PLI はシミュレーションのプロセスを制御できます。例えば、一時停止や終了など、デバッグに便利です。
  • PLI の拡張用途には、RAM/ROM プログラムダウンロードツール、消費電力解析、CModel インターフェース、協調シミュレーション環境などがあります。

ここで、PLI でよく使われる機能をまとめます：

  • (1) CModel と Verilog モデルの共同シミュレーションを実現します。複雑なシステムでは、開発者はまず C 言語で記述された正常に動作するモデルを作成し、その後モジュールごとに Verilog 記述に書き換えることがよくあります。
  • (2) テスト刺激を生成するか、直接検証を行います。データ量が大きい入力刺激や複雑な制御入力、特定環境でのデータ検証において、PLI の実装は Verilog よりも優れています。
  • (3) シミュレーションのプロセスと結果を取得し、ユーザーが受け入れやすい形式で出力します。例えば、いくつかのコーデックモジュールでは、ユーザー定義の表示効果を使用するとデバッグが容易になります。
  • (4) ソフトウェアとハードウェアの連携シミュレーション。例えば、設計に CPU エンティティが含まれる場合、ソフトウェアを機械語にコンパイルして対応する ROM にロードし、連携シミュレーションを行うことができます。

PLI バージョン

PLI の発展は主に3世代を経てきました。

1985年 - TF インターフェース

第1世代はタスク/関数（Task/Function）インターフェースと呼ばれ、TF インターフェースと略されます。TF インターフェースには一連の C 言語関数ライブラリが含まれており、すべて tf_ をプレフィックスとし、veriuser.h 内で定義されています。これらの C 関数は一般的に TF サブルーチンと呼ばれ、主にユーザー定義のタスクと関数、ユーティリティ関数、コールバック機構、データ出力が含まれます。

1989年 - ACC インターフェース

第2世代はアクセス（Access）インターフェースと呼ばれ、ACC インターフェースと略されます。ACC インターフェースの関数はすべて acc_ をプレフィックスとし、acc_user.h 内で定義されています。ACC サブルーチンは主に Verilog で記述されたさまざまなオブジェクトへのアクセスと変更に使用されます。ACC ライブラリ関数は TF ライブラリ関数の追加であり、置き換えではありません。

一般に PLI インターフェースは TF および ACC インターフェースを指します。

1995年 - VPI インターフェース

第3世代はプロセスインターフェース（Verilog Process Interface）と呼ばれ、VPI インターフェースと略されます。VPI サブルーチンは TF と ACC サブルーチンの機能を合わせたものであり、vpi_user.h 内で定義されています。

PLI サブルーチンが多くて乱雑であるのに対し、VPI は特に洗練されています。PLI は誕生当初、統一された標準がなく、完全に実践の中で発展してきたため、よく使われる PLI ライブラリ関数は約100個にもなり、プログラムを作成するときは基本的にマニュアルを参照する必要があります。

一方、VPI は一定の標準に基づいて計画的に策定され、多くのオブジェクト指向の考え方が取り入れられており、ライブラリ関数の簡潔さは PLI をはるかに上回ります。しかし、VPI の構造は比較的複雑で、習得が容易ではありません。VPI の最大の弱点は、シミュレータへのサポートが友好的ではないことです。

2003年 - SystemVerilog と DPI

Verilog の拡張として、2003 年に SystemVerilog 標準が公開され、より多くの形式のシミュレーションをサポートしました。

DPI インターフェース（Direct Procee Interface）は、ソフトウェアと SystemVerilog が対話するためのインターフェースとなり、現在主流です。

一般的な状況では、PLI の TF および ACC インターフェースを使用すればシミュレーションのニーズを満たせます。本章では TF と ACC インターフェースについて簡単に紹介するだけです。他のインターフェースについては、あの若者が学び終えたときに、改めて紹介します。

PLI の使用

システムタスクとシステム関数を作成することで、ユーザーは PLI と C プログラムを使用して Verilog 言語を拡張できます。これらのユーザー定義のシステムタスクと関数の名前は、必ずドル記号 "$" で始まる必要があります。このとき、Verilog のタスクはサブルーチンに相当します。タスクが呼び出されると、シミュレータの実行フローはサブルーチンにジャンプし、タスクを完了すると実行フローが戻ります。Verilog タスクは値を返しませんが、入力、出力、双方向の仮パラメータを持つことができます。

Verilog の関数は、ほとんどの言語の関数と同じです。関数が呼び出されると、一連の命令を実行し、呼び出し元の命令に値を返します。

次に、簡単なシステムタスク $hello_runoob を例に説明します。このシステムタスクが呼び出されると、1行の文字列 "Hello Runoob!" を出力します。

PLI でのシステムタスクの作成

C 言語で記述された出力プログラムは次のとおりです。ファイル名はhello_runoob.c 。

PLI 使用の一般的な流れを説明するため、このプログラムは TF/ACC サブルーチンを呼び出していません。

例

#include "stdio.h" //不包含 PLI 库子程序
int hello_runoob(){
        printf("Hello Runoob! \n");
}

PLI とシミュレータの接続

VCS の使用を例にとると、VCS コンパイル時に必要な C 関連ファイルをコンパイルまたは作成します。

上記の hello_runoob.c を簡単にコンパイルし、hello_runoob.o ファイルを出力します。相対パスに注意してください。

gcc -c ../tb/hello_runoob.c

VCS が認識できるリンクテーブルファイルを作成します。ファイル名は hello_runoob.tab とし、内容は以下のとおりです。

$hello_runoob call=hello_runoob

Verilog でのシステムタスクの呼び出し

Verilog では、システムタスク呼び出しの形式で $hello_runoob を呼び出します。記述は以下のとおりです。

例

`timescale 1ns/1ps
module test ;
   initial begin
     #10 ;
     $hello_runoob;
   end

   initial begin
      forever begin
         #100;
         if ($time >= 10000)  $finish ;
      end
   end
endmodule

Verilog のコンパイルとシミュレーション

RTL と作成した PLI 中間ファイルをコンパイルします。PLI ライブラリ内のテーブルファイルをリンクすることを示すには、"-P" パラメータで指定する必要があります。例えば、このシミュレーションでは VCS コマンドラインに次のパラメータを追加します（相対パスに注意）：

 
-P ../tb/hello_runoob.tab hello_runoob.o
