2.4.9 ListViewのデータ更新問題

カテゴリ Android 基礎入門チュートリアル

本節のイントロダクション：

私たちはこれまでにListViewの基本的な使い方を学んできましたが、注意深いあなたなら気づいたかもしれませんが、私たちのデータは最初に定義されていて、すべて静的です。しかし実際の開発では、データはしばしば動的に変化します。例えば、ある項目を追加・削除・変更した場合、リストに表示されるデータも同期して更新されるべきです。では、本節ではListViewのデータ更新の問題について検討します。全件更新と、その中の1項目の更新を含みます。それでは、本節の内容を始めましょう！〜

カスタムBaseAdapterの実装：MyAdapter.java：

/**
 * Created by Jay on 2015/9/21 0021.
 */
public class MyAdapter extends BaseAdapter {

    private Context mContext;
    private LinkedList<Data> mData;

    public MyAdapter() {}

    public MyAdapter(LinkedList<Data> mData, Context mContext) {
        this.mData = mData;
        this.mContext = mContext;
    }

    @Override
    public int getCount() {
        return mData.size();
    }

    @Override
    public Object getItem(int position) {
        return null;
    }

    @Override
    public long getItemId(int position) {
        return position;
    }

    @Override
    public View getView(int position, View convertView, ViewGroup parent) {
        ViewHolder holder = null;
        if(convertView == null){
            convertView = LayoutInflater.from(mContext).inflate(R.layout.item_list,parent,false);
            holder = new ViewHolder();
            holder.img_icon = (ImageView) convertView.findViewById(R.id.img_icon);
            holder.txt_content = (TextView) convertView.findViewById(R.id.txt_content);
            convertView.setTag(holder);
        }else{
            holder = (ViewHolder) convertView.getTag();
        }
        holder.img_icon.setImageResource(mData.get(position).getImgId());
        holder.txt_content.setText(mData.get(position).getContent());
        return convertView;
    }

    private class ViewHolder{
        ImageView img_icon;
        TextView txt_content;
    }
    
}

実行できますが、実行してみるとページにはデータが何もなく、真っ白で、このようなユーザー体験は良くありません。ListViewの1つのsetEmptyView(View)メソッドで、ListViewのデータが空の場合に対応するViewを表示します。また、このメソッドは奇妙なことに、動的に追加したViewが無効になってしまいます。ListViewのあるレイアウトファイルに、ListViewにデータがないときに表示したいViewを追加するしかありません。さらに、このsetEmptyViewで設定したViewは、読み込み時に表示されないという、とても不思議な現象があります....。例えば、ここではデータがないときに「データなし」と表示するTextViewを表示しています。コードの一部は以下の通りです：

<TextView
        android:id="@+id/txt_empty"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_gravity="center"
        android:textSize="15pt"
        android:textColor="#000000"/>
        
txt_empty = (TextView) findViewById(R.id.txt_empty);    
txt_empty.setText("暂无数据~");
list_one.setEmptyView(txt_empty);

もちろん、この方法以外にも、ListViewと同じサイズと位置のレイアウトを定義して、`android:visibility="gone"`に設定し、JavaコードでmDataコレクションのサイズを判定し、==0ならデータがないことを示すので、このレイアウトを表示させ、データがあるときはこのレイアウトを非表示にすることもできます。

3.ある項目を削除する

同様に、2つのメソッドを書きます。1つはオブジェクトを直接削除し、もう1つはカーソルに基づいて削除します。

public void remove(Data data) {
    if(mData != null) {
        mData.remove(data);
    }
    notifyDataSetChanged();
}

public void remove(int position) {
    if(mData != null) {
        mData.remove(position);
    }
    notifyDataSetChanged();
}

そして2つのButtonを追加して、これらの2つのメソッドを呼び出します：

case R.id.btn_remove:

    break;

4.すべてのレコードを削除する：

これはさらに簡単で、clearメソッドを直接呼び出すだけです！メソッドのコードは以下の通りです：

public void clear() {
    if(mData != null) {
        mData.clear();
    }
    notifyDataSetChanged();
}

5.あるレコードを更新する

注意深いあなたなら気づいたはずですが、データ変更操作を行った後は、必ずnotifyDataSetChanged()が呼び出されます。最初はこう思っていました：

notifyDataSetChanged()は画面上に表示されているitemをすべて再描画するので、UIパフォーマンスに影響するのではないでしょうか。データ量が非常に多く、1つの項目を変更するだけで全てのitemを再描画するのは、確かに不合理ですよね！そこで、私はあるItem内のコントロールの値を変更するために、愚かな方法を使いました。Javaコードに次のようなコードを書きました：

private void updateListItem(int postion,Data mData){
    int visiblePosition = list_one.getFirstVisiblePosition();
    View v = list_one.getChildAt(postion - visiblePosition);
    ImageView img = (ImageView) v.findViewById(R.id.img_icon);
    TextView tv = (TextView) v.findViewById(R.id.txt_content);
    img.setImageResource(mData.getImgId());
    tv.setText(mData.getContent());
}

その後、グループの友人たちと話し合って、自分が間違っていたことに気づきました。：

notifyDataSetChanged()メソッドは再レンダリングが必要かどうかを判断します。現在のitemに再レンダリングの必要がなければ再レンダリングされません。あるItemの状態が変化した場合、Viewの再描画が発生します。再描画されるのはすべてのItemではなく、Viewの状態が変化したそのItemだけです！したがって、notifyDataSetChange()メソッドを直接呼び出せばよいのです。もちろん、上記のメソッドを余分に知っていても問題はありません。
