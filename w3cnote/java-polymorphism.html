Javaにおけるポリモーフィズム

分類 プログラミング技術

ポリモーフィズムは一般的に、オーバーライド式ポリモーフィズムとオーバーロード式ポリモーフィズムの2種類に分けられます。

  • オーバーロード式ポリモーフィズムコンパイル時ポリモーフィズムとも呼ばれます。つまり、このポリモーフィズムはコンパイル時にすでに決定されています。オーバーロードは誰もが知っていると思います。メソッド名が同じでパラメータリストが異なる一連のメソッドがオーバーロードです。このようなオーバーロードされたメソッドを呼び出すとき、異なるパラメータを渡すことで最終的に異なる結果が得られます。

    しかし、ここには曖昧さがあります。オーバーロードをポリモーフィズムに含めるべきではないと考える人もいます。なぜなら、多くの人のポリモーフィズムの理解は次のようなものだからです：プログラム内で定義された参照変数が指す具体的な型と、その参照変数を通じて発行されるメソッド呼び出しは、プログラミング時には決定されておらず、プログラムの実行中に決定される、この状況をポリモーフィズムと呼びます。この定義で説明されているのは、私たちの2番目のポリモーフィズム、つまりオーバーライド式ポリモーフィズムです。さらに、オーバーロード式ポリモーフィズムはオブジェクト指向プログラミングに特有のものではありませんが、ポリモーフィズムはオブジェクト指向の3大特性の1つです（もし私の言い方が間違っていたら、どうか教えてください...）。

    皆さんが定義を深く追求する必要もないと思います。私の理解では、同じ動作が複数の異なる表現形式や形態を持つ能力がポリモーフィズムです。したがって、オーバーロードもポリモーフィズムの一種だと思います。この考えに同意できなくても、受け入れます。

  • オーバーライド式ポリモーフィズムランタイムポリモーフィズムとも呼ばれます。このポリモーフィズムは動的束縛（dynamic binding）技術によって実現され、実行中に参照されるオブジェクトの実際の型を判断し、その実際の型に基づいて対応するメソッドを呼び出すことを指します。つまり、プログラムが実行されて初めて、どのサブクラスのメソッドが呼び出されるのかがわかるのです。 このポリモーフィズムは、メソッドのオーバーライドとアップキャストによって実現されます。上のコードの例は完全なオーバーライド式ポリモーフィズムです。これから説明するすべてのポリモーフィズムはオーバーライド式ポリモーフィズムです。なぜなら、それがオブジェクト指向プログラミングにおける真のポリモーフィズムだからです。

アップキャスト

サブクラスの参照が指すオブジェクトを親クラスの型に変換することをアップキャストと呼びます。簡単に言えば、サブクラスのオブジェクトを親クラスのオブジェクトに変換することです。ここでの親クラスの型はインターフェースであってもかまいません。

誰もが知っている例を見てみましょう：

例

public class Animal { public void eat(){ System.out.println("animal eatting..."); } } public class Cat extends Animal{ public void eat(){ System.out.println("私は魚を食べる"); } } public class Dog extends Animal{ public void eat(){ System.out.println("私は骨を食べる"); } public void run(){ System.out.println("私は走れます"); } } public class Main { public static void main(String[] args) { Animal animal = new Cat(); //アップキャスト animal.eat(); animal = new Dog(); animal.eat(); } } //結果： //私は魚を食べる //私は骨を食べる

これがアップキャストです。Animal animal = new Cat();サブクラスのオブジェクト Cat を親クラスのオブジェクト Animal に変換します。このとき、animal という参照が呼び出すメソッドはサブクラスのメソッドです。

キャストの際に注意すべき問題

  • アップキャスト時、サブクラスで独自に定義したメソッドは失われます。例えば、上記のDogクラスで定義されたrunメソッドは、animal参照がDogクラスのインスタンスを指しているときにはアクセスできません。animal.run()エラーになります。
  • サブクラスの参照は親クラスのオブジェクトを指すことはできません。Cat c = (Cat)new Animal()これはできません。

アップキャストの利点

  • 重複コードを減らし、コードを簡潔にします。
  • システムの拡張性を高めます。

ダウンキャスト

アップキャストに対応するのがダウンキャストです。ダウンキャストは親クラスのオブジェクトをサブクラスのオブジェクトに変換することです。（注意してください！ここには落とし穴があります。）

事例で解説

まず例を見てみましょう：

//还是上面的animal和cat dog
Animal a = new Cat();
Cat c = ((Cat) a);
c.eat();
//输出  我吃鱼
Dog d = ((Dog) a);
d.eat();
// 报错 ： java.lang.ClassCastException：com.chengfan.animal.Cat cannot be cast to com.chengfan.animal.Dog
Animal a1 = new Animal();
Cat c1 = ((Cat) a1);
c1.eat();
// 报错 ： java.lang.ClassCastException：com.chengfan.animal.Animal cannot be cast to com.chengfan.animal.Cat

なぜ最初のコードはエラーにならないのでしょうか？もうお気づきかもしれませんが、a 自体が Cat オブジェクトなので、Cat にダウンキャストできるのは当然であり、Dog に変換できないのも当然です。犬が突然猫になるなんてありえないでしょう？

一方、a1 は Animal オブジェクトであり、どのサブクラスのオブジェクトにもダウンキャストできません。例えば、考古学の発掘で新種の生物を見つけたとき、それが動物であることはわかっても、「ああ、これは猫だ」とか「これは犬だ」と直接言うことはできません。

ダウンキャストの注意事項

  • ダウンキャストの前提は、親クラスのオブジェクトがサブクラスのオブジェクトを指していることです（つまり、ダウンキャストする前に、まずアップキャストされている必要があります）。

  • ダウンキャストは自分自身のクラスのオブジェクトにのみ変換できます（猫は犬になれません）。

古典的な例を見てみましょう：

例

class A { public String show(D obj) { return ("A and D"); } public String show(A obj) { return ("A and A"); } } class B extends A{ public String show(B obj){ return ("B and B"); } public String show(A obj){ return ("B and A"); } } class C extends B{ } class D extends B{ } public class Demo { public static void main(String[] args) { A a1 = new A(); A a2 = new B(); B b = new B(); C c = new C(); D d = new D(); System.out.println("1--" + a1.show(b)); System.out.println("2--" + a1.show(c)); System.out.println("3--" + a1.show(d)); System.out.println("4--" + a2.show(b)); System.out.println("5--" + a2.show(c)); System.out.println("6--" + a2.show(d)); System.out.println("7--" + b.show(b)); System.out.println("8--" + b.show(c)); System.out.println("9--" + b.show(d)); } } //結果： //1--A and A //2--A and A //3--A and D //4--B and A //5--B and A //6--A and D //7--B and B //8--B and B //9--A and D //この結果を理解できますか？まず自分で分析してみてください。

最初の3つは、無理やり分析すれば理解できるでしょう。しかし4つ目は、おそらく困惑するでしょう。なぜ「b and b」ではないのでしょうか？

ここで新しいことを学ぶ必要があります。

親クラスのオブジェクト参照変数がサブクラスのオブジェクトを参照しているとき、参照されるオブジェクトの型が誰のメンバーメソッドを呼び出すかを決定し、参照変数の型が呼び出し可能なメソッドを決定します。サブクラスでそのメソッドがオーバーライドされていない場合は、親クラスから探します。

読みにくいかもしれませんが、まず簡単な例を見てみましょう：

例

class X { public void show(Y y){ System.out.println("x and y"); } public void show(){ System.out.println("only x"); } } class Y extends X { public void show(Y y){ System.out.println("y and y"); } public void show(int i){ } } class main{ public static void main(String[] args) { X x = new Y(); x.show(new Y()); x.show(); } } //結果 //y and y //only x

Y は X を継承し、X の show(Y y) メソッドをオーバーライドしましたが、show() メソッドはオーバーライドしていません。

このとき、参照型が X の x が指すオブジェクトは Y であり、呼び出されるメソッドは Y によって決まり、まず Y の中から探します。x.show(new Y());このメソッドは Y 内で定義されているので、実行されるのは Y 内のメソッドです。

しかし、x.show();実行するとき、ある人は、「Y にはこのメソッドがないのでは？」と言うかもしれません。親クラスにそのメソッドを探しに行ったように見えます。なぜなら X のメソッドを呼び出したからです。

実際には、Y クラスにも show() メソッドがあります。このメソッドは X から継承されたもので、オーバーライドされていないだけです。そのため Y に明示的に書かれていないだけで、X のメソッドを呼び出しているように見えますが、実際には Y のメソッドを呼び出しています。

このとき、上記の理解しにくい文を振り返ると、理解しやすくなったのではないでしょうか。X は参照変数の型であり、どのメソッドを呼び出せるかを決定します。show() と show(Y y) は呼び出せますが、show(int i) は呼び出せません。Y は参照されるオブジェクトの型であり、誰のメソッドを呼び出すかを決定します：Y のメソッドを呼び出します。

上記は簡単な知識であり、複雑な例を理解するにはまだ十分ではありません。もう一つ次のような知識を見てみましょう：

継承チェーンにおけるオブジェクトメソッド呼び出しの優先順位：this.show(O)、super.show(O)、this.show((super)O)、super.show((super)O)。

この呼び出し関係を理解できれば、ポリモーフィズムをマスターしたことになります。あの複雑な例に戻りましょう：

A、B、C、D の関係は次のとおりです：C/D —> B —> A

まず 4 を分析しましょう：a2.show(b)

  • まず、a2 は型 A の参照型であり、型 B のオブジェクトを指しています。A が呼び出し可能なメソッドを決定します：show(D obj) と show(A obj)。
  • a2.show(b) ==> this.show(b)ここで this は B を指します。
  • 次に、B クラス内で show(B obj) を探します。見つかりましたが、残念ながら役に立ちません。show(B obj) メソッドが呼び出し可能範囲にないからです。this.show(O)失敗したので、次のレベルに進みます：super.show(O)super は A を指します。
  • A 内で show(B obj) を探しますが、失敗します。このメソッドが定義されていないためです。第3レベルに進みます：this.show((super)O)this は B を指します。
  • B 内で show((A)O) を探します。見つかりました：show(A obj) です。このメソッドを呼び出します。
  • 出力：B and A

このプロセスを理解でき、他のケースも分析できるなら、本当にマスターしたと言えます。

次に 9 を見てみましょう：b.show(d)

  • まず、b は型 B の参照型であり、型 B のオブジェクトを指しています。アップキャストは関係していないので、自分自身のクラスのメソッドのみを呼び出します。
  • B 内で show(D obj) メソッドを探します。もう「見つからない」とは言わないでしょう？見つかったので、そのメソッドを直接呼び出します。
  • 出力：A and D

まとめ

この記事の内容はおおむね以上です。まとめましょう。

  1. ポリモーフィズムとは、簡単に言えば、同じ動作が複数の異なる表現形式や形態を持つ能力です。
  2. ポリモーフィズムの分類：実行時ポリモーフィズムとコンパイル時ポリモーフィズム。
  3. 実行時ポリモーフィズムの前提：継承（実装）、オーバーライド、アップキャスト
  4. アップキャストとダウンキャスト。
  5. 継承チェーンにおけるオブジェクトメソッド呼び出しの優先順位：this.show(O)、super.show(O)、this.show((super)O)、super.show((super)O)。
