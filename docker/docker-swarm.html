Swarm クラスタ管理

はじめに

Docker Swarm は Docker のクラスタ管理ツールです。Docker ホストのプールを単一の仮想 Docker ホストに変換します。Docker Swarm は標準の Docker API を提供するため、Docker デーモンと通信するすべてのツールは、Swarm を使用して複数のホストに簡単に拡張できます。

サポートされるツールには、以下が含まれますが、これらに限定されません：

  • Dokku
  • Docker Compose
  • Docker Machine
  • Jenkins

原理

下図のように、swarm クラスタは管理ノード（manager）とワーカーノード（work node）で構成されます。

  • swarm mananger：クラスタ全体の管理業務を担当し、クラスタ設定、サービス管理など、クラスタに関連するすべての作業を含みます。
  • work node：図中の available node であり、主に対応するサービスを実行してタスク（task）を遂行します。

使用

以下の例は、すべて Docker Machine と virtualbox を使用して説明します。ホストに virtualbox がインストールされていることを確認してください。

1、swarm クラスタ管理ノード（manager）を作成

docker マシンを作成：

$ docker-machine create -d virtualbox swarm-manager

swarm クラスタを初期化します。初期化を行ったこのマシンがクラスタの管理ノードになります。

$ docker-machine ssh swarm-manager
$ docker swarm init --advertise-addr 192.168.99.107 #这里的 IP 为创建机器时分配的 ip。

上記の出力で、初期化が成功したことが確認できます。以下の行をコピーしておきます。ワーカーノードを追加するときに使用します。

docker swarm join --token SWMTKN-1-4oogo9qziq768dma0uh3j0z0m5twlm10iynvz7ixza96k6jh9p-ajkb6w7qd06y1e33yrgko64sk 192.168.99.107:2377

2、swarm クラスタワーカーノード（worker）を作成

ここでは直接2台のマシン、swarm-worker1 と swarm-worker2 を作成します。

それぞれ2つのマシンに入り、前の手順で作成したクラスタに追加するよう指定します。ここで前の手順でコピーした内容を使用します。

上記の出力は、追加が成功したことを示しています。

上の図では、前の手順でコピーした内容が長いため自動的に切り詰められています。実際に図で実行されたコマンドは次のとおりです。

docker@swarm-worker1:~$ docker swarm join --token SWMTKN-1-4oogo9qziq768dma0uh3j0z0m5twlm10iynvz7ixza96k6jh9p-ajkb6w7qd06y1e33yrgko64sk 192.168.99.107:2377

3、クラスタ情報を確認

管理ノードに入り、docker info を実行すると、現在のクラスタの情報を確認できます。

$ docker info

赤い丸で囲んだ場所から、現在実行中のクラスタには3つのノードがあり、そのうち1つが管理ノードであることがわかります。

4、サービスをクラスタにデプロイ

注意：クラスタ管理に関連するすべての操作は、管理ノード上で行います。

以下の例では、helloworld という名前のサービスを作成します。これはランダムに1つのワーカーノードに割り当てられます。

docker@swarm-manager:~$ docker service create --replicas 1 --name helloworld alpine ping docker.com

5、サービスのデプロイ状況を確認

helloworld サービスがどのノードで実行されているかを確認します。現在は swarm-worker1 ノードで実行されていることがわかります。

docker@swarm-manager:~$ docker service ps helloworld

helloworld のデプロイの詳細情報を確認：

docker@swarm-manager:~$ docker service inspect --pretty helloworld

6、クラスタサービスを拡張

上記の helloworld サービスを2つのノードに拡張します。

docker@swarm-manager:~$ docker service scale helloworld=2

1つのノードから2つのノードに拡張されたことがわかります。

7、サービスを削除

docker@swarm-manager:~$ docker service rm helloworld

削除されたかどうかを確認：

8、サービスのローリングアップグレード

以下の例では、redis のバージョンをより新しいバージョンにローリングアップグレードする方法を紹介します。

バージョン 3.0.6 の redis を作成します。

docker@swarm-manager:~$ docker service create --replicas 1 --name redis --update-delay 10s redis:3.0.6

redis をローリングアップグレードします。

docker@swarm-manager:~$ docker service update --image redis:3.0.7 redis

図から、redis のバージョンが 3.0.6 から 3.0.7 にアップグレードされたことがわかります。サービスが正常にアップグレードされたことを示しています。

9、特定のノードが新しいタスクを受信するのを停止

すべてのノードを確認：

docker@swarm-manager:~$ docker node ls

現在すべてのノードが Active であり、新しいタスクの割り当てを受信できることがわかります。

ノード swarm-worker1 を停止：

注意：swarm-worker1 の状態が Drain になります。クラスタのサービスには影響しませんが、swarm-worker1 ノードが新しいタスクを受信しなくなるだけで、クラスタの負荷容量が低下します。

以下のコマンドでノードを再びアクティブにできます：

docker@swarm-manager:~$  docker node update --availability active swarm-worker1
