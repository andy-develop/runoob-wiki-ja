Obsidian ワークフロー構築

これまで学んだ機能は、まるで工具箱の中のバラバラの部品のようなものです。ハンマーの使い方やドライバーの使い方は分かっても、まだテーブルの作り方は分かっていません。

この章では、中核機能とプラグインを組み合わせて 5 つの実用的なワークフローにまとめ、「ツールを使える」状態から「システムを持つ」状態へと引き上げます。

読書ノートワークフロー

読書は知識を取り込む主要な方法です。以下のワークフローは、1 冊の本を検索可能で関連付け可能な長期的な資産に変えるのに役立ちます。

プロセス概要

  1. 書籍ホームページノートを作成する：テンプレートですばやく作成し、本のメタ情報を記録する
  2. 読書中に抜粋とコメントを記録する：Callout を使用して原文の引用と自分の考えを区別する
  3. 中核概念ノートを抽出する：本の中の重要な概念を独立したアトミックノートにする
  4. 概念間のリンクを構築する：新しい概念を既存の知識ネットワークに接続する

毎日ワークフロー（GTD 簡易版）

このフローは厳密な GTD トレーニングを必要とせず、最も実用的な部分だけを取り入れています。

毎日のプロセス

  1. 朝：今日の日記を開き、今日の目標を 3 つ挙げる
  2. 日中：いつでも日記に考えを記録し、タスクを追加し、進捗を書く
  3. 夜：今日を振り返り、完了したタスクにチェックを入れ、簡単な要約を書く

Dataview で未完了タスクを集計する

ホームページノートに Dataview クエリブロックを置き、すべての日記の未完了タスクを自動的に収集します：


学習ノートワークフロー（Zettelkasten 簡易版）

これは Zettelkasten の方法論を基に改良した実用バージョンで、技術者や学生の学習シーンに適しています。

3 種類のノートタイプ

タイプ出どころ特徴保存場所
閃きノートいつでも浮かぶ考え、ひらめき形式にこだわらず、すばやく記録Daily Note または受信トレイフォルダー
文献ノート書籍、記事、チュートリアルを読んだときの記録自分の言葉で書き直し、原文の出典を添付対応する分野のリソースフォルダー
永久ノート閃きノートと文献ノートから抽出したものアトミック化、1 つの概念につき 1 ノート、双方向リンクで関連付けフォルダーに分けず、保管庫に分散させリンクで発見する

実践手順

  1. 新しい知識を学ぶとき、まず日記または一時ノートに記録します（閃きノート）
  2. 整理するとき、自分の言葉で中核概念を独立したノートとして書きます（文献ノート → 永久ノート）
  3. 各概念ノートに双方向リンクを追加し、既存の関連知識に接続します
  4. 逆リンクパネルを開き、新しいノートが他のノートに自然に引用されているか確認します

ライティングワークフロー

ひらめきから公開まで、全工程を Obsidian 内で完結します。

4 段階プロセス

段階ノートタイプツール
素材収集閃きノート、抜粋カードDaily Note + クイック記録
アウトライン計画アウトラインノートOutline パネル + Canvas のドラッグ＆ドロップ並べ替え
下書き作成下書きノート編集エリア + フォーカスモード
公開・エクスポート最終バージョンPDF書き出し / Obsidian Publish / Pandocで他の形式に変換

素材収集段階

日々の読書や思考の中で、執筆テーマに関連する内容に出会ったら、いつでも記録しておく。

各執筆プロジェクトに「素材プール」ノートを作成し、Dataview でクエリを実行できます。#執筆/プロジェクト名タグの内容。

アウトライン計画段階

Canvas でアウトラインカードを作成し、ドラッグ＆ドロップで順序を調整します。線で論理関係を表します。

または、アウトラインノートを直接作成し、見出しレベルで章構成を表して、アウトラインパネルで全体を確認します。

下書き作成段階

Cmd+P →「フォーカスモード」で全てのサイドバーを非表示にします。

1節書くごとに、その下で%%コメント%%（Obsidian のコメント構文）を使って、修正予定のマークを書きます。これらのコメントは編集モードでのみ表示され、プレビューモードでは非表示になります。

公開・エクスポート

PDF書き出し：Obsidian 内蔵の書き出し機能を直接使用します。

Word/HTML書き出し：Pandoc プラグインをインストールすると、Markdown を複数の形式に変換できます。

デジタルガーデンの構築：Obsidian Publish を使うと、Vault 全体をウェブサイトとして公開できます。

ホームページデザインの提案

設計の良いホームページ（Home Note）は、毎日 Obsidian を開いたときに最初に目にする画面です。

推奨する構成：

例

# おかえりなさい &#x1f3e0;

## クイックアクセス

- [[00-日記/{{date}}|今日の日記]]
- [[受信トレイ]]
- [[プロジェクトダッシュボード]]

## 現在のプロジェクト

```dataview
TABLE status, deadline
FROM "10-项目"
WHERE status = "进行中"
```

## 未完了タスク

```dataview
TASK
FROM "00-日记"
WHERE !completed
LIMIT 10
```

## 最近更新されたノート

```dataview
TABLE file.mtime as "最后修改"
FROM ""
SORT file.mtime DESC
LIMIT 5
```

ホームページの目的は「見た目が良い」ことではなく、「役に立つ」ことです。毎日 Obsidian を開いたときに最も見たい情報をホームページに置きます。今日のToDo、進行中のプロジェクト、最近変更したノートなどです。それが本当の入口になるまで調整し続けましょう。

ワークフロー選択のアドバイス

5つのワークフローをすべてそのまま取り入れる必要はありません。以下の優先順位に従って段階的に構築することをおすすめします：

段階最初に構築するもの理由
第1週デイリーワークフロー + ホームページ毎日 Obsidian を開く習慣を作ります。他のワークフローはここから広がっていきます。
第2週学習ノートワークフロー新しい知識を学んでいるなら、これが最も直接的な応用シーンです。
第1ヶ月読書ノートワークフロー次の本を読み始めるときは、テンプレートを使って最初のノートを作成するだけでOKです。
必要になったとき執筆ワークフロー / プロジェクト管理ワークフロー具体的な執筆タスクやプロジェクトができてから構築しましょう。前もって空の枠組みを作らないこと。
