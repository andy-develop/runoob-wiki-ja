Rust 並行プログラミング

安全かつ効率的に並行処理を行うことは Rust が生まれた目的の一つであり、主にサーバーの高負荷耐性を解決することを目的としています。

並行（concurrent）の概念は、プログラムの異なる部分が独立して実行されることを指します。これは並列（parallel）の概念と混同されがちですが、並列は「同時に実行すること」を強調しています。

並行はしばしば並列をもたらします。

この章では、並行処理に関連するプログラミングの概念と詳細について説明します。

スレッド

スレッド（thread）は、プログラム内で独立して実行される部分です。

スレッドがプロセス（process）と異なる点は、スレッドがプログラム内部の概念であることです。プログラムは通常、一つのプロセス内で実行されます。

オペレーティングシステムがある環境では、プロセスは交互にスケジューリングされて実行されます。一方、スレッドはプロセス内でプログラムによってスケジューリングされます。

スレッドの並行処理では並列が発生する可能性が高いため、並列処理で発生し得るデッドロックや遅延エラーは、並行処理機構を含むプログラムでよく発生します。

これらの問題を解決するために、多くの他の言語（Java、C# など）は特別なランタイム（runtime）ソフトウェアを使用してリソースを調整しますが、これによりプログラムの実行効率が大幅に低下することは間違いありません。

C/C++ 言語はオペレーティングシステムの最下層でマルチスレッドをサポートしていますが、言語自体とそのコンパイラには並列エラーを検出・回避する能力がないため、開発者にとって負担が大きく、エラーを防ぐために多大な労力を費やす必要があります。

Rust は C/C++ と同様に、ランタイム環境に依存しません。

しかし Rust は、言語自体に所有権メカニズムを含む手段を設計しており、最も一般的なエラーを可能な限りコンパイル段階で排除します。この点は他の言語にはありません。

しかし、これはプログラミング時に不注意でよいという意味ではありません。これまでのところ、並行処理によって引き起こされる問題は一般にはまだ完全に解決されておらず、エラーが発生する可能性は依然としてあります。並行プログラミングでは十分に注意してください！

Rust では、std::thread::spawn 関数を使用して新しいスレッドを作成します：

例

use std::thread;
use std::time::Duration;

fn spawn_function() {
    for i in 0..5 {
        println!("spawned thread print {}", i);
        thread::sleep(Duration::from_millis(1));
    }
}

fn main() {
    thread::spawn(spawn_function);

    for i in 0..3 {
        println!("main thread print {}", i);
        thread::sleep(Duration::from_millis(1));
    }
}

実行結果：

main thread print 0
spawned thread print 0
main thread print 1
spawned thread print 1
main thread print 2
spawned thread print 2

この結果は状況によって順序が変わることがありますが、全体的にはこのように出力されます。

このプログラムには子スレッドが1つあり、5行のテキストを出力することを目的としています。メインスレッドは3行のテキストを出力しますが、メインスレッドの終了に伴って spawn スレッドも終了してしまい、すべての出力は完了しません。

std::thread::spawn 関数の引数は引数なしの関数ですが、上記の書き方は推奨されません。クロージャ（closures）を使用して関数を引数として渡すことができます：

例

use std::thread;
use std::time::Duration;

fn main() {
    thread::spawn(|| {
        for i in 0..5 {
            println!("spawned thread print {}", i);
            thread::sleep(Duration::from_millis(1));
        }
    });

    for i in 0..3 {
        println!("main thread print {}", i);
        thread::sleep(Duration::from_millis(1));
    }
}

クロージャは、変数に保存したり、他の関数に引数として渡したりできる匿名関数です。クロージャは Rust におけるラムダ式に相当し、形式は次のとおりです：

|参数1, 参数2, ...| -> 返回值类型 {
    // 函数体
}

例：

例

fn main() {
    let inc = |num: i32| -> i32 {
        num + 1
    };
    println!("inc(5) = {}", inc(5));
}

実行結果：

inc(5) = 6

クロージャは型宣言を省略して、Rust の自動型推論メカニズムを使用できます：

例

fn main() {
    let inc = |num| {
        num + 1
    };
    println!("inc(5) = {}", inc(5));
}

結果は変わりません。

join メソッド

例

use std::thread;
use std::time::Duration;

fn main() {
    let handle = thread::spawn(|| {
        for i in 0..5 {
            println!("spawned thread print {}", i);
            thread::sleep(Duration::from_millis(1));
        }
    });

    for i in 0..3 {
        println!("main thread print {}", i);
        thread::sleep(Duration::from_millis(1));
    }

    handle.join().unwrap();
}

実行結果：

main thread print 0 
spawned thread print 0 
spawned thread print 1 
main thread print 1 
spawned thread print 2 
main thread print 2 
spawned thread print 3 
spawned thread print 4

join メソッドを使用すると、子スレッドの実行が終了してからプログラムの実行を停止させることができます。

move による所有権の強制移動

これはよく遭遇するケースです：

例

use std::thread;

fn main() {
    let s = "hello";
   
    let handle = thread::spawn(|| {
        println!("{}", s);
    });

    handle.join().unwrap();
}

子スレッド内で現在の関数のリソースを使用しようとすると、これは必ずエラーになります！所有権メカニズムがこのような危険な状況の発生を禁止しているからです。それは所有権メカニズムによるリソース破棄の確実性を損なうことになります。クロージャの move キーワードを使用して対処できます：

例

use std::thread;

fn main() {
    let s = "hello";
   
    let handle = thread::spawn(move || {
        println!("{}", s);
    });

    handle.join().unwrap();
}

メッセージ受け渡し

Rust でメッセージ受け渡しによる並行処理を実現する主なツールはチャネル（channel）です。チャネルは2つの部分から構成され、送信側（transmitter）と受信側（receiver）があります。

std::sync::mpsc にはメッセージ受け渡しのメソッドが含まれています：

例

use std::thread;
use std::sync::mpsc;

fn main() {
    let (tx, rx) = mpsc::channel();

    thread::spawn(move || {
        let val = String::from("hi");
        tx.send(val).unwrap();
    });

    let received = rx.recv().unwrap();
    println!("Got: {}", received);
}

実行結果：

Got: hi

子スレッドはメインスレッドの送信側 tx を取得し、その send メソッドを呼び出して文字列を送信しました。その後、メインスレッドは対応する受信側 rx を通じてそれを受信しました。

    エラーを引き起こすコード:

    struct Person {
    name : String,
    age : u8,
}

fn main() {
    let p = Person{ name: "Hao Chen".to_string(), age : 44};
    //可以运行，因为 <code data-enlighter-language="raw" class="EnlighterJSRAW">u8</code> 有 Copy Trait
    let age = |p : Person| p.age;

}

    //下面的声明可以正确译:
let name: for<'a> fn(&'a Person) -> &'a String = |p: &Person| &p.name;
