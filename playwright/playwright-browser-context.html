Playwright テスト分離と Browser Context

この章では、Playwright のテスト分離メカニズムと Browser Context の概念を説明します。これはテストの安定性と信頼性を保証するための重要な設計です。

テスト分離とは

テスト分離とは、各テストケースが完全に独立した環境で実行され、互いに影響を与えないことです。

Playwright では、各テストは自動的に独立したBrowser Context（ブラウザコンテキスト）を取得します。

Browser Context とは

Browser Context は、いわばまったく新しいブラウザのプロファイルに相当します。。

Context を作成することは、まったく新しいブラウザウィンドウを開くようなものです。独自の Cookie、localStorage、sessionStorage を持ちますが、オーバーヘッドは非常に低い（ミリ秒単位）です。

概念たとえ説明
Browser（ブラウザインスタンス）ブラウザプログラムを1つ起動した状態オーバーヘッドが大きく、通常はテスト実行全体で1回だけ作成される
Browser Context（ブラウザコンテキスト）ブラウザ内の独立したプロファイルオーバーヘッドが小さく、テストごとに1つ作成される
Page（タブ）ブラウザ内の1つのタブContext 内でページを開く

各テストでは、pageとcontextすべて新しいため、あるテストが localStorage や Cookie を変更しても、他のテストには影響しません。

Context で分離される内容

各 Browser Context 間では、以下が完全に分離されます：

分離項目説明
Cookies各 Context は独立した Cookie ストレージを持ちます
localStorageローカルストレージは完全に分離されます
sessionStorageセッションストレージは完全に分離されます
IndexedDBブラウザデータベースは分離されます
キャッシュ（Cache）HTTP キャッシュは分離されます

例

// テスト A が Cookie を設定
test('テスト A', async ({ page }) => {
  await page.goto('https://www.runoob.com/');

  // Cookie を設定（現在の Context でのみ有効）
  await page.context().addCookies([{
    name: 'runoob_session',
    value: 'abc123',
    domain: 'www.runoob.com',
    path: '/',
  }]);

  // 以降の操作でこの Cookie を使用
});

// テスト B は新しい Context を受け取るため、テスト A が設定した Cookie は存在しない
test('テスト B', async ({ page }) => {
  await page.goto('https://www.runoob.com/');

  // context().cookies() は空の配列を返す
  const cookies = await page.context().cookies();
  console.log(cookies); // []
});

context fixture の使用

`page` に加えて、pageテスト関数はcontext`context` fixture を使って Context レベルの操作を行うことができます。

例

test('context fixture を使用', async ({ context, page }) => {
  // Context レベルで権限を設定
  await context.grantPermissions(['geolocation']);
  await context.setGeolocation({ latitude: 39.9, longitude: 116.4 });

  // Context レベルでネットワークをインターセプト
  await context.route('**/*.{png,jpg,jpeg}', route => route.abort());

  // page は同じ context 内にあるため、上記の設定を引き継ぐ
  await page.goto('https://www.runoob.com/');
});

複数 Context のシナリオ

同じテスト内で複数の独立したユーザーをシミュレートする必要がある場合は、Context を手動で作成できます。

例

test('2人のユーザーが独立して操作', async ({ browser }) => {
  // 2人のユーザー用に独立した Context を作成
  const userAContext = await browser.newContext();
  const userBContext = await browser.newContext();

  // 2人のユーザーのページは完全に分離される
  const pageA = await userAContext.newPage();
  const pageB = await userBContext.newPage();

  await pageA.goto('https://www.runoob.com/login');
  await pageB.goto('https://www.runoob.com/login');

  // ユーザー A がログイン
  await pageA.getByLabel('ユーザー名').fill('user_a');
  await pageA.getByLabel('パスワード').fill('password_a');
  await pageA.getByRole('button', { name: 'ログイン' }).click();

  // ユーザー B がログイン（それぞれ独立した Cookie/Session で、互いに影響しない）
  await pageB.getByLabel('ユーザー名').fill('user_b');
  await pageB.getByLabel('パスワード').fill('password_b');
  await pageB.getByRole('button', { name: 'ログイン' }).click();

  // クリーンアップ
  await userAContext.close();
  await userBContext.close();
});

テスト分離の利点

1. 再現性

各テストは同じ初期状態から始まり、どのような順序で実行しても結果が一致します。

2. 連鎖的な失敗の防止

テスト A が失敗してもテスト B まで失敗することはありません。各テストは独立してデバッグできます。

3. 並列実行のサポート

テストが完全に独立しているため、Playwright は複数のワーカーでそれらを安全に並列実行できます。

テスト分離は Playwright のデフォルト動作です。各テストはtest()自動的に独立した Browser Context をpageとcontext取得するため、追加の設定は一切不要です。
