Playwright 拡張と移行

この章では、Playwright エコシステムの拡張機能について説明します。Library スクリプトモード、MCP サービス、Test Agents、および他のフレームワークから Playwright への移行ガイドが含まれます。

Playwright Library スクリプトモード

Playwright Library は、テストランナー以外のシナリオ向けのスタンドアロンのブラウザ自動化ライブラリです。

インストール

npm i playwright

典型的な使い方

実例

// スクリーンショットスクリプト
import { chromium } from 'playwright';

(async () => {
  const browser = await chromium.launch({ headless: true });
  const page = await browser.newPage();
  await page.goto('https://www.runoob.com/');
  await page.screenshot({ path: 'runoob.png', fullPage: true });
  await browser.close();
  console.log('スクリーンショットは runoob.png に保存されました');
})();

PDF 生成

実例

import { chromium } from 'playwright';

(async () => {
  const browser = await chromium.launch();
  const page = await browser.newPage();
  await page.goto('https://www.runoob.com/');
  // PDF を生成（Chromium のみサポート）
  await page.pdf({
    path: 'runoob.pdf',
    format: 'A4',
    margin: { top: '20px', bottom: '20px' },
  });
  await browser.close();
})();

Library モード vs Test Runner の選択

シナリオ推奨
E2E テストの作成Playwright Test Runner
Webページのスクリーンショット、PDF生成Playwright Library
WebデータのスクレイピングPlaywright Library
一回限りの自動化スクリプトPlaywright Library

Playwright MCP の概要

Playwright MCP（Model Context Protocol）サーバーにより、AI アシスタントがブラウザを直接制御できるようになります。

MCP のインストールと設定

# 为 Claude Code 添加 Playwright MCP
claude mcp add playwright npx @playwright/mcp@latest

VS Code または他の MCP クライアントで設定します：

実例

{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}

MCP の動作方式

AI Agent は、構造化されたアクセシビリティスナップショット（Accessibility Snapshot）を介してページのコンテンツを認識します。

各アクセシビリティ情報には、ref識別子（ref）があり、Agent はこの ref を使用してクリックや入力などの操作を行います。

この方法ではスクリーンショットが不要で、完全に構造化データのやり取りに基づいているため、高速で決定性が高くなります。

Playwright Test Agents

Test Agents は、テストを自動的に生成および修復できる、実験的な AI 駆動のテストツールです。

Agent機能トリガー方法
Plannerアプリを自動探索し、Markdown テスト計画を生成LLM Agent 駆動
Generatorテスト計画を Playwright テストコードに変換LLM Agent 駆動
Healerテストスイートを実行し、失敗したテストを自動修復LLM Agent 駆動

Test Agents を初期化します：

# 为 VS Code 初始化
npx playwright init-agents --loop=vscode

# 为 Claude Code 初始化
npx playwright init-agents --loop=claude

コンポーネントテストの概要（実験的）

Playwright は、完全なページ環境を必要とせずに、React/Vue コンポーネントを直接マウントしてテストできます。

実例

test('ボタンコンポーネントテスト', async ({ mount }) => {
  // React コンポーネントをマウント
  const component = await mount(
    <Button title="送信" />
  );

  // コンポーネントに表示されるテキストを検証
  await expect(component).toContainText('送信');

  // ボタンをクリック
  await component.click();
});

アクセシビリティテスト

Playwright は、アクセシビリティ名と説明のアサーションを提供し、ページのアクセシビリティを検証するのに役立ちます。

実例

// 要素に正しいアクセシビリティ名があることを検証
await expect(page.getByRole('button'))
  .toHaveAccessibleName('フォーム送信');

// 要素にアクセシビリティの説明があることを検証
await expect(page.getByLabel('ユーザー名'))
  .toHaveAccessibleDescription('4〜16文字の英数字を入力してください');

他のフレームワークからの移行

Puppeteer からの移行

Playwright と Puppeteer は Chrome DevTools Protocol の機能を共有しているため、移行は比較的簡単です。

PuppeteerPlaywright
puppeteer.launch()chromium.launch()
page.waitForSelector()不要（自動待機）またはpage.locator()
page.$(selector)page.locator(selector)
page.evaluate()page.evaluate()（同じ）
page.setRequestInterception()page.route()

Cypress からの移行

Playwright の Locator の考え方は Cypress のクエリチェーンに似ていますが、いくつかの重要な違いがあります：

CypressPlaywright
cy.get('.class')page.locator('.class')
cy.contains('text')page.getByText('text')
cy.get('[data-cy="btn"]')page.getByTestId('btn')（組み合わせてtestIdAttribute: 'data-cy'）
cy.intercept()page.route()
cy.wait()しない（自動待機）

Selenium からの移行

Selenium は WebDriver プロトコルを使用しますが、Playwright はブラウザプロトコルを直接制御するため、API スタイルの違いが大きいです。

SeleniumPlaywright
driver.findElement(By.id('x'))page.locator('#x')
driver.get(url)page.goto(url)
element.click()locator.click()
WebDriverWait不要（組み込みの自動待機）
new RemoteWebDriver()chromium.connect(url)

移行に関するアドバイス：すべてのテストを一度に移行しようとしないでください。

まず、核心機能を持つ1つまたは2つのテストを Playwright で書き直し、検証が成功したら、残りのテストを段階的に移行します。
