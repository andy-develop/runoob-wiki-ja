ビルダーパターン

ビルダーパターンは作成型デザインパターンの一つで、複雑なオブジェクトを作成する手順と表現方法を分離できるようにします。

ビルダーパターンは作成型デザインパターンの一つで、その主な目的は、複雑なオブジェクトの構築プロセスとその表現を分離し、異なる表現形式を持つオブジェクトを作成できるようにすることです。

概要

意図

複雑な構築プロセスとその表現を分離し、同じ構築プロセスで異なる表現を作成できるようにします。

主な解決

ソフトウェアシステムでは、複雑なオブジェクトの作成は通常、複数の部分で構成されます。これらの部分の組み合わせは頻繁に変化しますが、組み合わせのアルゴリズムは比較的安定しています。

使用するタイミング

一部の基本部品は変わらないが、その組み合わせが頻繁に変化する場合。

解決方法

変化する部分と変化しない部分を分離します。

キーコード

  • ビルダー：インスタンスを作成して提供します。
  • ディレクター：構築されたインスタンスの依存関係を管理し、構築プロセスを制御します。

適用例

  • ケンタッキーを例にとると、ハンバーガー、コーラ、フライドポテト、フライドチキンなどは変わりませんが、その組み合わせは頻繁に変化し、さまざまな「セット」が生成されます。
  • Java におけるStringBuilder。

長所

  • 構築プロセスと表現を分離することで、構築プロセスがより柔軟になり、異なる表現を構築できます。
  • 構築プロセスをより適切に制御でき、具体的な構築の詳細を隠すことができます。
  • コードの再利用性が高く、異なる構築プロセスで同じビルダーを再利用できます。

短所

  • 製品の属性が少ない場合、ビルダーパターンはコードの冗長性を引き起こす可能性があります。
  • システムのクラスとオブジェクトの数が増加します。

使用シーン

  • 生成するオブジェクトが複雑な内部構造を持つ場合。
  • 生成するオブジェクトの内部属性が相互に依存している場合。

注意事項

ファクトリーパターンとの違いは、ビルダーパターンが部品の組み立て順序により重点を置いていることです。

構造

ビルダーパターンには、以下の主要な役割が含まれます：

  • プロダクト（Product）：構築する複雑なオブジェクト。プロダクトクラスには通常、複数の部分または属性が含まれます。

  • 抽象ビルダー（Builder）：製品を構築するための抽象インターフェースを定義し、製品の各部分を構築するメソッドを含みます。

  • 具体ビルダー（Concrete Builder）：抽象ビルダーインターフェースを実装し、製品の各部分の構築方法を具体的に決定し、最終的に構築された製品を返す責任を負います。

  • ディレクター（Director）：ビルダーのメソッドを呼び出して製品を構築する責任を負います。ディレクターは具体的な構築プロセスを理解せず、製品の構築順序と方法のみに関心を持ちます。

実装

ファーストフード店のビジネスケースを想定します。典型的なセットは、ハンバーガー（Burger）と冷たい飲み物（Cold drink）で構成されます。ハンバーガー（Burger）は、ベジバーガー（Veg Burger）またはチキンバーガー（Chicken Burger）で、紙の箱に包まれています。冷たい飲み物（Cold drink）は、コカ・コーラ（coke）またはペプシ（pepsi）で、瓶に入っています。

私たちは、食品アイテム（ハンバーガーや冷たい飲み物など）を表すItemインターフェースと、それを実装するItemエンティティクラス、および食品の包装を表すPackingインターフェースと、それを実装するPackingエンティティクラスを作成します。ハンバーガーは紙の箱に包まれ、冷たい飲み物は瓶に入っています。

次に、私たちはMealクラスを作成します。このクラスにはItemのArrayListと、を組み合わせることでItem異なるタイプのMealオブジェクトを作成するためのMealBuilder。BuilderPatternDemoクラスを使用してMealBuilderを作成しますMeal。

    ビルダーパターンは、生成器パターンとも呼ばれます。複雑な構築とその表現を分離し、同じ構築プロセスで異なる表現を作成できるようにします。

    三つの役割：ビルダー、具体的なビルダー、監督者、使用者（厳密には含めない）

    • ビルダー役割：インスタンスを生成するために必要なすべてのメソッドを定義します；
    • 具体的なビルダー役割：インスタンスを生成するために必要なすべてのメソッドを実装し、最終的に生成されたインスタンスを取得するメソッドを定義します；
    • 監督者役割：ビルダー役割のメソッドを使用してインスタンスを生成するメソッドを定義します；
    • 使用者：ビルダーパターンを使用します。

    注意：定義にある「複雑な構築プロセスとその表現を分離する」というのは、ビルダーがすべてを担当するのではなく、監督者が複雑な構築プロセスを制御（定義）し、それぞれ異なるビルダーが構築プロセスで使用されるすべての構築ステップの実装を担当することを意味します。そうでなければ、「同じ構築プロセスで異なる表現を作成できる」という目標は達成できません。

    ビルダー役割：

    public abstract class Builder {
    public abstract void buildPart1();
    public abstract void buildPart2();
    public abstract void buildPart3();
}

    監督者の役割：

    public class Director {    // 将一个复杂的构建过程与其表示相分离
    private Builder builder;    // 针对接口编程，而不是针对实现编程
    public Director(Builder builder) {
        this.builder = builder;
    }
    public void setBuilder(Builder builder) {
        this.builder = builder;
    }

    public void construct() {   // 控制（定义）一个复杂的构建过程
        builder.buildPart1();
        for (int i = 0; i < 5; i++) {   // 提示：如果想在运行过程中替换构建算法，可以考虑结合策略模式。
            builder.buildPart2();
        }
        builder.buildPart3();
    }
}

    具体的なビルダー役割：

    /**
 * 此处实现了建造纯文本文档的具体建造者。
 * 可以考虑再实现一个建造HTML文档、XML文档，或者其它什么文档的具体建造者。
 * 这样，就可以使得同样的构建过程可以创建不同的表示
 */
public class ConcreteBuilder1 extends Builder {
  private StringBuffer buffer = new StringBuffer();//假设 buffer.toString() 就是最终生成的产品

    @Override
    public void buildPart1() {//实现构建最终实例需要的所有方法
        buffer.append("Builder1 : Part1\n");
    }

    @Override
    public void buildPart2() {
        buffer.append("Builder1 : Part2\n");
    }

    @Override
    public void buildPart3() {
        buffer.append("Builder1 : Part3\n");
    }
    
    public String getResult() {//定义获取最终生成实例的方法
        return buffer.toString();
    }
}

    public class Client {

    from abc import abstractmethod,ABCMeta

# 创建一个表示食物条目和食物包装的接口
class Item(metaclass=ABCMeta):
    @abstractmethod
    def myName(self):
        pass
    @abstractmethod
    def packing(self):
        pass
    @abstractmethod
    def price(self):
        pass

class Packing(metaclass=ABCMeta):
    @abstractmethod
    def pack(self):
        pass

# 实现Packing接口的实体类
class Wrapper(Packing):
    def pack(self):
        return "Wrapper"
class Bottle(Packing):
    def pack(self):
        return "Bottle"

# 实现Item接口的抽象类
class Burger(Item):
    def packing(self):
        return Wrapper()
    @abstractmethod
    def price(self):
        pass

class ColdDrink(Item):
    def packing(self):
        return Bottle()
    @abstractmethod
    def price(self):
        pass

# 创建扩展了Burger和ColdDrink的实体类
class VegBurger(Burger):
    def price(self):
        return 25.0
    def myName(self):
        return "Veg Burger"

class ChickenBurger(Burger):
    def price(self):
        return 50.5
    def myName(self):
        return "Chicken Burger"

class Coke(ColdDrink):
    def price(self):
        return 30.0
    def myName(self):
        return "Coke"

class Pepsi(ColdDrink):
    def price(self):
        return 35.0
    def myName(self):
        return "Pepsi"

# 设计一个Meal类，带有上面定义的对象
class Meal():
    __items = []
    
    #注意初始化，否则类变量会被重用
    def __init__(self):
        self.__items = []

    def addItem(self, aItem):
        self.__items.append(aItem)

    def getCost(self):
        mySum = 0
        for myCost in self.__items:
            mySum = mySum + myCost.price()
        return mySum

    def showItems(self):
        for myItem in self.__items:
            print("Item : %s , Packing : %s , Price : %5.2f" %(myItem.myName(), myItem.packing().pack(), myItem.price()))

# 设计一个MealBuilder类，负责创建Meal对象
class MealBuilder():
    def prepareVegmeal(self):
        meal = Meal()
        meal.addItem(VegBurger())
        meal.addItem(Coke())
        return meal

    def prepareNonVegMeal(self):
        meal = Meal()
        meal.addItem(ChickenBurger())

        meal.addItem(Pepsi())
        return meal

# 输出

    ビルダーパターンは、複雑な構造を持つオブジェクトを作成する必要があり、オブジェクトの作成プロセスが複数のステップやパラメータに関わる場合に適しています。ビルダーパターンを使用することで、オブジェクトの構築プロセスを分離でき、同じ構築プロセスで異なるオブジェクト表現を作成できます。

    ビルダーパターンには、次の主要な役割が含まれます：

    • 製品（Product）：構築される複雑なオブジェクトを表します。複数の部品やパーツを含み、これらの部品は異なる型でも構いませんが、全体として1つの完全なオブジェクトを構成します。
    • 抽象ビルダー（Builder）：製品の各部分を作成するための抽象インターフェースを定義します。通常、各部分を作成するメソッドを含み、最終的に構築された製品を返すことができます。
    • 具象ビルダー（Concrete Builder）：抽象ビルダーインターフェースを実装し、製品の各部分の構築メソッドを具体的に実装します。製品の各部分を組み立て、製品の具体的な構築ロジックを実現する役割を担います。
    • ディレクター（Director）：ビルダーのメソッドを呼び出し、構築プロセスの順序とロジックを制御します。製品を直接作成するのではなく、ビルダーのメソッドを呼び出すことで製品を構築します。

    以下は、ビルダーパターンを使用して自動車オブジェクトを構築する方法を示す簡単な例です：

    // 产品类
public class Car {
    private String brand;
    private String color;
    // 其他属性...

    public void setBrand(String brand) {
        this.brand = brand;
    }

    public void setColor(String color) {
        this.color = color;
    }

    // 其他方法...
}

// 抽象建造者
public interface CarBuilder {
    void setBrand(String brand);
    void setColor(String color);
    Car build();
}

// 具体建造者
public class SedanCarBuilder implements CarBuilder {
    private Car car;

    public SedanCarBuilder() {
        this.car = new Car();
    }

    public void setBrand(String brand) {
        car.setBrand(brand);
    }

    public void setColor(String color) {
        car.setColor(color);
    }

    public Car build() {
        return car;
    }
}

// 指挥者
public class CarDirector {
    private CarBuilder builder;

    public CarDirector(CarBuilder builder) {
        this.builder = builder;
    }

    public Car constructCar(String brand, String color) {
        builder.setBrand(brand);
        builder.setColor(color);
        return builder.build();
    }
}

// 使用示例
public class Main {
    public static void main(String[] args) {
        CarBuilder builder = new SedanCarBuilder();
        CarDirector director = new CarDirector(builder);

        Car car = director.constructCar("Toyota", "Red");

        System.out.println(car);
    }
}

    上記の例では、製品クラス Car、抽象ビルダーインターフェース CarBuilder、具象ビルダー SedanCarBuilder、およびディレクター CarDirector を定義しました。ディレクターが具象ビルダーのメソッドを呼び出すことで、一定の順序に従って自動車オブジェクトを構築します。

    package BuilderPattern;

public class Computer {
    private String CPU;
    private String Disk;
    private String Memory;
    private String GPU;
    private String MainBoard;

    @Override
    public String toString() {
        return "Computer{" +
                "CPU='" + CPU + '\'' +
                ", Disk='" + Disk + '\'' +
                ", Memory='" + Memory + '\'' +
                ", GPU='" + GPU + '\'' +
                ", MainBoard='" + MainBoard + '\'' +
                '}';
    }

    private Computer(ComputerBuilder cb){
        this.CPU= cb.CPU;
        this.Disk= cb.Disk;
        this.Memory= cb.Memory;
        this.GPU= cb.GPU;
        this.MainBoard= cb.MainBoard;
    }

    public static class ComputerBuilder{
        private String CPU;
        private String Disk;
        private String Memory;
        private String GPU;
        private String MainBoard;

        public ComputerBuilder setCPU(String CPU) {
            this.CPU = CPU;
            return this;
        }

        public ComputerBuilder setDisk(String disk) {
            Disk = disk;
            return this;
        }

        public ComputerBuilder setMemory(String memory) {
            Memory = memory;
            return this;
        }

        public ComputerBuilder setGPU(String GPU) {
            this.GPU = GPU;
            return this;
        }

        public ComputerBuilder setMainBoard(String mainBoard) {
            MainBoard = mainBoard;
            return this;
        }
        public Computer createComputer(){
            return new Computer(this);
        }
    }
}
