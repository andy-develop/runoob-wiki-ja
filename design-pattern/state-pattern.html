ステートパターン

ステートパターン（State Pattern）では、クラスの動作はその状態に基づいて変化します。このタイプのデザインパターンは振る舞い型パターンに属します。

ステートパターンでは、さまざまな状態を表すオブジェクトと、状態オブジェクトの変更に応じて動作が変わる context オブジェクトを作成します。

ステートパターンは、オブジェクトが内部状態の変化に応じてその動作を変更できるようにし、異なる状態で異なる動作を示すようにします。各状態を独立したクラスにカプセル化することで、状態遷移を実装するための大量の条件文を回避できます。

紹介

意図

オブジェクトがその内部状態の変化に応じて動作を変更できるようにし、あたかもクラスが変わったかのように見せます。

主に解決する問題

  • ステートパターンは、オブジェクトの動作がその状態に依存する問題を解決し、状態が変化したときにオブジェクトが動作を切り替えられるようにします。

使用シーン

  • コード内に大量の条件文が存在し、それらの条件文がオブジェクトの状態に依存している場合。

実装方法

  • 状態インターフェースを定義する：1つ以上のメソッドを宣言し、具体的な状態の動作をカプセル化します。
  • 具象状態クラスを作成する：状態インターフェースを実装し、状態に応じて具体的な動作を実装します。
  • コンテキストクラスを定義する：状態オブジェクトの参照を保持し、状態が変化したときにその動作を更新します。

重要なコード

  • 状態インターフェース：動作メソッドを宣言します。
  • 具象状態クラス：状態インターフェースを実装し、具体的な動作をカプセル化します。
  • コンテキストクラス：状態オブジェクトを保持し、その状態を変更するためのメソッドを提供します。

応用例

  • バスケットボール選手の状態：選手には通常、異常、超常などの状態があります。
  • 曽侯乙編鐘：編鐘をコンテキストとして、異なる鐘（状態）は異なる演奏効果を持ちます。

長所

  • 状態遷移ルールをカプセル化する：状態遷移ロジックを状態オブジェクト内部にカプセル化します。
  • 拡張が容易：新しい状態クラスを追加しても、既存のコードに影響を与えません。
  • 状態に関連する動作の集中化：特定の状態に関連するすべての動作を1つのクラスに集中させます。
  • 条件文の簡素化：動作を切り替えるために大量の条件文を使用することを避けます。
  • 状態の共有：複数のコンテキストオブジェクトが同じ状態オブジェクトを共有できるようにします。

短所

  • クラスとオブジェクトの数が増加する：各状態に具象状態クラスが必要です。
  • 実装が複雑：パターンの構造と実装が比較的複雑です。
  • 開放閉鎖原則のサポートが不十分：新しい状態の追加や状態の動作の変更には、既存のコードの修正が必要になる場合があります。

使用上のアドバイス

  • オブジェクトの動作が状態の変化に応じて変わる場合は、ステートパターンの使用を検討してください。
  • ステートパターンは、複雑な条件文や分岐文の代替に適しています。

注意事項

  • ステートパターンは、状態の数が有限（通常5つ以下）の場合に適しています。
  • システムが過度に複雑にならないよう、慎重に使用してください。

構造

ステートパターンには、以下の主要な役割が含まれます。

  • コンテキスト（Context）：クライアントが関心を持つインターフェースを定義し、現在の状態オブジェクトへの参照を保持します。コンテキストは状態オブジェクトを介して状態に関連する動作の処理を委譲できます。

  • 状態（State）：コンテキストに関連するある状態の動作をカプセル化するためのインターフェースを定義します。

  • 具象状態（Concrete State）：状態インターフェースを実装し、その状態に関連する動作の処理を担当します。具象状態オブジェクトは通常、内部にコンテキストオブジェクトへの参照を保持し、さまざまな条件に応じて異なる状態に切り替えられるようにします。

    # State Pattern with Python Code
from abc import abstractmethod,ABCMeta

# 创建State接口
class State(metaclass=ABCMeta):
    @abstractmethod
    def doAction(self,inContext):
        pass

# 创建实现State接口的实体类
class step1State(State):
    def doAction(self,inContext):
        if inContext.contextState != "Step1" :
            inContext.setState(step2State())
            inContext.doSomething()
        else :
            print("Player is in : Step1 state")

class step2State(State):
    def doAction(self,inContext):
        if inContext.contextState != "Step2" :
            inContext.setState(step3State())
            inContext.doSomething()
        else :
            print("Player is in : Step2 state")

class step3State(State):
    def doAction(self,inContext):
        if inContext.contextState != "Step3" :
            print("State wrong， Over！")
        else :
            print("Player is in : Step3 state")

# 创建Context类
class Context():
    _aState = None
    contextState = ""

    def __init__(self):
        self._aState = step1State()
        contextState = "Step1"
    def setState(self, inState):
        self._aState = inState
    def getState(self):
        return self._aState
    def doSomething(self):
        self._aState.doAction(self)

# 调用输出
if __name__ == '__main__':
    aContext = Context()
    aContext.contextState = "Step1"
    aContext.doSomething()

    起動 シャットダウン 再生

    起動中 不可 可 可

    シャットダウン中 可 不可 不可

    再生中 不可 可 不可

    状態を抽象化しても、それは computer の属性にすぎず、switch を書かなくても拡張しやすいというだけです。状態の変化は必ず computer 自身の動作に由来します。OO（オブジェクト指向）の考え方から見ると、呼び出し側は状態 state のAPIを見えないようにすべきです。

    状態間は分離されていないからこそ、状態パターンは「開放閉鎖の原則」へのサポートがあまり良くないと言われます。

    状態パターンではクラスが状態を持ち、状態の変更によってクラス全体の動作が変わります。

    ストラテジーは状態を持たず、ストラテジーの選択はクライアント側で決定されます。

    public class StateTest {
    public static void main(String[] args) {
        System.out.println("=====状态模式=====");
        TrafficLight light = new TrafficLight(ColorEnum.GREEN);
        for (int i = 0; i < 4; i++) {
            System.out.println("当前状态[" + light.getState() + "]");
            light.forward();
        }
    }
}
/* 抽象状态类 */
interface LightColor {
    void forward(TrafficLight light); // 向前转换
}
/* 具体状态枚举类 */
enum ColorEnum implements LightColor {
    GREEN {
        public void forward(TrafficLight light) {
            System.out.println("向前转换: 绿灯 => 黄灯");
            light.setState(ColorEnum.YELLOW); // 状态切换为黄灯        
        }
        public String toString() {
            return "绿灯@" + this.hashCode();
        }
    },
    YELLOW {
        public void forward(TrafficLight light) {
            System.out.println("向前转换: 黄灯 => 红灯");
            light.setState(ColorEnum.RED); // 状态切换为红灯
        }
        public String toString() {
        return "黄灯@" + this.hashCode();
        }
    },
    RED {
        public void forward(TrafficLight light) {
            System.out.println("向前转换: 红灯 => 绿灯");
            light.setState(ColorEnum.GREEN); // 状态切换为绿灯       
        }
        public String toString() {
            return "红灯@" + this.hashCode();
        }
    };
    public void forward(TrafficLight light) {
        throw new UnsupportedOperationException("Invalid forward!");
    }
}
/* 主题类 */
class TrafficLight {
    private LightColor color;
    // 维持一个对抽象状态对象的引用   
    public TrafficLight(LightColor color) {
        this.color = color;
    }
    // 设置状态对象    
    public void setState(LightColor color) {
        this.color = color;
    }
    // 获取当前状态对象    
    public LightColor getState() {
        return color;
    }
    public void forward() {
        color.forward(this);
    }
}
