プロキシパターン

プロキシパターン（Proxy Pattern）では、あるクラスが別のクラスの機能を代表します。このタイプのデザインパターンは構造型パターンに分類されます。

プロキシパターンは、プロキシオブジェクトを導入することで元のオブジェクトへのアクセスを制御します。プロキシオブジェクトはクライアントとターゲットオブジェクトの間で仲介役となり、クライアントのリクエストをターゲットオブジェクトに転送し、リクエストの転送前後に追加の処理を行うことができます。

プロキシパターンでは、既存のオブジェクトを持つオブジェクトを作成し、外部に機能インターフェースを提供します。

はじめに

意図

他のオブジェクトにプロキシを提供し、そのオブジェクトへのアクセスを制御します。

主な解決課題

  • プロキシパターンは、オブジェクトを直接アクセスする際に発生し得る問題、例えばオブジェクト生成コストが高い、セキュリティ制御やリモートアクセスが必要などの問題を解決します。

使用シーン

  • オブジェクトにアクセスする際に何らかの制御や追加処理が必要な場合。

実装方法

  • 中間層を追加する：プロキシクラスを作成し、実際のオブジェクトの中間層とします。
  • プロキシと実際のオブジェクトの組み合わせ：プロキシクラスは実際のオブジェクトへの参照を保持し、アクセス時に制御を行います。

キーコード

  • プロキシクラス：実際のオブジェクトと同じインターフェースを実装し、追加の制御ロジックを加えます。
  • 実際のオブジェクト：実際にタスクを実行するオブジェクト。

応用例

  • ショートカット：Windowsシステムのショートカットは、ファイルやプログラムのプロキシとして機能します。
  • なりすまし：孫悟空が高翠蘭のプロキシとなり、猪八戒は見分けられません。
  • 代理販売店：電車の切符を購入する際、代理販売店が駅のプロキシとして機能します。
  • 小切手：銀行口座の資金のプロキシとして、資金へのアクセスを制御します。
  • Spring AOP：プロキシパターンを使用してアスペクト指向プログラミングを実現します。

利点

  • 責任の分離：プロキシパターンはアクセス制御とビジネスロジックを分離します。
  • 拡張性：追加の機能や制御を柔軟に追加できます。
  • インテリジェント化：遅延ロードやキャッシュなど、アクセスリクエストをインテリジェントに処理できます。

欠点

  • パフォーマンスオーバーヘッド：プロキシ層が追加されることで、リクエストの処理速度に影響を与える可能性があります。
  • 実装の複雑さ：一部のタイプのプロキシパターンは実装が複雑になる場合があります。

使用上のアドバイス

  • 具体的なニーズに応じて、リモートプロキシ、仮想プロキシ、保護プロキシなどの適切なプロキシタイプを選択してください。
  • クライアントが透過的にプロキシを使用できるように、プロキシクラスと実際のオブジェクトのインターフェースを一致させてください。

注意事項

  • アダプターパターンとの違い：アダプターパターンはインターフェースを変更しますが、プロキシパターンはインターフェースを変更しません。
  • デコレーターパターンとの違い：デコレーターパターンは機能の拡張に使用され、プロキシパターンはアクセス制御に使用されます。

構造

主に以下のコアロールが関与します：

  • 抽象テーマ（Subject）:

    • 実際のテーマとプロキシテーマの共通インターフェースを定義します。これにより、実際のテーマを使用するあらゆる場所でプロキシテーマを使用できます。

  • 実際のテーマ（Real Subject）:

    • 抽象テーマインターフェースを実装し、プロキシオブジェクトが表す実際のオブジェクトです。クライアントは実際のテーマに直接アクセスしますが、特定の状況ではプロキシテーマを介して間接的にアクセスできます。

  • プロキシ（Proxy）:

    • 抽象テーマインターフェースを実装し、実際のテーマへの参照を保持します。プロキシテーマは通常、実際のテーマに基づいて、遅延ロード、権限制御、ログ記録などの追加機能を提供します。

  • クライアント（Client）:

    • 抽象テーマインターフェースを使用して実際のテーマまたはプロキシテーマを操作し、具体の実装クラスがどれであるかを知る必要はありません。

実装

以下を作成します：Imageインターフェースと、それを実装したImageインターフェースのエンティティクラス。ProxyImageプロキシクラスであり、削減しますRealImageオブジェクトの読み込みによるメモリ消費。

ProxyPatternDemoクラスは使用しますProxyImageを使用して、読み込むImageオブジェクトを取得し、必要に応じて表示します。

ステップ 1

インターフェースを作成します。

Image.java

public interface Image { void display(); }

ステップ 2

インターフェースを実装するエンティティクラスを作成します。

RealImage.java

public class RealImage implements Image { private String fileName; public RealImage(String fileName){ this.fileName = fileName; loadFromDisk(fileName); } @Override public void display() { System.out.println("Displaying " + fileName); } private void loadFromDisk(String fileName){ System.out.println("Loading " + fileName); } }

ProxyImage.java

public class ProxyImage implements Image{ private RealImage realImage; private String fileName; public ProxyImage(String fileName){ this.fileName = fileName; } @Override public void display() { if(realImage == null){ realImage = new RealImage(fileName); } realImage.display(); } }

リクエストされたとき、使用しますProxyImageを使用して取得しますRealImageクラスのオブジェクト。

ProxyPatternDemo.java

    JDK 標準の動的プロキシ

    • java.lang.reflect.Proxy: 動的プロキシクラスとオブジェクトを生成します；
    • java.lang.reflect.InvocationHandler（ハンドラインターフェース）：invokeメソッドを通じて

    実際のロールへのプロキシアクセスを実現できます。

    Proxy を介して生成されたプロキシクラスオブジェクトは、毎回対応するハンドラオブジェクトを指定する必要があります。

    コード：

    a) インターフェース：Subject.java

    **
 * @author gnehcgnaw
 * @date 2018/11/5 19:29
 */
public interface Subject {
    public int sellBooks();

    public String speak();
}

    b) 実際のオブジェクト：RealSubject.java

    /**
 * @author gnehcgnaw
 * @date 2018/11/5 18:54
 */
public class RealSubject implements Subject{
    @Override
    public int sellBooks() {
        System.out.println("卖书");
        return 1 ;
    }

    @Override
    public String speak() {
        System.out.println("说话");
        return "张三";
    }
}

    c) ハンドラオブジェクト：MyInvocationHandler.java

    import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;

/**
 * 定义一个处理器
 * @author gnehcgnaw
 * @date 2018/11/5 19:26
 */
public class MyInvocationHandler implements InvocationHandler {
    /**
     * 因为需要处理真实角色，所以要把真实角色传进来
     */
    Subject realSubject ;

    public MyInvocationHandler(Subject realSubject) {
        this.realSubject = realSubject;
    }

    /**
     *
     * @param proxy    代理类
     * @param method    正在调用的方法
     * @param args      方法的参数
     * @return
     * @throws Throwable
     */
    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("调用代理类");
        if(method.getName().equals("sellBooks")){
            int invoke = (int)method.invoke(realSubject, args);
            System.out.println("调用的是卖书的方法");
            return invoke ;
        }else {
            String string = (String) method.invoke(realSubject,args) ;
            System.out.println("调用的是说话的方法");
            return  string ;
        }
    }
}

    d) 呼び出し側：Main.java

    import java.lang.reflect.Proxy;

/**
 * 调用类
 * @author gnehcgnaw
 * @date 2018/11/7 20:26
 */
public class Client {
    public static void main(String[] args) {
        //真实对象
        Subject realSubject =  new RealSubject();

        MyInvocationHandler myInvocationHandler = new MyInvocationHandler(realSubject);
        //代理对象
        Subject proxyClass = (Subject) Proxy.newProxyInstance(ClassLoader.getSystemClassLoader(), new Class[]{Subject.class}, myInvocationHandler);

        proxyClass.sellBooks();

        proxyClass.speak();
    }
}

    Cglib動的プロキシは、プロキシ対象のクラスに対して、サブクラスを動的に生成し、そのサブクラスがプロキシクラスのメソッドをオーバーライドします。private や final で修飾されたメソッドはオーバーライドされません。

    CGLIBは、強力で高性能なコード生成パッケージです。インターフェースを実装していないクラスにプロキシを提供し、JDKの動的プロキシを補完します。通常はJavaの動的プロキシを使用してプロキシを作成できますが、プロキシ対象のクラスがインターフェースを実装していない場合や、より良いパフォーマンスが必要な場合は、CGLIBが良い選択肢です。

    CGLIBはオープンソースプロジェクトであり、コードはgithubでホストされています。アドレスは次のとおりです：https://github.com/cglib/cglib

    プロキシが必要なクラス:

    package cn.cpf.pattern.structure.proxy.cglib;
public class Engineer {
    // 可以被代理
    public void eat() {
        System.out.println("工程师正在吃饭");
    }

    // final 方法不会被生成的字类覆盖
    public final void work() {
        System.out.println("工程师正在工作");
    }

    // private 方法不会被生成的字类覆盖
    private void play() {
        System.out.println("this engineer is playing game");
    }
}

    CGLIB プロキシクラス:

    package cn.cpf.pattern.structure.proxy.cglib;

import net.sf.cglib.proxy.Enhancer;
import net.sf.cglib.proxy.MethodInterceptor;
import net.sf.cglib.proxy.MethodProxy;
import java.lang.reflect.Method;

public class CglibProxy implements MethodInterceptor {
    private Object target;

    public CglibProxy(Object target) {
        this.target = target;
    }

    @Override
    public Object intercept(Object o, Method method, Object[] objects, MethodProxy methodProxy) throws Throwable {
        System.out.println("###   before invocation");
        Object result = method.invoke(target, objects);
        System.out.println("###   end invocation");
        return result;
    }

    public static Object getProxy(Object target) {
        Enhancer enhancer = new Enhancer();
        // 设置需要代理的对象
        enhancer.setSuperclass(target.getClass());
        // 设置代理人
        enhancer.setCallback(new CglibProxy(target));
        return enhancer.create();
    }
}

    テストメソッド:

    import java.lang.reflect.Method;
import java.util.Arrays;

public class CglibMainTest {
    public static void main(String[] args) {
        // 生成 Cglib 代理类
        Engineer engineerProxy = (Engineer) CglibProxy.getProxy(new Engineer());
        // 调用相关方法

    }
}

    Python パターン：

    # Proxy Pattern with Python Code
rom abc import  abstractmethod,ABCMeta

# 定义Image接口
class Image(metaclass=ABCMeta):
    @abstractmethod
    def display(self):
        pass
# 实现Image的实体类：RealImage，ProxyImage类
class RealImage(Image):
    _strFilename = ""
    def __init__(self,inFilename):
        self._strFilename = inFilename
        self.loadFromDisk(inFilename)
    def display(self):
        print("Displaying "+self._strFilename)
    def loadFromDisk(self,inFilename):
        print("Loadng "+ inFilename)

class ProxyImage(Image):
    _realImage = None
    _strFilename = ""
    def __init__(self,inFilename):
        self._strFilename = inFilename
    def display(self):
        if self._realImage is None:
            self._realImage = RealImage(self._strFilename)
        self._realImage.display()

# 调用输出
if __name__ == '__main__':
    aImage = ProxyImage("test_10mb.jpg")
    #图片将从磁盘加载
    aImage.display()
    print("")
    #图片不需要从磁盘加载
    aImage.display()

    public Image

    プロキシパターンの応用：

    1. リモートプロキシ：オブジェクトが異なるアドレス空間に存在する事実を隠すために、異なるアドレス空間でそのオブジェクトのローカルな代表を提供します。

    2. 仮想プロキシ：必要に応じてコストの高いオブジェクトを作成し、インスタンス化に時間がかかる実際のオブジェクトを格納することで、パフォーマンスを最適化します。（例：大きなHTMLファイルを開くとき、そこには多くのテキストや画像が含まれているかもしれませんが、それでも素早く開くことができます。そのとき表示されるのはすべてのテキストで、画像は1枚ずつダウンロードされてから表示されます。まだ開かれていない画像ボックスは、実際の画像の代わりに仮想プロキシが使用されています。）（ブラウザはこのプロキシパターンを使用してダウンロードを最適化しています）

    3. 保護プロキシ：実際のオブジェクトにアクセスする際の権限を制御するために使用します。通常、オブジェクトごとに異なるアクセス権限が必要な場合に使用されます。

    4. スマートリファレンス：実際のオブジェクトを呼び出すときに、プロキシが他の処理を行います。（例：実際のオブジェクトの参照回数を計算し、そのオブジェクトへの参照がなくなったら自動的に解放します。永続オブジェクトが最初に参照されたときにメモリにロードします。または、実際のオブジェクトにアクセスする前に、他のオブジェクトが変更できないようにロックされているかどうかを確認します。これらはすべて、オブジェクトにアクセスする際にプロキシが付加する内部処理です。）
