MVC パターン

MVC パターンは Model-View-Controller（モデル-ビュー-コントローラ）パターンを表します。このパターンはアプリケーションの階層開発に使用されます。

  • Model（モデル）- モデルはデータにアクセスするオブジェクトまたは JAVA POJO を表します。データが変化したときにコントローラを更新するロジックを持つこともあります。
  • View（ビュー）- ビューはモデルが含むデータの可視化を表します。
  • Controller（コントローラ）- コントローラはモデルとビューに作用します。データがモデルオブジェクトへ流れるのを制御し、データが変化したときにビューを更新します。ビューとモデルを分離します。

概要

意図

アプリケーションをモデル（Model）、ビュー（View）、コントローラ（Controller）の3つのコアコンポーネントに分割し、関心事の分離を実現します。

解決する主な問題

  • アプリケーションにおけるビジネスロジック、データ、画面表示の結合の問題を解決し、開発と保守をより明確かつ簡単にします。

使用シーン

  • データ、ビジネスロジック、画面表示を分離して、独立して開発・保守する必要がある場合。

実装方法

  • モデル（Model）：データとビジネスロジックを担当し、通常はデータの保存、検索、ビジネスルールを含みます。
  • ビュー（View）：データ（モデル）を表示するユーザーインターフェースを担当し、ビジネスロジックは含みません。
  • コントローラ（Controller）：ユーザーの入力を受け取り、モデルとビューを呼び出してユーザーのリクエストを完了します。

キーコード

  • モデル：ビジネスロジックとデータ状態を含みます。
  • ビュー：表示ロジックを含み、モデルのデータをユーザーインターフェースにレンダリングします。
  • コントローラ：ユーザー入力に応答してモデルとビューを更新するロジックを含みます。

応用例

  • Webアプリケーション：ユーザーがブラウザ（ビュー）を通じてリクエストを送信し、サーバー側のコントローラがリクエストを処理し、モデルがデータ処理を行います。

利点

  • 関心事の分離：データ、ビジネスロジック、画面表示を分離し、結合度を低減します。
  • 保守が容易：各コンポーネントが特定のタスクを担当するため、個別に開発・保守しやすいです。
  • 拡張性：モデル、ビュー、コントローラを個別に置き換えたり更新したりできます。

欠点

  • 複雑性が増す可能性：単純なプロジェクトでは、MVCを導入することで不要な複雑性が増す可能性があります。
  • パフォーマンスの問題：正しく使用しないと、パフォーマンスの問題を引き起こす可能性があります。

使用上のアドバイス

  • 大規模なアプリケーションを開発し、データ、ビジネスロジック、ユーザーインターフェースを明確に分離する必要がある場合は、MVCパターンの使用を検討してください。

注意事項

  • モデル、ビュー、コントローラ間のやり取りを明確にし、相互依存を避けてください。

含まれる主な役割

  • モデル（Model）：

    • データとビジネスロジックを管理します。

  • ビュー（View）：

    • モデルのデータを表示し、ユーザーインターフェースを提供します。

  • コントローラ（Controller）：

    • ユーザー入力を受け取り、モデルとビューを呼び出して処理します。

  • ユーザー（User）（オプション）：

    • ビューと対話し、アプリケーションのフローをトリガーします。

StudentView.java

コントローラを作成します。

StudentController.java

public class StudentController { private Student model; private StudentView view; public StudentController(Student model, StudentView view){ this.model = model; this.view = view; } public void setStudentName(String name){ model.setName(name); } public String getStudentName(){ return model.getName(); } public void setStudentRollNo(String rollNo){ model.setRollNo(rollNo); } public String getStudentRollNo(){ return model.getRollNo(); } public void updateView(){ view.printStudentDetails(model.getName(), model.getRollNo()); } }

    Kotlin で MVC を実装：Kotlin のデータクラスを利用して model 層を実装し、標準ライブラリ関数を使用して構造をより直感的にします。

    /**
 * 数据类Modal
 */
data class Student(private var name: String, private var age: Int) {
 
    fun getName(): String = this.name
    fun setName(newName: String) = { name = newName }()
    fun getAge(): Int = this.age
    fun setAge(newAge: Int) = { age = newAge }()
}
 
/**
 * 视图层 View
 */
class View {
 
    fun showView(name: String, age: Int) = println("name:$name,age:$age")
}
 
/**
 * 控制器 Controller
 */
class Controller(private var view: View, private var modal: Student) {
 
    fun setName(newName: String) = modal.setName(newName)
    fun setAge(newAge: Int) = modal.setAge(newAge)
    fun getName(): String = modal.getName()
    fun getAge(): Int = modal.getAge()
    fun updateView() {
        println("更新视图:------------")
        view.showView(modal.getName(), modal.getAge())
    }
 
}
 
/**
 * kotlin MVC模式
 * @author IWH
 * android默认的开发模式就是MVC，activity属于控制器负责XML与Modal的处理
 */
fun main() {
    val view = View()
    val modal = Student("iwh", 20)
    val controller = Controller(view, modal)
    view.showView(controller.getName(), controller.getAge())
    controller.setAge(21)
    controller.setName("jack")
    controller.updateView()
    main2()
 
 
}
 
/**
 * 使用kotlin特性
 */
fun main2() {
    View().apply outer@{
        Student("iwh", 20).apply inner@{
            with(Controller(this@outer, this@inner)) last@{
                this@outer.showView(this.getName(), this.getAge())
                setName("jack")
                setAge(21)
                updateView()
            }
        }
    }
}
