ブリッジパターン

ブリッジ（Bridge）は抽象化と実装の結合を分離し、両者が独立して変化できるようにするためのものです。このタイプのデザインパターンは構造型パターンに属し、抽象化と実装の間のブリッジ構造を提供することで、両者の結合を分離します。

このパターンはブリッジとなるインターフェースを関与させ、エンティティクラスの機能がインターフェース実装クラスから独立するようにします。この2種類のクラスは互いに影響を与えることなく構造的に変更できます。

ブリッジパターンの目的は、抽象と実装を分離し、それらが独立して変化できるようにすることです。このパターンは、オブジェクトの抽象部分と実装部分を分離することで、それらを独立して変更できるようにします。継承ではなく、合成（コンポジション）の方法で抽象部分と実装部分を結び付けます。

以下の例でブリッジパターンの使い方を示します。ここでは、同じ抽象クラスのメソッドでも異なるブリッジ実装クラスを使用して、異なる色の円を描くことができます。

紹介

意図

抽象部分と実装部分を分離し、それらが独立して変化できるようにするために使用されます。。

主に解決する問題

継承の使用によるクラス爆発問題を回避し、より柔軟な拡張方法を提供します。

使用シーン

システムが複数の観点から分類される可能性があり、各観点が独立して変化する可能性がある場合、ブリッジパターンが適しています。

実装方法

  • 多角的な分類の分離：異なる観点の分類ロジックを分離し、それらが独立して変化できるようにします。
  • 結合の低減：抽象と実装の間の結合度を低減します。

キーコード

  • 抽象クラス：システムの一部として抽象クラスを定義します。
  • 実装クラス：1つ以上の実装クラスを定義し、抽象クラスと継承ではなく集約によって関連付けます。

応用例

  • 転生：魂（抽象）と肉体（実装）の分離により、魂が異なる肉体を選択できます。
  • 壁のスイッチ：スイッチ（抽象）と内部実装（実装）の分離により、ユーザーはスイッチの内部動作メカニズムを気にする必要がありません。

利点

  • 抽象と実装の分離：システムの柔軟性と保守性を向上させます。
  • 拡張性が高い：抽象と実装を独立して拡張できます。
  • 実装の詳細が透過的：ユーザーは実装の詳細を理解する必要がありません。

欠点

  • 理解と設計の難しさ：ブリッジパターンはシステムの理解と設計の難しさを増大させます。
  • 集約関連：開発者は抽象層で設計とプログラミングを行う必要があります。

使用上の提案

  • システムが抽象化ロールと具体化ロールの間に柔軟性を追加する必要がある場合は、ブリッジパターンの使用を検討してください。
  • 継承を使用したくない、または多層継承によるクラス数の急激な増加が見られるシステムには、ブリッジパターンが特に適しています。
  • クラスに独立して変化する2つの次元があり、その両方の次元を拡張する必要がある場合は、ブリッジパターンを使用します。

注意事項

  • ブリッジパターンは、独立して変化する2つの次元に適用され、それらが独立して拡張および変化できることを保証します。

構造

以下はブリッジパターンのいくつかの主要な役割です：

  • 抽象（Abstraction）：抽象インターフェースを定義し、通常は実装インターフェースへの参照を含みます。
  • 拡張抽象（Refined Abstraction）：抽象の拡張であり、抽象クラスのサブクラスまたは具体的な実装クラスにすることができます。
  • 実装（Implementor）：実装インターフェースを定義し、基本操作のインターフェースを提供します。
  • 具体的実装（Concrete Implementor）：実装インターフェースを実装する具体的なクラスです。

実装

ブリッジ実装として、DrawAPIインターフェースと、実装したDrawAPIインターフェースのエンティティクラスRedCircle、GreenCircle。Shapeは抽象クラスであり、使用するDrawAPIオブジェクト。BridgePatternDemoクラスは使用するShapeクラスを使用して異なる色の円を描きます。

ステップ 1

ブリッジ実装インターフェースを作成します。

DrawAPI.java

public interface DrawAPI { public void drawCircle(int radius, int x, int y); }

ステップ 2

実装したものを作成しますDrawAPIインターフェースのエンティティブリッジ実装クラス。

RedCircle.java

public class RedCircle implements DrawAPI { @Override public void drawCircle(int radius, int x, int y) { System.out.println("Drawing Circle[ color: red, radius: " + radius +", x: " +x+", "+ y +"]"); } }

GreenCircle.java

public class GreenCircle implements DrawAPI { @Override public void drawCircle(int radius, int x, int y) { System.out.println("Drawing Circle[ color: green, radius: " + radius +", x: " +x+", "+ y +"]"); } }

ステップ 3

使用するDrawAPIインターフェースで抽象クラスを作成しますShape。

Shape.java

public abstract class Shape { protected DrawAPI drawAPI; protected Shape(DrawAPI drawAPI){ this.drawAPI = drawAPI; } public abstract void draw(); }

ステップ 4

実装したものを作成しますShape抽象クラスのエンティティクラス。

Circle.java

public class Circle extends Shape { private int x, y, radius; public Circle(int x, int y, int radius, DrawAPI drawAPI) { super(drawAPI); this.x = x; this.y = y; this.radius = radius; } public void draw() { drawAPI.drawCircle(radius,x,y); } }

ステップ 5

使用するShapeとDrawAPIクラスで異なる色の円を描きます。

BridgePatternDemo.java

public class BridgePatternDemo { public static void main(String[] args) { Shape redCircle = new Circle(100,100, 10, new RedCircle()); Shape greenCircle = new Circle(100,100, 10, new GreenCircle()); redCircle.draw(); greenCircle.draw(); } }

ステップ 6

プログラムを実行し、結果を出力します：

Drawing Circle[ color: red, radius: 10, x: 100, 100]
Drawing Circle[  color: green, radius: 10, x: 100, 100]

    ブリッジパターン：Bridge Pattern

    抽象と実装を2つの異なるクラス階層に置き、それらが独立して変化できるようにする。——『Head First デザインパターン』

    クラスの機能階層構造と実装階層構造を分離する，両者が独立して変化できるようにする，そして両者の間に橋を架け、ブリッジを実現する。——『図解デザインパターン』

    クラスの機能階層構造：親クラスは基本機能を持ち、子クラスで新しい機能を追加します；

    クラスの実装階層構造：親クラスは抽象メソッドを宣言してインターフェースを定義し、子クラスは具体的なメソッドを実装してインターフェースを実装します；

    ブリッジパターンには4つの役割があります：

    抽象化ロール：実装者ロールが提供するインターフェースを使用して基本機能インターフェースを定義します。

    実装者ロールを保持し、機能インターフェース内でそれに委譲することで、橋を架ける役割を果たします；

    注意：抽象化ロールは、それが抽象クラスであることを意味するのではなく、実装を抽象化したものを指します。

    改善された抽象化ロール：抽象化ロールのサブクラスとして、新しい機能、つまり新しいインターフェース（メソッド）を追加します；それとクラスの機能階層構造を構成します；

    実装者ロール：抽象化ロールのためのインターフェースを提供します；それは抽象クラスまたはインターフェースです。

    具体的な実装者ロール：実装者ロールのサブクラスとして、具体的なメソッドを実装することでインターフェースを実装します；それとクラスの実装階層構造を構成します。

    抽象と実装の両方が独立して変化できないのであれば、ブリッジパターンとは言えません。

    ブリッジパターンでは、具体的な実装クラスは「橋」となるインターフェース内で実装され、「橋」インターフェースには機能を実装する抽象メソッドのみがあります。具体的な実装クラスは「橋」を継承し、実装クラスの抽象クラスを直接継承しません。抽象クラスと具体的な実装クラスは構造的に相互に独立しており、両者の変化は互いに影響しません。「橋」が変わらない限り、両者の変化は互いに影響しません。

    上記のチュートリアルのサンプルプログラムについて言えば、具体的な実装はRedCircle、GreenCircleであり、それらの抽象クラスはShapeです。一般的なロジックでは、Shapeを直接継承して異なる具体的なオブジェクトを作成しますが、ブリッジパターンでは「橋」DrawAPIを通じて抽象と具体的な実装の間の関連を確立し、DrawAPI内のメソッドを呼び出して具体的に実装します。

    Python での実装：

    # Bridge Pattern with Python Code
from abc import  abstractmethod,ABCMeta

# 创建桥接实现接口
class DrawAPI(metaclass=ABCMeta):
    @abstractmethod
    def drawCircle(self,inRadius,inX,inY):
        pass
# 创建实现了DrawAPI接口的实体桥接实现类
class RedCircle(DrawAPI):
    def drawCircle(self,inRadius,inX,inY):
        print("Drawing Circle [ color: red , radius: {0} , x : {1} , y : {2}]".format(inRadius, inX, inY))
class GreenCircle(DrawAPI):
    def drawCircle(self,inRadius,inX,inY):
        print("Drawing Circle [ color: green , radius: {0} , x : {1} , y : {2}]".format(inRadius, inX, inY))

# 使用DrawAPI接口创建抽象类Shape
class Shape(metaclass=ABCMeta):
    _drawAPI = None
    def __init__(self, inDrawAPI):
        self._drawAPI = inDrawAPI
# 创建实现了Shape接口的实体类
class Circle(Shape):
    _intX = 0
    _intY = 0
    _intRadius = 0
    def __init__(self,inX,inY,inRadius,inDrawAPI):
        Shape.__init__(self,inDrawAPI)
        self._intX = inX
        self._intY = inY
        self._intRadius = inRadius
    def draw(self):
        self._drawAPI.drawCircle(self._intRadius,self._intX,self._intY)

# 调用输出
if __name__ == '__main__':
    redCircle = Circle(100,100,10, RedCircle())
    greenCircle = Circle(100,100,10, GreenCircle())

    redCircle.draw()
    greenCircle.draw()

    PHP での実装：

    /**
 * Interface DrawAPI
 * 实现化(Implementor)角色：这个角色给出实现化角色的接口，但不给出具体的实现。
 */
interface DrawAPI
{
    public function drawCircle(int $radius, int $x, int $y);
}

/**
 * Class RedCircle
 * 具体实现化(ConcreteImplementorA)角色
 * 这个角色给出实现化角色接口的具体实现。
 */
class RedCircle implements DrawAPI
{

    public function drawCircle(int $radius, int $x, int $y)
    {
        echo "Drawing Circle[ color: red, radius: " . $radius . ", x: " . $x . ", " . $y . "]" . PHP_EOL;
    }
}

class GreenCircle implements DrawAPI
{

    public function drawCircle(int $radius, int $x, int $y)
    {
        echo "Drawing Circle[ color: green, radius: " . $radius . ", x: " . $x . ", " . $y . "]" . PHP_EOL;
    }
}

/**
 * Class Shape
 * 抽象化(Abstraction)角色
 * 给出定义,并保存一个对象实例化的引用
 */
abstract class Shape{
    protected $_drawAPI;
    public function __construct(DrawAPI $drawAPI)
    {
        $this->_drawAPI = $drawAPI;
    }
    public abstract function draw();
}

/**
 * Class Circle
 * 修正抽象化角色 RefinedAbstraction
 * 扩展抽象化角色，改变和修正父类对抽象化的定义。
 */
class Circle extends Shape{
    private $_x;
    private $_y;
    private $_radius;

    public function __construct(int $x,int $y,int $radius,DrawAPI $drawAPI)
    {
        parent::__construct($drawAPI);
        $this->_x = $x;
        $this->_y = $y;
        $this->_radius = $radius;
    }

    public function draw()
    {
        // TODO: Implement draw() method.
        $this->_drawAPI->drawCircle($this->_x,$this->_y,$this->_radius);
    }
}

class Demo{
    public static function main(){
        $red = new Circle(100,100,10,new RedCircle());
        $green = new Circle(100,100,10,new GreenCircle());
        $red->draw();
        $green->draw();
    }
}

Demo::main();

using std::cout;
using std::endl;

// 创建桥接实现接口。
__interface DrawAPI {
public:
    virtual void drawCircle(int __radius, int __x, int __y) = 0;
};
// 创建实现了 DrawAPI 接口的实体桥接实现类。
class RedCircle : public DrawAPI {
public:
    void drawCircle(int __radius, int __x, int __y) override {
        cout << "Drawing Circle[ color: red, radius: "
            << __radius << ", x: " << __x << ", " << __y << "]" << endl;
    }
};
class GreenCircle : public DrawAPI {
public:
    void drawCircle(int __radius, int __x, int __y) override {
        cout << "Drawing Circle[ color: green, radius: "
            << __radius << ", x: " << __x << ", " << __y << "]" << endl;
    }
};
// 使用 DrawAPI 接口创建抽象类 Shape。
class Shape {
protected:
    DrawAPI* _drawAPI;
    Shape(DrawAPI* __drawAPI) : _drawAPI(__drawAPI) {}
public:
    virtual void draw() = 0;
};
// 创建实现了 Shape 抽象类的实体类。
class Circle : public Shape {
private:
    int _x, _y, _radius;
public:
    Circle(int __x, int __y, int __radius, DrawAPI* __drawAPI)
        : Shape::Shape(__drawAPI), _x(__x), _y(__y), _radius(__radius) {}
    void draw() override {
        _drawAPI->drawCircle(_radius, _x, _y);
    }
};

// 使用 Shape 和 DrawAPI 类画出不同颜色的圆。
int main() {
    auto pRedCircle = new RedCircle();
    auto pGreenCircle = new GreenCircle();
    auto redCircle = Circle(100, 100, 10, pRedCircle);
    auto greenCircle = Circle(100, 100, 10, pGreenCircle);
    redCircle.draw();
    greenCircle.draw();

    delete pGreenCircle;

    ブリッジパターンの核となる考え方は、抽象と実装を分離し、互いに影響を与えずに独立して変化できるようにすることです。抽象部分は抽象インターフェースを定義し、実装部分は具体的な実装を提供します。ブリッジパターンにより、抽象部分と実装部分を互いに影響させずに独立して拡張・変更できます。

    以下は、ブリッジパターンを使用して抽象部分と実装部分を接続する方法を示す簡単な例です：

    // 实现接口
interface Implementor {
    void operationImpl();
}

// 具体实现类
class ConcreteImplementorA implements Implementor {
    @Override
    public void operationImpl() {
        // 具体实现A
    }
}

class ConcreteImplementorB implements Implementor {
    @Override
    public void operationImpl() {
        // 具体实现B
    }
}

// 抽象类
abstract class Abstraction {
    protected Implementor implementor;

    public Abstraction(Implementor implementor) {
        this.implementor = implementor;
    }

    public abstract void operation();
}

// 扩展抽象类
class RefinedAbstraction extends Abstraction {
    public RefinedAbstraction(Implementor implementor) {
        super(implementor);
    }

    @Override
    public void operation() {
        // 扩展抽象的操作
        implementor.operationImpl();
    }
}

// 示例代码
public class BridgePatternExample {
    public static void main(String[] args) {
        Implementor implementorA = new ConcreteImplementorA();
        Abstraction abstractionA = new RefinedAbstraction(implementorA);
        abstractionA.operation();

        Implementor implementorB = new ConcreteImplementorB();
        Abstraction abstractionB = new RefinedAbstraction(implementorB);
        abstractionB.operation();
    }
}

    上記の例では、Implementor が実装インターフェースを定義し、ConcreteImplementorA と ConcreteImplementorB が具体的な実装クラスです。Abstraction は抽象クラスで、Implementor への参照を含み、抽象的な操作インターフェースを定義しています。RefinedAbstraction は Abstraction の拡張であり、抽象的な操作インターフェースを実装し、操作の中で実装のメソッドを呼び出します。

    ブリッジパターンを使用すると、実行時に具体的な実装を動的に選択でき、抽象部分と実装部分を独立して拡張・変更できます。この疎結合化は、システムの柔軟性と保守性の向上に役立ちます。
