ブリッジパターン

ブリッジ（Bridge）は抽象化と実装の結合を分離し、両者が独立して変化できるようにするためのものです。このタイプのデザインパターンは構造型パターンに属し、抽象化と実装の間のブリッジ構造を提供することで、両者の結合を分離します。

このパターンはブリッジとなるインターフェースを関与させ、エンティティクラスの機能がインターフェース実装クラスから独立するようにします。この2種類のクラスは互いに影響を与えることなく構造的に変更できます。

ブリッジパターンの目的は、抽象と実装を分離し、それらが独立して変化できるようにすることです。このパターンは、オブジェクトの抽象部分と実装部分を分離することで、それらを独立して変更できるようにします。継承ではなく、合成（コンポジション）の方法で抽象部分と実装部分を結び付けます。

以下の例でブリッジパターンの使い方を示します。ここでは、同じ抽象クラスのメソッドでも異なるブリッジ実装クラスを使用して、異なる色の円を描くことができます。

紹介

意図

抽象部分と実装部分を分離し、それらが独立して変化できるようにするために使用されます。。

主に解決する問題

継承の使用によるクラス爆発問題を回避し、より柔軟な拡張方法を提供します。

使用シーン

システムが複数の観点から分類される可能性があり、各観点が独立して変化する可能性がある場合、ブリッジパターンが適しています。

実装方法

  • 多角的な分類の分離：異なる観点の分類ロジックを分離し、それらが独立して変化できるようにします。
  • 結合の低減：抽象と実装の間の結合度を低減します。

キーコード

  • 抽象クラス：システムの一部として抽象クラスを定義します。
  • 実装クラス：1つ以上の実装クラスを定義し、抽象クラスと継承ではなく集約によって関連付けます。

応用例

  • 転生：魂（抽象）と肉体（実装）の分離により、魂が異なる肉体を選択できます。
  • 壁のスイッチ：スイッチ（抽象）と内部実装（実装）の分離により、ユーザーはスイッチの内部動作メカニズムを気にする必要がありません。

利点

  • 抽象と実装の分離：システムの柔軟性と保守性を向上させます。
  • 拡張性が高い：抽象と実装を独立して拡張できます。
  • 実装の詳細が透過的：ユーザーは実装の詳細を理解する必要がありません。

欠点

  • 理解と設計の難しさ：ブリッジパターンはシステムの理解と設計の難しさを増大させます。
  • 集約関連：開発者は抽象層で設計とプログラミングを行う必要があります。

使用上の提案

  • システムが抽象化ロールと具体化ロールの間に柔軟性を追加する必要がある場合は、ブリッジパターンの使用を検討してください。
  • 継承を使用したくない、または多層継承によるクラス数の急激な増加が見られるシステムには、ブリッジパターンが特に適しています。
  • クラスに独立して変化する2つの次元があり、その両方の次元を拡張する必要がある場合は、ブリッジパターンを使用します。

注意事項

  • ブリッジパターンは、独立して変化する2つの次元に適用され、それらが独立して拡張および変化できることを保証します。

構造

以下はブリッジパターンのいくつかの主要な役割です：

  • 抽象（Abstraction）：抽象インターフェースを定義し、通常は実装インターフェースへの参照を含みます。
  • 拡張抽象（Refined Abstraction）：抽象の拡張であり、抽象クラスのサブクラスまたは具体的な実装クラスにすることができます。
  • 実装（Implementor）：実装インターフェースを定義し、基本操作のインターフェースを提供します。
  • 具体的実装（Concrete Implementor）：実装インターフェースを実装する具体的なクラスです。

実装

ブリッジ実装として、DrawAPIインターフェースと、実装したDrawAPIインターフェースのエンティティクラスRedCircle、GreenCircle。Shapeは抽象クラスであり、使用するDrawAPIオブジェクト。BridgePatternDemoクラスは使用するShapeクラスを使用して異なる色の円を描きます。

ステップ 1

ブリッジ実装インターフェースを作成します。

DrawAPI.java

public interface DrawAPI { public void drawCircle(int radius, int x, int y); }

ステップ 2

実装したものを作成しますDrawAPIインターフェースのエンティティブリッジ実装クラス。

RedCircle.java

public class RedCircle implements DrawAPI { @Override public void drawCircle(int radius, int x, int y) { System.out.println("Drawing Circle[ color: red, radius: " + radius +", x: " +x+", "+ y +"]"); } }

GreenCircle.java

public class GreenCircle implements DrawAPI { @Override public void drawCircle(int radius, int x, int y) { System.out.println("Drawing Circle[ color: green, radius: " + radius +", x: " +x+", "+ y +"]"); } }

ステップ 3

使用するDrawAPIインターフェースで抽象クラスを作成しますShape。

Shape.java

public abstract class Shape { protected DrawAPI drawAPI; protected Shape(DrawAPI drawAPI){ this.drawAPI = drawAPI; } public abstract void draw(); }

ステップ 4

実装したものを作成しますShape抽象クラスのエンティティクラス。

Circle.java

public class Circle extends Shape { private int x, y, radius; public Circle(int x, int y, int radius, DrawAPI drawAPI) { super(drawAPI); this.x = x; this.y = y; this.radius = radius; } public void draw() { drawAPI.drawCircle(radius,x,y); } }

ステップ 5

使用するShapeとDrawAPIクラスで異なる色の円を描きます。

BridgePatternDemo.java

public class BridgePatternDemo { public static void main(String[] args) { Shape redCircle = new Circle(100,100, 10, new RedCircle()); Shape greenCircle = new Circle(100,100, 10, new GreenCircle()); redCircle.draw(); greenCircle.draw(); } }

ステップ 6

プログラムを実行し、結果を出力します：

Drawing Circle[ color: red, radius: 10, x: 100, 100]
Drawing Circle[  color: green, radius: 10, x: 100, 100]
