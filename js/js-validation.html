JavaScript フォーム検証

HTML フォーム検証は JavaScript で行うことができます。

次のサンプルコードは、フォームフィールド (fname) の値が存在するかどうかを判断するために使用します。存在しない場合は、メッセージを表示してフォームの送信を阻止します：

JavaScript 例

function validateForm() { var x = document.forms["myForm"]["fname"].value; if (x == null || x == "") { alert("名前を入力してください。"); return false; } }

上記の JavaScript コードは HTML コードから呼び出すことができます：

HTML フォーム例

<form name="myForm" action="demo_form.php" onsubmit="return validateForm()" method="post"> 名前: <input type="text" name="fname"> <input type="submit" value="送信"> </form>

HTML フォーム自動検証

HTML フォーム検証はブラウザーで自動的に行うこともできます。

フォームフィールド (fname) の値が空の場合、required属性はフォームの送信を阻止します：

例

<form action="demo_form.php" method="post"> <input type="text" name="fname" required="required"> <input type="submit" value="送信"> </form>

データ検証

データ検証は、ユーザーが入力したデータが有効であることを保証するために使用されます。

一般的なデータ検証には以下があります：

  • 必須フィールドに入力があるか？
  • ユーザーが正当なデータを入力したか？
  • 数値フィールドにテキストが入力されていないか？

ほとんどの場合、データ検証はユーザーが正しくデータを入力することを保証するために使用されます。

データ検証はさまざまな方法で定義でき、複数の方法で呼び出すことができます。

サーバーサイドデータ検証データをサーバーに送信した後に検証します。

クライアントサイドデータ検証データをサーバーに送信する前に、ブラウザー上で検証を完了します。

HTML制約検証

HTML5 では HTML フォームの検証方法として制約検証（constraint validation）が追加されました。

制約検証は、フォームが送信されるときにブラウザーが検証を実装するために使用するアルゴリズムです。

HTML 制約検証は次に基づいています：

  • HTML入力属性
  • CSS 疑似クラスセレクター
  • DOM 属性とメソッド

制約検証 HTML入力属性

属性 説明
disabled 入力要素を無効として指定します
max 入力要素の最大値を指定します
min 入力要素の最小値を指定します
pattern 入力要素の値のパターンを指定します
required 入力要素フィールドが必須であることを指定します
type  入力要素のタイプを指定します

制約検証 CSS 疑似クラスセレクター

セレクター 説明
:disabled 「disabled」属性を持つ input 要素を選択します
:invalid 無効な input 要素を選択します
:optional 「optional」属性を持たない input 要素を選択します
:required 「required」属性を持つ input 要素を選択します
:valid 有効な値を持つ input 要素を選択します

    複数のフォームで同じ検証関数を使用する問題について：

    上記では js フォーム検証を使用してフォームフィールド (fname) の値が存在するかどうかを判断しています。複数のフォームで同じ関数を呼び出したい場合、パラメータを渡すと機能が失われます。どなたかこの問題を解決していただけないでしょうか。

    現在、インターネットで見つけた代替方法は以下のとおりです：

    function validateForm(form) {
    var x = form.name.value;
    if (x == null || x == "") {
        alert("输入不能为空！");
        return false;
    }
}

    すべてのフォームで呼び出し時に次を使用します：

    onsubmit="return validateForm(this)"

    検証済みでうまく動作します。

    onsubmit="return validateForm()"なぜ〜ではないのか onsubmit="validateForm()" ？？

    onsubmit="validateForm()"呼び出しが可能validateForm()フォームを検証しますが、検証が通らない場合、フォームの送信を阻止できません。

    onsubmit="return validateForm()"検証が通らない場合、false を返すとフォームの送信を阻止できます。

    なぜですか？

    実は onsubmit 属性は <form> という HTML オブジェクトのメソッド名のようなもので、その値（文字列）がメソッド本体であり、デフォルトで true を返します。

    onsubmit="return validateForm()"

    次と同等です：

    Form.prototype.onsubmit = function() {
    return validateForm()
};

    これにより onsubmit のデフォルトメソッド（デフォルトで true を返す）を上書きし、validateForm() の結果に応じて true または false を返します。検証が通らない場合は false を返すため、onsubmit="return false;" がフォームの送信を阻止します。

    ユーザーエクスペリエンスのヒント

    フォーム検証の HTML 属性 required にはいくつかの欠陥があります。

    つまり、input が required に設定されている場合、初期化時には空であるため invalid 疑似クラスが作用します。これは、まだ何も操作していないのに望ましくない状態です。

    これらの疑似クラスの前に親セレクター .invalid を統一的に付けることができます。この場合、親要素に invalid クラスがあるときだけ、これらの疑似クラスが作用します。submit イベントを設定し、フォーム送信が検証失敗で失敗した後、input の invalid イベントがトリガーされるので、form に invalid クラスを追加できます：

    form.addEventListener('invalid'， function() {this.className = 'invalid'}， true)

    invalid は form のイベントではなく Input のイベントであるため、ここでは第3引数を true に設定してイベントキャプチャ方式で処理します。また、CSS セレクターの使用が this.className に与える影響は事前に処理する必要があります。

    正規表現によるフォーム検証：

    <!DOCTYPE html>
<html>
<head>
<meta charset="utf-8">
<script>
function validateForm() {
    var x = document.forms["myForm"]["fname"].value;
    var pattern=/\S+/  //正则匹配空格等空白内容,限定符用*会出错，因为任意字串都会被匹配到
    if (x == null || !pattern.test(x)) {
        alert("需要输入名字。");
        return false;
    }
}
</script>
</head>
<body>

<form name="myForm" action="demo_form.php"
onsubmit="return validateForm()" method="post">
名字: <input type="text" name="fname">
<input type="submit" value="提交">
</form>

</body>
</html>
