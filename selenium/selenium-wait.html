Selenium 待機メカニズム

Selenium では、待機メカニズムはページ要素の読み込みが完了してから操作を行うための鍵となります。

ウェブページの読み込み速度はネットワークやサーバーの性能などの影響を受けるため、読み込みが完了していない要素を直接操作するとスクリプトが失敗します。

Selenium はこの問題を解決するために複数の待機メカニズムを提供しています。

1. 暗黙の待機（implicitly_wait）

1.1 暗黙的待機とは？

暗黙的待機はグローバルな待機メカニズムであり、要素を検索する際に一定時間待機します。指定された時間内に要素が見つかった場合、Selenium は直ちに後続の操作を続行します。タイムアウトしても要素が見つからない場合は、例外をスローしNoSuchElementExceptionます。

1.2 暗黙的待機の使用方法

暗黙的待機は、implicitly_wait()メソッドを使用して設定します。このメソッドは一度呼び出すだけで、以降のすべての要素検索操作はこの待機時間に従います。

例

from selenium import webdriver
from selenium.webdriver.chrome.service import Service as ChromeService

# 正しいドライバーパスを設定
service = ChromeService(executable_path="./chromedriver-mac-arm64/chromedriver")
options = webdriver.ChromeOptions()
driver = webdriver.Chrome(service=service, options=options)

# 暗黙的待機時間を10秒に設定
driver.implicitly_wait(10)

# ウェブページを開く
driver.get("https://example.com")

# 要素を検索
element = driver.find_element_by_id("element_id")

# ブラウザを閉じる
driver.quit()

1.3 暗黙的待機の長所と短所

長所：

  • シンプルで使いやすく、一度設定するだけで全ての要素検索操作に適用できます。
  • ほとんどの単純なシナリオに適しています。

短所：

  • グローバルな待機であり、不要な待機時間が発生する可能性があります。
  • 要素がクリック可能な状態になるのを待つなど、複雑な待機条件を処理できません。

2. 明示的待機（WebDriverWait と expected_conditions）

2.1 明示的待機とは？

明示的待機はより柔軟な待機メカニズムであり、特定の操作に対して待機条件を設定できます。明示的待機は通常、WebDriverWaitクラスおよびexpected_conditionsモジュールと一緒に使用されます。

2.2 明示的待機の使用方法

明示的待機の基本的な使用方法は次のとおりです：

例

from selenium import webdriver
from selenium.webdriver.chrome.service import Service as ChromeService
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

# 正しいドライバーパスを設定
service = ChromeService(executable_path="./chromedriver-mac-arm64/chromedriver")
options = webdriver.ChromeOptions()
driver = webdriver.Chrome(service=service, options=options)

# ウェブページを開く
driver.get("https://example.com")

# 明示的待機を設定し、要素が現れるまで最大10秒待機
element = WebDriverWait(driver, 10).until(
    EC.presence_of_element_located((By.ID, "element_id"))
)

# ブラウザを閉じる
driver.quit()

2.3 よく使われる expected_conditions

expected_conditionsモジュールは複数の事前定義された待機条件を提供します。以下はよく使われる条件です：

  • presence_of_element_located：要素が DOM に現れるのを待ちます。
  • visibility_of_element_located：要素が DOM に現れ、かつ表示可能になるのを待ちます。
  • element_to_be_clickable：要素がクリック可能になるのを待ちます。
  • text_to_be_present_in_element：要素のテキストが指定されたテキストを含むのを待ちます。

2.4 明示的待機の長所と短所

長所：

  • 柔軟性が高く、異なる操作に対して異なる待機条件を設定できます。
  • 複雑な待機シナリオを処理できます。

短所：

  • コードが比較的複雑で、より多くのコード量が必要です。
  • 各操作に対して個別に待機条件を設定する必要があります。

3. 固定待機（time.sleep）

3.1 固定待機とは？

固定待機は最も簡単な待機メカニズムであり、それはtime.sleep()メソッドによってスクリプトを指定した時間一時停止させます。ページの読み込みが完了しているかどうかに関係なく、スクリプトは指定した時間待機してから実行を続行します。

3.2 固定待機の使用方法

例

import time
from selenium import webdriver
from selenium.webdriver.chrome.service import Service as ChromeService

# 正しいドライバーパスを設定
service = ChromeService(executable_path="./chromedriver-mac-arm64/chromedriver")
options = webdriver.ChromeOptions()
driver = webdriver.Chrome(service=service, options=options)

# ウェブページを開く
driver.get("https://example.com")

# 5秒間固定待機
time.sleep(5)

# 要素を検索
element = driver.find_element_by_id("element_id")

# ブラウザを閉じる
driver.quit()

3.3 固定待機の長所と短所

長所：

  • シンプルで使いやすく、単純なテストシナリオに適しています。

短所：

  • 効率が低く、不要な待機時間が発生する可能性があります。
  • ページの読み込み状況に応じて待機時間を動的に調整できません。

4. Fluent Wait

機能：待機条件を動的に設定し、ポーリング頻度をカスタマイズして特定の例外を無視できます。

方法：WebDriverWait を polling_every および ignoring と組み合わせる

特徴：より柔軟で、待機時間を動的に調整する必要があるシナリオに適しています。

例

from selenium import webdriver
from selenium.webdriver.chrome.service import Service as ChromeService
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
from selenium.common.exceptions import NoSuchElementException

# 正しいドライバーパスを設定
service = ChromeService(executable_path="./chromedriver-mac-arm64/chromedriver")
options = webdriver.ChromeOptions()
driver = webdriver.Chrome(service=service, options=options)

driver.get("https://www.example.com")

# Fluent Wait を設定
wait = WebDriverWait(driver, timeout=10, poll_frequency=1, ignored_exceptions=[NoSuchElementException])
element = wait.until(EC.presence_of_element_located((By.ID, "username")))

5. まとめ

  • 暗黙的待機：単純なシナリオに適しており、グローバルな待機ですが、不要な待機時間が発生する可能性があります。
  • 明示的待機：複雑なシナリオに適しており、柔軟性が高いですが、コードは比較的複雑です。
  • 固定待機：シンプルで使いやすいですが、効率が低く、複雑なテストシナリオでの使用は推奨されません。
  • Fluent Wait：：待機時間を動的に調整する必要があるシナリオに適しています。

実際の自動化テストでは、具体的なテスト要件に応じて適切な待機メカニズムを選択することをお勧めします。通常、明示的待機はより良い柔軟性と効率を提供できるため、最も推奨される方法です。

6. 総合例

以下は、暗黙的待機と明示的待機の使用方法を示す完全な例です：

例

from selenium import webdriver
from selenium.webdriver.chrome.service import Service as ChromeService
from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

# 正しいドライバーパスを設定
service = ChromeService(executable_path="./chromedriver-mac-arm64/chromedriver")
options = webdriver.ChromeOptions()
driver = webdriver.Chrome(service=service, options=options)

# 暗黙的待機を設定
driver.implicitly_wait(5)

# ウェブページを開く
driver.get("https://www.example.com")

# 明示的待機を使用して要素が表示されるのを待つ
username = WebDriverWait(driver, 10).until(
    EC.visibility_of_element_located((By.ID, "username"))
)
username.send_keys("testuser")

# 明示的待機を使用して要素がクリック可能になるのを待つ
submit_button = WebDriverWait(driver, 10).until(
    EC.element_to_be_clickable((By.ID, "submit-btn"))
)
submit_button.click()

# ブラウザを閉じる
driver.quit()
