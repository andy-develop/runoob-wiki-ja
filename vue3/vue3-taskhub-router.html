ルーティングシステム

前の章で、タスク管理ロジックはPiniaを通じて永続化を実現しました。次に、アプリケーションに魂を注入する必要があります——ルーティングシステム。

エンタープライズ級開発において、ルーティングはページを切り替えるだけでなく、以下の重任も担っています：セキュリティ（権限制御）とユーザー体験（動的タイトル）という重任です。

インストールと基本設定

まずVue Routerをインストールします：

npm install vue-router

にsrcディレクトリの下にrouterディレクトリを作成し、 ファイルを作成します。router/index.jsファイル。

2つのページを定義します：ワークベンチ（Dashboard）とログインページ（Login）。

インスタンス

import { createRouter, createWebHistory } from 'vue-router'

const routes = [
  {
    path: '/login',
    name: 'Login',
    component: () => import('@/views/Login.vue'),
    meta: { title: 'ログイン - TaskHub', requiresAuth: false }
  },
  {
    path: '/',
    name: 'Dashboard',
    component: () => import('@/views/Dashboard.vue'),
    // ルートメタ情報 meta：カスタムデータを格納するために使用
    meta: {
      title: 'マイワークベンチ',
      requiresAuth: true,
      breadcrumb: 'ホーム'
    }
  }
]

const router = createRouter({
  history: createWebHistory(),
  routes
})

export default router

ログインロジックの実装 (Login.vue)

Tailwind v4を利用してミニマルなログインページを素早く構築し、ログイン動作をシミュレートします。

インスタンス

<script setup>
import { ref } from 'vue'
import { useRouter } from 'vue-router'

const router = useRouter()
const isLoading = ref(false)

const handleLogin = () => {
  isLoading.value = true
// 非同期リクエストをシミュレート
  setTimeout(() => {
    localStorage.setItem('isLoggedIn', 'true')
router.push('/') // ログイン成功でホームへ遷移
    isLoading.value = false
  }, 1000)
}
</script>

<template>
  <div class="min-h-screen flex items-center justify-center bg-slate-50">
    <div class="p-8 bg-white rounded-3xl shadow-xl w-full max-w-sm border border-slate-100">
      <h2 class="text-2xl font-black mb-6 text-slate-800">おかえりなさい</h2>
      <button
      @click="handleLogin"
      :disabled="isLoading"
      class="w-full bg-linear-to-r from-blue-600 to-indigo-600 text-white py-3 rounded-xl font-bold hover:opacity-90 active:scale-95 transition-all disabled:opacity-50"
    >
{{ isLoading ? 'ログイン中...' : 'ワンクリックでシステムへ' }}
      </button>
      <p class="mt-4 text-center text-xs text-slate-400">テスト環境：クリックでログインできます</p>
    </div>
  </div>
</template>

仕上げrouter/index.jsのガードロジック

ルート設定でガードモードが有効になっていることを確認してください：

インスタンス

import { createRouter, createWebHistory } from 'vue-router'

const routes = [
  {
    path: '/login',
    name: 'Login',
    component: () => import('@/views/Login.vue'),
    meta: { title: 'ログイン - TaskHub', requiresAuth: false }
  },
  {
    path: '/',
    name: 'Dashboard',
    component: () => import('@/views/Dashboard.vue'),
    // ルートメタ情報 meta：カスタムデータを格納するために使用
    meta: {
      title: 'マイワークベンチ',
      requiresAuth: true,
      breadcrumb: 'ホーム'
    }
  }
]

const router = createRouter({
  history: createWebHistory(),
  routes
})
// src/router/index.js (核心部分)
router.beforeEach((to, from, next) => {
  const isAuthenticated = localStorage.getItem('isLoggedIn') === 'true'

  // ホームへ行くが未ログインの場合 -> ログインページへ
  if (to.meta.requiresAuth && !isAuthenticated) {
    next('/login')
  }
  // ログイン済みなのにログインページへ行こうとする -> ホームへ戻す
  else if (to.path === '/login' && isAuthenticated) {
    next('/')
  }
  else {
    next()
  }
})
export default router

最終的な効果

  1. / にアクセスもしログインしていない場合、ページが一瞬表示されてからリダイレクトされます。/login。
  2. /login にアクセスボタンをクリックして、ローカルストレージに保存します。isLoggedInになる。true になり、その後瞬時にワークベンチへ切り替わります。
  3. ページを更新：PiniaはLocalStorageからタスクを読み取り、ルーターガードがログイン状態をチェックします。すべてのデータは失われません。

知識ポイントの解説

  1. なぜApp.vue空になったのですか？
    シングルページアプリケーション（SPA）では、App.vueはアプリケーション全体のシェルです。URLの変化に応じて、その中に異なるページ（DashboardまたはLogin）を動的に挿入できるように、空にしています。
  2. useRouterの実践：
    にDashboard.vueでは、 を通じてrouter.push('/login')ログアウト機能を実装しました。注意：pushはブラウザの履歴に新しいレコードを追加するため、ブラウザの戻るボタンをクリックすると戻ることができます。
  3. Tailwind v4のレイアウト継承：
    私たちは のApp.vueのグローバルコンテナに を追加したため、bg-slate-50とmin-h-screenすべての子ページ（Dashboard、Login）はデフォルトでこの薄い灰色の背景を継承し、視覚的な統一性が保証されます。
