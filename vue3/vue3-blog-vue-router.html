ルーティング遷移

この章では、Vue Router を使ってフロントエンドとバックエンドを分離したページ遷移を実装する方法を学びます。動的ルーティングパラメータも含みます。

なぜルーティングを使うのか？

従来の多ページWebサイトでは、リンクをクリックするとサーバーに新しいHTMLファイルをリクエストし、ページ全体がリフレッシュされて、白い画面が一瞬表示されていました。

Vue Router が実現しているのはフロントエンドルーティング：URL が変化してもサーバーにリクエストを送らず、JS が表示するコンポーネントを動的に切り替えます。

これによる利点は次のとおりです：リフレッシュなしでページを切り替えられ、ネイティブアプリのように滑らかな操作感。

Vue Router の中核概念

概念役割対応するコード
ルーティングテーブルURLパスとコンポーネントのマッピング関係を定義するroutes配列
ルーティング出口マッチしたコンポーネントが表示される位置<RouterView />
ナビゲーションリンククリックすると指定したルートに遷移する<RouterLink to="...">
動的ルーティングURLに変数が含まれる（記事IDなど）/post/:id

インストールと設定

プロジェクト作成時に Router を選択した場合は、インストール手順をスキップできます。

選択していない場合は、ターミナルで次のコマンドを実行します：

$ npm install vue-router@4

ルーティング設定ファイルの作成

例

// 文件路径：src/router/index.js
import { createRouter, createWebHistory } from 'vue-router'
import HomeView from '../views/HomeView.vue'

// 路由表：每条记录映射一个路径到一个组件
const routes = [
  {
    path: '/',                // URL 路径
    name: 'home',             // 路由名称（可选，编程式导航时用）
    component: HomeView       // 対応するページコンポーネント
  },
  {
    // 動的ルート：:id はプレースホルダーで、任意の値にマッチします
    // /post/1、/post/2、/post/hello はすべてこのルートに一致します
    path: '/post/:id',
    name: 'post',
    // 遅延読み込み：アクセス時に読み込まれ、ビルド時に独立したJSファイルとして分割される
    component: () => import('../views/PostView.vue')
  }
]

// 创建路由实例
const router = createRouter({
  history: createWebHistory(),  // 使用 HTML5 History 模式（URL 看起来像普通路径）
  routes                         // 注册路由表
})

export default router

2つのルーティングモードの違い：createWebHistoryクリーンなURL（/post/1）を生成し、サーバー設定のサポートが必要です。デプロイ環境が不明な場合は、次を使用できます。createWebHashHistory、URLに # が含まれ（/#/post/1）、サーバー設定は不要です。

main.js でルーティングを登録する

例

<!-- 文件路径：src/App.vue -->
<script setup>
import NavBar from './components/NavBar.vue'
</script>

<template>
  <NavBar />
  <main>
<!-- RouterView は魔法の位置です：現在のルートにマッチしたコンポーネントはここでレンダリングされます -->
    <RouterView />
  </main>
</template>

RouterLinkタグの代わりになります。<a>ページのリフレッシュは発生せず、JS で表示するコンポーネントを切り替えるだけです。

例

例
