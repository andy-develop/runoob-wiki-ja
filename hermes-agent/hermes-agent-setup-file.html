Hermes Agent 設定ファイル

インストール完了後、すべての設定とデータは~/.hermes/の下に保存されます：

~/.hermes/
├── config.yaml      # 主配置文件（模型、工具、终端后端等）
├── .env             # API 密钥和 Secret（不提交到版本库）
├── auth.json        # OAuth 凭据（Nous Portal 等）
├── SOUL.md          # Agent 人格设定文件
├── memories/        # 持久记忆（MEMORY.md、USER.md）
├── skills/          # 技能文件（Agent 自动创建和管理）
├── cron/            # 定时任务配置
├── sessions/        # 网关会话记录
└── logs/            # 日志（API 密钥自动脱敏）

重要な原則：

  • Secrets（APIキー、トークン、パスワード）保存先：.env
  • 通常の設定（モデル、ツール、ターミナルバックエンドなど）保存先：config.yaml
  • 使用するhermes config set KEY VALUEコマンドは自動的に正しいファイルにルーティングされます

モデルプロバイダーの選択

次のコマンドを実行して対話式選択に入ります：

hermes model

推奨パス：Nous Portal（最も手間がかからない）

1つのサブスクリプションで300以上のモデル + Tool Gateway（ウェブ検索、画像生成、TTS、クラウドブラウザ）をカバーし、複数のAPIキーを個別に申請する必要はありません：

hermes setup

実行後、OAuthでログインし、プロバイダー設定とツールゲートウェイの有効化が自動的に完了します。

一般的なプロバイダー一覧

プロバイダー 特徴 設定方法
Nous Portal サブスクリプション制、300+モデル、Tool Gateway hermes setup --portalOAuthログイン
Anthropic Claudeシリーズ、MaxサブスクリプションでOAuth可能 ANTHROPIC_API_KEYまたはOAuth
OpenAI Codex ChatGPT OAuth、Codexモデル hermes model→ OAuthデバイスコード
OpenRouter マルチプロバイダールーティング、200+モデル OPENROUTER_API_KEY
xAI Grok OAuth SuperGrok / Premium+ サブスクリプション、APIキー不要 hermes model → xAI Grok OAuth
GitHub Copilot Copilot サブスクリプション（GPT、Claude、Gemini） hermes model → OAuth
Google AI Studio Geminiシリーズ GOOGLE_API_KEY
DeepSeek DeepSeekシリーズ DEEPSEEK_API_KEY
ローカルモデル（Ollama） 完全ローカル、費用なし カスタムBase URLを設定

モデルのコンテキストウィンドウ要件：Hermesはモデルが少なくとも64,000 tokensのコンテキストをサポートすることを要求します。ローカルモデルを使用する場合、起動パラメータに十分なコンテキストサイズが設定されていることを確認してください（例：--ctx-size 65536）。

プロバイダーの切り替え

いつでも切り替え可能で、コードを変更する必要はありません：

hermes model

3つのSetupモード

初回実行hermes setup時に、初期化モードの選択が求められます：

モード1：Quick Setup（Nous Portal）

無料のOAuthログインで、モデル + Tool Gateway（ウェブ検索、画像生成、TTS、ブラウザ）を自動設定します。新規ユーザーに推奨します。

モード2：Full Setup

プロバイダー、ツールセット、メッセージプラットフォームなどを手動で項目ごとに設定します。明確なニーズがあり、APIキーを所有しているユーザーに適しています。

モード3：Blank Slate（空白の起点）

最小限の実行セット（プロバイダー、ファイルツール、ターミナルツール）のみを残し、その他はすべて無効にします。Agentの能力境界を正確に制御する必要がある上級ユーザーに適しています。空白モードは設定を明示的に書き込み、hermes update後で自動的に新機能が有効になるのを防ぎます。

最初の会話を開始する

設定が完了したら、Hermesを起動します：

hermes          # 经典 CLI 模式
hermes --tui    # 现代 TUI 模式（推荐，支持鼠标、弹窗等）

起動後、現在のモデル、利用可能なツール、読み込まれたスキルの情報を含むウェルカムバナーが表示されます。

すべてが正常に動作することを確認する

シンプルだが具体的なプロンプトでテストします：

現在のディレクトリを確認し、中にあるファイルを教えて、主要なプロジェクトのエントリーファイルを特定してください。

成功のサイン：

  • バナーに選択したモデル/プロバイダーが正しく表示される
  • Agentが正常に応答し、エラーメッセージがない
  • 必要に応じてツール（ターミナル、ファイル読み取りなど）を呼び出せる
  • 会話が複数ターン継続できる

セッション復元を確認する

セッションをまたいだ連続性が正常に動作することを確認します：

現在のディレクトリを確認し、中にあるファイルを教えて、主要なプロジェクトのエントリーファイルを特定してください。

ターミナル実行バックエンドの設定

Hermesは6つのターミナル実行環境をサポートしており、AgentのShellコマンドがどこで実行されるかを決定します：

バックエンド コマンドが実行される場所 隔離レベル 適用シナリオ
local（デフォルト） ローカルで直接実行 无 開発、個人使用
docker Dockerコンテナ内 完全な隔離 安全なサンドボックス、CI/CD
ssh リモートサーバー ネットワーク境界 リモート開発、高性能マシン
modal Modal クラウドサンドボックス 完全（クラウドVM） 一時的なクラウドコンピューティング、評価
daytona Daytona ワークスペース 完全（クラウドコンテナ） マネージドクラウド開発環境
singularity Singularity コンテナ 名前空間の隔離 HPCクラスタ、共有マシン

Docker バックエンドへの切り替え（本番環境に推奨）

hermes config set terminal.backend docker

または直接編集~/.hermes/config.yaml：

terminal:
  backend: docker
  docker_image: "nikolaik/python-nodejs:python3.11-nodejs20"

セキュリティに関する注意：デフォルトのlocalバックエンドは、Agentにあなたと同じファイルシステム権限を与えます。Agentの操作範囲を制限したい場合、dockerバックエンドに切り替えるのが最も簡単で効果的な方法です。

ツールセット管理

Hermesは70以上の組み込みツールを28のツールセットにグループ化しており、必要に応じて有効化または無効化できます：

hermes tools    # 打开可视化工具集管理界面（curses UI）

主要ツールセット

ツールセット 含まれる機能
filesystem ファイル読み書き、ディレクトリ操作
terminal Shellコマンドの実行
web ウェブ検索、コンテンツ抽出
browser 完全なブラウザ自動化（Playwrightが必要）
code コード実行（execute_codeツール）
vision 画像分析
audio 音声からテキスト、TTS
memory メモリ管理ツール
skills スキル管理ツール
mcp MCPサーバーツールセット（動的）

特定のツールセットを無効化する：そのツールセットはシステムプロンプトから完全に消えます。単に無効化されるだけではありません——これによりTokenを節約し、Agentが使用すべきでないツールを誤って使うのを防げます。

設定管理のよく使うコマンド

# 查看当前完整配置
hermes config

# 用编辑器打开 config.yaml
hermes config edit

# 设置单个配置值（自动路由到正确文件）
hermes config set model anthropic/claude-sonnet-4-6
hermes config set terminal.backend docker
hermes config set OPENROUTER_API_KEY sk-or-...   # 自动存入 .env

# 检查是否有新版本引入的配置项未填写
hermes config check

# 交互式补全缺失配置
hermes config migrate

# 诊断所有配置问题
hermes doctor

# 更新到最新版本
hermes update

よくある問題のトラブルシューティング

問題1：hermes: command not found

# 刷新 Shell 配置
source ~/.bashrc   # 或 source ~/.zshrc

# 如果仍然找不到，检查 PATH
echo $PATH
# 确保 ~/.local/bin 在其中
export PATH="$HOME/.local/bin:$PATH"

問題2：API key not set/ モデルが応答しない

# 重新配置提供商
hermes model

# 或直接设置 API Key
hermes config set OPENROUTER_API_KEY sk-or-...

問題3：返信が空または文字化けする

プロバイダーの認証またはモデル選択が間違っている可能性があります：

# 重新选择模型
hermes model

# 全面诊断
hermes doctor

問題4：コンテキストウィンドウ不足のエラー

Hermesはモデルが少なくとも64Kトークンのコンテキストをサポートする必要があります。より大きなコンテキストをサポートするモデルに切り替えるか、ローカルモデル使用時にコンテキストパラメータを増やしてください（例：Ollama：OLLAMA_NUM_CTX=65536）。

問題5：hermes --continue古いセッションが見つからない

# 查看所有会话
hermes sessions list

# 确认当前 Profile
hermes profile list

万能リカバリーツールキット

奇妙な問題が発生した場合は、以下の順序で実行してください：

hermes doctor           # 1. 诊断
hermes model            # 2. 检查模型配置
hermes setup            # 3. 重新向导配置
hermes sessions list    # 4. 查看会话状态
hermes --continue       # 5. 尝试恢复会话
hermes gateway status   # 6. 检查网关状态（如已启用）

上級設定のプレビュー

基本インストール完了後、以下の機能を必要に応じて有効にできます（詳細は後続の章で説明）：

メッセージプラットフォームとの連携

hermes gateway setup    # 交互式配置 Telegram、Discord、Slack 等
hermes gateway          # 启动消息网关

音声モードの有効化

# 安装语音依赖
cd ~/.hermes/hermes-agent
uv pip install -e ".[voice]"

# 在 CLI 中启用
/voice on
# 按 Ctrl+B 开始录音

MCPサーバーとの連携

在 ~/.hermes/config.yamlに追加：

mcp_servers:
  github:
    command: npx
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_PERSONAL_ACCESS_TOKEN: "ghp_xxx"
hermes mcp    # 交互式管理 MCP 服务器

エディター統合（ACP）

hermes acp    # 启动编辑器 Agent 模式（VS Code / Zed / JetBrains）
