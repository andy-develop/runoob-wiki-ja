チェックポイント、スケジュールタスクと永続目標

この章では、Hermesの3つの自動化・安全性保証メカニズムを紹介します。チェックポイントは危険な操作を実行する前にファイルを保護し、スケジュールタスクはエージェントが計画に従って自律的に実行できるようにし、永続目標はエージェントがセッションをまたいで長期的な作業を推進できるようにします。

チェックポイントとロールバック

Hermesはファイルシステムレベルのチェックポイント（Checkpoint）メカニズムを提供しており、エージェントが危険な操作を実行する前にスナップショットを作成し、必要に応じてロールバックできます。

手動作成と復元

例

# セッション内で手動チェックポイントを作成
/checkpoint リファクタリング前の状態

# すべてのチェックポイントを一覧表示
/rollback

# 指定したチェックポイントにロールバック
/rollback 2

コマンドライン管理

例

# すべてのチェックポイントを一覧表示
hermes checkpoints list

# 指定したチェックポイントに復元
hermes checkpoints restore <id>

自動チェックポイント：高リスクな操作（大規模なファイル変更、データベース変更など）を実行する前に、エージェントが自動的にチェックポイントを作成し、手動での介入は不要です。

チェックポイントはファイルシステムレベルのスナップショットであり、エージェントに大規模なリファクタリングやデータ移行を実行させる前に手動で作成するのに適しています。これはGitコミットの代替品ではなく、追加の安全保証です。

スケジュールタスク（Cron）

HermesはファーストクラスのCronスケジューリングシステムを内蔵しており、複数の形式のスケジュール計画をサポートしています。

スケジュールタスクの作成

例

# 対話形式でスケジュールタスクを作成
hermes cron create

# コマンドラインでデイリーブリーフィングタスクを作成
hermes cron create \
  --name "daily-briefing" \
  --schedule "0 8 * * *" \
  --prompt "今日のAI分野の最新動向を検索して、要約をTelegramに送信" \
  --platform telegram \
  --chat-id 123456789

スケジュールタスクの管理

例

# すべてのタスクを一覧表示
hermes cron list

# タスクを一時停止/再開/削除
hermes cron pause daily-briefing
hermes cron resume daily-briefing
hermes cron delete daily-briefing

# 1回だけ即時実行（テスト用）
hermes cron run daily-briefing

セッション内でのCron管理

例

# 任意のプラットフォームのセッションでスラッシュコマンドを使用してスケジュールタスクを管理
/cron list                 # すべてのタスクを表示
/cron pause <name>         # 指定したタスクを一時停止
/cron resume <name>        # 指定したタスクを再開

Cron設定形式

各スケジュールタスクは独立したJSONファイルです：

例

// ファイルパス：~/.hermes/cron/daily-briefing.json
{
  "name": "daily-briefing",
  "schedule": "0 8 * * *",
"prompt": "今日のAI分野の最新動向を検索して、ブリーフィングにまとめる",
  "platform": "telegram",
  "chat_id": "123456789",
  "toolsets": ["web", "memory"],
  "enabled": true
}

対応しているスケジュール形式

形式例意味
cron式"0 8 * * *"毎朝8時
自然言語"every day at 8am"同上
間隔"every 2 hours"2時間ごとに1回実行

Cronの安全性：危険なコマンドの処理

スケジュールタスク中に承認が必要な危険なコマンドに遭遇した場合、デフォルトの動作は拒否（承認を待つのではなく——午前4時に誰もapproveをクリックして待ってはいないからです）：

例

# ファイルパス：~/.hermes/config.yaml
# スケジュールタスクの承認ポリシー
approvals:
  cron_mode: deny     # deny（デフォルト）| approve（自動承認、注意して使用）

cron_mode: approve は、スケジュールタスク内の危険なコマンドが自動承認されて実行されることを意味します——タスクの内容を完全に信頼できる場合にのみ使用してください。

永続目標（Persistent Goals）

永続目標により、Hermesは毎回のリマインドなしで、複数のセッションにわたって長期的なタスクを自律的に推進できます。

永続目標の管理

例

# 永続目標を設定
hermes goals add "毎週GitHub上のHermes AgentのIssueを監視し、
未解決の問題をまとめてSlackに送信"

# すべての目標を表示
hermes goals list

# 目標を一時停止/完了/削除
hermes goals pause <id>
hermes goals complete <id>
hermes goals delete <id>

永続目標 vs スケジュールタスク

比較項目スケジュールタスク（Cron）永続目標（Goals）
トリガー方法固定された時間に自動トリガーエージェントがいつ行動するかを自律的に決定
実行内容固定されたPrompt、毎回同じエージェントがコンテキストに基づいて動的に決定
状態追跡なし（毎回独立して実行）進捗を追跡
適用シーン定期レポート、日次サマリーコンテキスト判断が必要な長期的なタスク
代表的な例毎朝8時にAIニュースを送信特定のリポジトリのIssueを継続的に監視してフォローアップする

Cronは「決まった時間に決まったことをする」のに適しており、永続目標は「エージェント、目標はこれだ、ペースは自分で決めて」という場合に適しています。両者は補完関係であり、代替関係ではありません。
