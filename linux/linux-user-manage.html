Linux ユーザーとユーザーグループの管理

Linuxシステムはマルチユーザー・マルチタスクの時分割オペレーティングシステムです。システムリソースを使用したいユーザーは、まずシステム管理者にアカウントを申請し、そのアカウントでシステムに入る必要があります。

ユーザーアカウントは、一方ではシステム管理者がシステムを使用するユーザーを追跡し、システムリソースへのアクセスを制御するのに役立ちます。他方では、ユーザーがファイルを整理するのを助け、ユーザーにセキュリティ保護を提供します。

各ユーザーアカウントは、一意のユーザー名とそれぞれのパスワードを持っています。

ユーザーはログイン時に正しいユーザー名とパスワードを入力すると、システムと自分のホームディレクトリに入ることができます。

ユーザーアカウントの管理を実現するには、主に以下の作業を完了する必要があります：

  • ユーザーアカウントの追加、削除、変更。
  • ユーザーパスワードの管理。
  • ユーザーグループの管理。

一、Linuxシステムユーザーアカウントの管理

ユーザーアカウントの管理作業は、主にユーザーアカウントの追加、変更、削除に関わります。

ユーザーアカウントの追加とは、システムに新しいアカウントを作成し、新しいアカウントにユーザーID、ユーザーグループ、ホームディレクトリ、ログインシェルなどのリソースを割り当てることです。追加されたばかりのアカウントはロックされており、使用できません。

1、新しいユーザーアカウントの追加はuseraddコマンドを使用します。その構文は次のとおりです。

useradd 选项 用户名

パラメータの説明：

  • オプション：

    • -c comment コメント記述を指定します。
    • -d ディレクトリ ユーザーのホームディレクトリを指定します。このディレクトリが存在しない場合は、-mオプションも使用してホームディレクトリを作成できます。
    • -g ユーザーグループ ユーザーが所属するユーザーグループを指定します。
    • -G ユーザーグループ, ユーザーグループ ユーザーが所属する追加グループを指定します。
    • -s シェルファイル ユーザーのログインシェルを指定します。
    • -u ユーザーID ユーザーのユーザーIDを指定します。-oオプションを同時に指定すると、他のユーザーの識別子を再利用できます。

  • ユーザー名：

    新しいアカウントのログイン名を指定します。

例1

# useradd –d  /home/sam -m sam

このコマンドはユーザーsamを作成します。-dおよび-mオプションは、ログイン名samのホームディレクトリ /home/sam を生成するために使用されます（/homeはデフォルトのユーザーホームディレクトリがある親ディレクトリです）。

例2

# useradd -s /bin/sh -g group –G adm,root gem

このコマンドはユーザーgemを新規作成します。このユーザーのログインシェルは/bin/shであり、groupユーザーグループに属し、同時にadmおよびrootユーザーグループにも属します。ここでgroupユーザーグループがプライマリグループです。

ここで新しいグループを作成する可能性があります：#groupadd group及groupadd adm

ユーザーアカウントの追加は、/etc/passwdファイルに新しいユーザーのレコードを追加し、同時に/etc/shadow、/etc/groupなどの他のシステムファイルを更新することです。

Linuxは統合システム管理ツールuserconfを提供しており、これを使用してユーザーアカウントを一元的に管理できます。

2、アカウントの削除

ユーザーのアカウントが不要になった場合、システムから削除できます。ユーザーアカウントの削除とは、/etc/passwdなどのシステムファイルからそのユーザーのレコードを削除し、必要に応じてユーザーのホームディレクトリも削除することです。

既存のユーザーアカウントの削除にはuserdelコマンドを使用します。その形式は次のとおりです。

userdel 选项 用户名

一般的なオプションは-rで、ユーザーのホームディレクトリも一緒に削除する働きがあります。

例：

# userdel -r sam

このコマンドは、システムファイル（主に/etc/passwd、/etc/shadow、/etc/groupなど）内のユーザーsamのレコードを削除し、同時にユーザーのホームディレクトリを削除します。

3、アカウントの変更

ユーザーアカウントの変更とは、実際の状況に応じてユーザーID、ホームディレクトリ、ユーザーグループ、ログインシェルなどのユーザーの関連属性を変更することです。

既存ユーザーの情報の変更にはusermodコマンドを使用します。その形式は次のとおりです。

usermod 选项 用户名

一般的なオプションには-c, -d, -m, -g, -G, -s, -u以及-o等があり、これらのオプションの意味はuseraddコマンドのオプションと同じで、ユーザーに新しいリソース値を指定できます。

さらに、一部のシステムではオプション：-l 新しいユーザー名を使用できます。

このオプションは新しいアカウントを指定し、元のユーザー名を新しいユーザー名に変更します。

例：

# usermod -s /bin/ksh -d /home/z –g developer sam

このコマンドは、ユーザーsamのログインシェルをkshに変更し、ホームディレクトリを/home/zに変更し、ユーザーグループをdeveloperに変更します。

4、ユーザーパスワードの管理

ユーザー管理における重要な内容の一つは、ユーザーパスワードの管理です。ユーザーアカウントは作成直後はパスワードがありませんが、システムによってロックされているため使用できません。パスワードを指定して初めて使用できます。空のパスワードを指定する場合でも同様です。

ユーザーパスワードを指定・変更するシェルコマンドはpasswd。スーパーユーザーは自分自身と他のユーザーにパスワードを指定でき、一般ユーザーはこれを使用して自分のパスワードのみを変更できます。コマンドの形式は次のとおりです：

passwd 选项 用户名

使用できるオプション：

  • -l パスワードをロック、つまりアカウントを無効にします。
  • -u パスワードのロックを解除。
  • -d アカウントをパスワードなしにする。
  • -f ユーザーに次回ログイン時のパスワード変更を強制します。

ユーザー名を省略した場合、現在のユーザーのパスワードを変更します。

例えば、現在のユーザーがsamの場合、次のコマンドはそのユーザー自身のパスワードを変更します：

$ passwd 
Old password:****** 
New password:******* 
Re-enter new password:*******

スーパーユーザーの場合は、次の形式で任意のユーザーのパスワードを指定できます：

# passwd sam 
New password:******* 
Re-enter new password:*******

一般ユーザーが自分のパスワードを変更する場合、passwdコマンドはまず元のパスワードを尋ね、検証後にユーザーに新しいパスワードを2回入力するよう要求します。2回の入力が一致すれば、そのパスワードがユーザーに設定されます。一方、スーパーユーザーがユーザーにパスワードを指定する場合は、元のパスワードを知る必要はありません。

システムの安全のため、ユーザーはより複雑なパスワードを選択すべきです。例えば、8桁のパスワードが望ましく、大文字、小文字、数字を含み、氏名や誕生日などとは異なるものにすべきです。

ユーザーに空のパスワードを指定する場合は、次の形式のコマンドを実行します：

# passwd -d sam

このコマンドはユーザーsamのパスワードを削除するため、ユーザーsamが次回ログインしようとすると、システムはそのユーザーのログインを許可しなくなります。

passwdコマンドは-l(lock)オプションを使用して特定のユーザーをロックし、ログインできないようにすることもできます。例：

# passwd -l sam

二、Linuxシステムユーザーグループの管理

各ユーザーにはユーザーグループがあり、システムはユーザーグループ内のすべてのユーザーを集中的に管理できます。Linuxシステムによってユーザーグループの規定は異なります。例えば、Linuxではユーザーは自分と同名のユーザーグループに属し、このユーザーグループはユーザー作成時に同時に作成されます。

ユーザーグループの管理には、ユーザーグループの追加、削除、変更が含まれます。グループの追加、削除、変更は、実際には/etc/groupファイルの更新です。

1、新しいユーザーグループの追加はgroupaddコマンドを使用します。その形式は次のとおりです。

groupadd 选项 用户组

使用できるオプションは次のとおりです：

  • -g GID 新しいユーザーグループのグループ識別番号（GID）を指定します。
  • -o 通常は-gオプションと同時に使用し、新しいユーザーグループのGIDがシステムに既存のユーザーグループのGIDと同じであってもよいことを示します。

例1：

# groupadd group1

このコマンドはシステムに新しいグループgroup1を追加します。新しいグループのグループ識別番号は、現在存在する最大のグループ識別番号に1を加えたものになります。

例2：

# groupadd -g 101 group2

このコマンドはシステムに新しいグループgroup2を追加し、同時に新しいグループのグループ識別番号として101を指定します。

2、既存のユーザーグループを削除する場合は、groupdelコマンドを使用します。その形式は次のとおりです。

groupdel 用户组

例：

# groupdel group1

このコマンドはシステムからグループgroup1を削除します。

3、ユーザーグループの属性の変更はgroupmodコマンドを使用します。その構文は次のとおりです。

groupmod 选项 用户组

よく使われるオプションは次のとおりです。

  • -g GID ユーザーグループに新しいグループ識別番号を指定します。
  • -o -gオプションと同時に使用し、ユーザーグループの新しいGIDがシステムに既存のユーザーグループのGIDと同じであってもよいことを示します。
  • -n 新しいユーザーグループ名 ユーザーグループの名前を新しい名前に変更します。

例1：

# groupmod -g 102 group2

このコマンドはグループgroup2のグループ識別番号を102に変更します。

例2：

# groupmod –g 10000 -n group3 group2

このコマンドはグループgroup2の識別番号を10000に変更し、グループ名をgroup3に変更します。

4、ユーザーが同時に複数のユーザーグループに属している場合、ユーザーはユーザーグループ間で切り替えて、他のユーザーグループの権限を持つことができます。

ユーザーはログイン後、newgrpコマンドを使用して他のユーザーグループに切り替えることができます。このコマンドの引数は目的のユーザーグループです。例：

$ newgrp root

このコマンドは現在のユーザーをrootユーザーグループに切り替えます。前提条件は、rootユーザーグループが実際にそのユーザーの主グループまたは追加グループであることです。ユーザーアカウントの管理と同様に、ユーザーグループの管理も統合されたシステム管理ツールを使用して行うことができます。

三、ユーザーアカウントに関連するシステムファイル

ユーザー管理の作業を完了する方法は多数ありますが、どの方法も実際には関連するシステムファイルを変更することです。

ユーザーとユーザーグループに関連する情報は一部のシステムファイルに格納されます。これらのファイルには、/etc/passwd、/etc/shadow、/etc/groupなどがあります。

以下でこれらのファイルの内容をそれぞれ説明します。

1、/etc/passwdファイルはユーザー管理作業に関わる最も重要なファイルです。

Linuxシステムの各ユーザーは/etc/passwdファイルに対応する記録行を持ち、このユーザーのいくつかの基本的な属性を記録しています。

このファイルはすべてのユーザーが読み取り可能です。その内容は次の例のようなものです。

＃ cat /etc/passwd

root:x:0:0:Superuser:/:
daemon:x:1:1:System daemons:/etc:
bin:x:2:2:Owner of system commands:/bin:
sys:x:3:3:Owner of system files:/usr/sys:
adm:x:4:4:System accounting:/usr/adm:
uucp:x:5:5:UUCP administrator:/usr/lib/uucp:
auth:x:7:21:Authentication administrator:/tcb/files/auth:
cron:x:9:16:Cron daemon:/usr/spool/cron:
listen:x:37:4:Network daemon:/usr/net/nls:
lp:x:71:18:Printer administrator:/usr/spool/lp:
sam:x:200:50:Sam san:/home/sam:/bin/sh

上の例からわかるように、/etc/passwdの1行のレコードは1人のユーザーに対応し、各行のレコードはコロン(:)で7つのフィールドに区切られています。その形式と具体的な意味は次のとおりです。

用户名:口令:用户标识号:组标识号:注释性描述:主目录:登录Shell

1）「ユーザー名」はユーザーアカウントを表す文字列です。

通常、長さは8文字以内で、大文字と小文字の英字および/または数字で構成されます。ログイン名にはコロン(:)を含めることはできません。ここではコロンが区切り文字だからです。

互換性のため、ログイン名にはピリオド(.)を含めないほうがよく、ハイフン(-)やプラス記号(+)で始めないようにします。

2）「パスワード」一部のシステムでは、暗号化されたユーザーパスワード文字列が格納されています。

このフィールドにはユーザーパスワードの暗号化された文字列だけが格納されており、平文ではありませんが、/etc/passwdファイルはすべてのユーザーが読み取り可能なため、これでも依然としてセキュリティ上のリスクです。そのため、現在多くのLinuxシステム（SVR4など）ではshadow技術を採用し、実際の暗号化されたユーザーパスワードを/etc/shadowファイルに格納し、/etc/passwdファイルのパスワードフィールドには「x」や「*」などの特別な文字だけを格納しています。

3）「ユーザーID」は整数で、システム内部でユーザーを識別するために使用されます。

通常、これはユーザー名と1対1で対応します。複数のユーザー名に対応するユーザー識別番号が同じ場合、システム内部ではそれらを同じユーザーとみなしますが、それらは異なるパスワード、異なるホームディレクトリ、異なるログインシェルなどを持つことができます。

通常、ユーザー識別番号の範囲は0〜65,535です。0はスーパーユーザーrootの識別番号で、1〜99はシステムによって管理アカウントとして予約され、一般ユーザーの識別番号は100から始まります。Linuxシステムでは、この境界は500です。

4）「グループID」フィールドには、ユーザーが所属するユーザーグループが記録されます。

これは/etc/groupファイル内の1つのレコードに対応します。

5）「コメント記述」フィールドには、ユーザーの個人情報が記録されます。

例えば、ユーザーの本名、電話番号、住所などです。このフィールドには実際の用途はあまりありません。異なるLinuxシステムでは、このフィールドの形式は統一されていません。多くのLinuxシステムでは、このフィールドには任意のコメント的説明文が格納され、fingerコマンドの出力として使用されます。

6）「ホームディレクトリ」、つまりユーザーの初期作業ディレクトリです。

これはユーザーがシステムにログインした後にいるディレクトリです。ほとんどのシステムでは、各ユーザーのホームディレクトリは同じ特定のディレクトリの下にまとめられており、ユーザーのホームディレクトリの名前はそのユーザーのログイン名です。各ユーザーは自分のホームディレクトリに対して読み取り、書き込み、実行（検索）権限を持ち、他のユーザーのこのディレクトリへのアクセス権限は状況に応じて設定されます。

7)ユーザーがログインした後、ユーザーの操作をカーネルに伝えるプロセスを起動します。このプロセスは、ユーザーがシステムにログインした後に実行されるコマンドインタープリタまたは特定のプログラム、すなわちシェルです。

シェルはユーザーとLinuxシステムの間のインターフェースです。Linuxのシェルには多くの種類があり、それぞれ異なる特徴があります。一般的なものには、sh（Bourne Shell）、csh（C Shell）、ksh（Korn Shell）、tcsh（TENEX/TOPS-20 type C Shell）、bash（Bourne Again Shell）などがあります。

システム管理者は、システムの状況やユーザーの習慣に応じて、ユーザーに特定のシェルを指定できます。シェルを指定しない場合、システムはshをデフォルトのログインシェルとして使用します。つまり、このフィールドの値は/bin/shになります。

ユーザーのログインシェルは、特定のプログラム（コマンドインタープリタではないプログラム）に指定することもできます。

この特徴を利用して、ユーザーが指定されたアプリケーションのみを実行できるように制限し、そのアプリケーションの実行が終了すると、ユーザーは自動的にシステムからログアウトします。一部のLinuxシステムでは、システムに登録されたプログラムのみがこのフィールドに現れることができます。

8)システムには、擬似ユーザー（pseudo users）と呼ばれる種類のユーザーがいます。

これらのユーザーは/etc/passwdファイルにも1つのレコードを持ちますが、ログインシェルが空であるためログインできません。それらが存在するのは主にシステム管理を容易にし、対応するシステムプロセスのファイル所有者に対する要件を満たすためです。

一般的な疑似ユーザーは次のとおりです。

伪 用 户 含 义 
bin 拥有可执行的用户命令文件 
sys 拥有系统文件 
adm 拥有帐户文件 
uucp UUCP使用 
lp lp或lpd子系统使用 
nobody NFS使用

アカウントファイルを所有しています

1、上に挙げた疑似ユーザーの他にも、audit、cron、mail、usenetなど、多くの標準的な疑似ユーザーがあります。それらもそれぞれ関連するプロセスやファイルに必要とされています。

/etc/passwdファイルはすべてのユーザーが読み取り可能なため、ユーザーのパスワードが単純すぎたり、規則性が明らかだったりすると、通常のコンピューターでも簡単に解読できてしまいます。そのため、セキュリティ要件が高いLinuxシステムでは、暗号化されたパスワードを分離して、/etc/shadowファイルという別のファイルに格納しています。スーパーユーザーのみがこのファイルの読み取り権限を持ち、これによりユーザーパスワードの安全性が保証されます。

2、/etc/shadowのレコード行は/etc/passwdのものと1対1に対応しており、pwconvコマンドによって/etc/passwdのデータに基づいて自動的に生成されます。

そのファイル形式は/etc/passwdと似ており、複数のフィールドで構成され、フィールド間は「:」で区切られます。これらのフィールドは次のとおりです。

ログイン名:暗号化パスワード:最終変更時間:最小時間間隔:最大時間間隔:警告時間:非アクティブ時間:失効時間:フラグ
  1. 「ログイン名」は、/etc/passwdファイルのログイン名と一致するユーザーアカウントです。
  2. 「パスワード」フィールドには、暗号化されたユーザーパスワードが格納され、長さは13文字です。空の場合、対応するユーザーにはパスワードがなく、ログイン時にパスワードは不要です。集合 { ./0-9A-Za-z }に属さない文字が含まれている場合、対応するユーザーはログインできません。
  3. 「最終変更時間」は、ある時点からユーザーが最後にパスワードを変更した時点までの日数を表します。時間の起点はシステムによって異なる場合があります。例えばSCO Linuxでは、この時間の起点は1970年1月1日です。
  4. 「最小時間間隔」は、パスワードを2回変更する間に必要となる最小日数を指します。
  5. 「最大時間間隔」は、パスワードが有効である最大日数を指します。
  6. 「警告時間」フィールドは、システムがユーザーに警告を開始してからユーザーのパスワードが正式に失効するまでの日数を表します。
  7. 「非活動時間」は、ユーザーのログイン活動がないがアカウントがまだ有効に保たれる最大日数を表します。
  8. 「失効時間」フィールドは絶対的な日数を示します。このフィールドが使用されている場合、対応するアカウントの有効期間が示されます。期間が満了すると、そのアカウントはもはや有効なアカウントではなくなり、ログインに使用できなくなります。

3、ユーザーグループのすべての情報は/etc/groupファイルに格納されています。

ユーザーをグループ化することは、Linuxシステムにおいてユーザーを管理し、アクセス権限を制御するための1つの手段です。

各ユーザーは何らかのユーザーグループに属します。1つのグループには複数のユーザーを含めることができ、1人のユーザーが異なるグループに属することもできます。

ユーザーが同時に複数のグループのメンバーである場合、/etc/passwdファイルにはユーザーが所属する主グループ、つまりログイン時に所属するデフォルトのグループが記録され、他のグループは追加グループと呼ばれます。

ユーザーが補助グループに属するファイルにアクセスする場合、最初にnewgrpコマンドを使用して、アクセスしたいグループのメンバーになる必要があります。

ユーザーグループのすべての情報は/etc/groupファイルに格納されています。このファイルの形式は/etc/passwdファイルに似ており、コロン(:)で区切られたいくつかのフィールドがあります。これらのフィールドは次のとおりです：

グループ名:パスワード:グループID:グループ内ユーザーリスト
  1. 「グループ名」はユーザーグループの名前で、文字または数字で構成されます。/etc/passwdのログイン名と同様に、グループ名は重複してはなりません。
  2. 「パスワード」フィールドには、ユーザーグループの暗号化されたパスワードが格納されます。一般的にLinuxシステムのユーザーグループにはパスワードがなく、このフィールドは通常空または*です。
  3. 「グループID」はユーザーIDと似ており、整数であり、システム内部でグループを識別するために使用されます。
  4. 「グループ内ユーザーリスト」はこのグループに属するすべてのユーザーのリストで、ユーザー間はカンマ(,)で区切ります。このユーザーグループはユーザーのプライマリグループの場合もあれば、補助グループの場合もあります。

/etc/groupファイルの例は次のとおりです：

root::0:root
bin::2:root,bin
sys::3:root,uucp
adm::4:root,adm
daemon::5:root,daemon
lp::7:root,lp
users::20:root,sam

四、一括ユーザーの追加

ユーザーの追加と削除は、どのLinuxシステム管理者にとっても簡単なことです。厄介なのは、数十人、数百人、さらには数千人のユーザーを追加する場合です。useraddを使用して1人ずつ追加することはほぼ不可能なので、大量のユーザーを作成する簡単な方法を見つける必要があります。Linuxシステムには多数のユーザーを作成するためのツールが用意されており、すぐに大量のユーザーを作成できます。方法は次のとおりです：

（1）最初にテキストユーザーファイルを編集します。

各列は/etc/passwdパスワードファイルの形式に従って記述します。各ユーザーのユーザー名、UID、ホームディレクトリは同じであってはならないことに注意してください。パスワード欄は空白のままにするか、xを入力できます。サンプルファイルuser.txtの内容は次のとおりです：

user001::600:100:user:/home/user001:/bin/bash
user002::601:100:user:/home/user002:/bin/bash
user003::602:100:user:/home/user003:/bin/bash
user004::603:100:user:/home/user004:/bin/bash
user005::604:100:user:/home/user005:/bin/bash
user006::605:100:user:/home/user006:/bin/bash

（2）root権限でコマンドを実行します/usr/sbin/newusers、作成したばかりのユーザーファイルからuser.txtデータをインポートしてユーザーを作成します：

# newusers < user.txt

その後、コマンドを実行してvipw 或 vi /etc/passwd確認します/etc/passwdファイルにこれらのユーザーのデータが表示されているか、ユーザーのホームディレクトリが作成されているかを確認します。

（3）コマンド/usr/sbin/pwunconvを実行します。

将 /etc/shadow生成されたshadowパスワードをデコードして、書き戻します/etc/passwdに、そして/etc/shadowのshadowパスワード欄を削除します。これは次のパスワード変換作業を容易にするためで、つまり先にshadow password機能を無効にします。

# pwunconv

（4）各ユーザーのパスワード対応ファイルを編集します。

形式は次のとおりです：

ユーザー名:パスワード

サンプルファイルpasswd.txtの内容は次のとおりです：

user001:123456
user002:123456
user003:123456
user004:123456
user005:123456
user006:123456

（5）root権限でコマンドを実行します/usr/sbin/chpasswd。

ユーザーパスワードを作成します。chpasswdは/usr/bin/passwdコマンドでエンコードされたパスワードを/etc/passwdのパスワード欄に書き込みます。

# chpasswd < passwd.txt

（6）パスワードがエンコードされて/etc/passwdのパスワード欄に書き込まれたことを確認した後。

コマンドを実行します/usr/sbin/pwconvパスワードをshadow passwordにエンコードし、結果を/etc/shadow。

# pwconv

に書き込みます。これで大量のユーザー作成が完了です。その後、/homeの下でこれらのユーザーのホームディレクトリの権限設定が正しいかどうかを確認し、ログインしてユーザーパスワードが正しいかどうかを検証できます。
