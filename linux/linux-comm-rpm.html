Linux rpm コマンド

Linux コマンド大全

Linux rpm コマンドはパッケージの管理に使用されます。

rpm（英語の正式名称：redhat package manager）は、元々 Red Hat Linux ディストリビューションが Linux の各パッケージを管理するために特化したプログラムです。GPL ルールに従い、機能が強力で便利なため、広く人気を集めました。次第に他のディストリビューションにも採用されるようになりました。RPM パッケージ管理方式の登場により、Linux のインストールやアップグレードが容易になり、間接的に Linux の適用度が向上しました。

構文

rpm [-acdhilqRsv][-b<完成阶段><套间档>+][-e<套件挡>][-f<文件>+][-i<套件档>][-p<套件档>＋][-U<套件档>][-vv][--addsign<套件档>+][--allfiles][--allmatches][--badreloc][--buildroot<根目录>][--changelog][--checksig<套件档>+][--clean][--dbpath<数据库目录>][--dump][--excludedocs][--excludepath<排除目录>][--force][--ftpproxy<主机名称或IP地址>][--ftpport<通信端口>][--help][--httpproxy<主机名称或IP地址>][--httpport<通信端口>][--ignorearch][--ignoreos][--ignoresize][--includedocs][--initdb][justdb][--nobulid][--nodeps][--nofiles][--nogpg][--nomd5][--nopgp][--noorder][--noscripts][--notriggers][--oldpackage][--percent][--pipe<执行指令>][--prefix<目的目录>][--provides][--queryformat<档头格式>][--querytags][--rcfile<配置档>][--rebulid<套件档>][--rebuliddb][--recompile<套件档>][--relocate<原目录>=<新目录>][--replacefiles][--replacepkgs][--requires][--resign<套件档>+][--rmsource][--rmsource<文件>][--root<根目录>][--scripts][--setperms][--setugids][--short-circuit][--sign][--target=<安装平台>+][--test][--timecheck<检查秒数>][--triggeredby<套件档>][--triggers][--verify][--version][--whatprovides<功能特性>][--whatrequires<功能特性>]

パラメータの説明：

  • -a 　すべてのパッケージを照会します。
  • -b<ビルド段階><パッケージファイル>+または -t <ビルド段階><パッケージファイル>+ 　パッケージのビルド段階を設定し、パッケージファイルのファイル名を指定します。
  • -c 　構成設定ファイルのみを一覧表示します。このパラメータは「-l」パラメータと併用する必要があります。
  • -d 　テキストファイルのみを一覧表示します。このパラメータは「-l」パラメータと併用する必要があります。
  • -e<パッケージファイル>または--erase<パッケージファイル> 　指定したパッケージを削除します。
  • -f<ファイル>+ 　指定したファイルを所有するパッケージを照会します。
  • -hまたは--hash 　パッケージインストール時にマークを一覧表示します。
  • -i 　パッケージの関連情報を表示します。
  • -i<パッケージファイル>または--install<パッケージファイル> 　指定したパッケージファイルをインストールします。
  • -l 　パッケージのファイルリストを表示します。
  • -p<パッケージファイル>+ 　指定した RPM パッケージファイルを照会します。
  • -q 　問い合わせモードを使用します。問題が発生した場合、rpm コマンドはまずユーザーに問い合わせます。
  • -R 　パッケージの関連性情報を表示します。
  • -s 　ファイルの状態を表示します。このパラメータは「-l」パラメータと併用する必要があります。
  • -U<パッケージファイル>または--upgrade<パッケージファイル> 　指定したパッケージファイルをアップグレードします。
  • -v 　コマンドの実行プロセスを表示します。
  • -vv 　コマンドの実行プロセスを詳細に表示し、トラブルシューティングを容易にします。
  • -addsign<パッケージファイル>+ 　指定したパッケージに新しい署名認証を追加します。
  • --allfiles 　すべてのファイルをインストールします。
  • --allmatches 　指定したパッケージに含まれるファイルを削除します。
  • --badreloc 　エラーが発生した場合、ファイルを再設定します。
  • --buildroot<ルートディレクトリ> 　パッケージを生成する際にルートディレクトリとして扱うディレクトリを設定します。
  • --changelog 　パッケージの変更履歴を表示します。
  • --checksig<パッケージファイル>+ 　そのパッケージの署名認証を検証します。
  • --clean 　パッケージの作成完了後、作成プロセス中に作成されたディレクトリを削除します。
  • --dbpath<データベースディレクトリ> 　RPM データベースを保存するディレクトリを設定します。
  • --dump 　各ファイルの検証情報を表示します。このパラメータは「-l」パラメータと併用する必要があります。
  • --excludedocs 　パッケージをインストールするとき、ドキュメントをインストールしません。
  • --excludepath<除外ディレクトリ> 　指定したディレクトリ内のすべてのファイルを無視します。
  • --force 　パッケージまたはファイルを強制的に置き換えます。
  • --ftpproxy<ホスト名またはIPアドレス> 　FTP プロキシサーバーを指定します。
  • --ftpport<通信ポート> 　FTP サーバーまたはプロキシサーバーが使用する通信ポートを設定します。
  • --help 　オンラインヘルプ。
  • --httpproxy<ホスト名またはIPアドレス> 　HTTP プロキシサーバーを指定します。
  • --httpport<通信ポート> 　HTTP サーバーまたはプロキシサーバーが使用する通信ポートを設定します。
  • --ignorearch 　パッケージファイルの構造の正確性を検証しません。
  • --ignoreos 　パッケージファイルの構造の正確性を検証しません。
  • --ignoresize 　インストール前にディスク容量が十分かどうかをチェックしません。
  • --includedocs 　パッケージをインストールするとき、ドキュメントも一緒にインストールします。
  • --initdb 　正しいデータベースが使用可能であることを確認します。
  • --justdb 　ファイルを変更せずにデータベースのみを更新します。
  • --nobulid 　いかなるビルド段階も実行しません。
  • --nodeps 　パッケージファイルの相互関連性を検証しません。
  • --nofiles 　ファイルの属性を検証しません。
  • --nogpg 　すべての GPG 署名認証をスキップします。
  • --nomd5 　MD5 エンコード演算を使用してファイルのサイズと正確性を確認しません。
  • --nopgp 　すべての PGP 署名認証をスキップします。
  • --noorder 　パッケージ間の関連性を満たすためにインストール順序を並べ替えません。
  • --noscripts 　いかなるインストールスクリプトファイルも実行しません。
  • --notriggers 　そのパッケージ内のいかなるスクリプトファイルも実行しません。
  • --oldpackage 　旧バージョンのパッケージにアップグレードします。
  • --percent 　パッケージのインストール時に完了率のパーセンテージを表示します。
  • --pipe<実行コマンド> 　パイプを作成し、出力結果をその実行コマンドの入力データに変換します。
  • --prefix<目的ディレクトリ> 　ファイルを再設定する場合、ファイルを指定したディレクトリに配置します。
  • --provides 　そのパッケージが提供する互換性を照会します。
  • --queryformat<ヘッダーフォーマット> 　ヘッダーの表示方法を設定します。
  • --querytags 　ヘッダーフォーマットに使用できるタグを一覧表示します。
  • --rcfile<設定ファイル> 　指定した設定ファイルを使用します。
  • --rebulid<パッケージファイル> 　ソースコードパッケージをインストールし、バイナリファイルのパッケージを再生成します。
  • --rebuliddb 　既存のデータベースを基に、データベースを再構築します。
  • --recompile<パッケージファイル> 　このパラメータの効果は「--rebulid」パラメータと似ていますが、パッケージファイルは生成されません。
  • --relocate<元ディレクトリ>=<新ディレクトリ> 　元のディレクトリに配置されるはずだったファイルを新しいディレクトリに配置します。
  • --replacefiles 　ファイルを強制的に置き換えます。
  • --replacepkgs 　パッケージを強制的に置き換えます。
  • --requires 　そのパッケージが必要とする互換性を照会します。
  • --resing<パッケージファイル>+ 　既存の認証を削除し、署名認証を再生成します。
  • --rmsource 　パッケージの作成完了後、ソースコードを削除します。
  • --rmsource<ファイル> 　ソースコードと指定したファイルを削除します。
  • --root<ルートディレクトリ> 　ルートディレクトリとして扱うディレクトリを設定します。
  • --scripts 　パッケージをインストールするスクリプトの変数を一覧表示します。
  • --setperms 　ファイルの権限を設定します。
  • --setugids 　ファイルの所有者と所属グループを設定します。
  • --short-circuit 　指定したビルド段階のステップを直接スキップします。
  • --sign 　PGP または GPG の署名認証を生成します。
  • --target=<インストールプラットフォーム>+ 　生成されるパッケージのインストールプラットフォームを設定します。
  • --test 　テストのみ行い、実際にはパッケージをインストールしません。
  • --timecheck<チェック秒数> 　時間チェックのタイマー秒数を設定します。
  • --triggeredby<パッケージファイル> 　そのパッケージの作成者を照会します。
  • --triggers 　パッケージファイル内のスクリプトを表示します。
  • --verify 　このパラメータの効果は「-q」パラメータと同じです。
  • --version 　バージョン情報を表示します。
  • --whatprovides<機能特性> 　そのパッケージが指定した機能特性に対して提供する互換性を照会します。
  • --whatrequires<機能特性> 　そのパッケージが指定した機能特性に対して必要とする互換性を照会します。

例

ソフトウェアのインストール

# rpm -hvi dejagnu-1.4.2-10.noarch.rpm 
警告：dejagnu-1.4.2-10.noarch.rpm: V3 DSA 签名：NOKEY, key ID db42a60e
准备...           
########################################### [100%]

ソフトウェアのインストール情報を表示

# rpm -qi dejagnu-1.4.2-10.noarch.rpm
