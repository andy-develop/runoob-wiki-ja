Linux システムディレクトリ構造

 ls /

ツリー状のディレクトリ構造：

以下はこれらのディレクトリの説明です：

ディレクトリ 役割の詳細 一般的なファイル / 例
/ ルートファイルシステム。すべてのマウントポイントとパスの起点。システムに必須のサブディレクトリとエントリ構造を含む。 具体的なデータファイルはなく、サブディレクトリ構造のみ。
/bin システム起動およびシングルユーザーモードで必要な基本コマンド。全ユーザーが実行可能。 ls, cp, mv, rm, bash
/sbin システム管理および保守コマンド。root向け。 fsck, reboot, shutdown
/usr ユーザーレベルのプログラムとライブラリの主要な集合。大部分のシステムソフトウェア、ドキュメント、ツールを含む。 /usr/bin, /usr/lib, /usr/share
/usr/bin 通常のユーザープログラムの主要な配置ディレクトリ。 python3, vim, git
/usr/sbin 管理ツールの拡張集合。 useradd, apache2ctl
/usr/lib /usr内部のプログラムが依存する動的ライブラリとモジュール。 各種.so動的ライブラリ
/usr/local このマシンにインストールまたはコンパイルされたソフトウェアの独立した領域。 /usr/local/bin, /usr/local/lib
/lib 或 /lib64 システム起動用のコアライブラリ、動的リンカがある場所。 libc.so.6, ld-linux.so
/etc システムレベルの設定センター。すべてのサービスとシステム設定を一元的に格納。 passwd, group, fstab, ssh/sshd_config
/home 一般ユーザーの個人ホームディレクトリの集合。 /home/user/.bashrc, /home/user/Documents
/root rootユーザーのホームディレクトリ。 /root/.ssh/
/var 頻繁に変更されるデータ：ログ、キャッシュ、データベース実行ファイルなど。 /var/log, /var/lib, /var/cache
/var/log すべてのシステムおよびサービスログの集中場所。 syslog, auth.log, kern.log
/var/cache アプリケーションおよびパッケージマネージャーのキャッシュ。 /var/cache/apt/
/var/lib サービスの永続化状態データ。 mysql/, docker/
/tmp プログラム実行時の一時ファイル領域。いつでもクリア可能。 一時ファイル、ソケットパス
/boot 起動に必要なファイル：カーネル、initramfs、ブート設定。 vmlinuz-*, initrd.img, grub/grub.cfg
/dev デバイスノードの集合。ファイルがデバイスである。 /dev/sda, /dev/null, /dev/tty0
/proc カーネルが提供する仮想ファイルシステム。システムとプロセスのリアルタイム情報を表示。 /proc/cpuinfo, /proc/<pid>/
/sys デバイス、ドライバー、カーネルサブシステムの状態インターフェース。 /sys/class/net/, /sys/block/
/mnt 手動でマウントする一時的なマウントポイント。 /mnt/usb
/media 外部デバイスを自動マウントするデフォルトの場所。 /media/user/USB_DRIVE
/run ランタイムデータの格納場所。再起動後にクリアされる。 *.pid, 実行状態のソケットファイル

Linuxでは、次のディレクトリはシステムの重要領域に属し、誤って削除または変更するとシステムの動作を直接破壊します：

/etc — システム設定の核心

すべての重要な設定がここに集中している。誤った変更はサービスの停止や、システムが起動できなくなる可能性がある。

/bin、/sbin、/usr/bin、/usr/sbin — システムコマンド領域

システムにプリインストールされたコマンドの場所。

  • /bin、/usr/bin：一般ユーザー向けの基本コマンド（例lsにある/bin/ls）。
  • /sbin、/usr/sbin：システム管理コマンド。主にrootが使用。

/var — 動的データ領域

システムの実行中に絶えず書き込まれるデータがここに置かれる。
重要なのは/var/log、各種サービスログがすべてここに格納される。メール、キャッシュ、キューなどもこのディレクトリで管理される。

    LinuxまたはUnixオペレーティングシステムでは、すべてのファイルとディレクトリは、ルートノードを起点とする逆さまのツリー構造として整理されています。

    ファイルシステムの最上位層はルートディレクトリから始まり、システムは/を使用してルートディレクトリを表します。ルートディレクトリの下にはディレクトリもファイルも置くことができ、各ディレクトリにはさらにサブディレクトリやファイルを含めることができます。これを繰り返すことで、大規模なファイルシステムを構成できます。

    Linuxファイルシステムには2つの特別なディレクトリがあります。1つはユーザーがいる作業ディレクトリ（現在のディレクトリとも呼ばれます）で、ドット1つ.で表します。もう1つは現在のディレクトリの上位ディレクトリ（親ディレクトリとも呼ばれます）で、ドット2つ..で表します。

    • . ：現在のディレクトリを表します。./ でも表せます；
    • .. ：上位のディレクトリを表します。../ でも表せます。

    ディレクトリ名またはファイル名がドット . で始まる場合、そのディレクトリまたはファイルは隠しディレクトリまたは隠しファイル（例：.bashrc）であることを意味します。つまり、デフォルトの方法で検索した場合、そのディレクトリまたはファイルは表示されません。

    システム起動に必須：

    • /boot：Linux起動時に使用するカーネルファイルを格納します。リンクファイルやイメージファイルも含みます。
    • /etc：格納すべてのシステムに必要な設定ファイル和サブディレクトリのリスト。このディレクトリ内のファイルを変更すると、システムが起動できなくなる可能性があります。
    • /lib：基本コードライブラリ（C++ライブラリなど）を格納します。その役割はWindowsのDLLファイルに似ています。ほとんどすべてのアプリケーションがこれらの共有ライブラリを必要とします。
    • /sys：これはLinux 2.6カーネルの大きな変化です。このディレクトリには、2.6カーネルで新たに登場したファイルシステム sysfs がマウントされています。sysfsファイルシステムは、以下の3つのファイルシステムの情報を統合しています：プロセス情報向けのprocファイルシステム、デバイス向けのdevfsファイルシステム、および擬似端末向けのdevptsファイルシステムです。このファイルシステムはカーネルデバイスツリーの直感的な反映です。カーネルオブジェクトが作成されると、対応するファイルとディレクトリもカーネルオブジェクトサブシステム内に作成されます。

    コマンド集合：

    • /bin：最も一般的に使用されるプログラムとコマンドを格納します
    • /sbin：システム管理者のみが使用できるプログラムとコマンド。

    外部ファイル管理：

    • /dev ：Device（デバイス）の略称で、Linuxの外部デバイスを格納します。注意：Linuxでは、デバイスへのアクセスとファイルへのアクセス方法は同じです。
    • /media：Windowsに似たその他のデバイス。例えばUSBメモリや光学ドライブなどです。認識されるとLinuxはデバイスをこのディレクトリに配置します。
    • /mnt：他のファイルシステムを一時的にマウントするためのものです。光学ドライブを/mnt/にマウントして、そのディレクトリに入ると光学ドライブの内容を確認できます。

    一時ファイル：

    • /run：一時ファイルシステムで、システム起動以降の情報を保存します。システムが再起動すると、このディレクトリ内のファイルは削除またはクリアされるべきです。システムに /var/run ディレクトリがある場合は、run を指すようにするべきです。
    • /lost+found：通常は空ですが、システムが不正にシャットダウンされた後、ここにいくつかのファイルが保存されます。
    • /tmp：このディレクトリは一時ファイルを保存するために使用されます。

    アカウント：

    • /root：システム管理者のユーザーホームディレクトリ。
    • /home：ユーザーのホームディレクトリで、ユーザーのアカウント名にちなんで名付けられています。
    • /usr：ユーザーの多くのアプリケーションとファイルがこのディレクトリに置かれます。WindowsのProgram Filesディレクトリに似ています。
    • /usr/bin：システムユーザーが使用するアプリケーションとコマンド。
    • /usr/sbin：スーパーユーザーが使用する、より高度な管理プログラムとシステムデーモン。
    • /usr/src：カーネルソースコードのデフォルトの配置ディレクトリ。

    実行中に使用するもの：

    • /var：頻繁に変更されるデータを格納します。例えば、プログラム実行のログファイル（/var/log ディレクトリ内）などです。
    • /proc：管理するメモリ空間！仮想ディレクトリであり、システムメモリのマッピングです。このディレクトリに直接アクセスしてシステム情報を取得できます。このディレクトリの内容はハードディスク上ではなくメモリ内にあり、内部の一部のファイルを直接変更することもできます。

    拡張用：

    • /opt：デフォルトでは空で、追加のソフトウェアをインストールするときにここに置くことができます。
    • /srv：サービス起動後に抽出する必要があるデータを格納します（サーバーを使わなければ空です）
