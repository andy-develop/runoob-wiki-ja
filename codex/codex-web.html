Codex クラウド版

Codex Web はクラウド版で、あらゆるデバイスから Codex にアクセスし、分離された環境でタスクを実行できます。

Codex Web にアクセス

クラウド版 Codex にアクセス：

https://chatgpt.com/codex

使用前提

  • ChatGPT Plus / Pro / Business / Enterprise プラン
  • または OpenAI API Key を使用

API Key を使用する場合、一部のクラウド機能が利用できない場合があります。

クラウド環境（Environments）

Environment は Codex Web の中核となる概念であり、各環境は分離されたワークスペースです。

環境の作成

  1. GitHub アカウントを接続
  2. リポジトリを選択
  3. セットアップスクリプトと環境変数を設定
  4. ネットワークアクセスポリシーを選択

タスク実行フロー

クラウドタスクは次のフローで実行されます：

  1. コンテナを作成し、選択したブランチにリポジトリをクローン
  2. セットアップスクリプトを実行して依存関係をインストール
  3. ネットワークアクセス設定を適用
  4. Agent がタスクを実行（コードの編集、コマンドの実行、結果の検証）
  5. 結果とファイルの変更を表示

デフォルトイメージ

クラウドではuniversalという名前のデフォルトコンテナイメージを使用します：

  • 一般的な言語をプリインストール：Python、Node.js、Go、Rust
  • 一般的なツールを含む：npm、pip、cargo、git
  • ランタイムのバージョンを固定可能

バージョン固定

バージョンの固定

# Environment 設定

# Python バージョンを固定
python_version = "3.11"

# Node.js バージョンを固定
node_version = "20"

セットアップスクリプト

セットアップスクリプトはコンテナ作成時に自動実行されます：

自動検出

Codex がプロジェクトタイプを自動的に識別し、対応するインストールを実行します：

  • Node.js：npm install / yarn / pnpm を自動実行
  • Python：pip install / poetry install を自動実行

手動スクリプト

カスタムセットアップスクリプト

# Setup Script
# 環境設定で構成

npm install
npm run build
pip install -r requirements.txt

メンテナンススクリプト

メンテナンススクリプトはキャッシュコンテナの起動時に実行されます：

  • 依存関係の更新や再ビルドに使用
  • 完全なセットアップよりも高速

セットアップスクリプトと Agent は異なる Bash セッションで実行されるため、export コマンドは永続化されません。

環境変数と Secrets

環境変数

環境変数はタスク全体を通じて利用可能です：

環境変数の設定

# Environment Variables
NODE_ENV=production
DEBUG=false
API_ENDPOINT=https://api.example.com

Secrets

Secrets は機密情報の保存に使用されます：

  • 追加の暗号化ストレージ
  • タスク実行時のみ復号化
  • セットアップスクリプトでのみ利用可能
  • Agent フェーズで自動的に削除
タイプ可視範囲用途
Environment Variablesセットアップスクリプト + Agent通常の設定
SecretsセットアップスクリプトのみAPI Key、パスワード

ネットワークアクセス制御

クラウド環境のネットワークアクセスはデフォルトで制限されています：

デフォルト設定

フェーズネットワークアクセス
セットアップスクリプト許可（依存関係のインストールに必要）
Agent禁止（デフォルト）

Agent のネットワークアクセスオプション

設定説明
Offネットワークアクセスを完全に禁止
Onネットワークアクセスを許可（ドメインを制限可能）

ドメインホワイトリスト

ドメイン設定

# ネットワーク設定

# ホワイトリストのプリセット
domain_allowlist = "common-dependencies"
# 含まれるもの：github.com, npmjs.com, pypi.org など

# カスタムドメイン
domain_allowlist = [
    "github.com",
    "api.mycompany.com"
]

# HTTP メソッドを制限
allowed_methods = ["GET", "HEAD", "OPTIONS"]

セキュリティリスク

Agent のネットワークアクセスを有効にするとリスクが増加します：

  • プロンプトインジェクション（悪意のあるウェブページから命令を取得）
  • データ漏洩（コードや鍵を外部に送信）
  • 悪意のある依存関係のダウンロード

必要な場合のみ Agent のネットワークアクセスを有効にし、ドメインホワイトリストで制限してください。

コンテナキャッシュ

クラウドはコンテナ状態をキャッシュして後続のタスクを高速化します：

  • キャッシュは最大 12 時間
  • セットアップスクリプトまたは環境変数が変更されると自動的に無効化
  • 新しいタスクの起動が高速化

クラウドタスク管理

タスクの作成

  1. 環境を選択
  2. タスクの説明を入力
  3. モデルと設定を選択
  4. タスクを開始

タスクの監視

  • 進行状況をリアルタイムで確認
  • ファイルの変更を確認
  • コマンド出力を確認

結果の処理

  • 変更の Diff を確認
  • Pull Request を作成
  • 変更されたファイルをダウンロード

並行タスク

クラウドは複数のタスクを並行して実行できます：

  • 異なる機能を同時に処理
  • 複数の環境が独立して動作
  • 全体の効率を向上

複数のタスクが同じファイルを同時に変更しないようにしてください。競合が発生する可能性があります。

よくある質問

Q: Cloud とローカルの違いは何ですか？

Cloud はリモートサーバーで実行され、並行タスクやリモートアクセスに適しています。ローカルではファイルを直接操作します。

Q: 料金はどうなっていますか？

クラウドタスクはクォータを消費し、料金はモデルと使用量に基づいて計算されます。

Q: ローカルファイルにアクセスできますか？

クラウドからローカルファイルにはアクセスできませんが、Git で同期できます。

Q: ネットワークアクセスはいつ必要ですか？

Agent がリアルタイムデータや外部 API を必要とする場合のみ必要です。セットアップスクリプトで通常は十分です。
