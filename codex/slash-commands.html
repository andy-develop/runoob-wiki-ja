Codex スラッシュ / コマンド

Codex のスラッシュ/はクイックコマンドシステム（Slash Commands）です。

入力欄に / 記号を入力すると、システムはすぐにコマンドパネルを表示し、利用可能なすべてのコマンドとその説明を一覧表示します。

MCP、Skills、ブラウザなどを使用したい場合は、/ を入力して対応する機能を選択するだけです。

ペットを呼び出したい場合は、次のように入力します。/宠物、英語版では次のように入力します。/pet:

コマンド分類

機能別に4つのカテゴリに分けられます：コンテキスト管理、コードと開発ワークフロー、モデルと推論制御、パーソナライズとその他です。

コンテキスト管理

会話スレッドとコンテキストウィンドウを制御するコマンドグループです。

コマンド機能説明適用シーン
/compact、/压缩コンテキストの圧縮現在の会話履歴をスマートに要約し、重要な情報を保持しながら token 領域を解放します。長い会話で「コンテキストが満杯です」という警告が表示されたとき
/status、/状态状態の確認現在の会話ID、消費済みコンテキスト token 数、残りクォータなどの重要な実行パラメータを出力します。token を消費する操作を実行するかどうかを判断する前

/compact は重要なコンテキストを失いません。重要なコード断片や決定情報をスマートに保持し、冗長な会話ターンのみを圧縮します。

コードと開発ワークフロー

開発者向けの核心機能コマンドグループです。

コマンド機能説明適用シーン
/review、/コードレビューコードレビューClaude に現在のファイルまたは指定されたコードセグメントを体系的にレビューさせ、潜在的なバグ、セキュリティ問題、パフォーマンスのボトルネック、コードスタイルをチェックします。PR を提出する前、コードリファクタリング後
/side、/侧边サイド会話一時的なブランチで独立した会話を開始し、メインラインに影響を与えません。完了後にマージ、破棄、または保持できます。ある案を素早く試したいが、メインの会話履歴を汚したくない場合
/fork、/派生派生ブランチ会話をローカルの Git ブランチまたは新しいワークツリーに分岐させ、異なる案の並行探索をサポートします。プランAとプランBを比較する必要がある場合
/mcpMCP 状態現在の会話で接続されているすべての MCP（Model Context Protocol）サーバーを一覧表示し、オンラインステータスと利用可能なツールリストを確認します。外部ツールが応答しないときに接続状態を調査します。

/side と /fork の違い：/side は会話レベルのブランチで、素早い試行に適しています；/fork は Git ブランチを作成し、コードレベルの並行開発に適しています。

モデルと推論制御

AI の能力と思考の深さを調整するコマンドグループです。

コマンド機能説明適用シーン
/reasoning、/推論モード推論強度低 / 中 / 高の3段階の推論強度を切り替え、コマンド実行後に現在のレベルをリアルタイム表示します。複雑なアルゴリズム問題では高に設定し、日常の Q&A では中低を維持します。
/model、/模型モデル切り替え異なる AI モデルを切り替え、コマンド実行後に現在のモデル名を表示します。ボイラープレートコードを素早く生成する場合は軽量モデルを選択し、詳細なアーキテクチャ分析にはフラッグシップモデルを選択します。

高強度の推論は応答が遅いですが、答えはより正確です。低強度は応答が速くなります。複雑なバグをデバッグするときは、高推論モードに切り替えることをお勧めします。

パーソナライズとその他

エクスペリエンスのカスタマイズと補助機能のコマンドグループです。

コマンド機能説明適用シーン
/persona、/个性パーソナリティの設定Claude の応答のトーンとスタイルを調整します。「簡潔で直接的」、「詳しく教える」、「シニアエンジニア」などのプリセットがあります。チームコラボレーション時に出力スタイルを統一します。
/feedback、/反馈フィードバックの送信フィードバックチャネルをすばやく開き、バグを報告したり、機能提案を提出したり、使用体験を共有したりします。出力品質の問題に遭遇したらすぐにフィードバックします。
/pet、/宠物デスクトップペットClaude Code 内蔵のデスクトップペットの表示状態を切り替えます。小さなイースターエッグ機能です。集中が必要なときは収納し、休憩時に呼び出します。

おすすめワークフロー

スラッシュコマンドを日常の開発フローに取り入れると、半分の労力で2倍の効果が得られます。

# 步骤1：开始新任务前，检查上下文余量
/status

# 步骤2：遇到复杂问题，提升推理强度
/reasoning   # 切换至"高"档

# 步骤3：完成代码改动后，启动审查
/review

# 步骤4：探索不确定的方案，开启侧边对话
/side

# 步骤5：上下文快满时，压缩历史
/compact
ステップタイミングおすすめコマンド目的
1新しいタスクを開始する前/statusコンテキストの残量とクォータを確認し、新しい会話を作成する必要があるかを判断します。
2複雑な問題に遭遇したとき/reasoning推論強度を上げて、より深い分析を得ます。
3PR を提出する前/review見逃される可能性のある境界条件と潜在的なバグを検出します。
4新しい案の探索/side または /fork安全な環境で試行し、メインラインの進行に影響を与えません。
5コンテキストが満杯になりそうなとき/compact履歴会話を圧縮し、重要なコンテキストを保持します。

コマンド機能簡易説明
