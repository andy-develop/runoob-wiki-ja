DeepSeek Harness インストール

この章の紹介3つのインストール方法：npmワンクリックインストール、ソースコードインストール、Python SDK。

インストール前の準備

DeepSeek Harness のランタイムは Node.js ベースです、公式推奨のワンクリックインストール方法は追加の依存関係を必要としません。

ソースコードインストールには pnpm と Git も必要です。

Python SDK 方式には Python 3.10 以上が必要です。

オペレーティングシステム：Linux、macOS、Windowsいずれも可

Python SDK は Linux x64 / arm64 と macOS 14+（arm64）をサポートしています。

環境要件npm ワンクリックインストールソースコードインストールPython SDK
Node.js 必須 必須 不要（SDK にランタイム同梱）
Git 任意 必須 必須
pnpm 不要 必須 不要
Python 3.10+ 不要 不要 必須
DeepSeek API キー 3つの方法すべてで必要です（モデルの設定に使用。OpenAI 互換エンドポイントもサポート）

まずローカル環境を確認してください。Node.js（例：v20+）が必要です：

node -v

ソースコードインストール時は git が必要です：

git --version

方法1：npm ワンクリックインストール（推奨）

npm コマンドでグローバルインストールできます：

npm install -g @deepseek-ai/dsh

この方法でインストールすると、後で を使用するのに便利ですdshコマンド。インストール完了後、以下のコマンドを入力すると起動できます：

dsh web

npx コマンドでインストールして手軽に試すこともできます。ターミナルで実行：

npx @deepseek-ai/dsh web

コマンドは Web UI を起動し、初回実行時に自動的に初期化を行いますweb設定テンプレートを初期化し、アクセスアドレスを表示します——デフォルトはhttp://127.0.0.1:3080。

成功したか確認するには：

1. ブラウザでターミナルに表示されたアドレスを開きます（デフォルトhttp://127.0.0.1:3080）；

2. DeepSeek Harness の Web 画面が表示されればインストール成功です；

3. 注意：新しい Web UI はワークスペースを追加するまでどのワークスペースも選択しません——これは正常な動作です。次のステップで設定します。

豆知識：dsh は呼び出しディレクトリをデフォルトのファイルシステム位置として使用します。先にcdプロジェクトディレクトリに移動してから を実行することをおすすめしますnpx @deepseek-ai/dsh web、これにより、後でワークスペースを選択するときに最も便利です。

方法2：ソースコードからインストール

プラグイン開発、ソースコード閲覧、コントリビュートに適しています。リポジトリをクローンして順に実行：

git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install     # 安装依赖（需要 pnpm，可用 npm install -g pnpm 安装）
pnpm run build   # 构建包与前端产物（生产运行需要）
pnpm dsh web     # 以源码方式启动 Web UI

ソースコードから実行する際の他のエントリ：

pnpm dsh --profile headless "run the tests"—— タスクを一度だけ実行し、最終回答を表示します；

pnpm dsh --profile web --dump-config—— 実際に起動する完全な設定ツリーを表示します（プラグイン開発時に便利）。

方法3：Python SDK インストール

前提条件：Python 3.10+、Git、DeepSeek 互換の API エンドポイントと認証情報、agent が変更できる分離された workspace。仮想環境を作成してインストール：

git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
python -m venv .venv
. .venv/bin/activate
python -m pip install deepseek-harness-sdk

認証情報を設定するとプログラムから呼び出せます（SDK にランタイムが同梱されており、システムに Node.js は不要です）：

export DEEPSEEK_API_KEY=sk-your-key-here
# 如果模型不是默认 DeepSeek 端点，而是 OpenAI 兼容代理，还需要：
# export DEEPSEEK_BASE_URL=http://127.0.0.1:8000/v1
# export DSH_MODEL=deepseek-v4-flash

自分の Python プログラムでの使用例：

from deepseek_harness import DeepSeekHarness—— リポジトリ内蔵のexamples/jsonrpc-agent/minimal.pyは SDK 呼び出しの軽量ラッパーで、直接参考にできます。実行後、assistant の最終応答が表示され、セッションディレクトリにはモデルリクエストとツール呼び出しを含む JSONL ログが保存されます。

初回設定と最初のタスク

どの方法で起動した Web UI でも、初回は3ステップだけです：

ステップ操作説明
1モデルの設定 設定 → モデル DeepSeek API キーを入力して保存。モデルルーティングは即座に有効になり、サーバーの再起動は不要です；他のプロバイダーやカスタム OpenAI 互換エンドポイントもサポート
2ワークスペースの選択 「ワークスペースを選択」をクリック dsh 起動時のプロジェクトディレクトリを追加して選択します。ワークスペースを選択するまで、セッション入力欄は使用できません
3タスクの実行 セッションで指示を入力 例：Summarize this repository and identify its main packages.—— agent はワークスペースのファイルを読み書きし、コマンドを実行し、サブエージェントを委任し、計画を管理します；権限ポリシーを超える操作は事前に承認を求めます

最初のタスクは軽量な指示から始めることをおすすめします："Summarize this repository and identify its main packages."

まず agent にワークスペースを慣れさせてから、徐々に実際のタスクを任せましょう。—— 公式クイックスタートガイドは を推奨しています

よく使うコマンド早見表

コマンド用途
npx @deepseek-ai/dsh web Web UI を起動（ と同等）--profile web）
dsh --profile headless "任务描述" タスクを一度だけ実行し、最終回答を表示して終了（スクリプト/CI に最適）
dsh plugin --profile <name> <pnpm 参数> 特定の profile のプラグインを管理（profile ディレクトリで pnpm に転送して実行）
dsh --profile web --dump-config 実際に起動する完全な設定ツリーを表示（サーバーを起動しない）
dsh --profile web --dump-default-config デフォルトの設定ツリーを表示（ユーザー patch を含まない）
pip install deepseek-harness-sdk Python SDK をインストール（ランタイム同梱）

Profile について：webとheadless2つの profile は初回使用時に内蔵テンプレートから自動初期化されます；残りの profile は によってdsh plugin作成します。dsh の起動パラメータが先、アプリケーションパラメータが後です。例：dsh --profile web --port 8080 中 --portは Web アプリケーションに属します。

よくある質問とトラブルシューティング

問題1：ブラウザで http://127.0.0.1:3080 を開けない

ターミナルで dsh プロセスがまだ実行中でエラーがないことを確認してください；ポートが占用されている場合は、 を使用してdsh --profile web --port 8080別のポートに変更します；ファイアウォールがローカルポートを許可しているか確認します。

問題2：npx が @deepseek-ai/dsh を見つけられない、またはバージョンが古すぎる

まず Node.js がインストールされ、バージョンが新しいことを確認してください（node -v）；プロジェクトは開発者プレビュー段階で、イテレーションが速いため、必要に応じて npx キャッシュをクリアして再試行するか、ソースコードインストールに切り替えてください。

問題3：ソースコードインストール時に pnpm install / build が失敗する

pnpm がインストールされていることを確認してください（npm install -g pnpm）；ネットワークが制限されている場合は npm/pnpm にミラーソースを設定できます；ビルドにはリポジトリの package.json の engines 宣言を満たす Node.js バージョンが必要です。

問題4：セッション入力欄が使用できない / agent がファイルを読み書きできない

最も一般的な原因はワークスペースを選択していないことです——「ワークスペースを選択」に戻ってプロジェクトディレクトリを追加・選択します；「設定 → モデル」で有効な API キーを保存していることを確認してください。モデルルーティングは再起動なしで有効になります。

問題5：Python SDK ランタイムが Node.js を見つけられない

SDK にはランタイムが同梱されており、通常はシステムの Node.js は不要です；ランタイムが見つからないエラーが発生する場合は、SDK と同じバージョンの完全なパッケージをインストールしているか確認してください（python -m pip install deepseek-harness-sdk），そして公式の前提条件に従って Linux x64 / arm64 または macOS 14+（arm64）を使用します。
