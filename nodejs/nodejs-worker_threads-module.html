Node.js worker_threads モジュール

Node.js 組み込みモジュール

Node.js のworker_threadsモジュールにより、開発者は Node.js アプリケーションでマルチスレッドを作成できます。従来のシングルスレッドの Node.js モデルとは異なり、このモジュールを使用すると、別のスレッドで JavaScript コードを実行できるため、真の並列処理を実現できます。

なぜマルチスレッドが必要なのか

Node.js はデフォルトでシングルスレッドです。つまり：

  1. CPU 集中型のタスクはイベントループをブロックします
  2. マルチコア CPU の性能を十分に活用できません
  3. 長時間実行される計算はアプリケーションの応答速度を低下させます

worker_threadsモジュールはこれらの問題を解決し、計算集中型タスクを他のスレッドに振り分けることができます。

基本概念

メインスレッド vs ワーカースレッド

  1. メインスレッド：アプリケーションの主要な実行スレッドであり、ワーカースレッドの作成と管理を担当します
  2. ワーカースレッド：メインスレッドによって作成される独立した実行スレッドで、特定のタスクを実行するために使用されます

スレッド間通信

ワーカースレッドとメインスレッドは、共有メモリではなくメッセージパッシングによって通信します。この方法により、複雑な同期問題を回避できます。

コア API

worker_threads モジュールの主要コンポーネント

例

const {
  Worker,          // 新しいスレッドを作成するためのクラス
  isMainThread,    // 現在メインスレッドかどうかを判定する
  parentPort,      // 親スレッドと通信するために使用する
  workerData       // スレッド作成時に渡されるデータ
} = require('worker_threads');

使用例

シンプルなワーカースレッドを作成する

メインスレッドコード (main.js):

例

const { Worker, isMainThread } = require('worker_threads');

if (isMainThread) {
  // メインスレッドコード
  console.log('これはメインスレッドです');
 
  // ワーカースレッドを作成
  const worker = new Worker('./worker.js', {
    workerData: {
      message: 'こんにちは、ワーカースレッド!'
    }
  });
 
  // ワーカースレッドからのメッセージを監視
  worker.on('message', (msg) => {
    console.log(`ワーカースレッドから受信: ${msg}`);
  });
 
  worker.on('error', (err) => {
    console.error('ワーカースレッドエラー:', err);
  });
 
  worker.on('exit', (code) => {
    if (code !== 0) {
      console.error(`ワーカースレッドが異常終了しました。終了コード: ${code}`);
    }
  });
} else {
  // ワーカースレッドコード
  require('./worker.js');
}

ワーカースレッドコード (worker.js):

例

const { parentPort, workerData } = require('worker_threads');

console.log('これはワーカースレッドです');
console.log('メインスレッドからメッセージを受信:', workerData.message);

// 何らかの作業をシミュレート
setTimeout(() => {
  // メインスレッドにメッセージを送信
  parentPort.postMessage('作業完了!');
}, 2000);

高度な使い方

複雑なデータの受け渡し

例

// メインスレッド
const worker = new Worker('./worker.js', {
  workerData: {
    array: new Uint8Array([1, 2, 3, 4]),
    object: { key: 'value' }
  }
});

// ワーカースレッド
console.log(workerData.array);  // Uint8Array [ 1, 2, 3, 4 ]
console.log(workerData.object); // { key: 'value' }

共有メモリ (SharedArrayBuffer)

例

// メインスレッド
const sharedBuffer = new SharedArrayBuffer(16);
const arr = new Uint8Array(sharedBuffer);
arr[0] = 1;

const worker = new Worker('./worker.js', {
  workerData: { sharedBuffer }
});

// ワーカースレッド
const { sharedBuffer } = workerData;
const arr = new Uint8Array(sharedBuffer);
console.log(arr[0]); // 1

ベストプラクティス

  1. 適切な使用：すべての小さなタスクにスレッドを作成しないでください。スレッド作成にはオーバーヘッドがあります
  2. エラーハンドリング：ワーカースレッドの 'error' イベントと 'exit' イベントを常に監視してください
  3. リソースのクリーンアップ：タスク完了後にワーカースレッドが正しく終了することを確認してください
  4. 通信の最適化：スレッド間通信のデータ量を最小限に抑えてください
  5. CPU 親和性：長時間実行されるスレッドの場合は、CPU 親和性の設定を検討してください

パフォーマンスの考慮事項

  1. スレッドプール：頻繁に発生する短時間のタスクには、スレッドプールパターンの使用を検討してください
  2. 負荷分散：マルチコアシステム上でワーカースレッドを均等に分散させます
  3. メモリ使用量：各ワーカースレッドには独自の V8 インスタンスとメモリ空間があります

よくある質問

いつ worker_threads を使うべきですか？

  • CPU 集中型の計算
  • 複数のタスクを並列処理する必要がある場合
  • マルチコア CPU を活用する必要がある場合

worker_threads と cluster モジュールの違いは何ですか？

  • cluster複数の Node.js プロセスが作成されます。
  • worker_threadsスレッドが作成され、同じプロセスを共有します。

ワーカースレッドをデバッグするには？

使用して--inspectと--inspect-brkフラグを設定し、各ワーカースレッドに異なるデバッグポートを割り当てます。

例

node --inspect=9229 main.js

まとめ

Node.js のworker_threadsモジュールは JavaScript に真のマルチスレッド機能をもたらし、開発者が最新のマルチコア CPU の性能をより活用できるようにします。ワーカースレッドを適切に使用することで、CPU 集中型アプリケーションのパフォーマンスを大幅に向上させると同時に、Node.js のノンブロッキング I/O の利点を維持できます。
