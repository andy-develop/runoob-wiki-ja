Maven リポジトリ

Maven の用語では、リポジトリは場所（place）です。

Maven リポジトリとは、プロジェクトが依存するサードパーティ製ライブラリのことです。このライブラリが配置されている場所をリポジトリと呼びます。

Maven では、依存関係、プラグイン、プロジェクトビルドの出力などはすべてアーティファクトと呼ぶことができます。

Maven リポジトリは、アーティファクト（主に JAR）の管理を支援します。すべての JAR ファイル（WAR、ZIP、POM など）を配置する場所です。

Maven リポジトリの種類：

リポジトリの種類保存場所役割アクセス優先順位
ローカルリポジトリユーザーディレクトリ配下.m2/repositoryリモートからダウンロードした依存関係をキャッシュする1
リモートリポジトリネットワークサーバー依存関係とプラグインの集中ストレージを提供する2
- 中央リポジトリrepo.maven.apache.orgMaven 公式が管理するデフォルトリポジトリ2.1
- プライベートリポジトリ社内で構築（Nexus など）プライベート依存関係を管理し、ビルドを高速化する2.2
- その他の公開リポジトリ例：阿里云、JCenter など中央リポジトリのミラーまたは補完2.3

ローカルリポジトリ

Maven のローカルリポジトリは、Maven のインストール後には作成されず、最初に Maven コマンドを実行したときに作成されます。

Maven の実行時、Maven が必要とするすべてのアーティファクトはローカルリポジトリから直接取得されます。ローカルリポジトリにない場合は、まずリモートリポジトリからアーティファクトをローカルリポジトリにダウンロードし、その後ローカルリポジトリのアーティファクトを使用します。

デフォルトでは、Linux でも Windows でも、各ユーザーのユーザーディレクトリ配下に .m2/repository/ というパスのリポジトリディレクトリがあります。

  • Windows: C:\Users\<用户名>\.m2\repository

  • Linux/macOS: ~/.m2/repository

Maven のローカルリポジトリは、デフォルトで %USER_HOME% ディレクトリに作成されます。デフォルトの場所を変更するには、%M2_HOME%\conf ディレクトリにある Maven の settings.xml ファイルで別のパスを定義します。

<settings> <localRepository>C:/MyLocalRepository</localRepository> </settings>

Maven コマンドを実行すると、Maven は依存ファイルを指定したパスにダウンロードします。

ローカルリポジトリのクリーンアップ:

mvn dependency:purge-local-repository
# 或手动删除~/.m2/repository目录

中央リポジトリ

Maven 中央リポジトリは Maven コミュニティが提供するリポジトリで、多数の一般的なライブラリが含まれています。

中央リポジトリには、大多数の一般的なオープンソース Java アーティファクトに加えて、ソースコード、作者情報、SCM 情報、ライセンス情報などが含まれています。一般に、単純な Java プロジェクトが依存するアーティファクトはここでダウンロードできます。

中央リポジトリの重要な概念：

  • このリポジトリは Maven コミュニティによって管理されています。
  • 設定は不要です。
  • ネットワーク経由でアクセスする必要があります。

中央リポジトリ（明示的な設定は不要）のデフォルトアドレス：https://repo.maven.apache.org/maven2/

リモートリポジトリ

リポジトリのカスタム設定

Maven が中央リポジトリでも依存ファイルを見つけられない場合、ビルドプロセスを停止し、エラーメッセージをコンソールに出力します。この状況を避けるため、Maven はリモートリポジトリの概念を提供しています。これは開発者が自分でカスタマイズするリポジトリで、必要なコードライブラリや他のプロジェクトで使用される JAR ファイルを含みます。

例として、次の pom.xml を使用すると、Maven はこの pom.xml で宣言されている依存ファイル（中央リポジトリで取得できないもの）をリモートリポジトリからダウンロードします。

例

<repositories>
    <repository>
        <id>aliyun</id>
        <name>Aliyun Maven</name>
        <url>https://maven.aliyun.com/repository/public</url>
        <releases>
            <enabled>true</enabled>
        </releases>
        <snapshots>
            <enabled>false</enabled> <!-- 禁用SNAPSHOT版本 -->
        </snapshots>
    </repository>
</repositories>

ミラーリポジトリ（推奨）

settings.xml で設定します：

例

<mirrors>
    <mirror>
        <id>aliyun</id>
        <name>Aliyun Mirror</name>
        <url>https://maven.aliyun.com/repository/public</url>
        <mirrorOf>central</mirrorOf> <!-- 覆盖中央仓库 -->
    </mirror>
</mirrors>

Maven 阿里云(Aliyun)リポジトリ

Maven リポジトリはデフォルトで海外にあるため、中国国内で使用するとどうしても遅くなります。阿里云のリポジトリに変更できます。

maven のルートディレクトリにある conf フォルダ内の settings.xml ファイルを変更し、mirrors ノードに次の内容を追加します：

<mirror> <id>aliyunmaven</id> <mirrorOf>*</mirrorOf> <name>阿里云公開リポジトリ</name> <url>https://maven.aliyun.com/repository/public</url> </mirror>

他のプロキシリポジトリを使用したい場合は、<repositories></repositories>ノードに対応するリポジトリの使用アドレスを追加します。spring プロキシリポジトリを使用する場合の例：

<repository> <id>spring</id> <url>https://maven.aliyun.com/repository/spring</url> <releases> <enabled>true</enabled> </releases> <snapshots> <enabled>true</enabled> </snapshots> </repository>

pom.xml ファイルの<denpendencies></denpendencies>ノードに参照するファイル情報を追加します：

<dependency> <groupId>[GROUP_ID]</groupId> <artifactId>[ARTIFACT_ID]</artifactId> <version>[VERSION]</version> </dependency>

取得コマンドを実行します：

mvn install

gradle 設定ガイド

build.gradle ファイルに以下のコードを追加します:

allprojects { repositories { maven { url 'https://maven.aliyun.com/repository/public/' } mavenLocal() mavenCentral() } }

他のプロキシリポジトリを使用したい場合、spring リポジトリを使用する例は次のとおりです:

allProjects { repositories { maven { url 'https://maven.aliyun.com/repository/public/' } maven { url 'https://maven.aliyun.com/repository/spring/' } mavenLocal() mavenCentral() } }

参照するファイル情報を追加します：

dependencies { compile '[GROUP_ID]:[ARTIFACT_ID]:[VERSION]' }

次のコマンドを実行して依存関係をインストールします：

gradle dependencies 
或 
./gradlew dependencies

プライベートリポジトリ

リポジトリの種類：

リポジトリの種類用途
hostedプライベートアーティファクトを格納する
proxyリモートリポジトリをプロキシする
group複数のリポジトリを集約する

プライベートリポジトリへの公開

pom.xml で設定します：

<distributionManagement>
    <repository>
        <id>nexus-releases</id>
        <url>http://your-nexus/repository/maven-releases</url>
    </repository>
    <snapshotRepository>
        <id>nexus-snapshots</id>
        <url>http://your-nexus/repository/maven-snapshots</url>
    </snapshotRepository>
</distributionManagement>

settings.xml で認証を設定します：

<servers>
    <server>
        <id>nexus-releases</id>
        <username>deploy-user</username>
        <password>deploy-pwd</password>
    </server>
</servers>

公開コマンド：

mvn deploy

Maven 依存関係の検索順序

Maven のビルドコマンドを実行すると、Maven は次の順序で依存ライブラリを検索します：

  • 手順 1- ローカルリポジトリ内を検索し、見つからない場合は手順 2 を実行し、見つかった場合は他の操作を実行します。
  • 手順 2- 中央リポジトリ内を検索し、見つからず、1 つ以上のリモートリポジトリが設定されている場合は手順 4 を実行します。見つかった場合は、将来の参照に備えてローカルリポジトリにダウンロードします。
  • 手順 3- リモートリポジトリが設定されていない場合、Maven は処理を停止し、エラー（依存ファイルが見つかりません）をスローします。
  • 手順 4- 1 つ以上のリモートリポジトリで依存ファイルを検索し、見つかった場合は将来の参照に備えてローカルリポジトリにダウンロードします。見つからない場合、Maven は処理を停止してエラー（依存ファイルが見つかりません）をスローします。

よく使うコマンド

コマンド役割
mvn dependency:resolve依存関係を解決する
mvn dependency:tree依存関係ツリーを表示する
mvn dependency:purge-local-repositoryローカルリポジトリをクリーンアップする
mvn deployリモートリポジトリに公開する

よくある問題の解決

1. 依存関係のダウンロード失敗の現象：Could not transfer artifact...

解決方法：
  • ネットワーク接続を確認する
  • リポジトリの URL が正しいか検証する
  • 一時的にファイアウォールを無効にしてテストする

2. 認証失敗の現象：401 Unauthorized

解決方法：

  • settings.xml の <server> 設定を確認する
  • ユーザー名/パスワードにリポジトリへのアクセス権限があるか確認する

3. 依存関係の競合

調査：

mvn dependency:tree -Dverbose

解決方法：<dependencyManagement> でバージョンを統一する
