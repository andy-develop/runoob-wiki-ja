Ollama コマンド完全マニュアル

この章では、Ollama 関連の実行コマンドについて説明します。インストール、モデル管理、実行パラメータ、Modelfile、REST API、環境変数、一般的なトラブルシューティングを網羅しており、すべて Ollama 0.17.x に基づいてまとめています。

インストールと起動

3つのプラットフォームにはそれぞれ標準のインストール方法があります。インストールが完了すると、Ollama は自動的にバックグラウンドサービスとして実行され、リッスンします。127.0.0.1:11434。

プラットフォームインストール方法説明
macOSbrew install ollama公式サイトから dmg インストーラをダウンロードすることもできます。
Linuxcurl -fsSL https://ollama.com/install.sh | sh公式のワンクリックスクリプトで、systemd サービスを自動設定します。
Windows公式サイトからインストーラをダウンロードウィザードに従ってインストールし、システムサービスとして自動登録します。
Dockerdocker run -d -v ollama:/root/.ollama -p 11434:11434 ollama/ollamaデータボリューム ollama にモデルを永続保存します。

ほとんどのシナリオでは手動でサービスを起動する必要はありませんが、トラブルシューティングや一時的な設定変更の際に使用します。ollama serve。

例

# フォアグラウンドでサービスを起動し、ログを端末に直接出力します。トラブルシューティングで最もよく使われます。
ollama serve

# サービスが準備できているか確認： "Ollama is running" が返れば正常です。
curl http://localhost:11434

ポートが使用中であるというメッセージが表示された場合、バックグラウンドサービスがすでに実行されていることを意味します。このとき、別のターミナルで ollama serve を実行するとエラーが発生しますが、これは正常です。そのままコマンドラインまたは API を使用してください。

モデル管理コマンド一覧

モデル管理は Ollama コマンドラインの中心であり、約10個のコマンドを以下の表にすべてまとめています。

コマンド機能例
ollama pull <model>モデルライブラリからモデルをダウンロードします。tag を指定しない場合、デフォルトで latest を取得します。ollama pull qwen3.5:4b
ollama run <model>モデルを対話的に実行します。ローカルにない場合は自動的に pull します。ollama run qwen3.5
ollama list / ollama lsローカルのモデル、サイズ、変更日時を一覧表示します。ollama list
ollama show <model>モデルの詳細を表示：パラメータ、テンプレート、システムプロンプトなどollama show qwen3.5
ollama psメモリにロードされているモデルと残りの有効時間を表示します。ollama ps
ollama stop <model>実行中のモデルをすぐに停止してアンロードします。ollama stop qwen3.5
ollama cp <src> <dst>モデルをコピーまたは名前変更します。ollama cp qwen3.5 runoob-clone
ollama rm <model>ローカルモデルを削除し、ディスク領域を解放します。ollama rm qwen3.5:0.8b
ollama create <name> -f <file>Modelfile に基づいてカスタムモデルを作成します。ollama create runoob-coder -f Modelfile
ollama push <model>モデルをリモートのモデルライブラリにプッシュします。事前にログインが必要です。ollama push myteam/runoob-coder
ollama serveバックグラウンドサービスを起動します。通常はシステムとともに自動実行されます。ollama serve

日常的にもっとも頻繁に使用する組み合わせは run、list、ps、rm の4つです。モデルの実行、在庫の確認、メモリの確認、領域のクリアができます。

例

# 指定したサイズのモデルをダウンロード
ollama pull qwen3.5:0.8b

# コピーして自分の名前に変更
ollama cp qwen3.5 runoob-clone

# コピーが成功したことを確認したら、不要になったサイズを削除
ollama rm qwen3.5:0.8b

rm が削除するのはそのタグに対応するモデルファイルです。他のタグが同じ基盤ウェイト（blobs）を共有している場合、ディスク領域は最後にそれを参照しているタグが削除されて初めて実際に解放されます。

run コマンドと対話モード

run は一度きりの Q&A ツールとしても、複数ターンの対話モードとしても使用でき、実行時のパラメータ変更にも対応しています。

コマンドライン引数

引数はモデル名の後に記述し、今回の実行にのみ有効で、モデル設定には書き込まれません。

例

# 対話的会話
ollama run qwen3.5

# 単発 Q&A：プロンプトをモデル名の後に続けて指定し、回答後に自動終了します。
ollama run qwen3.5 "runoob 菜鸟教程 を一言で紹介してください"

# token 統計を表示：総所要時間、1秒あたりの token 数などのパフォーマンス指標
ollama run qwen3.5 --verbose

# モデルに JSON 形式での出力を強制
ollama run qwen3.5 --format json

# コンテキストウィンドウを拡大（単位は token）
ollama run qwen3.5 --num-ctx 8192

# モデルレイヤーを可能な限り GPU に配置（999 は無制限を意味）
ollama run qwen3.5 --num-gpu 999

対話モード内のスラッシュコマンド

対話モードに入ると、スラッシュで始まるコマンドでセッションの状態を調整できます。これらの調整は現在のセッションにのみ有効です。

コマンド機能
/set parameter <name> <value>推論パラメータを一時的に調整します（temperature など）
/set system <prompt>system プロンプトを一時的に設定します
/show info現在のモデル情報を表示
/show modelfile現在のモデルに対応する Modelfile を表示
/save <name>現在のセッションの設定を新しいモデルとして保存
/load <name>保存済みのモデルまたはセッションをロード
/clear現在の対話コンテキストをクリアしてやり直し
/bye対話モードを終了

スラッシュコマンドで調整したパラメータを長期的に保持したい場合は、/save で新しいモデルとして保存します。これは内部的に Modelfile を生成する処理です。

対話モードを終了するもう1つのショートカットは Ctrl+D です。効果は /bye と同じです。

Modelfile によるカスタムモデル

Modelfile は Dockerfile に似た構文を使用し、「ベースモデル + パラメータ + システムプロンプト」を1つの新しいモデルにパッケージします。

例

# ファイルパス：Modelfile
# FROM でベースモデルを指定（必須）。ローカルの GGUF ファイルパスも指定可能
FROM qwen3.5

# 一般的な推論パラメータ（オプション）
PARAMETER temperature 0.2
PARAMETER num_ctx 8192

# システムプロンプト。モデルの役割と動作を決定します（オプション）
SYSTEM あなたはシニア Python エンジニアです。簡潔で、型注釈付きの、テスト可能なコードを出力してください。

例

# Modelfile を使用して新しいモデルを構築
ollama create runoob-coder -f Modelfile

# 通常のモデルと同じように実行
ollama run runoob-coder "クイックソートをテスト付きで書いてください"

ローカルの GGUF ウェイトをインポートするには、FROM にファイルパスを指定するだけです。オープンソースコミュニティからダウンロードしたモデルファイルを実行する際によく使われます。

例

# ファイルパス：Modelfile
# FROM にローカルの GGUF ウェイトを指定
FROM ./model-file.gguf

Modelfile の全ディレクティブは以下の表のとおりです。最初の3行が最もよく使われる組み合わせです。

ディレクティブ機能必須かどうか
FROMベースモデルまたは GGUF ファイルパスを指定必須
PARAMETER推論パラメータを設定：temperature、num_ctx、top_p、stop などオプション
SYSTEMシステムプロンプトを設定オプション
TEMPLATE対話プロンプトテンプレートをカスタマイズオプション
ADAPTERLoRA アダプタをロードオプション
MESSAGE対話例をプリセットし、few-shot ガイダンスを実現オプション
LICENSEモデルのライセンスを宣言オプション

既存のモデルをベースに改造したいが、ゼロから書きたいわけではない場合は、まず次を実行します。ollama show --modelfile 模型名完全なレシピをエクスポートし、修正後に create を実行するだけです。

REST API クイックリファレンス

Ollama サービス起動後、デフォルトでリッスンします。http://localhost:11434CLI でできることはすべて API でもできます。

エンドポイントメソッド機能
/api/generatePOST単発のテキスト生成。デフォルトでストリーミング返信
/api/chatPOST複数ターンの対話。messages 配列で履歴を渡します
/api/embedPOSTテキストのベクトル埋め込みを生成し、RAG 検索に使用
/api/tagsGETローカルモデルを一覧表示。ollama list に対応
/api/showPOSTモデルの詳細を表示。ollama show に対応
/api/pullPOSTモデルを取得。ollama pull に対応
/api/deleteDELETEモデルを削除。ollama rm に対応

例

# 単発生成（ストリーミング）
curl http://localhost:11434/api/generate -d '{
  "model": "qwen3.5",
"prompt": "Python で Hello World を書いてください"
}'

# 複数ターンの対話
curl http://localhost:11434/api/chat -d '{
  "model": "qwen3.5",
"messages": [{"role": "user", "content": "REST API とは何か説明してください"}]
}'

# ベクトル埋め込みを生成
curl http://localhost:11434/api/embed -d '{
  "model": "nomic-embed-text",
"input": "あなたのテキスト内容"
}'

# ローカルモデルを一覧表示
curl http://localhost:11434/api/tags

# モデルの詳細を表示
curl http://localhost:11434/api/show -d '{"model": "qwen3.5"}'

# モデルを削除
curl -X DELETE http://localhost:11434/api/delete -d '{"model": "qwen3.5"}'

OpenAI 互換インターフェース

Ollama は OpenAI 互換エンドポイントを提供します/v1/chat/completions既存のOpenAIエコシステムのコードは、base_urlをローカルに向けるだけでそのまま使えます。

例

# ファイルパス：openai_compat.py
from openai import OpenAI

# base_url はローカルの Ollama を指定。api_key は空でない任意の文字列でOK
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

resp = client.chat.completions.create(
    model="qwen3.5",  # ローカルにダウンロード済みのモデル名
    messages=[{"role": "user", "content": "こんにちは、runoobについて紹介してください"}],
)
print(resp.choices[0].message.content)
$ python3 openai_compat.py
你好！runoob（菜鸟教程）是一个面向初学者的编程学习网站，提供大量免费的基础技术教程。

環境変数クイックリファレンス

環境変数は Ollama サービスの動作を設定する主要な方法です。変更後はサービスの再起動が必要です。

変数説明デフォルト値
OLLAMA_HOSTサービスがリッスンするアドレス。0.0.0.0 は LAN からのアクセスを許可することを示します127.0.0.1:11434
OLLAMA_MODELSモデルの保存パス。大容量ディスクに交換するときに使用します~/.ollama/models
OLLAMA_NUM_GPUGPU に配置するモデルのレイヤー数。999 はすべてを意味します自動
OLLAMA_NUM_PARALLEL同一モデルへの同時リクエスト数自動
OLLAMA_MAX_LOADED_MODELSメモリに常駐させる最大モデル数自動
OLLAMA_FLASH_ATTENTIONFlash Attention を有効化。長いコンテキストでは有効にすることを推奨オフ
OLLAMA_KEEP_ALIVEモデルがアイドル状態になってからメモリからアンロードされるまでの時間5m
OLLAMA_DEBUGデバッグログを有効化し、より詳細な実行情報を出力しますオフ

例

# LAN からのアクセスを許可 + モデルをデータディスクへ移動
export OLLAMA_HOST=0.0.0.0:11434
export OLLAMA_MODELS=/data/ollama-models
ollama serve

OLLAMA_KEEP_ALIVE を 0 に設定すると、各リクエスト後にモデルが即座にアンロードされ、メモリは節約できますが、リクエストのたびに再読み込みが必要になります。常駐させたい場合は -1 に設定します。この値の書き方はバージョンによって異なるため、`ollama serve --help` と公式ドキュメントを基準にしてください。

よくある問題のトラブルシューティング

異常が発生したら、まず以下の表で原因を特定してください。ほとんどの問題は「モデル名が間違っている、サービスが起動していない、リソースが不足している」の3つに分類されます。

問題調査手順
ビデオメモリ / メモリ不足（OOM）より小さいモデル仕様または低い量子化精度に変更します。例：9b の代わりに 4b を使用
model not found というメッセージが表示されるモデル名とタグが正しいか確認します。タグはコロンで区切ります。例：qwen3.5:4b（qwen3.5-4b ではありません）
connection refusedサービスが実行中かどうか確認し、11434 番ポートが使用されているかチェックします
応答が遅い`ollama ps` で PROCESSOR 列を確認し、モデルが実際に GPU 上で動作しているかを確認します。num_ctx を適切に小さくします
複数バージョンのモデルの混同タグを書かない場合、内部ルールで「最新」バージョンが選ばれます。常に完全なタグを明示的に指定することをお勧めします

一行クイックリファレンス

最後に、最もよく使うコマンドを1つの表にまとめました。コピーしてそのまま使えます。

コマンド機能
ollama pull <model>モデルのダウンロード
ollama run <model>モデルの実行 / 対話モードに入る
ollama listダウンロード済みモデルの確認
ollama show <model>モデル詳細の確認
ollama ps実行中モデルの確認
ollama stop <model>モデルの停止とアンロード
ollama rm <model>モデルの削除
ollama cp <old> <new>モデルのコピー / 名前変更
ollama create <name> -f ModelfileModelfile を使用してカスタムモデルを作成
ollama serveサービスの起動

Ollama は更新が速く、パラメータやコマンドの動作がバージョンに応じて調整される場合があります。作業前に `ollama --help` と公式ドキュメントを確認してください。
