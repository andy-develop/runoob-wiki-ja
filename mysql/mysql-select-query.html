MySQL データのクエリ

MySQL データベースの使用SELECT文を使用してデータをクエリします。

あなたは次の方法でmysql>コマンドプロンプトウィンドウでデータベース内のデータをクエリするか、PHP スクリプトを使用してデータをクエリできます。

構文

以下は、MySQL データベースでデータをクエリするための一般的な SELECT 構文です：

SELECT column1, column2, ...
FROM table_name
[WHERE condition]
[ORDER BY column_name [ASC | DESC]]
[LIMIT number];

パラメータの説明：

  • column1, column2, ... は選択したい列の名前です。* を使用する場合*すべての列を選択することを意味します。
  • table_nametable_name は、データをクエリするテーブルの名前です。
  • WHERE conditionWHERE condition はオプションの句であり、フィルタ条件を指定し、条件に一致する行のみを返すために使用します。
  • ORDER BY column_name [ASC | DESC]ORDER BY column_name はオプションの句であり、結果セットの並べ替え順序を指定するために使用します。デフォルトは昇順（ASC）です。
  • LIMIT numberLIMIT はオプションの句であり、返される行数を制限するために使用します。

MySQL SELECT 文の簡単な適用例：

例

-- すべての列のすべての行を選択
SELECT * FROM users;

-- 特定の列のすべての行を選択
SELECT username, email FROM users;

-- WHERE 句を追加して、条件を満たす行を選択
SELECT * FROM users WHERE is_active = TRUE;

-- ORDER BY 句を追加して、特定の列の昇順で並べ替え
SELECT * FROM users ORDER BY birthdate;

-- ORDER BY 句を追加して、特定の列の降順で並べ替え
SELECT * FROM users ORDER BY birthdate DESC;

-- LIMIT 句を追加して、返される行数を制限
SELECT * FROM users LIMIT 10;

SELECT 文は柔軟です。実際のニーズに応じてこれらの句を組み合わせて使用できます。たとえば、WHERE と ORDER BY 句を同時に使用したり、LIMIT を使用して返される行数を制御したりできます。

にWHERE句の中では、さまざまな条件演算子（例：=, <, >, <=, >=, !=）、論理演算子（例：AND, OR, NOT）、およびワイルドカード（例：%）など。

以下は、上級の SELECT 文の例です：

例

-- AND 演算子とワイルドカードを使用
SELECT * FROM users WHERE username LIKE 'j%' AND is_active = TRUE;

-- OR 演算子を使用
SELECT * FROM users WHERE is_active = TRUE OR birthdate < '1990-01-01';

-- IN 句を使用
SELECT * FROM users WHERE birthdate IN ('1990-01-01', '1992-03-15', '1993-05-03');

PHP スクリプトを使用してデータを取得する

PHP 関数のmysqli_query() 及 SQL SELECTコマンドを使用してデータを取得します。

この関数は SQL コマンドを実行するために使用され、その後 PHP 関数mysqli_fetch_array() を使用して、クエリされたすべてのデータを使用または出力します。

mysqli_fetch_array() 関数は結果セットから 1 行を連想配列、数値配列、またはその両方として取得します。 結果セットから取得した行に基づいて生成された配列を返し、それ以上行がない場合は false を返します。

次の例では、データテーブル runoob_tbl からすべてのレコードを読み取ります。

例

次の例を試して、データテーブル runoob_tbl のすべてのレコードを表示します。

mysqli_fetch_array の MYSQLI_ASSOC パラメータを使用してデータを取得する：

<?php $dbhost = 'localhost'; //MySQL サーバーのホストアドレス $dbuser = 'root'; //MySQL ユーザー名 $dbpass = '123456'; //MySQL ユーザー名のパスワード $conn = mysqli_connect($dbhost, $dbuser, $dbpass); if(! $conn ) { die('接続失敗:' . mysqli_error($conn)); } //文字コードを設定し、中国語の文字化けを防止 mysqli_query($conn , "set names utf8"); $sql = 'SELECT runoob_id, runoob_title, runoob_author, submission_date FROM runoob_tbl'; mysqli_select_db( $conn, 'RUNOOB' ); $retval = mysqli_query( $conn, $sql ); if(! $retval ) { die('データを読み取れません:' . mysqli_error($conn)); } echo '<h2>菜鸟教程 mysqli_fetch_array テスト</h2>'; echo '<table border="1"><tr><td>チュートリアル ID</td><td>タイトル</td><td>著者</td><td>提出日</td></tr>'; while($row = mysqli_fetch_array($retval, MYSQLI_ASSOC)) { echo "<tr><td> {$row['runoob_id']}</td> ". "<td>{$row['runoob_title']} </td> ". "<td>{$row['runoob_author']} </td> ". "<td>{$row['submission_date']} </td> ". "</tr>"; } echo '</table>'; mysqli_close($conn); ?>

    MySQL limit の応用例。

    構文形式：

    SELECT * FROM table LIMIT [offset,] rows | rows OFFSET offset

    解説：LIMIT 句は、SELECT 文が指定したレコード数を返すように強制するために使用できます。LIMIT は 1 つまたは 2 つの数値引数を受け取ります。引数は整数定数である必要があります。2 つの引数が指定された場合、最初の引数は最初に返されるレコード行のオフセットを指定し、2 番目の引数は返されるレコード行の最大数を指定します。最初のレコード行のオフセットは 0 です（1 ではありません）。PostgreSQL との互換性のため、MySQL も構文 LIMIT # OFFSET # をサポートしています。

    mysql> SELECT * FROM table LIMIT 5,10; // 检索记录行 6-15   
  
//如果只给定一个参数，它表示返回最大的记录行数目：    
mysql> SELECT * FROM table LIMIT 5; //检索前 5 个记录行   
  
//换句话说，LIMIT n 等价于 LIMIT 0,n。

    MySQL のページングクエリ文のパフォーマンス分析

    MySql のページネーション SQL 文は、MSSQL の TOP 構文と比較すると、MySQL の LIMIT 構文の方がはるかに優雅に見えます。それを使ってページネーションを行うのはごく自然なことです。

    2.1 最も基本的なページネーション方法：

    SELECT ... FROM ... WHERE ... ORDER BY ... LIMIT ...

    中小規模のデータ量の場合、このような SQL で十分です。唯一注意すべき点は、インデックスが使用されていることを確認することです。

    例えば、実際の SQL が以下のような文の場合、category_id, id の2つの列に複合インデックスを構築するのが良いでしょう。

    SELECT * FROM articles WHERE category_id = 123 ORDER BY id LIMIT 50, 10

    2.2 サブクエリによるページネーション方法

    データ量の増加に伴い、ページ数がどんどん増え、後半のページを表示する SQL は次のようになるかもしれません：

    SELECT * FROM articles WHERE category_id = 123 ORDER BY id LIMIT 10000, 10

    一言で言えば、ページを進めるほど LIMIT 文のオフセットが大きくなり、速度も明らかに遅くなります。

    この場合、サブクエリを使用してページネーションの効率を向上させることができます。おおよそ次のようになります：

    SELECT * FROM articles WHERE  id >=
 (SELECT id FROM articles  WHERE category_id = 123 ORDER BY id LIMIT 10000, 1) LIMIT 10

    2.3 JOIN によるページネーション方法

    SELECT * FROM `content` AS t1    
JOIN (SELECT id FROM `content` ORDER BY id desc LIMIT ".($page-1)*$pagesize.", 1) AS t2    
WHERE t1.id <= t2.id ORDER BY t1.id desc LIMIT $pagesize;

    私のテストによると、join ページネーションとサブクエリページネーションの効率は基本的に同じレベルで、消費時間もほぼ同じです。

    explain SQL 文：

    id select_type table type possible_keys key key_len ref rows Extra

1 PRIMARY <derived2> system NULL NULL NULL NULL 1  

1 PRIMARY t1 range PRIMARY PRIMARY 4 NULL 6264 Using where

2 DERIVED content index NULL PRIMARY 4 NULL 27085 Using index

    なぜそうなるのでしょうか？サブクエリはインデックス上で実行されますが、通常のクエリはデータファイル上で実行されるからです。一般的に、インデックスファイルはデータファイルよりもはるかに小さいため、操作もより効率的になります。

    実際には、ストラテジーパターンに似た方法でページネーションを処理できます。例えば、100ページ以内であれば最も基本的なページネーション方法を使用し、100ページを超える場合はサブクエリによるページネーション方法を使用する、といった具合です。

    SQL 文の結合クエリ

    左結合（LEFT JOIN）:left join ... on ...

    右結合（RIGHT JOIN）:right join... on ...

    形式:

    select 字段 from 表1 left join 表2 on  条件 (一般为表1与表2的关联条件)

    ユーザーのすべての注文情報をクエリする :

    user 用户表   
orders 订单表
    select * from user left join orders on user.id = orders.user_id

    少し複雑にして、ユーザーの注文数を集計します（ユーザーのidでグループ化する必要があります）

    select user.username,orders.id,count(*) from user right join orders on user.id = orders.user_id GROUP BY user.id;
mysql> select user.username,orders.id,count(*) from user right join orders on user.id = orders.user_id GROUP BY user.id;

| 王五     |  3 |        2 |
| 张三     |  5 |        1 |

2 rows in set (0.07 sec)

    ここでは、王五（id=3）という名前のユーザーに2件の注文、張三（id=5）に1件の注文があることを示しています。

    ここでは右結合クエリを使用しています。右結合を使うのは理にかなっています。なぜなら左結合と右結合は異なるクエリだからです。違いは、left join on は左側のテーブルを主テーブルとし、right join on は右側のテーブルを主テーブルとすることです。

    MySQL のページネーションクエリ

    バックエンドで mysql 文を書いてフロントエンドのページネーションクエリ要求を処理するのは実は非常に簡単で、limit を使うだけです。

    例：

    select * from foo limit 100,200

    100 はオフセットを指し、200 はクエリ件数を指します。

    したがって、バックエンドコードは2つのパラメータを受け取る必要があります：オフセット（offset）、クエリ件数（rows）。

    フロントエンドからバックエンドに渡すパラメータは、page_num（何ページ目か）、page_size（各ページに表示するデータ件数）にすることができます。バックエンドは page_num と page_size を受け取った後、(page_num - 1) * page_size という式で offset を換算できます。クエリ件数（rows）は page_size です。

    バックエンドコード全体：

    def paging(page_count, page_size):
    table_name = 'Test'
    offset = (page_count - 1) * page_size
    sql = 'select * from %s limit %d, %d'%(table_name, offset, page_size)
    print(sql)
    conn.execute(sql)
    conn.commit()
