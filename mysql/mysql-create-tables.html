MySQL テーブルの作成

MySQL テーブルの作成には以下の情報が必要です：

  • テーブル名
  • テーブルのフィールド名
  • 各テーブルフィールドのデータ型を定義する

構文

以下は MySQL テーブルを作成するための SQL の一般的な構文です：

CREATE TABLE table_name (
    column1 datatype,
    column2 datatype,
    ...
);

パラメータの説明：

  • table_name作成するテーブルの名前です。
  • column1, column2, ... はテーブルの列名です。
  • datatype各列のデータ型です。

以下は、ユーザーテーブルを作成する具体的な例です。users：

例

CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL,
    birthdate DATE,
    is_active BOOLEAN DEFAULT TRUE
);

例の解説：

  • id: ユーザーID、整数型、自動増加、主キーとして。
  • username: ユーザー名、可変長文字列、NULL を許可しない。
  • email: ユーザーメール、可変長文字列、NULL を許可しない。
  • birthdate: ユーザーの誕生日、日付型。
  • is_active: ユーザーがアクティブ化されているかどうか、ブール型、デフォルト値は true。

上記は単純な例であり、INT、VARCHAR、DATE、BOOLEAN などの一般的なデータ型を使用しています。実際のニーズに応じてさまざまなデータ型を選択できます。AUTO_INCREMENT キーワードは自動増加列を作成するために使用され、PRIMARY KEY は主キーを定義するために使用されます。

テーブル作成時にストレージエンジン、文字セット、照合順序などを指定したい場合は、次を使用できます。CHARACTER SET 和 COLLATE句：

例

CREATE TABLE mytable (
    id INT PRIMARY KEY,
    name VARCHAR(50)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

上記のコードは、utf8mb4 文字セットと utf8mb4_general_ci 照合順序を使用するテーブルを作成します。

以下の例では、RUNOOB データベースにテーブル runoob_tbl を作成します：

例

CREATE TABLE IF NOT EXISTS `runoob_tbl`(
   `runoob_id` INT UNSIGNED AUTO_INCREMENT,
   `runoob_title` VARCHAR(100) NOT NULL,
   `runoob_author` VARCHAR(40) NOT NULL,
   `submission_date` DATE,
   PRIMARY KEY ( `runoob_id` )
)ENGINE=InnoDB DEFAULT CHARSET=utf8;

例の解説：

  • フィールドを ... にしたくない場合、空フィールドの属性を ... に設定できます。NOT NULL上記の例の runoob_title と runoob_author フィールドのように、データベース操作時にこのフィールドのデータが空の場合、エラーが発生します。

  • AUTO_INCREMENT列を自動増加の属性として定義します。通常は主キーに使用され、数値は自動的に 1 加算されます。
  • PRIMARY KEYキーワードは列を主キーとして定義するために使用されます。複数の列を使用して主キーを定義できます。列間はカンマで,区切ります。
  • ENGINEストレージエンジンを設定し、CHARSET文字セットを設定します。

コマンドプロンプトでテーブルを作成する

を使用すると mysql>コマンドウィンドウで非常に簡単に MySQL テーブルを作成できます。

SQL 文を使用してCREATE TABLEテーブルを作成できます。

例

以下はテーブル runoob_tbl を作成する例です：

例

root@host# mysql -u root -p
Enter password:*******
mysql> USE RUNOOB;
DATABASE changed
mysql> CREATE TABLE runoob_tbl(
   -> runoob_id INT NOT NULL AUTO_INCREMENT,
   -> runoob_title VARCHAR(100) NOT NULL,
   -> runoob_author VARCHAR(40) NOT NULL,
   -> submission_date DATE,
   -> PRIMARY KEY ( runoob_id )
   -> )ENGINE=InnoDB DEFAULT CHARSET=utf8;
Query OK, 0 ROWS affected (0.16 sec)
mysql>

注意：MySQL コマンドの終端記号はセミコロンです。; 。

注意： ->は改行文字の識別子です。コピーしないでください。

PHP スクリプトを使用してテーブルを作成する

PHP のmysqli_query()関数を使用して、既存のデータベース内のテーブルを作成します。

この関数には2つのパラメータがあり、実行が成功すると TRUE を返し、そうでなければ FALSE を返します。

構文

mysqli_query(connection,query,resultmode);
パラメータ 説明
connection 必須。使用する MySQL 接続を指定します。
query 必須。クエリ文字列を指定します。
resultmode

オプション。定数です。次のいずれかの値を指定できます：

  • MYSQLI_USE_RESULT（大量のデータを取得する必要がある場合はこれを使用してください）
  • MYSQLI_STORE_RESULT（デフォルト）

例

以下の例では、PHP スクリプトを使用してテーブルを作成しています：

テーブルの作成

<?php $dbhost = 'localhost'; //MySQL サーバーのホストアドレス $dbuser = 'root'; //MySQL ユーザー名 $dbpass = '123456'; //MySQL ユーザー名のパスワード $conn = mysqli_connect($dbhost, $dbuser, $dbpass); if(! $conn ) { die('接続失敗：' . mysqli_error($conn)); } echo '接続成功<br />'; $sql = "CREATE TABLE runoob_tbl( ". "runoob_id INT NOT NULL AUTO_INCREMENT, ". "runoob_title VARCHAR(100) NOT NULL, ". "runoob_author VARCHAR(40) NOT NULL, ". "submission_date DATE, ". "PRIMARY KEY ( runoob_id ))ENGINE=InnoDB DEFAULT CHARSET=utf8; "; mysqli_select_db( $conn, 'RUNOOB' ); $retval = mysqli_query( $conn, $sql ); if(! $retval ) { die('テーブルの作成失敗：' . mysqli_error($conn)); } echo "テーブルの作成成功\n"; mysqli_close($conn); ?>

    MySQL のフィールド属性はできるだけ NOT NULL に設定すべきです

    NULL 値を使用する特別な理由がない限り、常にフィールドを NOT NULL に保つべきです。これは少し議論があるように見えますが、以下をお読みください。

    1、まず、空値"" 和 NULLの概念を明確にしましょう：

    • 1）空値はスペースを占有しません。
    • 2）MySQL の NULL は実際にはスペースを占有します。

    いわゆる NULL とは、何もないことであり、\0さえもない、\0文字列では終端文字ですが、物理メモリではスペースを占有し、1バイトに相当します。しかし NULL は、その1バイトさえも持ちません。

    2、次に、データベースでは厳密に区別されます。任意の数と NULL との演算はすべて NULL になります。値が NULL に等しいかどうかを判断するには、単に = を使用するのではなく、IS NULL キーワードを使用する必要があります。

    3、データベースのフィールド col1 を NOT NULL に設定することは、そのフィールドが NULL になることができないことを示すだけで、つまり、以下の場合にのみ:

    INSERT INTO table1(col1) VALUES(NULL);

    この場合、データベースはエラーになります。一方:

    INSERT INTO table1(col1) VALUES('');

    エラーにはなりません。

    （フィールドが自動増加 ID の場合、最初の文ではエラーになりません。これは NULL を許可していることを示すのではなく、データベースシステムが ID に設定されたデフォルト値で埋めるか、自動増加フィールドの場合は自動的に 1 加算するなどのデフォルト操作を行うからです。）

    4、空値を含む列はクエリの最適化が難しく、またテーブルのインデックス作成時には NULL 値は保存されないため、インデックスのフィールドが NULL を許可すると、インデックスの効率は大幅に低下します。それらはインデックス、インデックスの統計情報、比較演算をより複雑にするからです。空値の代わりに 0、特別な値、または空文字列を使用するべきです。

    5、テーブル結合クエリのとき、例えば LEFT JOIN table2 の場合、レコードがなければ、取得される table2 のフィールドはすべて null になります。table2 の一部のフィールド自体が null を許可している場合、table2 内の not null のフィールドを取得しない限り、関連レコードがないのか、それとも別の状況なのかを区別するのが難しくなります。

    MySQL ストレージエンジン InnoDB と MyISAM

    ENGINE = innodb

    ストレージエンジンは innodb です。innodb は MySQL 上で最初に外部キー制約を提供するデータストレージエンジンです。トランザクション処理を提供するだけでなく、InnoDB は行ロックをサポートし、Oracle と同じ一貫性のある非ロック読み取りを提供します。これにより、同時読み取りユーザー数を増やしてパフォーマンスを向上させることができ、ロックの数は増えません。InnoDB の設計目標は、大容量データを処理する際にパフォーマンスを最大化することであり、その CPU 利用率は、ディスクベースの他のすべてのリレーショナルデータベースエンジンの中で最も効率的です。

    InnoDB は MySQL のバックグラウンドに置かれた完全なデータベースシステムです。InnoDB には独自のバッファプールがあり、データとインデックスをバッファすることができます。また InnoDB はデータとインデックスをテーブルスペースに格納し、複数のファイルを含む場合があります。これは MyISAM テーブルとはまったく異なります。MyISAM では、テーブルは個別のファイルに格納されます。InnoDB テーブルのサイズはオペレーティングシステムのファイルサイズにのみ制限され、通常は 2GB です。

    詳細については、次を参照してください：MySQL ストレージエンジン InnoDB と MyISAM の6つの違い
