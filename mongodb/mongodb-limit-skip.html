MongoDB Limit と Skip メソッド

MongoDB Limit() メソッド

MongoDB で指定された数のデータレコードを読み取る必要がある場合は、MongoDB の limit() メソッドを使用できます。指定された数のドキュメントをスキップしてデータを読み取りたい場合は、skip() メソッドを使用できます。

limit() メソッドはクエリ結果で返されるドキュメント数を制限するために使用され、skip() メソッドは指定された数のドキュメントをスキップするために使用されます。この2つのメソッドは通常一緒に使用され、ページネーションクエリや大規模データセットでのバッチ処理を実装するために使用できます。

limit() メソッド

limit() メソッドは、クエリ結果で返されるドキュメント数を制限するために使用されます。

構文

limit() メソッドの基本構文は次のとおりです：

db.collection.find().limit(<limit>)
  • <limit>：返されるドキュメント数。

例

// 最初の10個のドキュメントを返す
db.myCollection.find().limit(10);

例

コレクション col のデータは次のとおりです：

{ "_id" : ObjectId("56066542ade2f21f36b0313a"), "title" : "PHP 教程", "description" : "PHP 是一种创建动态交互性站点的强有力的服务器端脚本语言。", "by" : "菜鸟教程", "url" : "http://www.runoob.com", "tags" : [ "php" ], "likes" : 200 }
{ "_id" : ObjectId("56066549ade2f21f36b0313b"), "title" : "Java 教程", "description" : "Java 是由Sun Microsystems公司于1995年5月推出的高级程序设计语言。", "by" : "菜鸟教程", "url" : "http://www.runoob.com", "tags" : [ "java" ], "likes" : 150 }
{ "_id" : ObjectId("5606654fade2f21f36b0313c"), "title" : "MongoDB 教程", "description" : "MongoDB 是一个 Nosql 数据库", "by" : "菜鸟教程", "url" : "http://www.runoob.com", "tags" : [ "mongodb" ], "likes" : 100 }

次の例は、クエリされたドキュメント内の2件のレコードを表示します：

> db.col.find({},{"title":1,_id:0}).limit(2)
{ "title" : "PHP 教程" }
{ "title" : "Java 教程" }
>

注：limit() メソッドのパラメータを指定しない場合は、コレクション内のすべてのデータが表示されます。

skip() メソッド

limit() メソッドを使用して指定された数のデータを読み取ることに加えて、skip() メソッドを使用して指定された数のデータをスキップすることもできます。skip() メソッドも同様に、スキップするレコード数を示す数値パラメータを受け取ります。

skip() メソッドは、指定された数のドキュメントをスキップして、ページネーションやバッチクエリを実現するために使用されます。

構文

skip() メソッドの構文形式は次のとおりです：

db.collection.find().skip(<skip>)
  • <skip>：スキップするドキュメント数。

例

// 最初の10個のドキュメントをスキップし、次の10個のドキュメントを返す
db.myCollection.find().skip(10).limit(10);

例

次の例では、2番目のドキュメントデータのみが表示されます。

>db.col.find({},{"title":1,_id:0}).limit(1).skip(1)
{ "title" : "Java 教程" }
>

ページネーションクエリ：

例

// 1ページ目、各ページ10個のドキュメント
db.myCollection.find().skip(0).limit(10);

// 2ページ目、各ページ10個のドキュメント
db.myCollection.find().skip(10).limit(10);

// 3ページ目、各ページ10個のドキュメント
db.myCollection.find().skip(20).limit(10);

注：skip() メソッドのデフォルトパラメータは 0 です。

注意事項

  • skip() 和 limit()メソッドは通常、組み合わせて使用され、ページネーションクエリを実現します。ただし、大規模データセットでの使用はskip()パフォーマンスの問題を引き起こす可能性があります。MongoDB はクエリの実行時に指定された数のドキュメントをスキャンしてスキップする必要があるため、必要な場合にのみ使用することをお勧めしますskip()メソッドは、大規模データセット上で連続して使用することをできるだけ避けてください。
  • 組み合わせる場合skip() 和 limit()のとき、skip()すべきですlimit()の前に使用して、予期しない動作を避けてください。

を使用することでlimit() 和 skip()メソッドを使用すると、MongoDB でのクエリ結果のページネーション処理を実装でき、クエリの柔軟性とパフォーマンスを向上させることができます。

    補足説明：skip と limit メソッドは小規模データのページネーションにのみ適しています。100万単位になると効率が非常に低くなります。skip メソッドはデータを1件ずつ数えていくためです。where_limit の使用をお勧めします。

    いくつかの資料を調べたところ、すべての資料が次のように述べていました：

    Skip を安易にクエリに使用しないでください。そうしないと、データ量が多くなった場合にパフォーマンスが急激に低下します。これは、Skip が1件ずつ数えていくためで、数が多くなれば自然と遅くなるからです。

    ということは、Skip の使用は避けるべきだということです。では、どうすれば避けられるのでしょうか？まず、SQL ページネーションの後者の方式であるタイムスタンプページネーション方式を振り返ってみましょう。この方式はフィールドの順序性を利用し、クエリを利用してデータを取得するため、大量の数え上げを直接回避できます。つまり、そのような条件を付けることができればクエリ効率は向上するはずですが、実際にそうなのでしょうか？検証してみましょう：

    ここでは、100001件目のデータをクエリすると仮定します。このデータの Amount の値は 2399927 です。2つのステートメントをそれぞれ次のように書いてみましょう：

    b.test.sort({"amount":1}).skip(100000).limit(10)  //183ms
db.test.find({amount:{$gt:2399927}}).sort({"amount":1}).limit(10)  //53ms

    結果はすでにコメントに添付されています。明らかに後者のパフォーマンスは前者の3分の1であり、その差は非常に大きいです。これは Skip の効率が悪いという理論を裏付けています。

    limit(n) は表示する件数を指定するために使用され、skip(n) は条件に一致するレコードのうち、最初のレコードからスキップする件数を指定するために使用されます。この2つの関数は入れ替えて使用できます。

    例：find({},{age:1,_id:0}).limit(2).skip(1) の場合、条件に一致するドキュメントのうち2件のドキュメントを表示し、表示位置は最初のレコードをスキップした後から始まります。これはあまり理解しやすいとは言えません。

    find({},{age:1,_id:0}).skip(1).limit(2) と書くと、条件に一致するドキュメントのうち、最初に最初のドキュメントをスキップし、その後2件のドキュメントを表示するため、理解しやすくなります。
