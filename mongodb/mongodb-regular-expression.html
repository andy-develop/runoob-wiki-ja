MongoDB 正規表現

正規表現は、単一の文字列を使用して、特定の構文規則に一致する一連の文字列を記述・照合するものです。

多くのプログラミング言語が、正規表現を使用した文字列操作をサポートしています。

MongoDB は$regex演算子を使用して、一致する文字列の正規表現を設定します。

MongoDB は PCRE (Perl Compatible Regular Expression) を正規表現言語として使用します。

全文検索とは異なり、正規表現を使用する場合、追加の設定は一切必要ありません。

以下を考慮してくださいpostsコレクションのドキュメント構造です。このドキュメントには記事の内容とタグが含まれています。

{
   "post_text": "enjoy the mongodb articles on runoob",
   "tags": [
      "mongodb",
      "runoob"
   ]
}

正規表現を使用する

次のコマンドは、正規表現を使用して runoob という文字列を含む記事を検索します。

>db.posts.find({post_text:{$regex:"runoob"}})

上記のクエリは次のようにも記述できます：

>db.posts.find({post_text:/runoob/})

大文字と小文字を区別しない正規表現

検索で大文字と小文字を区別する必要がない場合は、$options を $i に設定できます。

次のコマンドは、大文字と小文字を区別せずに文字列 runoob を検索します。

>db.posts.find({post_text:{$regex:"runoob",$options:"$i"}})

コレクション内の runoob という文字列を含むすべてのデータが、大文字と小文字を区別せずに返されます。

{
   "_id" : ObjectId("53493d37d852429c10000004"),
   "post_text" : "hey! this is my post on  runoob", 
   "tags" : [ "runoob" ]
}

配列要素での正規表現の使用

配列フィールドでも正規表現を使用して内容を検索できます。これはタグの実装に非常に便利です。run で始まるタグデータ（ru、run、runoob）を検索する必要がある場合は、次のコードを使用できます：

>db.posts.find({tags:{$regex:"run"}})

正規表現クエリの最適化

  • ドキュメントのフィールドにインデックスが設定されている場合、インデックスを使用すると、正規表現でマッチングしてすべてのデータを検索するよりもクエリ速度が速くなります。
  • 正規表現がプレフィックス式の場合、一致するすべてのデータは指定されたプレフィックス文字列で始まります。例： ^tut クエリ文は tut で始まる文字列を検索します。

ここで正規表現を使用する際、注意すべき点が2つあります：

正規表現内で変数を使用する場合。必ず eval を使用して組み合わせた文字列を変換してください。文字列を単純に連結して式に渡すことはできません。そうしないとエラーは表示されず、結果が空になるだけです。例は次のとおりです：

var name=eval("/" + 变量值key +"/i");

以下は、title キーワードを含むあいまい検索を、大文字と小文字を区別せずに行う例です：

title:eval("/"+title+"/i")    // 等同于 title:{$regex:title,$Option:"$i"}

    regex 演算子の紹介

    MongoDB は $regex 演算子を使用して、一致する文字列の正規表現を設定し、PCRE (Pert Compatible Regular Expression) を正規表現言語として使用します。

    • regex 演算子
      • {<field>:{$regex:/pattern/，$options:’<options>’}}
      • {<field>:{$regex:’pattern’，$options:’<options>’}}
      • {<field>:{$regex:/pattern/<options>}}
    • 正規表現オブジェクト
      • {<field>: /pattern/<options>}

    $regex と正規表現オブジェクトの違い：

    • $in 演算子では正規表現オブジェクトのみを使用できます。例: {name:{$in:[/^joe/i,/^jack/}}
    • 暗黙の $and 演算子を使用する場合、$regex のみを使用できます。例: {name:{$regex:/^jo/i, $nin:['john']}}
    • option オプションに X または S オプションが含まれる場合、$regex のみを使用できます。例: {name:{$regex:/m.*line/,$options:"si"}}

    $regex 演算子の使用

    $regex 演算子の option オプションは、正規表現マッチングのデフォルトの動作を変更できます。これには i、m、x、S の4つのオプションが含まれ、その意味は次のとおりです。

    • i は大文字と小文字を無視します。{<field>{$regex/pattern/i}}。i オプションを設定すると、パターン内の文字は大文字と小文字を区別しないマッチングを行います。
    • m は複数行マッチングモードです。{<field>{$regex/pattern/,$options:'m'}。m オプションは ^ と $ メタ文字のデフォルトの動作を変更し、それぞれ入力文字列の先頭と末尾ではなく、行の先頭と末尾にマッチします。
    • x はエスケープされていない空白文字を無視します。{<field>:{$regex:/pattern/,$options:'m'}。x オプションを設定すると、正規表現内のエスケープされていない空白文字が無視され、同時に#（シャープ）はコメントの先頭として解釈されます。これは option オプションに明示的に指定した場合のみ有効です。
    • s は単一行マッチングモードです。{<field>:{$regex:/pattern/,$options:'s'}。s オプションを設定すると、パターン内のドット(.)メタ文字のデフォルトの動作が変更され、改行文字(\n)を含むすべての文字にマッチします。これは option オプションに明示的に指定した場合のみ有効です。

    $regex 演算子を使用する際は、以下の点に注意する必要があります：

    • i、m、x、s は組み合わせて使用できます。例: {name:{$regex:/j*k/,$options:"si"}}
    • インデックスが設定されたフィールドで正規表現マッチングを行うとクエリ速度が向上します。また、正規表現がプレフィックス式の場合、クエリ速度はさらに向上します。例: {name:{$regex: /^joe/}
