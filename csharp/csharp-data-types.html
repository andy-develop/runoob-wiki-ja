C# データ型

C# では、変数は以下のいくつかの型に分けられます：

  • 値型（Value types）
  • 参照型（Reference types）
  • ポインタ型（Pointer types）

値型（Value types）

値型の変数は直接値を割り当てることができます。これらはクラスからSystem.ValueType派生しています。

値型はデータを直接含みます。例えばint、char、float、それらはそれぞれ数値、文字、浮動小数点数を格納します。型を宣言すると、intシステムは値を格納するためにメモリを割り当てます。

型または変数の特定プラットフォームでの正確なサイズを取得するには、sizeofメソッドを使用します。式sizeof(type)オブジェクトまたは型の保存サイズをバイト単位で生成します。以下に任意のマシンでのint型の保存サイズを取得する例を示します：

例

using System;

namespace DataTypeApplication
{
   class Program
   {
      static void Main(string[] args)
      {
         Console.WriteLine("Size of int: {0}", sizeof(int));
         Console.ReadLine();
      }
   }
}

上記のコードがコンパイルおよび実行されると、次の結果が生成されます：

Size of int: 4

参照型（Reference types）

参照型には、変数に格納された実際のデータは含まれませんが、変数への参照が含まれます。

言い換えれば、それらはメモリ位置を指します。複数の変数を使用する場合、参照型は1つのメモリ位置を指すことができます。メモリ位置のデータが1つの変数によって変更されると、他の変数も自動的にこの値の変更を反映します。組み込みの参照型は次のとおりです：object、dynamic 和 string。

オブジェクト（Object）型

オブジェクト（Object）型は、C# 共通型システム（Common Type System - CTS）におけるすべてのデータ型の最終的な基底クラスです。Object は System.Object クラスの別名です。したがって、オブジェクト（Object）型には、他の任意の型（値型、参照型、定義済み型、ユーザー定義型）の値を割り当てることができます。ただし、値を割り当てる前に、型変換を行う必要があります。

値型がオブジェクト型に変換される場合、これはボックス化と呼ばれます。一方、オブジェクト型が値型に変換される場合、これはボックス化解除。

object obj;
obj = 100; // 这是装箱

動的（Dynamic）型

動的データ型変数には、任意の型の値を格納できます。これらの変数の型チェックは実行時に行われます。

動的型を宣言する構文：

dynamic <variable_name> = value;

例：

dynamic d = 20;

動的型はオブジェクト型に似ていますが、オブジェクト型変数の型チェックはコンパイル時に行われ、動的型変数の型チェックは実行時に行われます。

文字列（String）型

文字列（String）型を使用すると、変数に任意の文字列値を割り当てることができます。文字列（String）型は System.String クラスの別名です。これはオブジェクト（Object）型から派生しています。文字列（String）型の値は、引用符と @引用符の2つの形式で割り当てることができます。

例：

String str = "runoob.com";

@引用符文字列：

@"runoob.com";

C# string 文字列の前には @（「逐語的文字列」と呼ばれる）を付けることができ、エスケープ文字（\）を通常の文字として扱います。例：

string str = @"C:\Windows";

次と同等です：

string str = "C:\\Windows";

@ 文字列は任意の場所で改行でき、改行文字とインデントのスペースは文字列の長さに含まれます。

string str = @"<script type=""text/javascript"">
    <!--
    -->
</script>";

ユーザー定義の参照型には、class、interface、delegate があります。これらの型については後の章で説明します。

ポインタ型（Pointer types）

ポインタ型変数は、別の型のメモリアドレスを格納します。C# のポインタは、C または C++ のポインタと同じ機能を持ちます。

ポインタ型を宣言する構文：

type* identifier;

例：

char* cptr;
int* iptr;

ポインタ型については、「安全でないコード」の章で説明します。

    ボックス化とボックス化解除について

    ボックス化：値型をオブジェクト型に変換します。例：

    int val = 8;
object obj = val;//整型数据转换为了对象类型（装箱）

    ボックス化解除：以前に値型から変換されたオブジェクト型を値型に戻します。例：

    int val = 8;
object obj = val;//先装箱
int nval = （int）obj;//再拆箱

    ボックス化されたデータのみボックス化解除できます

    C# における String と string の違い

    string は C# のクラスであり、String は .net Framework のクラスです（C# IDE では青く表示されません）。C# の string は .net Framework の String にマップされます。string を使用すると、コンパイラはそれを String にコンパイルするため、直接 String を使用すればコンパイラの作業を少し減らすことができます。

    C# を使用する場合は、string を使用することをお勧めします。仕様により、string は常に System.String (1.x) または ::System.String (2.0) を表します。String は、前に using System; があり、現在の名前空間に String という名前の型（class、struct、delegate、enum）がない場合にのみ System.String を表します。string はキーワードであり、String はキーワードではありません。つまり、string はクラス、構造体、列挙型、フィールド、変数、メソッド、プロパティの名前として使用できませんが、String は使用できます。

    String は CLR の型名（キーワードとも言えます）で、string は C# のキーワードです。string はコンパイル時に C# コンパイラによって既定で String に変換され、ここで数行の変換コードが追加されます。多くの場合、C# の型ではなく CLR の型を使用することが推奨されます（これは専門家のアドバイスです）。例えば、int を使用する場合は Int32 を使用する方が良いなど。多くの場合は習慣の問題、仕様の問題です。もう1つの違いは、VS での表示色が異なることです：String は緑色、string は青色です。

    すべての値型には、自分の値を保存する独立したメモリ領域があり、それを呼び出すときはその値を呼び出します。一方、参照型はメモリ内のアドレスを呼び出します。例えば、参照型 a1=10 を定義すると、メモリには 10 が保存されます。a1 を a2 に代入すると、両者は同じメモリ空間を参照するため、a2 の値は a1 の値として保存されます。a2 を 20 に変更すると、a1 と a2 は同じものを参照しているので、a1 も 20 になります。これが参照型です。値型は、a1 を a2 に代入すると、a2 のために新しい領域を確保して a1 の値を保存します。a2 を 20 に変更すると、a2 の領域に 20 が保存され、a1 とは関係ありません。

    値型、参照型、および「スタック」と「ヒープ」の関係について

    値型：値型を宣言するとき、「スタック」にメモリ空間を確保して対応する値を格納します。値型の値が変更された場合は、そのメモリ空間に保存されている値を直接変更します。例：

    int n1 = 5;
int n2 = n1;
Console.WriteLine(n1 + "  "+ n2);    // 5  5
n2 = 7;
Console.WriteLine(n1 + "  " + n2)    // 5  7

    ここでは、まず「スタック」に n1 の値 5 を保存するためのメモリ空間を確保し、次に「スタック」に n2 の値 5 を保存するための新しいメモリ空間を確保します。したがって、表示される結果は 5 5 です。次に、n2 の「スタック」内の対応するメモリ空間に保存されている値を 7 に変更するため、表示される結果は 5 7 になります。

    参照型：参照型を宣言するとき、まず「ヒープ」にメモリ空間を確保して対応する値を格納し、次に「スタック」にメモリ空間を確保して「ヒープ」に確保したメモリ空間のアドレスを保存します。システムが参照型を呼び出すとき、まず「スタック」からアドレスを取得し、そのアドレスに基づいて「ヒープ」内の対応するメモリ空間を見つけて対応する値を取得します。例えば配列のような参照型

    string[] a1 = new string[]{ "a" , "b" , "c" };
string[] a2 = a1;
for(int i = 0; i < a2.Length; i++)
{
    Console.Write(a2[i] + " ");    //a b c
}
a1[2] = "d";
Console.WriteLine();            //换行
for(int i = 0; i < a2.Length; i++)
{
    Console.Write(a2[i] + " ");    //a b d
}
Console.WriteLine();

    ここでは、まず「ヒープ」にメモリ空間（仮定：0X55）を確保して配列 a1 の値を保存し、次に「スタック」にメモリ空間（a1）を確保してアドレス 0X55 を保存します。a1 を a2 に代入すると、アドレスが a2 に代入されます。つまり、「スタック」にメモリ空間（a2）を確保してアドレス 0X55 を保存します。したがって、a2 の出力値は a b c です。a1

    一方、string は特別な参照型です。次のコードを見てください：

    string a = "123";
string b = a; 
Console.WriteLine(a+" "+b);  //123 123
string b = "456";
Console.WriteLine(a+" "+b);  //123 456

    配列と同様に、ここではまず「ヒープ」にメモリ空間（仮定：0X88）を確保して a の値 123 を保存し、次に「スタック」にメモリ空間（a）を確保してアドレス 0X88 を保存します。

    配列とは異なり、a を b に代入するとき、まず「ヒープ」に新しいメモリ空間（仮定：0X101）を確保して値 123 を保存し、次に「スタック」にメモリ空間（b）を確保してアドレス 0X101 を保存します。したがって、出力結果は 123 123 です。

    b の値を変更するとき、「ヒープ」内の 0X101 メモリ空間の値を変更するのではなく、「ヒープ」に新しいメモリ空間（仮定：0X210）を確保して b の変更後の値を保存し、次に b が「スタック」内で対応するメモリ空間に保存されているアドレスを 0X210 に変更します。したがって、出力結果は 123 456 です。「ヒープ」内の 0X101 メモリ空間は、次のガベージコレクションで回収されます。

    値型と参照型の違い：

    メモリの観点から見ると、値型はスタック上の操作であり、参照型はヒープ上の操作です。

    （結果として => 値型はアクセス速度が速く、参照型はアクセス速度が遅い。）

    本質的に、値型は実際のデータを表し、参照型はメモリヒープに格納されているデータを指すポインタまたは参照を表します。

    （値型はその具体的な数値が占める空間の大きさであり、参照型はその数値を格納している空間のアドレスです。）

    由来の観点から見ると、値型は System.ValueType を継承し、参照型は System.Object を継承します。

    特に：構造体は値型であり、クラスと string は参照型です。

    値型がオブジェクト型に変換されるとき、それはボックス化；一方、オブジェクト型が値型に変換されるとき、それはボックス化解除。

    動的型はオブジェクト型と似ていますが、オブジェクト型変数の型チェックはコンパイル時に行われ、動的型変数の型チェックは実行時に行われます。
