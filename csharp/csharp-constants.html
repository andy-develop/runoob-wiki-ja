C# 定数

定数は固定値であり、プログラムの実行中に変更されることはありません。定数は任意の基本的なデータ型にすることができます。例えば、整数定数、浮動小数点定数、文字定数、文字列定数、および列挙定数です。

定数は通常の変数として扱うことができますが、定義後に値を変更することはできません。

整数定数

整数定数は、10進数、8進数、16進数の定数にすることができます。プレフィックスが基数を指定します：0x または 0X は16進数を示し、0 は8進数を示し、プレフィックスがない場合は10進数を示します。

整数定数にはサフィックスを付けることもできます。サフィックスは U と L の組み合わせにすることができ、U は unsigned、L は long をそれぞれ表します。サフィックスは大文字でも小文字でもよく、複数のサフィックスは任意の順序で組み合わせることができます。

ここにいくつかの整数定数の例があります：

212         /* 合法 */
215u        /* 合法 */
0xFeeL      /* 合法 */
078         /* 非法：8 不是一个八进制数字 */
032UU       /* 非法：不能重复后缀 */

以下は様々なタイプの整数定数の例です：

85         /* 十进制 */
0213       /* 八进制 */
0x4b       /* 十六进制 */
30         /* int */
30u        /* 无符号 int */
30l        /* long */
30ul       /* 无符号 long */

浮動小数点定数

浮動小数点定数は、整数部、小数点、小数部、指数部から構成されます。浮動小数点定数は、小数形式または指数形式で表すことができます。

ここにいくつかの浮動小数点定数の例があります：

3.14159       /* 合法 */
314159E-5L    /* 合法 */
510E          /* 非法：不完全指数 */
210f          /* 非法：没有小数或指数 */
.e55          /* 非法：缺少整数或小数 */

浮動小数点形式で表す場合は、小数点、指数、またはその両方を含める必要があります。指数形式で表す場合は、整数部、小数部、またはその両方を含める必要があります。符号付き指数は e または E で表されます。

文字定数

文字定数は単一引用符で囲まれます。例えば 'x' であり、単純な文字型変数に格納できます。文字定数は、普通の文字（例: 'x'）、エスケープシーケンス（例: '\t'）、またはユニバーサル文字（例: '\u02C0'）のいずれかです。

C# には特定の文字があり、その前にバックスラッシュを付けると特別な意味を持ちます。改行文字（\n）やタブ（\t）を表すために使用できます。ここでは、いくつかのエスケープシーケンスコードを示します：

エスケープシーケンス意味
\\バックスラッシュ文字
\'シングルクォート文字
\"ダブルクォート文字
\?クエスチョンマーク文字
\aアラートまたはベル
\bバックスペース
\fフォームフィード（改ページ）
\n改行
\rキャリッジリターン
\t水平タブ
\v垂直タブ
\ooo1〜3桁の8進数
\xhh . . .1桁以上の16進数

以下はいくつかのエスケープシーケンス文字の例です：

namespace EscapeChar
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("Hello\tWorld\n\n");
            Console.ReadLine();
        }
    }
}

上記のコードをコンパイルして実行すると、次の結果が生成されます：

Hello   World

文字列定数

文字列定数は二重引用符で囲まれ""るか、または@""で囲まれます。文字列定数に含まれる文字は文字定数と似ており、普通の文字、エスケープシーケンス、ユニバーサル文字のいずれかです。

文字列定数を使用するとき、非常に長い行を複数の行に分割できます。各部分をスペースで区切ることができます。

ここにいくつかの文字列定数の例があります。以下に示すさまざまな形式は同じ文字列を表します。

string a = "hello, world";                  // hello, world
string b = @"hello, world";               // hello, world
string c = "hello \t world";               // hello     world
string d = @"hello \t world";               // hello \t world
string e = "Joe said \"Hello\" to me";      // Joe said "Hello" to me
string f = @"Joe said ""Hello"" to me";   // Joe said "Hello" to me
string g = "\\\\server\\share\\file.txt";   // \\server\share\file.txt
string h = @"\\server\share\file.txt";      // \\server\share\file.txt
string i = "one\r\ntwo\r\nthree";
string j = @"one
two
three";

定数の定義

定数はconstキーワードを使用して定義されます。定数を定義する構文は次のとおりです：

const <data_type> <constant_name> = value;

次のコードは、プログラム内で定数を定義して使用する方法を示しています：

例

using System;

public class ConstTest
{
    class SampleClass
    {
        public int x;
        public int y;
        public const int c1 = 5;
        public const int c2 = c1 + 5;

        public SampleClass(int p1, int p2)
        {
            x = p1;
            y = p2;
        }
    }

    static void Main()
    {
        SampleClass mC = new SampleClass(11, 22);
        Console.WriteLine("x = {0}, y = {1}", mC.x, mC.y);
        Console.WriteLine("c1 = {0}, c2 = {1}",
                          SampleClass.c1, SampleClass.c2);
    }
}

上記のコードをコンパイルして実行すると、次の結果が生成されます：

x = 11, y = 22
c1 = 5, c2 = 10

    1、Convert.ToDouble と Double.Parse の違い。実際、Convert.ToDouble と Double.Parse はかなり似ています。実際、Convert.ToDouble は内部的に Double.Parse を呼び出しています：

    (1) パラメータが null の場合：

    • Convert.ToDouble のパラメータが null の場合、0.0 を返します；
    • Double.Parse のパラメータが null の場合、例外をスローします。

    (2) パラメータが "" の場合：

    • Convert.ToDouble のパラメータが "" の場合、例外をスローします；
    • Double.Parse のパラメータが "" の場合、例外をスローします。

    (3) その他の違い：

    • Convert.ToDouble は変換できる型が多い；
    • Double.Parse は数値型の文字列のみ変換できます。
    • Double.TryParse は Double.Parse とかなり似ていますが、例外は発生しません。変換に成功すると true を返し、失敗すると false を返します。最後のパラメータは出力値で、変換に失敗した場合の出力値は 0.0 です。

    テストコード付き：

    using System;
using System.Collections.Generic;
using System.Linq;
using System.Text;

namespace ConsoleApplication1
{
    class Program
    {
        static void Main(string[] args)
        {
            try
            {
                //string a = "0.2";
                //string a = null;
                string a = "";
                try
                {
                    double d1 = Double.Parse(a);
                }
                catch (Exception err)
                {
                    Console.WriteLine("d1转换出错:" + err.Message);
                }

                try
                {
                    double d2 = Convert.ToDouble(a);
                }
                catch (Exception err)
                {
                    Console.WriteLine("d2转换出错:" + err.Message);

                }
                try
                {
                    double d3;
                    Double.TryParse(a,out d3);
                }
                catch (Exception err)
                {
                    Console.WriteLine("d3转换出错:" + err.Message);
                }
            }
            finally
            {
                Console.ReadKey();
            }

        }
    }
}

    2. Convert.ToInt32() と int.Parse() の違い

    Convert.ToInt32 と int.Parse() の細かい違いを理解せずに使うのは絶対に避けるべきです。そうしないと予期しない結果を引き起こす可能性があります。例えば、URL からパラメータ page の値を取得する場合、その値が int であることはわかっているので、Convert.ToInt32(Request.QueryString["page"]) を使うこともできますし、int.Parse(Request.QueryString["page"]) を使うこともできます。しかし、page パラメータが URL に存在しない場合、前者は 0 を返します。0 は有効な値かもしれないため、URL に元々このパラメータがなかったことに気づかずに次の処理を続けてしまい、予期しない影響が出る可能性があります。一方、後者の方法では page パラメータがないと例外がスローされるため、例外をキャッチして適切な処理を行うことができます。例えば、ユーザーにパラメータが不足していることを通知するなど、パラメータ値を 0 として扱うのではありません。

    (1) これら2つのメソッドの最大の違いは、null 値の処理方法です：

    Convert.ToInt32(null) は 0 を返し、例外は発生しませんが、int.Parse(null) は例外を発生させます。

    (2) データを四捨五入するときの違い

    a. Convert.ToInt32(double value)

    value が2つの整数の中間の数値である場合、2つのうちの偶数を返します。つまり、3.5 は 4、4.5 は 4、5.5 は 6 に変換されます。ただし、4.6 は 5 に変換でき、4.4 は 4 に変換されます。

    b. int.Parse("4.5")

    直接エラーが発生します：「入力文字列の形式が正しくありません」。

    c. int(4.6) = 4

    Int が他の数値型を Int に変換するとき、四捨五入はなく、強制変換です。

    (3) 変換対象の型の違い

    int.Parse は String を int に変換します。

    Convert.ToInt32 は Object から継承したオブジェクトを int に変換します（その他の多くの型のデータも可能です）。

    object オブジェクトを取得し、それを int に変換したい場合、int.Parse ではできません。Convert.ToInt32 を使用する必要があります。

    1. 静的定数（コンパイル時定数）const

    コンパイル時に値が確定され、宣言時に初期化する必要があり、その後変更することはできません。クラスとメソッド内で定義できます。定義方法は次のとおりです：

    const double a=3.14；// 正确声明常量的方法
const int b;         // 错误，没有初始化

    2. 動的定数（実行時定数）readonly

    実行時に値が確定され、宣言時またはコンストラクタ内でのみ初期化でき、クラス内でのみ定義できます。定義方法は次のとおりです：

    class Program
{
    readonly int a=1;  // 声明时初始化
    readonly int b;    // 构造函数中初始化
    Program()
    {
        b=2;
    }
    static void Main()
    {
    }
}

    const の値はコンパイル期間中にわかっている必要があります。言い換えると、定数に初期値を与える必要があり、変数を使って定数を初期化することはできません：

    static void Main(string[] args)
{
  int a=14;//必须要有初始值
  const int b=a;//报错
}

    定数のコンパイル時に、定数の値を定数に置き換えるため、実行効率を向上させることができます。

    しかし、アセンブリ(A)内で定数(a)の値を変更した（12から14に変えた）が、Aアセンブリを実行していない場合、この定数(a)を参照するアセンブリ(B)では、その定数の値は依然として12のままです。

    また、すべての値を定数で初期化できるわけではありません。定数でサポートされていない値を使いたい場合は、readonly を使用してください。

    static A a;
readonly A a1=a;
const A a2=a;// 只能为 null

    そして readonly は const の欠点を解決します：

    これは「読み取り専用フィールド」と呼ばれ、クラス内でのみ宣言できます。

    実行時に計算やロードが可能で、コンストラクタ内で初期化することもできます：

    int a1=14;
readonly int a;
A()
{
  a=a1;
}

    readonly を使うことで、const におけるアセンブリの欠点も回避できます。
