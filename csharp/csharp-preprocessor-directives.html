C# 预处理器指令

プリプロセッサディレクティブ（Preprocessor Directives）は、実際のコンパイルが開始される前に情報を前処理するようコンパイラに指示します。

これらのディレクティブを使用することで、コンパイラがファイルをどのようにコンパイルするか、またはどの部分をコンパイルするかを制御できます。一般的なプリプロセッサディレクティブには、条件付きコンパイルやマクロ定義などがあります。

すべてのプリプロセッサディレクティブは#行の先頭で開始され、1つの行上では、プリプロセッサディレクティブの前には空白文字のみを置くことができます。

プリプロセッサディレクティブはステートメントではないため、セミコロンで終了しません。;结束。

C# コンパイラには独立したプリプロセッサはありませんが、ディレクティブは独立したプリプロセッサがあるかのように処理されます。C# では、プリプロセッサディレクティブは条件付きコンパイルで機能します。C や C++ とは異なり、マクロを作成するために使用されることはありません。プリプロセッサディレクティブは、その行の唯一のディレクティブである必要があります。

C# プリプロセッサディレクティブの一覧

次の表に、C# で使用できるプリプロセッサディレクティブを示します：

指令描述
#defineシンボルを定義します。条件付きコンパイルに使用できます。
#undefシンボルの定義を解除する。
#if条件付きコンパイルブロックを開始します。シンボルが定義されている場合、コードブロックが含まれます。
#elif如果前面的#if 或 #elif条件が満たされず、現在の条件が満たされる場合、コードブロックが含まれます。
#else如果前面的#if 或 #elif条件が満たされない場合、コードブロックが含まれます。
#endif条件付きコンパイルブロックを終了します。
#warningコンパイラの警告情報を生成します。
#errorコンパイラのエラー情報を生成します。
#regionコード領域をマークします。IDE ではこのコード領域を折りたたんだり展開したりできるため、コードの整理と可読性に役立ちます。
#endregionコード領域を終了する。
#lineコンパイラ出力の行番号とファイル名を変更します。デバッグやコード生成ツールに使用できます。
#pragmaコンパイラに特別な指示を送るために使用します。例えば、特定の警告を無効化または復元します。
#nullablenull 許容コンテキストと注釈を制御し、null 許容参照型に対するコンパイラのチェックを有効または無効にすることができます。

实例

#define DEBUG

#if DEBUG
    Console.WriteLine("Debug mode");
#elif RELEASE
    Console.WriteLine("Release mode");
#else
    Console.WriteLine("Other mode");
#endif

#warning This is a warning message
#error This is an error message

#region MyRegion
    // Your code here
#endregion

#line 100 "MyFile.cs"
    // The next line will be reported as line 100 in MyFile.cs
    Console.WriteLine("This is line 100");
#line default
    // Line numbering returns to normal

#pragma warning disable 414
    private int unusedVariable;
#pragma warning restore 414

#nullable enable
    string? nullableString = null;
#nullable disable

#define と #undef プリプロセッサ

#defineシンボルを定義するために使用されます（通常は条件付きコンパイル用）。#undefシンボルの定義を解除するために使用する。

#define DEBUG

#undef RELEASE

#define を使用すると、シンボルを定義できます。これにより、#if ディレクティブに渡す式としてシンボルを使用すると、式は true を返します。構文は次のとおりです：

#define symbol

次のプログラムはこれを説明しています。

实例

#define PI
using System;
namespace PreprocessorDAppl
{
   class Program
   {
      static void Main(string[] args)
      {
         #if (PI)
            Console.WriteLine("PI is defined");
         #else
            Console.WriteLine("PI is not defined");
         #endif
         Console.ReadKey();
      }
   }
}

上記のコードがコンパイルおよび実行されると、次の結果が生成されます。

PI is defined

条件指令：#if, #elif, #else 和 #endif

您可以使用#ifディレクティブを使用して条件ディレクティブを作成します。

条件ディレクティブは、シンボルが真であるかどうかをテストするために使用されます。真の場合、コンパイラは実行します。#if次のディレクティブとの間のコード。

条件ディレクティブの構文：

#if symbol [operator symbol]...

其中，symbolテスト対象のシンボル名です。true や false を使用したり、シンボルの前に否定演算子を置いたりすることもできます。

一般的な演算子は次のとおり：

  • == (等于)
  • != (等しくない)
  • && (与)
  • || (或)

括弧を使用してシンボルと演算子をグループ化することもできます。条件ディレクティブは、デバッグビルドや指定された構成のコンパイル時にコードをコンパイルするために使用されます。1つの#ifディレクティブで始まる条件ディレクティブは、明示的に1つのディレクティブで終了する必要があります。#endif指令终止。

#define DEBUG

#if DEBUG
    Console.WriteLine("Debug mode");
#elif RELEASE
    Console.WriteLine("Release mode");
#else
    Console.WriteLine("Other mode");
#endif

次のプログラムは、条件ディレクティブの使用法を示しています：

实例

#define DEBUG
#define VC_V10
using System;
public class TestClass
{
   public static void Main()
   {

      #if (DEBUG && !VC_V10)
         Console.WriteLine("DEBUG is defined");
      #elif (!DEBUG && VC_V10)
         Console.WriteLine("VC_V10 is defined");
      #elif (DEBUG && VC_V10)
         Console.WriteLine("DEBUG and VC_V10 are defined");
      #else
         Console.WriteLine("DEBUG and VC_V10 are not defined");
      #endif
      Console.ReadKey();
   }
}

上記のコードがコンパイルおよび実行されると、次の結果が生成されます。

DEBUG and VC_V10 are defined

#warning 和 #error

#warning はコンパイラ警告を生成するために使用され、#error はコンパイラエラーを生成するために使用されます。

#warning This is a warning message
#error This is an error message

#region 和 #endregion

コードの折りたたみに使用され、コードをより読みやすくします。

#region MyRegion
    // Your code here
#endregion

#line

ファイルの行番号とファイル名のコンパイラ出力を変更するために使用されます。

#line 100 "MyFile.cs"
    // The next line will be reported as line 100 in MyFile.cs
    Console.WriteLine("This is line 100");
#line default
    // Line numbering returns to normal

#pragma

コンパイラに特別な指示を送るために使用されます。最も一般的な使用法は、特定の警告を無効にすることです。

#pragma warning disable 414
    private int unusedVariable;
#pragma warning restore 414

プリプロセッサディレクティブを使用する際の注意事項

  • コードの可読性を高める：使用#regionコードブロックを区切り、コードの組織性を高めるのに役立ちます。
  • 条件编译：通过#ifなどのディレクティブを使用すると、開発環境と本番環境で異なるコードをコンパイルでき、デバッグとリリースに便利です。
  • 警告和错误：通过#warning和#errorコンパイル時に開発者に特定の問題への注意を促すことができます。

これらのプリプロセッサディレクティブを正しく使用することで、コードのコンパイルプロセスをより適切に制御し、コードの柔軟性と保守性を向上させることができます。

    プリプロセッサディレクティブの用途の理解：

    プログラムのデバッグと実行において重要な役割を果たします。例えば、プリプロセッサディレクティブはコンパイラがコードの一部をコンパイルするのを禁止できます。基本バージョンとより多くの機能を持つエンタープライズバージョンの2つのバージョンのコードをリリースする予定がある場合、これらのプリプロセッサディレクティブを使用して制御できます。ソフトウェアの基本バージョンをコンパイルする際に、プリプロセッサディレクティブを使用して、追加機能に関連するコードをコンパイラがコンパイルするのも禁止できます。また、デバッグ情報を提供するコードを作成する際にも、プリプロセッサディレクティブを使用して制御できます。全体的に、通常の制御文（ifなど）と機能は似ていますが、便利な点は、プリプロセッサディレクティブに含まれる未実行部分はコンパイルする必要がないことです。

    #define PI
using System;
namespace PreprocessorDAppl
{
   class Program
   {
      static void Main(string[] args)
      {
         #if (PI)
            Console.WriteLine("PI is defined");     //PI不存在，则这条语句不编译
         #else
            Console.WriteLine("PI is not defined"); //PI存在，则这条语句不编译
         #endif
         Console.ReadKey();
      }
   }
}

    その他のプリプロセッサディレクティブ：

    #warning 和 #error：

    コンパイラがこれらのディレクティブに遭遇すると、それぞれ警告またはエラーが生成されます。コンパイラが #warning ディレクティブに遭遇した場合、#warning ディレクティブの後のテキストがユーザーに表示され、その後コンパイルは続行されます。コンパイラが #error ディレクティブに遭遇した場合、その後のテキストがコンパイルエラーメッセージとしてユーザーに表示され、コンパイルは直ちに終了します。これら2つのディレクティブを使用すると、#define ステートメントで何か誤りを犯していないかを確認でき、#warning ステートメントを使用すると、ある操作を実行するように自分自身に注意を促すことができます。

    #if DEBUG && RELEASE  
#error "You've defined DEBUG and RELEASE simultaneously!"  
#endif  
#warning "Don't forget to remove this line before the boss tests the code!"  
Console.WriteLine("*I hate this job.*");

    2. #region 和 #endregion

    #region および #endregion ディレクティブは、コードの一部を指定された名前を持つブロックとしてマークするために使用されます。次に示すとおりです：

    #region Member Field Declarations
int x;
double d;
Currency balance;
#endregion

    これは一見役に立たないように思えるかもしれませんが、コンパイルプロセスには影響しません。これらのディレクティブの利点は、Visual Studio .NET エディタを含む一部のエディタで認識できることです。これらのエディタは、これらのディレクティブを使用して、コードを画面上でより適切にレイアウトできます。

    3. #line

    #line ディレクティブは、コンパイラが警告およびエラーメッセージで表示するファイル名と行番号の情報を変更するために使用できます。あまり一般的ではありません。

    コードを作成する際に、コードをコンパイラに送信する前に何らかのソフトウェアパッケージを使用して入力コードを変更する場合、このディレクティブを使用できます。これは、コンパイラが報告する行番号やファイル名が、ファイル内の行番号や編集されたファイル名と一致しないことを意味するためです。#line ディレクティブを使用すると、この一致を復元できます。また、構文「#line default」を使用して、行番号をデフォルトの行番号に復元することもできます：

    #line 164 "Core.cs" // 在文件的第 164 行
// Core.cs, before the intermediate
// package mangles it.
// later on
#line default // 恢复默认行号

    4. #pragma

    #pragma ディレクティブは、指定されたコンパイル警告を抑制または復元できます。コマンドラインオプションとは異なり、#pragma ディレクティブはクラスまたはメソッドレベルで実行でき、抑制する警告の内容と抑制するタイミングをより細かく制御できます。次のとおりです：

    #pragma warning disable 169    // 取消编号 169 的警告（字段未使用的警告）
public class MyClass
{
    int neverUsedField;       // 编译整个 MyClass 类时不会发出警告
}
#pragma warning restore 169   // 恢复编号 169 的警告
