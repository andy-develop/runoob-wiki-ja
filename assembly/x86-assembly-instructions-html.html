アセンブリ命令早見表

本稿は最も一般的なx86アーキテクチャのアセンブリ言語を対象に、よく使われる命令ニーモニックを機能別に分類整理し、学習とクイックリファレンスを容易にします。

命令ニーモニックは異なるアセンブラ（MASM、NASM、GAS）で基本的に一致しており、オペランドの記述形式にのみ若干の違いがあります。

9大分類の命令概要：

分类 指令数量 主要用途
データ転送命令 15 条 レジスタ、メモリ、I/Oポート間でデータを転送する
算術演算命令 18 条 加減乗除、比較及び数制調整
論理演算とシフト命令 14 条 ビットごとのAND、OR、NOT、XOR、シフトおよびローテートシフト
串操作指令 8 条 連続したメモリ領域を処理し、繰り返しプレフィックスと組み合わせて一括操作を行う
制御転送命令 30+ 条 ジャンプ、ループ、プロシージャ呼び出しと割り込み
条件設定命令 16 条 フラグに基づいてバイト値を設定し、分岐を排除するために使用
入出力命令 4 条 I/Oポートの読み書き
プロセッサ制御命令 14 条 フラグ制御、同期、システム管理
浮動小数点命令（x87 FPU） 14 条 従来のx87浮動小数点スタック演算

データ転送命令

データ転送命令は最も基本的な命令タイプであり、レジスタ、メモリ、I/Oポート間でデータを転送する役割を担います。

ほとんどの転送命令はフラグに影響しません（SAHF、POPF を除く）。

助记符 功能简述
MOV ソースオペランドをデスティネーションオペランドにコピーし、レジスタ間、レジスタとメモリ間、即値からレジスタまたはメモリへの転送をサポートする
MOVSX 符号拡張付き転送。小さいサイズのオペランドを符号拡張して大きいサイズにします（例：バイトをダブルワードに拡張し、上位ビットを符号ビットで埋める）
MOVZX ゼロ拡張付き転送。上位ビットに0を補います（符号なし整数の拡張に使用）
PUSH オペランドをスタックにプッシュします。スタックポインタ ESP/RSP は自動的に減少します（減算してから格納）
POP スタックからデータをポップして目的オペランドに格納します。スタックポインタは自動的に増加します（取得してから加算）
PUSHA / PUSHAD すべての汎用レジスタをスタックにプッシュします（16ビットでは PUSHA、32ビットでは PUSHAD）。コンテキストの保存によく使用されます
POPA / POPAD スタックからすべての汎用レジスタを復元します。PUSHA/PUSHAD と対称的に使用します
XCHG 2つのオペランドの内容を交換します。少なくとも一方のオペランドはレジスタである必要があります
LEA 実効アドレスをロード（Load Effective Address）します。ソースオペランドのアドレスをメモリの内容ではなく目的レジスタに格納し、ポインタ計算によく使用されます
LDS / LES / LFS / LGS / LSS 遠方ポインタをセグメントレジスタと汎用レジスタにロードします（現代のフラットメモリモデルではあまり使用されません）
LAHF フラグレジスタの下位8ビットをAHレジスタにロードします
SAHF AHレジスタの内容をフラグレジスタの下位8ビットに格納します
PUSHF / PUSHFD フラグレジスタのプッシュ（16ビットではPUSHF、32ビットではPUSHFD）
POPF / POPFD スタックからフラグレジスタを復元する
XLAT / XLATB テーブル参照変換命令。ALのインデックス値に対応するメモリ内のバイトをALにロードします。BX/EBX はテーブルのベースアドレスを指します

LEAとMOVの重要な違い：LEA REG, [ADDR]ロードされるのはアドレス値そのものであり、MOV REG, [ADDR]ロードされるのはそのアドレスにあるメモリの内容です。アドレス計算を行う場合（例：LEA EAX, [EBX+4*ECX+8]）の場合、LEAは非常に効率的です。

算術演算命令

算術演算命令は加算、減算、乗算、除算、比較などの操作を行い、実行結果はフラグレジスタ内の関連フラグに直接影響を与える。

プログラマは通常、演算後のゼロフラグ(ZF)、キャリーフラグ(CF)、サインフラグ(SF)、オーバーフローフラグ(OF)に基づいて計算結果を判断する。

助记符 功能简述
ADD 加算。目的 = 目的 + ソース。OF、SF、ZF、CF などのフラグに影響します
ADC キャリ付き加算。目的 = 目的 + ソース + CF。多倍長算術演算に使用します
SUB 減算、デスティネーション = デスティネーション - ソース
SBB ボロー付き減算。目的 = 目的 - ソース - CF。ADC と組み合わせて多倍長演算に使用します
INC オペランドに1を加算します。CFフラグには影響しません
DEC オペランドから1を減算します。CFフラグには影響しません
MUL 符号なし乗算、被乗数はAL/AX/EAX、積はAX/DX:AX/EDX:EAXに格納される
IMUL 符号付き乗算。単一オペランド、二重オペランド、三重オペランドの3つの形式をサポートします
DIV 符号なし除算。被除数は AX/DX:AX/EDX:EAX にあり、商と余りは指定されたレジスタに格納されます
IDIV 符号付き除算。規則は DIV と似ていますが、符号を処理します
CMP 2つのオペランドを比較し、減算を実行するが結果は保存せず、フラグのみに影響を与える（通常は条件ジャンプが続く）。
NEG 補数を求めます。オペランドを反転して1を加えます。0からオペランドを引くことと同等です
DAA 加算後の10進補正。ALをパックBCDコード形式に調整します
DAS 減算後の十進調整
AAA 加算後のASCII補正。アンパックBCDコードに使用します
AAS 減算後のASCII調整
AAM 乗算後のASCII調整
AAD 除算前のASCII調整
CBW / CWDE 符号拡張：CBW は AL を AX に符号拡張し、CWDE は AX を EAX に符号拡張します
CWD / CDQ 符号拡張：CWD は AX を DX:AX に拡張し、CDQ は EAX を EDX:EAX に拡張します（除算前に被除数を準備するためによく使用されます）

符号付き演算では使用IMUL / IDIV、無符号演算では使用MUL / DIV。命令を誤って選ぶと結果が誤る——例えば、同じバイナリ値でも符号付きと符号なしの解釈では異なる数値を表す。

論理演算とシフト命令

この種の命令は、ビットごとのAND、OR、NOT、XORなどの論理演算と、シフトおよびローテートシフトを実行します。

シフト演算は、2のべき乗の高速乗除算、ビットフィールド抽出、ビットマスク操作によく使用されます。

助记符 功能简述
AND ビットごとのAND。マスク操作（特定ビットをクリアする）によく使用されます
OR ビット単位のOR。特定のビットを1にセットするためによく使われる。
XOR ビットごとのXOR。同じビットは0、異なるビットは1になります。XOR REG, REG はレジスタをクリアする古典的で効率的な記述です
NOT ビット単位の否定（NOT）。すべてのビットが反転する。
TEST ビットのテスト。AND演算を実行するが結果は保存せず、フラグのみに影響を与える（特定のビットが0かどうかを調べるためによく使われる）。
SHL / SAL 論理左シフト / 算術左シフト。両者の機能は完全に同じで、下位ビットに0を補い、上位ビットはCFに移されます
SHR 論理右シフト。上位ビットに0を補い、下位ビットはCFに移されます（符号なし整数用）
SAR 算術右シフト。上位ビットは元の符号ビットで埋められ、数値の符号が保持されます（符号付き整数用）
ROL 循環左シフト（ローテート左シフト）。あふれたビットは反対側に補われる。
ROR 循環右シフト（ローテート右シフト）。あふれたビットは反対側に補われる。
RCL キャリ付きローテート左シフト。CF が循環に参加します（CF は一時的な格納ビットとして機能）
RCR キャリ付きローテート右シフト。CF が循環に参加します
SHLD ダブルプレシジョン左シフト。デスティネーションとソースオペランドを結合して左シフトし、結果はデスティネーションに格納される。
SHRD ダブルプレシジョン右シフト。デスティネーションとソースオペランドを結合して右シフトし、結果はデスティネーションに格納される。

XOR REG, REGレジスタをクリアする最良の方法です。生成されるマシンコードはMOV REG, 0より短く、実行速度もより速い。

串操作指令

文字列操作命令は連続したメモリ領域を専門に扱い、反復プレフィックスと組み合わせて使用される。配列コピー、メモリ比較、バッファ検索などの一括操作によく使われる。

これらの命令のソースアドレスはデフォルトでDS:ESIが指し、デスティネーションアドレスはES:EDI指向。

助记符 功能简述
MOVS 文字列転送。[DS:ESI]を[ES:EDI]にコピーし、ESI、EDIを自動更新する。オペランドサイズによりMOVSB（バイト）、MOVSW（ワード）、MOVSD（ダブルワード）に分かれる。
STOS 文字列ストア。AL/AX/EAXを[ES:EDI]に格納し、EDIを更新する。メモリ領域を同じ値で初期化するためによく使われる。
LODS 文字列ロード。[DS:ESI]からAL/AX/EAXに読み込み、ESIを更新する。一度に1つの値しかアキュムレータにロードされないため、あまり使われない。
CMPS 文字列比較。[DS:ESI]と[ES:EDI]を比較し、フラグに影響を与える。通常REPE/REPNEと組み合わせて、一致または不一致の位置を検索する。
SCAS 文字列スキャン。AL/AX/EAXと[ES:EDI]を比較し、EDIを更新する。メモリ内で特定の値を検索するためによく使われる。
REP 繰り返しプレフィックス。ECX ≠ 0 の間、後続の文字列命令を繰り返し実行し、実行ごとに ECX が自動的に1減算されます
REPE / REPZ 等しい/ゼロの間繰り返す。ECX ≠ 0 かつ ZF = 1 の間続行（通常、CMPS、SCAS と併用して一致項目を検索します）
REPNE / REPNZ 不等/非ゼロのとき繰り返し、ECX ≠ 0 かつ ZF = 0 のとき続行（不一致の検索用）

方向标志DF文字列操作のポインタの移動方向を制御します：CLD実行後 DF=0 となり、ポインタは増加します（順方向処理）。実行STD実行後 DF=1 となり、ポインタは減少します（逆方向処理）。文字列操作を使用する前に DF を明示的に設定し、デフォルト値に依存しないでください。

制御転送命令

制御転送命令はプログラムの実行フローを変更します。無条件ジャンプ、条件ジャンプ、ループ、プロシージャの呼び出しと復帰が含まれます。

これはプログラムの論理分岐、ループ、関数呼び出しを実装するための基礎です。

無条件ジャンプとコール

無条件ジャンプは条件をチェックせず、EIP/RIP の値を直接変更して、CPU が新しいアドレスから実行を続行します。

助记符 功能简述
JMP 無条件ジャンプ。短距離ジャンプ（-128 から +127 バイト）、近距離ジャンプ（セグメント内）、遠距離ジャンプ（セグメント間）をサポートします
CALL プロシージャを呼び出します。まず戻りアドレスをスタックにプッシュし、その後ターゲットアドレスへジャンプします
RET / RETF プロシージャから復帰します。RET は近距離復帰（セグメント内）、RETF は遠距離復帰（セグメント間）に使用します。即値オペランドを指定して、スタック上の引数領域を同時に解放できます

条件跳转

条件ジャンプは、フラグレジスタ内の特定のフラグビットの値に基づいてジャンプするかどうかを決定します。

通常はすぐ後に続くCMP 或 TEST命令の後に使用。

助记符 跳转条件 典型用途
JE / JZ ZF = 1（等しい / ゼロ） CMPの後、等しい場合にジャンプ
JNE / JNZ ZF = 0（等しくない / ゼロでない） CMPの後、等しくない場合にジャンプ
JS SF = 1（結果が負） 演算結果が負のときジャンプ
JNS SF = 0（結果が正） 演算結果が非負のときジャンプ
JC CF = 1（有进位/借位） 符号なし比較で未満の場合にジャンプします。JB と同等です
JNC CF = 0（无进位/借位） 符号なし比較で以上の場合にジャンプします。JAE と同等です
JO OF = 1（オーバーフローあり） 符号付き演算でオーバーフローした場合にジャンプ
JNO OF = 0（オーバーフローなし） 符号付き演算でオーバーフローしない場合にジャンプ
JP / JPE PF = 1（下位8ビット内の1の個数が偶数） パリティが偶数のときジャンプ
JNP / JPO PF = 0（1の個数が奇数） パリティが奇数のときジャンプ
JA / JNBE CF = 0 且 ZF = 0 符号なし大なり（Above）
JAE / JNB CF = 0 符号なし以上（Above or Equal）
JB / JNAE CF = 1 符号なし小なり（Below）
JBE / JNA CF = 1 或 ZF = 1 符号なし以下（Below or Equal）
JG / JNLE ZF = 0 且 SF = OF 符号付き大なり（Greater）
JGE / JNL SF = OF 符号付き以上（Greater or Equal）
JL / JNGE SF ≠ OF 符号付き小なり（Less）
JLE / JNG ZF = 1 或 SF ≠ OF 符号付き以下（Less or Equal）
JCXZ CX = 0のときジャンプ 16ビットモードで CX がゼロかどうかを判定します
JECXZ ECX = 0のときジャンプ 32ビットモードで ECX がゼロかどうかを判定します

符号なし比較と符号付き比較では異なるジャンプ命令を使用します。これは初心者が最も間違いやすい点です。例えば、2つの数値を比較する場合JA符号なしの大なりをチェックし、JG符号付きの大なりをチェックする——同じCMP結果でも、この2つの判断では異なる場合がある。

循环指令

ループ命令は ECX をカウンタとして使用し、反復ごとに自動的に減算してループを続行するかどうかを判定します。

助记符 功能简述
LOOP ECX を1減算し、ECX ≠ 0 ならターゲットアドレスへジャンプします
LOOPE / LOOPZ ECXを1減算し、ECX ≠ 0 かつ ZF = 1 ならジャンプ（等しい場合はループを継続）
LOOPNE / LOOPNZ ECXを1減算し、ECX ≠ 0 かつ ZF = 0 ならジャンプ（等しくない場合はループを継続）

中断と復帰

助记符 功能简述
INT n ソフトウェア割り込み。割り込みベクタ番号 n の割り込みサービスルーチンを呼び出します（例：DOS では INT 21h がシステム機能呼び出し）
INTO オーバーフロー割り込み。OF = 1 のときに INT 4 を呼び出します（算術オーバーフロー例外の捕捉に使用）
IRET / IRETD 割り込みサービスルーチンから復帰し、割り込み時の EFLAGS と戻りアドレスを復元します

条件設定命令

条件設定命令（386 以降のプロセッサでサポート）は、フラグの状態に基づいて目的バイトを1または0に設定します。

この種の命令は、分岐ジャンプを排除してコード実行効率を向上させるためによく使用されます。条件設定を短い分岐の代わりに使用することで、分岐予測の失敗による性能低下を回避できます。

助记符 设置条件 等价语义
SETZ / SETE ZF = 1 等しい / 結果がゼロのときに設定
SETNZ / SETNE ZF = 0 等しくない / 結果がゼロでないときに設定
SETC CF = 1 有进位/借位时设置
SETNC CF = 0 无进位/借位时设置
SETO OF = 1 オーバーフローありのときに設定
SETNO OF = 0 オーバーフローなしのときに設定
SETS SF = 1 結果が負のときに設定
SETNS SF = 0 結果が正のときに設定
SETG / SETNLE ZF=0 且 SF=OF 符号付きで大なりのときに設定
SETGE / SETNL SF = OF 符号付きの以上の場合にセット
SETL / SETNGE SF ≠ OF 符号付きで小なりのときに設定
SETLE / SETNG ZF=1 或 SF≠OF 符号付きの以下の場合にセット
SETA / SETNBE CF=0 且 ZF=0 符号なしで大なりのときに設定
SETAE / SETNB CF = 0 符号なしの以上の場合にセット
SETB / SETNAE CF = 1 符号なしで小なりのときに設定
SETBE / SETNA CF=1 或 ZF=1 符号なしの以下の場合にセット

CMP EAX, EBX后跟SETG ALの効果は次のとおりです。EAX が符号付きで EBX より大きい場合、AL は1に設定され、それ以外の場合は0になります。これはJG label; MOV AL, 1; JMP done; label: MOV AL, 0; done:より簡潔で効率的です。

入出力命令

I/O 命令は、CPU と外部デバイスポート間のデータ交換に使用されます。

x86 アーキテクチャでは、ポートアドレス空間とメモリアドレス空間は互いに独立しており、専用の I/O 命令を使用してアクセスする必要があります。

助记符 功能简述
IN 指定されたポートから AL/AX/EAX にデータを読み込みます。ポートアドレスが 0〜255 の場合は即値を直接記述できますが、255 を超える場合は DX レジスタで指定する必要があります
OUT AL/AX/EAX のデータを指定されたポートに書き込みます。ポートアドレスの規則は IN と同じです
INS ポートからバイト/ワード/ダブルワードを ES:EDI が指すメモリへ読み込み、EDI を自動的に更新します（STOS に似ていますが、I/O から読み込みます）
OUTS DS:ESI が指すメモリのバイト/ワード/ダブルワードをポートに出力し、ESI を自動的に更新する。

現代のオペレーティングシステム（Windows、Linux）では、ユーザーモードのプログラムは通常 I/O 命令を直接実行できません。これらの命令はオペレーティングシステムによりカーネルモードでのみ使用可能に制限されています。DOS 環境やベアメタルプログラミングでは自由に使用できます。

プロセッサ制御とその他の命令

これらの命令は、フラグ操作、同期制御、システム情報の取得など、プロセッサの動作状態を制御するために使用される。

助记符 功能简述
CLC キャリーフラグをクリアし、CFを0にする
STC キャリーフラグをセットし、CFを1にする
CMC キャリーフラグを反転させ、CF をその逆の値にします
CLD 方向フラグをクリアし、DF を 0 に設定します。文字列操作のポインタは自動的に増加します
STD 方向フラグを設定し、DF を 1 に設定します。文字列操作のポインタは自動的に減少します
CLI 割り込みフラグをクリアし、IF を 0 に設定します。マスク可能なハードウェア割り込みを禁止します
STI 割り込みフラグを設定し、IF を 1 に設定します。マスク可能なハードウェア割り込みを許可します
NOP ノーオペレーション。マシンコードは 0x90 で、実質的な操作は実行しません。命令のアライメント、遅延の埋め込み、パッチ領域の確保によく使用されます
HLT 停止。プロセッサは外部割り込みまたはリセット信号を受信するまで実行を一時停止します
WAIT / FWAIT FPU が現在の操作を完了するのを待ちます。主に x87 コプロセッサとの同期に使用します。
LOCK バスロックプレフィックス。直後の命令をアトミックに実行させます。代表的な使用法：LOCK XCHG によるスピンロックの実装、LOCK CMPXCHG による CAS 操作の実装。
CPUID CPU の特徴情報を取得します。ベンダー ID、サポートされている命令セット拡張などが含まれます。呼び出し前に EAX に機能番号を設定する必要があります。
RDTSC タイムスタンプカウンタを読み取り、64 ビットのカウント値を EDX:EAX に格納します。高精度のパフォーマンス測定に使用します。

浮点指令

以下は従来の x87 FPU 浮動小数点命令です。浮動小数点スタックを使用した科学計算の場面に適しています。

現代のプログラミングでは、SSE/SSE2 などの SIMD 命令セットが x87 を徐々に置き換えていますが、レガシーコードを理解する場合や単純な浮動小数点演算を行う場合には、x87 は今でも広く使用されています。

助记符 功能简述
FLD メモリから浮動小数点数を FPU スタックの先頭 ST(0) にロードし、スタックポインタを上に移動します。
FST / FSTP スタックの先頭データをメモリに格納します。FST はスタックをポップしませんが、FSTP はスタックをポップします（スタックポインタが下に移動します）。
FADD 浮動小数点加算。ST(0)と指定されたオペランドを加算し、結果をST(0)に格納する。
FSUB 浮動小数点減算。ST(0) から指定されたオペランドを減算します。
FMUL 浮点乘法
FDIV 浮動小数点除算。ST(0) を指定されたオペランドで除算します。
FCOM / FCOMP ST(0) と指定されたオペランドを比較し、FPU ステータスワード内の条件コードを設定します。FCOMP は比較後にスタックをポップします。
FCHS ST(0) 内の数値の符号を変更します（正→負、負→正）。
FSQRT ST(0)の平方根を計算し、結果をST(0)に格納する。
FSIN / FCOS ST(0)の正弦/余弦値を計算し（引数はラジアン単位）、結果をST(0)に格納する。
FPTAN ST(0) のタンジェントを計算
FLD1 定数 1.0 をFPUスタックトップにプッシュ
FLDZ 定数 0.0 をFPUスタックトップにプッシュ
FLDPI 定数 π（3.14159...）をFPUスタックトップにプッシュ

x87 FPU 使用浮点寄存器栈（ST(0)～ST(7)、合計 8 つの 80 ビットレジスタ）に対して操作を行います。使用前にスタックの深さの制限に注意してください。8 個を超える値をプッシュするとスタックオーバーフロー例外が発生します。

注意事项

  • 符号付き命令と符号なし命令を区別する。MUL/IMUL、DIV/IDIV、条件ジャンプのJG/JA系は異なる数値解釈に対応します。アセンブラは型をチェックしてくれません——間違った命令を使うと静かに誤った結果を生成します。

  • 文字列操作の前に必ず DF フラグを設定してください。CLD（増加方向）または STD（減少方向）を使用して方向を明示的に指定し、デフォルト値を仮定しないでください。コンパイラや呼び出し規約が異なると、デフォルトの DF 状態が異なる可能性があります。

  • 現代のオペレーティングシステムは特権命令を制限している。CLI/STI、HLT、IN/OUT などの命令は Ring 3（ユーザーモード）で実行すると例外が発生します。これらの命令は通常、オペレーティングシステムのカーネルやベアメタル環境でのみ使用されます。

  • 現代の命令セットを優先して使用する。新しいコードでは、条件設定命令（SETcc）が条件分岐よりも優れています（分岐予測のオーバーヘッドを排除）。SSE/AVX 命令は x87 よりも優れています（パフォーマンスが向上し、プログラミングモデルがよりシンプル）。この表で扱う x87 および従来型命令は、主にレガシーコードを理解するために使用されます。
