アセンブリ言語 - 環境構築

この章では、Linux システム上に NASM アセンブリ開発環境を構築し、最初のアセンブリプログラムを作成する手順を説明します。

Linux 環境の準備

Windows システムを使用している場合は、インストールを推奨します。WSL（Windows Subsystem for Linux）または仮想マシンを使用して Linux 環境を用意してください。

macOS ユーザーは仮想マシンに Linux をインストールするか、Docker コンテナを使用できます。

本チュートリアルのすべての例は基づいていますUbuntu/Debianシステム、他のディストリビューションではパッケージマネージャのコマンドを適宜調整してください。

NASM アセンブラのインストール

Ubuntu/Debian システムでは、apt パッケージマネージャーを使用して NASM をインストールします：

$ sudo apt update
$ sudo apt install nasm

インストールが完了したら、NASM が正常にインストールされたかどうかを確認します：

$ nasm -version
NASM version 2.16.01

バージョン番号の出力が表示されれば、NASM は正常にインストールされています。

安装链接器

アセンブラが生成するのは目标文件（.o 文件）、直接実行できません。

オブジェクトファイルを実行可能ファイルに変換するにはリンカが必要です。ここでは GCC に付属のリンカを使用します：

$ sudo apt install gcc

その他にも、GNU リンカ ld を直接使用することもできます：

$ ld --version

本チュートリアルでは、主に使用しますgccリンクにはこれを使用します。低レベルの詳細を自動的に処理するため、初心者に適しています。

デバッグツール GDB のインストール

GDB（GNU Debugger）Linux で最もよく使われるデバッガで、プログラムのステップ実行、レジスタ状態の表示、メモリ内容の検査ができます。

$ sudo apt install gdb

GDB のインストール確認：

$ gdb --version
GNU gdb (Ubuntu 12.1-0ubuntu1) 12.1

最初のアセンブリプログラム：Hello, サンプル

新しいファイルを作成するhello.asm次の内容を入力します：

实例

; 文件路径：hello.asm
; 第一个汇编程序：打印 Hello, サンプル!
; NASM 语法，Linux 32位

section .data                       ; データセグメント：初期化済みデータを格納
    msg db 'Hello, サンプル!', 0xA    ; 文字列 msg を定義する。0xA は改行文字
    len equ $ - msg                 ; 计算字符串长度：当前地址 - msg 起始地址

section .text                       ; 代码段：存放可执行指令
    global _start                   ; _start をプログラムのエントリポイントとして宣言する

_start:                             ; 程序入口
    ; 系统调用 sys_write (4)：向 stdout 输出字符串
    mov eax, 4                      ; 系统调用号 4 = sys_write
    mov ebx, 1                      ; 文件描述符 1 = stdout（标准输出）
    mov ecx, msg                    ; 出力する文字列のアドレス
    mov edx, len                    ; 字符串长度
    int 0x80                        ; 触发中断，执行系统调用

    ; 系统调用 sys_exit (1)：正常退出程序
    mov eax, 1                      ; 系统调用号 1 = sys_exit
    mov ebx, 0                      ; 返回值 0 = 正常退出
    int 0x80                        ; 触发中断，执行系统调用

コンパイルと実行

コンパイルと実行の全体的な流れは図のとおりです：

次のコマンドを使用してこのプログラムをコンパイルして実行します：

$ nasm -f elf32 hello.asm -o hello.o    # 汇编：将 .asm 转为 .o 目标文件
$ ld -m elf_i386 hello.o -o hello       # 链接：将 .o 转为可执行文件
$ ./hello                               # 运行程序
Hello, サンプル!

上記の3つのコマンドのそれぞれの役割：

步骤命令说明
1. 汇编nasm -f elf32 hello.asm -o hello.o-f elf32 は出力形式を 32 ビット ELF に指定し、-o は出力ファイル名を指定します。
2. 链接ld -m elf_i386 hello.o -o hello-m elf_i386 は 32 ビットのリンクモードを指定し、実行可能ファイル hello を生成します。
3. 运行./hello現在のディレクトリでプログラムを実行する

GCC を使用したリンク（推奨方法）

お使いの環境の ld 設定が複雑な場合、gcc を使用してリンクできます。gcc が C ランタイムなどの詳細を自動的に処理します：

$ nasm -f elf32 hello.asm -o hello.o
$ gcc -m32 hello.o -o hello -nostartfiles
$ ./hello
Hello, サンプル!

-nostartfilesこのオプションは GCC にデフォルトの起動コードを追加しないよう指示します。自分で定義しているためです。_start入口点。

コード構造の解析

上記のプログラムを段階的に理解しましょう：

部分代码说明
数据段声明section .dataデータセグメントを宣言し、変数と定数を格納する
字符串定义msg db 'Hello, サンプル!', 0xAdb はバイト列を定義し、0xA は改行文字の ASCII コードです。
长度计算len equ $ - msg$ は現在のアドレスを表し、msg のアドレスを引くことで文字列の長さが得られます。
代码段声明section .textコードセグメントを宣言し、命令を格納する
入口声明global _start_start をグローバルシンボルとしてエクスポートします。リンカがそれを必要とします。
入口标签_start:プログラムの実行が開始される位置

int 0x80Linux 32 ビットのシステムコール命令です。ソフトウェア割り込みを発生させ、カーネルに eax で指定したシステムコールを実行させます。これはユーザープログラムと OS カーネルの間の橋渡しです。

GDB を使用したデバッグ

コンパイル時にデバッグ情報を追加し、GDB でステップ実行します：

$ nasm -f elf32 -g hello.asm -o hello.o       # -g 添加调试信息
$ ld -m elf_i386 hello.o -o hello
$ gdb ./hello
(gdb) break _start                             # 在 _start 处设置断点
(gdb) run                                      # 运行程序
(gdb) stepi                                    # 单步执行一条指令
(gdb) info registers                           # 查看所有寄存器
(gdb) x/s msg                                  # 查看 msg 字符串内容
(gdb) quit                                     # 退出 GDB
GDB 命令功能
break _start_start ラベルにブレークポイントを設定します。
runプログラムを実行し、ブレークポイントで停止する
stepi機械語命令を1ステップ実行する
info registersすべてのレジスタの現在値を表示する
x/s 地址指定したアドレスの内容を文字列形式で表示する

常见问题

64 ビットシステムで 32 ビットのアセンブリをコンパイルする場合は、32 ビット互換ライブラリをインストールする必要があります：sudo apt install gcc-multilib

ld リンク時に "cannot find entry symbol _start" というエラーが表示された場合は、コードが正しく記述されているか確認してください。global _startおよびラベル名が完全に一致していることを確認してください（アンダースコアに注意）。
