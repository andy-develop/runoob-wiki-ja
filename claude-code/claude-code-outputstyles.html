Claude Code 出力スタイル

出力スタイル（Output Style）を使うと、Claude Code の対話スタイルや応答方式をカスタマイズでき、ソフトウェア開発以外のさまざまな使用シーンに適合させることができます。同時に、ローカルスクリプトの実行、ファイルの読み書き、ToDo の追跡といったコア機能も維持されます。

その本質は、システムプロンプト（System Prompt）を変更することで、Claude Code の対話ロジックと応答スタイルを変えることです。

内蔵出力スタイル

Claude Code は、すぐに使える出力スタイルを3種類提供しています。

スタイル名 適用シーン 主な特徴
デフォルトスタイル（default） 日常のソフトウェアエンジニアリングタスク コーディング、デバッグ、リファクタリングなどの作業に効率的に集中し、簡潔で直接的な返答を行います。
説明スタイル（explanatory） 学びながら進めるシーン タスクを完了しながら、実装の考え方やデザインパターンなどの知識ポイントを解説します。コードを深く理解したい開発者に適しています。
学習スタイル（learning） 主体的に実践する学習 あなたと協力してタスクを完了し、重要な位置にTODO(human)マークを追加して、直接答えを与えるのではなく、核心的なコード断片を自分の手で実装するように導きます。

動作原理

出力スタイルを切り替えると、Claude Code は以下のルールに従ってシステムプロンプトを調整します。

  1. すべてのスタイルは、デフォルトの「簡潔な返答、効率的な出力」などの制約命令を削除します。
  2. カスタムスタイルは、デフォルトで「テストでコードを検証する」などのコーディング関連の命令を除外します（保持したい場合は、スタイルファイルで有効にすることができます。keep-coding-instructions: true）
  3. 各スタイルは、システムプロンプトの末尾にカスタムルールを追加し、デフォルトの動作を上書きします。
  4. 対話中にコンプライアンスチェックがトリガーされ、Claude が常に現在のスタイルの指示に従うようにします。

出力スタイルの切り替え

スタイルの切り替えには2つの方法があり、設定はプロジェクトディレクトリの.claude/settings.local.jsonファイルに保存され、現在のプロジェクトのみに有効です。：

方法1：メニュー選択——コマンドを入力した後、インタラクティブメニューで目的のスタイルを選択します。

/output-style

方法2：直接指定——コマンドの後にスタイル名を直接追加して、一発で切り替えます。

/output-style explanatory
/output-style learning
/output-style default

コマンドでの切り替え以外に、以下のファイルを直接編集することもできます。.claude/settings.local.json（プロジェクトレベル）または~/.claude/settings.json（グローバルレベル）ファイルのoutputStyleフィールドの値を変更してスタイルを切り替えます。

カスタム出力スタイルの作成

内蔵スタイルで要件を満たせない場合は、Markdown ファイルを使用して専用スタイルを定義できます。

1、ファイルの保存場所

レベル 保存パス 適用範囲
ユーザーレベル ~/.claude/output-styles/ 現在のユーザーのすべてのプロジェクトで使用できます。
プロジェクトレベル .claude/output-styles/（プロジェクトルートディレクトリ内） 現在のプロジェクトのみで使用可能で、git にコミットしてチームと共有できます。

2、ファイル形式

カスタムスタイルファイルは2つの部分から構成されます：上部のYAML frontmatter（メタデータ設定）と、その下のMarkdown 本文（具体的な指示内容）です。

例

---
name: data-analyst               # スタイル名。/output-style メニューに表示されます（未入力の場合はファイル名を使用）
description: 複雑なデータを可視化レポートと分析結論に変換することに注力します
                                 # スタイルの説明。メニューの説明文に表示されます（オプション）
keep-coding-instructions: false  # デフォルトのコーディング関連指示を保持するかどうか
                                 # false（デフォルト）：コーディング関連指示を除外します。非開発シーンに適しています
                                 # true：コーディング関連指示を保持し、さらにカスタムルールを重ねます
---

# 役割の定義
あなたはプロのデータ分析アシスタントであり、Python を使用してさまざまな構造化データを処理するのが得意です。
また、複雑なデータを簡潔でわかりやすい可視化レポートに変換します。

## 応答ルール
1. すべての分析には「結論 + データの裏付け + 改善提案」の3つの部分を含める必要があります
2. コードを生成する際は詳細なコメントを必ず付け、Pandas と Matplotlib を優先して使用します
3. 専門用語の羅列を避け、わかりやすい言葉で複雑な概念を説明します

## 形式要件
1. 結論部分は太字で表示します
2. コードブロックは ```python タグで囲みます
3. 提案部分は番号付きリストで表示します

## 特別なシーン
1. 欠損データに遭遇した場合は、直接エラーを出すのではなく、ユーザーに重要な情報の補充を積極的に促します
2. 可視化チャートを生成する際は、デフォルトで中国語のラベルとライトテーマを使用します

3、frontmatter パラメータの説明

パラメータ名 必須かどうか 説明 デフォルト値
name 否 スタイル名。表示されるのは/output-styleメニュー内です。未入力の場合はファイル名（.md 拡張子を除く）を使用します ファイル名
description 否 スタイル機能の簡単な説明。メニューの説明文に表示され、複数のカスタムスタイルを区別するのに役立ちます。 无
keep-coding-instructions 否 デフォルトのシステムプロンプト内のコーディング関連指示を保持するかどうか。設定がtrueの場合、カスタム指示がデフォルトのコーディング指示に重ねて適用されます。 false

4、使用手順

  1. 上記の形式に従って.mdファイルを作成し（例：data-analyst.md）
  2. ファイルを対応するディレクトリに配置します：
    • すべてのプロジェクトで使用可能：~/.claude/output-styles/data-analyst.md
    • 現在のプロジェクトのみ使用可能：.claude/output-styles/data-analyst.md
  3. Claude Code でコマンドを実行すると、/output-styleメニューに新しく作成したスタイルが表示され、選択できるようになります。

関連機能との違い

出力スタイルは以下の機能と似ていますが、作用するレベルが異なります。

比較対象 主な違い
出力スタイル vs CLAUDE.md 出力スタイルは置き換えることで、デフォルトのソフトウェアエンジニアリングシステムプロンプトを置き換え、Claude の作業モードを根本から変えます。CLAUDE.md はユーザーメッセージとしてプロジェクトの背景や規約を追加するもので、システムプロンプト自体は変更しません。
出力スタイル vs --append-system-prompt 出力スタイルはデフォルトのプロンプトを置き換えて無効にします；--append-system-promptデフォルトのプロンプトの末尾に内容を追加するもので、どちらも元のプロンプトを保持します。
出力スタイル vs サブエージェント（Subagent） 出力スタイルはメインエージェントのシステムプロンプトを変更し、グローバルな対話スタイルに影響します。サブエージェントは独立したタスク処理モジュールであり、モデル、ツール、トリガー条件をカスタマイズでき、特定のサブタスクを処理した後に結果を返します。
出力スタイル vs カスタムスラッシュコマンド 出力スタイルは「保存されたシステムプロンプト」であり、Claude 全体の対話スタイルを決定します。カスタムスラッシュコマンドは「保存されたユーザープロンプト」であり、特定の指示やタスクをすばやく実行するために使用します。

カスタムスタイルテンプレート

以下は汎用のカスタム出力スタイルテンプレートの[ ]内容を実際のニーズに置き換え、.mdファイルとして保存すれば使用できます：

例

---
name: [スタイル名。例：ライティングアシスタント]
description: [用途を一言で説明。例：技術文書の作成に注力し、構造が明確で表現が正確なコンテンツを出力します]
keep-coding-instructions: [true または false]
---

# 一、コアとなる位置づけ
[Claude の役割と専門性を定義します。例：
あなたは専門的な技術文書作成アシスタントであり、複雑な技術概念を明確でわかりやすい文章に変換するのが得意です。]

# 二、応答ルール
[Claude の返答ロジックを規定します。例：
1. 毎回の返答には「要点 + 詳細な説明 + 例」の3つの部分を含める必要があります
2. 能動態を使用し、受動態の文は避けます
3. 専門用語が初めて登場するときは、簡単な説明を添えます]

# 三、形式要件
[出力のレイアウト形式を指定します。例：
1. 見出しは## を使用したレベル2見出し
2. コード例はコードブロックを使用し、言語タイプを明記します
3. 重要な情報は太字で強調します]

# 四、特別なシーンの処理
[特定の状況に対する処理ルール。例：
1. 例を挙げる必要がある場合、抽象的な例ではなく実際のシーンを優先する
2. 表現が不明確な要件に遭遇した場合、意図を確認してから書き始める]
