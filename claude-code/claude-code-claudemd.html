CLAUDE.md 使用ガイド

CLAUDE.mdは Claude Code において最も重要な設定ファイルであり、Claude にプロジェクトレベルの永続的な指示を伝えるために使用されます。Claude Code セッションを起動するたびに、このファイルの内容が自動的に読み込まれ、システムレベルのコンテキストとしてすべての会話に組み込まれます。

わかりやすく言うと、CLAUDE.mdこれは、プロジェクト内で Claude に渡す「仕事マニュアル」のようなものです。このプロジェクトが何なのか、どのような規約に従うのか、どのような注意点があるのかを Claude に伝え、毎回の会話で改めて説明し直すことなく、毎回プロジェクトの要件に沿った方法で作業できるようにします。

CLAUDE.md の役割

[CLAUDE.md] がない場合、CLAUDE.mdClaude は毎回ゼロからプロジェクトを理解する必要があり、どのパッケージマネージャーを使うのか、コードスタイルは何か、テストの実行方法、どのファイルを変更してはいけないのかを、何度も伝えなければなりません。[CLAUDE.md] があれば、CLAUDE.mdこれらの情報は一度書くだけで、Claude は毎回それを守ってくれます。

具体的には、CLAUDE.md以下のことを実現できます：

  • チームの行動を統一する：ファイルを git にコミットすれば、すべてのチームメンバーが Claude Code を使用する際に同じ規約を守ることができます
  • 重複したコミュニケーションを減らす：プロジェクトの約束事、アーキテクチャのルール、禁止事項を一度書くだけで、永続的に有効になります
  • エラー発生の確率を下げる：Claude にどの操作にリスクがあるかを明確に伝え、誤った判断を避けさせます
  • AI の理解を加速する：Claude が重要なファイルを素早く見つけ、プロジェクト構造を理解するのを助け、不要なファイル探索を減らします

ファイルの配置場所

Claude Code は複数の場所から [CLAUDE.md] を読み込みますCLAUDE.md。場所によってファイルの適用範囲が異なります：

場所 パス 適用範囲 git にコミットするか
プロジェクトルートディレクトリ {项目根目录}/CLAUDE.md 現在のプロジェクトのすべてのセッション ✅ コミット推奨、チームで共有
プロジェクトローカル {项目根目录}/.claude/CLAUDE.md 現在のプロジェクトのすべてのセッション ❌ .gitignore に追加、個人のみで使用
サブディレクトリ {任意子目录}/CLAUDE.md Claude がそのディレクトリ内のファイルを開いたときに自動的に読み込まれる ✅ マルチモジュールリポジトリに適している
グローバルユーザーレベル ~/.claude/CLAUDE.md 現在のユーザーのすべてのプロジェクト ❌ 個人設定、コミットしない

複数の場所に存在する場合、CLAUDE.mdClaude Code はそれらをすべて読み込んでマージします。優先順位は高いものから低いものの順に次のとおりです：

プロジェクトローカル → プロジェクトルートディレクトリ → サブディレクトリ → グローバルユーザーレベル

プロジェクトルートディレクトリの [CLAUDE.md]CLAUDE.mdは git にコミットして、チーム全体で同じ AI 作業規約を共有することをお勧めします。

個人的な好み（例：セミコロンを付けたくない）は [CLAUDE.md] に.claude/CLAUDE.md入れて、[.gitignore] にも追加すれば、.gitignore他の人に影響を与えません。

CLAUDE.md をすばやく作成する

最も簡単な方法は、Claude Code に初期バージョンを自動生成させることです。プロジェクトディレクトリで Claude Code を起動した後、以下を実行します：

/init

Claude Code は、プロジェクトの構造、コードスタイル、既存の設定ファイル（例：package.json、pyproject.toml、.eslintrcなど）を分析し、プロジェクトの実情に合った [CLAUDE.md] を自動生成します。CLAUDE.mdその後、これを基に補足や調整を行うことができます。

プロジェクトディレクトリに手動で作成することもできます：

touch CLAUDE.md

CLAUDE.mdは通常の Markdown ファイルであり、強制的なフォーマット要件はありませんが、適切な構造は Claude が重要な情報をより早く見つけるのに役立ちます。以下は推奨される内容構成です：

- 语言：Python 3.11
- 框架：FastAPI 0.110
- 数据库：PostgreSQL 15 + SQLAlchemy ORM
- 测试：pytest

3、コーディング規約

Claude にプロジェクトのコードスタイルと約束事を伝え、生成されるコードが既存のコードベースのスタイルと一致することを保証します：

## 编码规范

### 通用
- 文件名使用 kebab-case（如 `user-profile.ts`），类名使用 PascalCase
- 优先使用具名导出（named export），避免默认导出（default export）
- 异步函数一律使用 async/await，禁止使用 .then() 链式调用

### 组件规范
- 组件文件与其测试文件放在同一目录（如 `Button.tsx` 和 `Button.test.tsx`）
- Props 类型使用 interface 定义，命名格式为 `${组件名}Props`
- 不要将业务逻辑写在组件中，提取为自定义 Hook 或 Service

### 错误处理
- API 路由使用统一的错误响应格式：`{ error: string, code: string }`
- 客户端错误通过 Error Boundary 捕获，不要在每个组件里单独 try/catch

4、アーキテクチャの制約と禁止事項

これは、Claude が「賢いが誤った」判断をするのを防ぐための重要な部分です。あなたが知っているが Claude が知らない特別な状況については、明確に書き出す必要があります：

## 架构约束

- 所有数据库查询必须通过 `src/lib/db/queries/` 中的函数执行，不要在路由或组件中直接写 SQL
- 状态管理使用 Zustand，不要引入 Redux 或其他状态管理库
- 样式使用 Tailwind CSS utility class，不要新增 CSS 文件或使用 CSS Modules

## 注意事项（重要）

- `legacy/` 目录下的代码是遗留代码，**禁止修改**，只能读取
- `.env.local` 和 `.env.production` 包含真实密钥，**禁止输出文件内容**
- `prisma/migrations/` 中已有的迁移文件**禁止修改**，数据库变更只能新增迁移
- 修改 `src/middleware.ts` 前必须先告知我，该文件影响所有路由的认证逻辑

CLAUDE.md のメンテナンスに関する提案

1、簡潔に保つ

CLAUDE.md[CLAUDE.md] の内容は毎回のセッションでコンテキストウィンドウを占有します。内容が多すぎると、Claude が実際に利用できるコンテキスト空間が圧縮され、逆に効率が低下します。次の原則に従うことをお勧めします：

  • 各ルールは一度だけ書き、同じ意味を繰り返し表現しない
  • コードと無関係な背景情報（会社紹介、製品計画など）は書き込まない
  • コード自体で伝えられる情報（eslint 設定がすでにコードスタイルを定義している場合など）は、CLAUDE.md[CLAUDE.md] で重複して宣言する必要はありません。
  • 総文字数は500字以内に収めることを推奨します。1000字を超える場合は簡素化を検討する必要があります。

2、継続的に更新する

プロジェクトの進化に伴い、CLAUDE.md[CLAUDE.md] も同期して更新する必要があります。以下のタイミングで更新すべきです：

  • パッケージマネージャーやビルドツールを変更した
  • 重要な依存ライブラリを追加または削除した
  • 新しいコーディング規約を制定した
  • Claude が同じ種類のエラーを繰り返していることに気づいた（[CLAUDE.md] にCLAUDE.md補足説明を追加する必要があることを示しています）
  • 特定のファイルやモジュールが簡単に変更できなくなった（注意事項に追加する）

3、命令形の言語を使う

指示が明確であればあるほど、Claude が従う確率が高くなります。曖昧な説明を避け、直接的な命令を使用してください：

❌ 曖昧な説明 ✅ 明確な指示
コードはきれいにすべき 関数は50行を超えないこと。超えた場合は分割すること
できるだけテストを書くこと 新しく追加する関数には、必ず対応するユニットテストを書くこと
セキュリティに注意すること ユーザー入力は必ずsanitize()関数で処理してからデータベースクエリに渡すこと
legacy ディレクトリはあまり重要ではない 変更禁止：legacy/そのディレクトリ内のすべてのファイル
pnpm を使う方が良い 依存関係の管理は pnpm のみを使用し、npm や yarn の使用は禁止する

以下は Node.js + TypeScript フルスタックプロジェクトのCLAUDE.md[CLAUDE.md] の完全な例です。あなたのプロジェクトの参考テンプレートとして使用できます：

実例

# MyApp — EC管理バックエンド

Next.js ベースjs 14 App Router + Prisma +PostgreSQL を使用した EC 管理システム。

## 技術スタック
-フロントエンド：Next.jsjs 14（App Router）、TypeScript、Tailwind CSS、shadcn/ui
-バックエンド：Next.jsjs API Routes、Prisma ORM
-データベース：PostgreSQL15
-認証：NextAuth.jsjs v5
-パッケージ管理：pnpm

## よく使うコマンド

```bash
pnpm dev # 開発サーバーを起動（ポート3000）
pnpm build &&pnpm start # ビルドして本番サーバーを起動
pnpm test # 全テストを実行
pnpm test:e2e # エンドツーエンドテストを実行（事前に dev server を起動する必要あり）
pnpm db:migrate # データベースマイグレーションを実行
pnpm db:studio # Prisma Studio を開く（データベース可視化ツール）
pnpm lint &&pnpm typecheck # コードチェックと型チェック
```

## プロジェクト構成

- `src/app/` — App Router ページと API ルート
- `src/app/(dashboard)/` — ログインが必要な管理ページ
- `src/app/api/` — API ルート（RESTful スタイル）
- `src/components/` — 再利用可能なコンポーネント
- `src/lib/` — ユーティリティ関数、データベースクライアント、認証設定
- `prisma/schema.prisma` — データベーススキーマ定義

## コーディング規約

-名前付きエクスポートのみ使用（namedexport）、禁止default export（Next.js を除くjsページファイル以外）
-サーバーコンポーネントはデフォルトで async、クライアントコンポーネントはファイルの先頭に ` を追加"use client"`
-API ルートの統一返却形式：成功 `{ data: T }`、失敗 `{ error: string, code: string }`
-データベースクエリは `src/lib/db/` ディレクトリにカプセル化し、他の場所では直接 `prisma` クライアントを使用しない

## 注意事項

- `prisma/migrations/` 内の既存ファイルは**変更禁止**、データベース変更は `pnpm db:migrate` で新しいマイグレーションを実行するのみ
- `.env.local` には実際の秘密鍵が含まれるため、**ファイル内容の読み取り・出力を禁止**
- `src/lib/auth.ts` は認証の中核ファイルであり、**変更前には必ず私に知らせること**
-`prisma/schema.prisma` を変更したら必ず `pnpm db:migrate` を実行し、マイグレーションファイルをコミットすること

よくある質問

Q：CLAUDE.md のルールを Claude が守らない場合はどうすればいいですか？

まず、ルールの表現が十分に明確かを確認してください（上記の「命令形を使う」という提案を参照）。表現が明確なのに守らない場合は、個別の会話で再度強調するか、そのルールをファイルの前方に移動してください——Claude はファイル前半部分の内容に注意を払いやすいです。

Q：CLAUDE.md は長いほど良いですか？

いいえ。内容が多すぎると 2 つの副作用があります。1 つはコンテキストウィンドウを占有し、Claude が実際のタスクを処理するスペースを圧迫すること。もう 1 つは重要なルールが大量の文章に埋もれて、かえって守られにくくなることです。定期的に見直し、適用されなくなった項目や価値の低い項目を削除することをお勧めします。

Q：サブディレクトリの CLAUDE.md はいつロードされますか？

Claude がそのサブディレクトリ内のファイルを開いたり編集したりすると、そのサブディレクトリのCLAUDE.mdが自動的にロードされます。Claude に手動で読み取るよう指示する必要はなく、プロセス全体が自動です。

Q：CLAUDE.md 内で別の CLAUDE.md を参照できますか？

直接参照はできませんが、@ファイルパス構文を使用して任意の Markdown ファイルの内容を参照できます。モジュール間で共有する規約がある場合は、独立したドキュメントファイルに抽出し、それぞれのCLAUDE.mdで@参照することをお勧めします。
